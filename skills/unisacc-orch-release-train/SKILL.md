# 发布列车

通用规程,不含某一版的流水与事故;具体版本的账本在 `prd_mempalace.md` 与证据目录,事故转改进见 `unisacc-pipeline-lessons`,督导见 `unisacc-orch-supervise`。数字、摘要、时刻一律从命令输出或证据文件机器提取,不手抄;称呼只用真版本号。

## (1) 阶段顺序

槽行 -> 内容截止 -> 合入 -> 编号提交 -> 整链 -> 预跑 -> 补跑与折叠 -> 冻结 -> 发布执行(推送、草稿、CI、公开、读回) -> 公开后记账 -> 解冻。

每段完成核产物身份与退出状态再进下一段,不盲目自动续排。上一段假绿会在下一段以更贵的形式爆出。

## (2) 起链前置清单

- 共享检出与版本树工作区干净;根目录的产品与构建元数据文件是常规文件副本,不是符号链接。
- 版本车在飞期间共享主干不再前进(含纯文档提交,它会让"落后于远端"类门变红);文档留工作区,公开后统一提交。
- 编号提交一次做全:版本序号、候选表的版本列、冻结行(base 为最后一个编号提交,单独最后一笔)、版本计划文档;编号集合以仓内登记表为准(查 chain-ready 的编号门),后置的测试登记不触发"编号晚于冻结"。
- 派生物同步做完(见 (7)),再跑 `chain-ready` 全门,不是只跑几门。
- 环境口径固定且最小:`env -i` 加 HOME、PATH、TMPDIR、DEVSVC_OWNER 和显式的身份帮手路径;不继承任何其它 `UNISACC_*` 变量(缓存目录、免拉取开关等会污染多个门)。
- 并发敏感的门(如 core 编译类)在负载下会超时,必须静默单跑取证,不凭一次红判定。
- 起链与预跑期间全体零重编译、负载低于阈值;同输入无在途链(`pgrep` 真实 PID)。
- 起链由唯一写手执行,起后回报 job id、PID/PGID、起始、预计完成;回执标题必须与证据一致。

## (3) 整链失败类别与最便宜拦截点

| 根因 | 最便宜拦截点 |
|---|---|
| Root 文件是符号链接 | 起链前 `test -L` 核类型 |
| 快照缓存类型不对 | 复用前核类型,不只核提交号 |
| 绑定与模板不同步 | 改绑定时同提交跑模板一致性检查 |
| 链模板被新拒绝规则打中 | 新增拒绝规则时对链模板跑一遍 |
| 模板常量未同步 | 改模板即重算常量,检查比对 |
| 目标平台声明表未同步 | 新增系统调用或进程原语时同步平台声明 |
| 检查写死数量 | 检查改读表,不写字面量;新增项同提交改常量 |
| 身份帮手缺失 | 起链入口自检,帮手路径显式 |
| 新增批后派生表漏同步 | 提交前跑 (7) 的清单 |

共同教训:每类都能在提交时用秒级检查拦住,而不是在整链里花分钟级发现。

## (4) 运行方式

- 整链用 `bg-candidate` 脱离终端以守护进程运行,用 Monitor 订阅终态,不定时轮询。
- 观察超时不等于进程终态,核真实 PID/PGID 后再判。
- 同一目录、起链、公开步骤同一时刻只有一个写手;并发起手式会互相删目录。

## (5) 预跑

- 起跑形态固定:外层 `timeout` 带 `-k`,总时限留足,`--resume --keep-going`,并发窗数与每窗作业数按本机核数取;无外层 timeout 的预跑立即终止重起。工具打印的推荐命令与本规程冲突时以规程为准并记缺口。
- 参数以各子命令的真实参数表为准;串成多步时任一步被拒即停,不得在被拒后派生 wrapper 绕过。
- 预跑目录绑定冻结 REV:红停后的修补提交即使源码身份不变,也不能原位续跑消费;旧目录整体 `mv` 备份(不删),新目录重跑;人工调度标记续跑只在所有者或编排者明确授权时,写明授权人、时刻、原因、原证据摘要,账本同记,不冒充工具产物。
- 暖机窗首试超时是预期(冷工具链加冷材料),重试转通过;半成品材料目录(有目录无清单)必须 `mv` 备份后重备。
- 红停先读发码源码行,手跑复现,再分类:陈旧常量或派生表、贴限批、真回归、首跑冷态、负载性。判回归必须有同布局交替对照原行,不凭差值;合车版产品红两次即拆回单车。
- 补跑窗口:窗号唯一并校验不存在,先同布局预热一次丢弃再正式取原始证据;补跑命令禁止任何 `rm`、`mv`、覆盖证据文件。折叠按批 ID、按文件名字典序摄入,补跑文件名必须排在原窗口文件之后;后行通过覆盖旧失败与未知,原行永不删。
- 贴限批首试超时、重试通过是冷态,不登记预期未测;热态仍超时的才走登记;失败不能走登记,必须修。批的装箱不得把贴近单批内限的批并入普通窗。

## (6) 发布站与公开后

- 顺序:归档、预演、发布执行各步、公开后记账(版本序号标记必须在公开读回之后,解冻、旧产品资产登记、备份证据)。
- 发布执行没有单步入口,`--from-step` 会继续后续步骤,不能用来单步演练;推送与公开前后核双远端引用;链后合并路径独立实算源码身份并留痕。
- 公开正文与提交内 notes 用原字节比对(`jq -j`,不用 `jq -r`)。公开说明如实写已知缺口:首跑冷态、红停与修补、补跑与折叠、被延后的车及原因、残留。证据归档里的家目录绝对路径脱敏并标注原字节摘要对应。
- 记账写 `prd_mempalace.md`(决定、依据、证据入口、回滚办法);`release-post run --execute` 默认自动装根并做 sha256/版本/冒烟与备份回滚闭环, 跳过须 `--no-root-upgrade 理由` 且写 SKIPPED 绝不记 DONE; Step 8 / `thaw` 强制绑定本版 40 位 Y2、版本 SHA 与 `root-current --no-candidate-ahead`(门 24, 原设计称门 20), 候选超前与落后根一律拒绝解冻。

## (7) 新增批、生成器、分片、产品输入文件之后必查

1. 全生成器清单的总数与检查里的常量及分半口径对账。
2. 日常编译冒烟的分片表与日常层批的双射。
3. 产品输入文件集合的派生表。
4. `derive.cx --check` 全量(先 `--prepare-native`)。
5. 层 API 版本、接口哈希、库包登记、核心接口表(新增导出符号)、链接表。
6. 工具编译源表、`register.cx --tool` 登记、批次与覆盖与批的产品输入三表。
7. 扫描测试目录下所有 `--write` 工具,确认没有别的"新增批后需重生成的分片表"。
