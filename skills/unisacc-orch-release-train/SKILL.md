# 发布列车

## (1) 阶段顺序

槽行 -> 内容截止 -> 合入 -> 整链 -> 预跑 -> 冻结 -> 阶段 A -> release-exec -> 公开后记账 -> Root 升级 -> 解冻。

每段完成核产物身份与退出状态再进下一段,不盲目自动续排。原因:上一段假绿会在下一段以更贵的形式爆出。

## (2) 起链前置清单

- `sh ./unisacc.com tools/chain-ready.cx` 全部项通过,末行 `READY=yes`。
- Root 与快照文件必须是常规文件,不是符号链接。原因:符号链接让身份核对指向别处,链中途被拒。
- 快照缓存按提交号复用但不核文件类型,起链前自己核一遍类型。
- 本机无同输入在途链(pgrep 真实 PID)。原因:同输入双链互写产物。

## (3) 整链失败七类根因与最便宜拦截点

| 根因 | 最便宜拦截点 |
|---|---|
| Root 文件是符号链接 | 起链前 `test -L` 核类型 |
| 快照缓存类型不对 | 复用前核类型,不只核提交号 |
| parse2 绑定与模板不同步 | 改绑定时同提交跑模板一致性检查 |
| 链模板原型被新拒绝规则打中 | 新增拒绝规则时对链模板跑一遍 |
| 链模板 SHA 常量未同步 | 改模板即重算常量,检查比对 |
| win 目标 fork 未声明 | 新增 fork 时同步平台声明表 |
| 检查写死生成器数量 | 检查改读表,不写字面量 |

共同教训:每类都能在提交时用秒级检查拦住,而不是在整链里花分钟级发现。

## (4) 运行方式

- 整链用 bg-candidate 脱离终端以守护进程运行。原因:终端会话结束会带走子进程。
- 用 Monitor 订阅终态事件,不定时轮询。原因:轮询占上下文且易误判超时为终态。
- 观察超时不等于进程终态,核真实 PID/PGID 后再判。

## (5) 预跑

- 先修 `windows.tsv` 并发列,使与本机核数一致。
- W0000 暖机窗:kit 构建超窗时用 `dvqualify --resume` 分次补完,不放宽窗时限。
- W0001 prebuild-self 在资格布局内预制。
- 窗口外层 58 秒放不下重窗口会空停,用 `dvqualify --resume` 收尾。
- 真 FAIL 保留 FAIL 行,用 `-r2` 窗口取代;G1 认 SUPERSEDED。原因:删 FAIL 行是篡改证据。
- 严格证据按窗口序号逐窗原样拼接,不用 merge。原因:merge 会重排或去重,破坏逐字节证据。

## (6) 冻结合并预演

在私有副本里预演版本分支合入 main:列冲突文件;跑 `tools/scrub-home-paths.cx` 与 `tools/no-home-path.cx` 确认无家目录绝对路径新增。原因:冻结后才发现冲突或隐私行要重冻结。

## (7) 公开后

记账写 `prd_mempalace.md`(决定、依据、证据入口、回滚办法);Root 升级后才解冻,解冻后合入积压的版本短名分支。
