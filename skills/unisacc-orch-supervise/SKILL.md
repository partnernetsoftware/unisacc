# 督导与巡检

## (1) 事件驱动优于定时轮询

用 Monitor 或 devsvc 事件订阅等终态;不得不轮询时同时设总 deadline 与次数上限。原因:无界轮询占上下文,且把观察超时误当进程终态。定时器只做"周期性补漏与推进"的心跳(见 (9)),不用来等某个具体作业的终态。

## (2) 窗口终态判定

- 只以真实句柄判:PID/PGID 不在、退出码已落、证据文件已写。
- 代理消息与旧日志不算终态。
- 超时只说明观察结束,先核后代进程再决定清理,绝不据超时盲目重启。

## (3) 已停立即派下一件

窗口停下就从任务板取下一件派出,确认送达。原因:流水线断档的成本远高于额外一次派工。等待期间做未来版本预备、清洁、根治红灯。

## (4) 信封频率

每个窗口每 20 分钟至多一条信封。原因:频繁打断让执行者反复丢上下文,产出反而下降。

## (5) 暂停令

写清停什么、不停什么、何时恢复、恢复条件。例:"停止向 main 推送;下一版版本分支照常推;0.0.NN 公开后恢复"。原因:只写"暂停"会让执行者全停,浪费并行。

## (6) 巡检项

| 项 | 做法 |
|---|---|
| 磁盘 | `df -h` 看仓与临时目录所在分区;清自己产生的过期产物 |
| 残锁 | 列 devsvc 锁与 private index 锁,持锁 PID 不在才清,只清自己的 |
| 孤儿轮询壳 | pgrep 找无父会话的 while/sleep 壳,按真实 PID 终止,先在账本写一行 |
| 在途作业 | 核每个作业的输入身份、deadline、真实 PID |
| 工作位置 | 每轮三数:(1)`/tmp` 里 unisacc-session-、chain-ready-check-、check-guard-hook.d.、cx-layers- 等族近 2 小时新增数(应接近 0,窗口 TMPDIR 已指向自己的 w- 树);(2)`~/.local/share/unisacc` 近 2 小时新增文件数(应为 0,历史 .patch/.md 只读);(3)`git worktree list` 的 w- 树与在岗窗口对账(孤儿树删,每窗口一棵)。超线点名窗口并让其删,不看口头回执。整仓副本(含 cx/ 与 tools/ 的目录)出现在 /tmp 或 ~/.local/share 即违规 |
| 根版本漂移 | 每轮巡检调用 `cx tools/root-current.cx` (门 `24-root-current`, 原设计称门 20), 解冻必传 `--no-candidate-ahead`, 否则红灯禁止解冻 |

## (7) 任务板

保持精简,不超过 8 条;同类小项池化合并成一条。原因:长任务板让优先级失真,编排者自己也会漏派。

## (8) 不理会执行者的上下文与额度

不以执行者窗口上下文长短或额度为由让其休息;停了就派。原因:额度不紧,休息即断档;上下文由执行者自己的机制处理。巡检与简报不看、不报上下文余量;codex 窗口若自称上下文不足(提余量、拒接活、要交接),编排者直接向其发送 `/compact` 触发压缩后照常派活(所有者 2026-11-28)。

## (9) 双定时器编排(长会话经验)

- 两个 CronCreate:15 分钟档(`4,19,34,49 * * * *`,提示词"按 plans/goal-15m-unisacc.md 来推进")做读在途、核对、补派;10 分钟档(`2,12,22,32,42,52 * * * *`,提示词"坚持[扩散并行工作思维]开fable继续推进结构改进")每次开一个只读 fable 诊断。避开 :00 与 :30。仅本会话有效、30 天过期、会话被 ^C 即丢;改定时器就是 CronDelete 再 CronCreate。
- 追加规则:回看上一轮简报,"待你决定"非"无"时不留给用户,开 fable 协商并裁定一个选项再执行;不可逆对外动作(公开、删他人数据)仍单列。
- 恢复:会话丢失后,从旧会话 jsonl 的 `"subtype":"scheduled_task_fire"` 记录读触发分钟还原周期,提示词取用户原话,重建后向用户报任务 ID 与下次运行时间。
- fable 诊断一次一个主题、12 分钟截止、至多 3 条带证据与可证伪条件的建议;读它自述的"我最可能错在哪",没实跑的结论先估占比再决定做不做(例:PATH 试错只占约 1.6%,不改产品)。
- 每轮简报:结论一句,其余表格或短列表,段落不超 400 字(停机钩子 tools/hook-prose.cx 会拦);尾行"待你决定:无"或单列。
- 派工:`mux envelope --body-file 文件 -- 1:窗口名 "标题"`(用窗口名不用索引,不带 --from);回执无 `submitted` 标记的,下一轮读回窗口末几行确认。注意 (4) 的频率约束:一轮内对同一窗口合并成一封,本次长会话多次违反,造成打断。
- 同文件多窗口同改会首尾相接阻塞(proc.cx、sysnums.cx、NSYS 计数):破死锁办法是在途半成品方把改动撤出共享路径并保留补丁,先落先到者再重放;提交取索引,不用整文件工作区取内容吞他人半成品。
- 复测别人报的数字再采纳;rc=124 与 refused 是具名结果,读发码源码行再定性;行为变更(如双 fd poll 改顺序等待)必须补最坏用例与变异自证。
- 版本分支只放产品输入类改动;tools/、devsvc 与 plans/devsvc.md 等开发基础设施一律在 main 上改,避免版本分支与 main 对同一文件双改、合并时语义未证。
- 冻结前做一次"并集树只读预合并检查"(归档 main 加分支独有文件,逐个跑生成器 --check 与 derive --check、check-derive),把语义冲突提前暴露。
- `git revert` 带 `merge=union` 表的陷阱:`tests/batches.tsv`、`tests/coverage.tsv`、`build/links.tsv` 等在 `.gitattributes` 配了 `merge=union`,当待回退提交的增删行与后续追加行发生上下文重叠时,`git revert` 的 union 合并驱动会静默保留本应删除的行(即使 `tests/manifests/*.tsv` 已删),回退后必须显式核对并剔除残留行再跑 `links-gen --write` 与 `derive --check`。
- 常驻铁律(压缩与长会话必丢对话里的规则,所以只认写在此处、记忆索引与定时器提示词里的):(1) 冻结或预跑期间只禁共享检出 main 与冻结域,不禁未来版本工作;发冻结广播时同一封信里给每个窗口派一个版本工作树任务,闲置窗口是编排者的失误;(2) 不说"你说得对"类认错话,只报动作与结果;(3) 所有者要决定的事自己开 fable 裁定并执行;(4) 工具打印的命令必须用目标子命令的参数表自检后再执行;(5) 预跑窗口首轮超时重试后转通过属冷态,同一窗口连续两次先看续跑重轮,不立刻判确定性缺陷。
- 工具:devsvc f write/edit 在版本工作目录下相对路径会落到主检出,一律用绝对路径;改文件不用 sed -i;主调度自己的提交也走 devsvc 或 commit-own,原生 git commit 会使 devsvc 因 unowned-pending 拒绝推送。

## (10) 通用纪律补充

- 每个窗口基本只在自己的仓内私有工作树 `.claude/worktrees/w-<窗口名>` 里工作(2026-11-26 所有者令):在树里提交并交提交号,编排者 cherry-pick 落库;报告写树内 `.work/`;`/tmp` 与 `~/.local/share/unisacc` 不是工作目录。派工信必带"工作位置"一段(见 unisacc-orch-dispatch)。

- 单写手:预跑目录、起链、公开步骤、共享检出索引同一时刻只有一个写手;并发起手式会互相删目录。
- 证据不得删:补跑与恢复命令禁止 `rm`、`mv`、覆盖证据文件;会话压缩后恢复的执行者首轮先读最新信封再动手,信封里复述"保留某文件"类约束。
- 红停先读发码源码行再分类,判回归必须有同条件交替对照;合车件产品红两次即拆回单车。
- 新增批、生成器、分片、产品输入文件后跑派生物同步清单(见 unisacc-orch-release-train),否则预跑必红停。
- 数字与摘要机器提取,不手抄;回执标题必须与证据一致。
- 不因执行者上下文余量让其停手、换人或清上下文;停了就派。
- 历史账本不进技能:某一版的流水、事故与分数记在 `prd_mempalace.md`、证据目录或研究页,技能只放可复用规程。
