# omp 编排组章程（cc 编排）

日期：2026-11-02。起因：主人指出“编排好几次被 cc 搞混乱了”。本文记录事实、成因和今后的固定做法，不是口号。

## 1. 已发生的编排错误（事实清单）

| # | 错误 | 后果 | 成因 |
|---|---|---|---|
| 1 | 首次给 agent 派活用裸 `tmux send-keys` | 无落款、不可追踪 | 不知道有 `moltbaby/bin/envelope`，没先读 SKILL |
| 2 | 裁定“直接原子替换 M4 候选”，忘了所有工具靠 `sh ./unisacc.com` 需要 APE 壳 | 安装失败、回滚 | 没核对“产物形态 vs 使用方式” |
| 3 | 给 omp-go 写“请与 omp-ds 对齐谁改 process.cx”“登记前先问对方” | 主人看到 ds↔go 直接对话 | 措辞让 agent 互相对接，且没有路由表 |
| 4 | 把规则说成“协同对象只有 cc”，又自己在 bdy 与 go 之间传话 | go 过度保守、cc 成瓶颈 | 规则过宽，没区分主线搭档与单线 agent |
| 5 | 提交新 `.cx` 文件前后只看了提交前的 ratchets | cxtrunc 红了三次（streampack、root-identity） | 棘轮只数已跟踪文件，提交后才暴露 |
| 6 | 看到检查失败（35/3）仍在同一命令里继续提交 | 事后才复核（碰巧是瞬时） | 把“跑检查”和“提交”写进一条命令 |
| 7 | 归因错：把 cxtrunc 红归给 check-register.cx | 派错人 | 没读 ratchets 明细就转述 |
| 8 | commit-own 把符号链接按内容提交 | HEAD 里出现拷贝 | 用工具时没测特殊文件类型（已修） |
| 9 | 估数口径混用（“33 个”“约 30 个”） | bdy 需要核对纠正 | 引用旧会话数字当目标口径 |

## 2. 路由表

| 谁 | 对谁直接沟通 | 必须找 cc |
|---|---|---|
| omp-bdy ↔ omp-go（0.0.44 主线搭档） | 彼此直接：接口约定、文件归属与先后、评审往返、复现与验证结果。事后给 cc 一行摘要“谁→谁:什么事:结论” | 范围变更、授权类、对外/不可逆、跨车道、harness 冻结与长跑会话、共享表冲突、需主人决定的事 |
| omp-ds | 只与 cc | 一切 |
| omp-go2 | 只与 cc | 一切 |
| cc | 派活、审核、提交（commit-own）、冻结/解冻、对主人汇报 | — |

规则：cc 派活时不得写“请与某某对齐”；涉及他人文件，由 cc 点名归属。cc 不当 bdy↔go 的传话筒。

## 3. 派活信封模板（缺一项不发）

1. 目标（一句话）与验收证据（可执行命令/断言）。
2. 读写路径：可写哪些、禁写哪些、哪些文件有人正在改（先 `git status` 看）。
3. 当前是否有长跑会话/冻结（影响能不能改 tools/ tests/ cx/）。
4. 硬规：进程数限制只写子 shell 且按线程算；不 `pkill -f`；不自行提交（cc 用 commit-own）。
5. 回报方式：`envelope cc`，附结论与证据路径。

## 4. cc 的提交检查清单（两步，禁止写在一条命令里）

1. 单独跑被提交内容的检查，**读完结果**，失败就停。
2. 提交（`commit-own --whole/--keyed`，只带对方路径）。
3. 提交后立刻重跑 `tools/ratchets.cx`（棘轮只数已跟踪文件）；若引入新文件，确认 cxtrunc 等 0 增量。
4. 符号链接/目录链接提交后用 `git ls-tree` 核对类型。

## 5. 冻结与长跑会话协议

- 任何 all-waves 会话 init 前：cc 先确认 `git diff HEAD -- tools tests cx src include weights exec` 为空（HEAD=工作区），再发冻结通知；会话结束 owner 宣布，cc 解冻。
- 解冻后改 run-batch/allsession/zero-wave 之前，问 cc 有无长跑会话。
- 检查失败时先判断是否“候选在运行期被改”（闸门行为，不是缺陷）。

## 6. 单一状态板

`plans/omp-board.md`（cc 维护）：每个窗口当前任务、拥有的路径、阻塞项、下一次确认时间。派活和回信后更新；主人问“谁在做什么”以它为准。

## 7. 对主人的汇报口径

只讲结论、后果、需要主人决定的事（并说明为什么需要）；技术细节由 cc 拍板；发布第 7 步（签名/Draft/Latest/公开）与花钱、对外发送内容才请示。
