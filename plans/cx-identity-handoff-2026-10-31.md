# CX 模块身份一致性：分层审计移交草案（2026-10-31）

状态：**草案，不是生效合同，不授权修改源码或 spec**。由 `plans/cx-architecture-evolution-2026-10-31.md` 的同 realpath 双入口实证引出；CX-W-1、CX-U-4 不改。实施方须补齐预算、诊断与三源实际可行性，并由 cdx 在修改 `cxmod` / `entry-build` 之前把最终四项发给 `omp-ds`；双命令行根另裁，W-6 包根与 W-7 宿主运行不在此刀。

## 1. 解析起点与模块名

保持现行 CX-U-4：每条 `use NAME` 以**使用方词法路径的目录**为解析起点，NAME 的点号转目录并加 `.cx`，`std` 仍按现行规则处理。不把根改为包根，不修改 `module/use` 语法。先解析每个可达词法入口的依赖，再比较同真实文件的上下文；不得以 realpath 所在目录替代词法起点。

## 2. 去重身份与时机

维持经 `use` 引入模块按 realpath 合并，不按内容哈希或 inode 合并。新增加入合并前的一致性核验：同 realpath 各可达词法入口，比较实际有效公开函数集合和对应直接依赖的真实目标，并保留各侧词法上下文递归核验传递依赖。无清单时的默认全集与显式清单列出同一全集视为相等。`cxpack.tsv` 不存在（ENOENT）或没有匹配行仍按现行合同取默认全集；EACCES、ENOTDIR、文件存在但读取失败或行非法必须具名拒绝，不得降级为默认全集。

核验状态键须包含**两侧词法上下文**；边与上下文数须有明确预算，耗尽具名拒绝而非截断或假定一致；循环仍按既有模块图 cycle 合同处理。预算值与三源实现、实际仓库适配尚待实施方给出，未确定前不能声称方案可实施。相同上下文合并后保留首入路径，对象只编一份；不一致先拒绝，不依导入顺序选一个。命令行双根当前不折叠，本刀不擅改。

## 3. 双入口与边口径

审计与构造分别记账：分层工具保留每个词法入口的直接 `use` 边；两个入口产生两条待核对边，即使目标 realpath 相同也不把边计数合并。编译图仅在一致性核验完成后才可按真实文件身份合并对象；一个物理模块不代表只有一个解析上下文。现有向上边、未解析白名单、AMB/OUT 的检查和 UNKNOWN 口径不因本提案自动变动。

若同真实文件的两入口依赖或有效公开集不一致，拒绝诊断至少具名两条词法入口、共享 realpath；依赖不一致还要给 `use` 行、两条词法目标和两条真实目标；公开集差异要指出不一致的符号或足以定位的接口差异。不输出受权限限制无法读取的虚构路径。

## 4. 拒绝类与诊断前缀（提议，尚待三源核定）

| 类别 | 提议诊断片段 | 附加信息 |
|---|---|---|
| 同真实文件入口依赖不一致 | `module context mismatch: dependency` | 两个入口、use 行、两目标及真实路径 |
| 同真实文件入口有效公开集不一致 | `module context mismatch: public set` | 两个入口、公开符号差异 |
| 上下文／边预算耗尽 | `module context budget exceeded` | 所触限额及入口；不继续构造 |
| 缺模块、读取失败、模块环、跨层 | 复用各自现行归属与诊断 | 不改报为身份不一致；跨层仍由分层审计负责 |

具体前缀须由实施方证明三源可一致输出并经 cdx/审计方确认；权限错误、ENOENT、超限不能互相吞并。依赖与公开集不一致须分别断言第二段诊断，只匹配共同前缀不足以证明两类均覆盖。诊断提出不等于已经触发或 spec 已修订。

## 预检快照前置条件（尚未满足）

- 文件清单从固定 commit 的树对象取 mode/type/object/path（例如 `git ls-tree -rz --full-tree`），并核对同一 commit 的 `git archive` 内容及摘要；共享 index 的 `git ls-files` 不能替代。外置产品须显式路径、SHA-256 和来源，身份不符则 UNKNOWN、非零，不从工作区另找一只替代。
- 树模式 `160000` 的 gitlink 单列 UNKNOWN、非零；不得丢弃或当普通源码。普通 `.cx` 可生成 `symindex --in` 列表，mode `120000` 单独保留为词法入口；无法无损进入行清单的路径具名 UNKNOWN，不静默遗漏。
- 软链目标必须解析到该 commit 快照内且可关联其 shard；绝对目标、通过 `..` 越界、悬空及环均 UNKNOWN、非零，禁止跟到活工作区。传递源码、清单、软链解析链和索引都要绑定身份；结束复核只是变化检测，不等于可写目录上的原子快照。
- 实际根清单及来源仍未核定；生产根、工具根和预期拒绝的 SOURCE 负例分表，不得合成同一峰值。pair 的方向、顺序、算法版本和文件仍须冻结，静态 realpath 组的组合数不替代递归遍历峰值；反序两次不证明所有排列。

这四项完成书面细化与审阅前不开测。外置未提交树、生成物、越界与缺失各自记 UNKNOWN，不转授本工作区或发布资格。

## 实施前门与验收

- `cx/cx0/plan.cx`、`src/cxmod.c` 投影、`cx/compiler/cxmod.cx` 的实际入口及上限分开核实；同一个 C 参考实现投影逐字约束、已装产品和候选身份不混淆。
- 正例：不同词法入口解析闭包相同，包含无清单/显式全集等价、传递软链、菱形，保留现有单入口和去重行为。
- 反例：直接目标不同；直接目标 realpath 同但传递依赖不同；有效公开集不同；缺模块、目录错误、无权限、清单超限及上下文/边预算耗尽；交换导入顺序都不得选中不同结果。现有 `module cycle` 负例不退化。硬链接不同 realpath 保持现状。
- 同一候选分别实跑所覆盖的 unisacc 与 gcc_cx/clang_cx 路径，逐一记录每入口支持的命令及未覆盖；`-funit` 对象形状、闭包链接与 unisacc 原有 `-run` 保留既有回归。gcc_cx/clang_cx 只用现行编译入口探测，不借未生效的 W-7 `-run`。不能把 `-cx-plan` 单项成功冒充全部编译行为。
- 审计工具由 `omp-ds` 管理，收到最终四项后按新的观测和拒绝合同核实；其 AMB/OUT 仍按未决规则分账。各平台只按实际执行证据记账，不授安装或跨平台资格。
