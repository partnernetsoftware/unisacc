- **R16-9 减法安全门禁（P0）**：0.0.15 两次事故——AGENTS.md↔CLAUDE.md 链接成环致规则清空（bc86247），归档了仍被 7 个 lib 检查导入的模块致 8 项红（30be224）。新门禁 `subtract-safety`：① `archive/` 下的每个文件在 `archive/` 之外无人引用（import、source、路径字面量）；② AGENTS.md 与 CLAUDE.md 解析后非空、不是链接环。验收：对两次事故各造一个反例，门禁都能抓到。 **[v] 2026-10-01 db59cd5**：`tests/subtractsafety.py`，门禁 `subtract-safety` + `subtract-safety-selftest`（自测重建两次事故并要求抓到）；首跑抓到 3 处指向已归档 v0.0.14 计划的旧链接（应写 archive/plans/v0.0.14.md），已改。

- **R16-1 A2 续行 `__LINE__`**（原文不变）：拼接点之前 token 的 `__LINE__` 多 1，两侧同错；验收新红例与 cc 同，C99 账本 6.10.8 回到 covered。
- **R16-10 诊断位置**：B1 产品侧 9 类、B2 参考侧 3 类拒绝补 file:line:col；验收 `tests/diag.knownfail` 清空。
- **R16-11 依赖生成**：参考侧已有 `-M/-MM/-MD/-MMD/-MF/-MT/-MQ/-MP`（src/main.c），产品报 “option not migrated”（2026-10-01 实测）；迁到产品驱动，输出与 gcc 同格式。验收：对 fb12 夹具与 gcc 的依赖文件逐字比较。 **[v] 2026-10-01**：实测参考侧原本只接受不实现（-M/-MM/-MT/-MQ/-MP 被吞掉），且 .d 是每行一个依赖的自家格式。现在参考（src/main.c、src/front_pp.c）与产品（exec/c/compiler.c）都按 gcc mkdeps 写：72 列换行、空格/#/$ 转义、-MQ 转义 -MT 原样、-MP 幻目标、默认目标 basename.o、-M 去 -o 或 stdout、-MD 去 -o.d 或当前目录 basename.d；fb12 夹具没有用户头文件，改用专门夹具（嵌套包含、长名换行、空格/#/$ 路径），期望字节取自 Lima 里 gcc 15.2.0，exec-driver-core-dependencies 对参考和三个驱动逐字节比较；cli 64/64。
- **R16-7 工具链第一步（收窄，政委 2026-10-01）**：本版只做 ① **设计文档** docs/toolchain.md（格式范围、重定位种类清单、与系统工具互操作矩阵、三版递进）；② **ELF `-c`**：写出可重定位 ELF `.o`（符号表、重定位），与**系统 ld / cc 的 `.o`** 互链成可运行程序，lnx/x86_64 与 lnx/arm64 各一例 + difftest 子集一致。今天 `-c` 写出的是 tape 文本、`-S` 也是 tape（实测），README 须如实写。Mach-O/COFF `-c` 与自带链接器在 0.0.17，汇编器在 0.0.18。 **[v] 2026-10-01**：设计文档 docs/toolchain.md（后端事实表、三版递进、互操作矩阵、.o 规格、验证）；参考后端 `-c -b lnx/x86_64|arm64` 写出 ET_REL（八节、.rela.text、局部符号 + 全局 _start；x86 只用 R_X86_64_PC32，arm64 只用 ADR_PREL_PG_HI21/ADD_ABS_LO12_NC；数据区无地址值单元故无 .rela.data）；门禁 `elfobj`：7 探针 × 2 架构 = 14 个 .o、427 条重定位，.text 去重定位字段后与映像相同、.data 相同，lld 两架构链接，Lima 里 GNU ld 链接 + 运行与映像输出相同；裸 `-c` 仍是 tape（86 处套件），`-c -b osx/*|win/*` 报错指向文档。**未做**：产品 δ 的 .o 写出（0.0.17，盘点表如实标注）、x86_64 程序的实际运行（需 x86 虚拟机，发布前必跑清单）、与 cc `.o` 的符号互引（需 extern→UND，0.0.17）。difftest 子集一致性由 .text 不变量覆盖。
