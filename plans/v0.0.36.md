# v0.0.36 计划（草案，10-08 建立，承接 0.0.35 收口）

主题与退出条件沿用 [roadmap-0.0.x.md](roadmap-0.0.x.md)（79667f4d）与 prd.md §「.cx 替代 .sh/.py 的分期」。本计划只整理范围与完成标准，不改方向、不删测试；顺延项以 0.0.35 收口回执为准，下表是 0.0.35 尚未验收的项的原样承接。

## 主题：K1 构建与发布链（roadmap 0.0.36 行）

把构建与发布链的脚本改为 `.cx`，由上一版 `unisacc.com -run` 运行；自举链除宿主 cc 外不再需要 shell/Python。旧 `.sh`/`.py` 删除，删除数量写进发布回执。

### 范围（改 .cx 的脚本清单）

| 组 | 脚本 | 归属 |
|---|---|---|
| release/ 13 `.sh` | apple-sign、approve_signing、build_candidate、build_seed、candidate_chain、install_root、precheck、publish、queue、rc_tag、release_prep、seal_candidate、windows_sign（均在 `release/tools/`） | cc |

| 工具 | `tests/term.sh`、`tests/bound.py` | cc |

说明：`release/tools/build_candidate.sh` 已含在 release/ 13 个 `.sh` 内；`buildcompiler.sh` 独立于 `exec/c/`。

### 完成标准（K1 验收）

1. 每个脚本改为 `.cx`，shebang `#!/usr/bin/env unisacc.com -run`，由上一版 `unisacc.com` 运行。
2. 不经 shell/Python：子进程用 `cx_runv_timeout`（argv/execvp，非 popen/system），沿用 K0 的 `include/cx.h` 模块（文件、目录遍历、进程与超时、退出码、sha256、JSON/TSV）。
3. 功能对拍：改 .cx 后与旧 `.sh`/`.py` 逐字节或语义等价（按各脚本既有输出契约），不得放松摘要/校验。
4. 自带单元测试，含故障注入（超时、非零退出、缺文件）。
5. 旧 `.sh`/`.py` 删除，删除数量写进发布回执；本版不新增 `.py`/`.sh`。
6. 完成判据（roadmap §.cx 分期）：干净机器只装 `unisacc.com` 与宿主 cc 即可构建、门禁、发布。

## 执行规则（沿用 roadmap）

1. 每版只做本版主题（K1）加顺延项；新发现的问题，是红就修，不是红就记 0.1.x，不插进本版。
2. 顺序固定：版本号提交 → 候选 → comboot → 契约层全绿 → 封存 → 队列 → Linux → 签名 → 政委确认 → 公开。
3. 到点没做完的项，原样移到下一版（同一项最多两次），不拖整版。
