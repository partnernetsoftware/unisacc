# L0 补格式化、数值解析、标准流与描述符标志（2026-10-30，cc）

csih 车道要把 apps/csih 里的直接 libc 调用全部换掉，向 L0 要了下面这批接口，要求与 libc 语义一致，便于机械替换。`plans/cx-layers.md` 当时有他人的暂存改动，L0 清单的补充先记在这里。

## 接口

| 模块（use） | 文件 | 函数 | 对应 libc |
|---|---|---|---|
| `text.fmt` | `cx/text/fmt.cx` | `int tx_snprintf(char *dst, size_t cap, const char *fmt, ...)`、`int tx_vsnprintf(char *dst, size_t cap, const char *fmt, va_list ap)` | snprintf、vsnprintf：截断写入，cap>0 时以 NUL 结尾，返回完整输出应有的长度，cap 为 0 时 dst 可为 0 |
| `text.num` | `cx/text/num.cx` | `long tx_atol(const char *s)`、`long tx_strtol(const char *s, char **end, int base)`、`unsigned long tx_strtoul(const char *s, char **end, int base)`、`double tx_strtod(const char *s, char **end)` | atol、strtol、strtoul、strtod：返回值、溢出钳位、*end 一致 |
| `text.num` | `cx/text/num.cx` | `int tx_strtol_r(const char *s, char **end, int base, long *out)`、`int tx_strtoul_r(const char *s, char **end, int base, unsigned long *out)`、`int tx_strtod_r(const char *s, char **end, double *out)` | 同上，错误走返回值：0、-EINVAL（s/out 为空、base 不是 0 或 2..36、没有数字）、-ERANGE（*out 为 libc 给的钳位值） |
| `sys.io` | `cx/sys/io.cx` | `int sy_printf(const char *fmt, ...)`、`int sy_eprintf(const char *fmt, ...)`、`int sy_vprintf(const char *fmt, va_list ap)`、`int sy_veprintf(const char *fmt, va_list ap)`、`int sy_puts(const char *s)` | printf、fprintf(stderr)、vprintf、vfprintf(stderr)、puts |
| `sys.io` | `cx/sys/io.cx` | `int sy_fd_nonblock(int fd, int on)`、`int sy_fd_cloexec(int fd, int on)` | fcntl F_GETFL/F_SETFL O_NONBLOCK、F_GETFD/F_SETFD FD_CLOEXEC；0 或 -errno，Windows 为 -ENOSYS |
| `sys.io` | `cx/sys/io.cx` | `int sy_isatty(int fd)` | isatty：1 或 0，不返回 -errno |
| `sys.io` | `cx/sys/io.cx` | `const char *sy_strerror(int e)` | strerror：e 可以是正 errno，也可以是 sy_* 的 -errno；文本与前导 strerror 相同 |
| `sys.env` | `cx/sys/env.cx` | `long sy_euid(void)` | geteuid；Windows 为 0 |

## 取舍

- **text.cx 保持无 libc。** 格式化放进新模块 `cx/text/fmt.cx`，解析放进 `cx/text/num.cx`。两个模块都不 use 其它模块，不需要新加软链。
- **`cx_fmt` 不能替代 snprintf**：它溢出时清空 dst。`tx_snprintf` 才是逐字节等价的替换。
- **errno 不跨模块。** errno 是每个编译单元一份（`plans/errno-per-unit-2026-10-30.md`）。所以 `tx_strtol` 等设置的 ERANGE 只留在 num 模块里，调用方读不到。要判断越界的调用方改用 `_r` 版本。迁移时，`errno = 0; v = strtol(...); if (errno == ERANGE)` 这种写法必须改成 `_r`，不能只替换函数名。
- **前导 strtol 与 glibc 的差异**：base 非法时前导不设 EINVAL，只返回 0，`*end = s`。`tx_strtol` 照前导行为，`tx_strtol_r` 返回 -EINVAL。
- **标准流顺序**：`sy_printf` 等直接调前导的 `vfprintf(stdout/stderr)` 和 `puts`，用的是同一个 FILE。前导对标准流不做缓冲，直接写（`include/stdio.h` 的 `_u_st_wput`），所以 sy_* 与残留的 printf、puts、fprintf(stderr) 交错调用时，字节顺序和调用顺序一致，中间不需要 flush。

## 检查

- `tools/check-cx-fmt.cx`，批次 `cx-l0-fmt`（`tests/batches.tsv`、`tests/coverage.tsv`）：38 条。做法是同一组输入分别交给前导 libc 和新接口，对比结果。printf 一组以 `-- child out` 重新运行本文件；isatty=1 那条在 script(1) 的 pty 下以 `-- child tty` 运行，没有 script(1) 的机器记 UNMEASURED。
- 本机实跑：`CX_FMT ok=38 failed=0`；`tests/run-batch.cx` 对 `cx-l0-fmt` 报 PASS（candidate 79fb84e6）。`check-cx-sys` 108/0，`check-cx-text` failed=0。
- 跨目标只编到 tape，没有执行：用 sys.io、sys.env、text.fmt、text.num 的小程序，`-t win/x86_64`、`osx/x86_64`、`lnx/arm64` 都能出 tape；`tools/tape-gap.cx` 对三个 tape 都报 gaps=0、ccw=0。Windows 上 fd 标志返回 -ENOSYS 的路径、macOS 的路径都没有实跑。
