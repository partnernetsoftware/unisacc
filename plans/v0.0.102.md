## 1. 现场:__u 的生成点与消费点(git grep 实查,不含 archive)

生成点(两处,各自独立,规则不同):

| 位置 | 生成什么 | unit 从哪来 |
|---|---|---|
| `cx/compiler/tapelink.cx:68-73` `tl_name` | 本单元私有名(`tl_kind==1`)改写为 `__u<u>_<name>`;`__init_u` 改写为 `__init_u<u>` | `tl_unit(t,n,u)`;调用方 `src/drivelink.cx:127`(局部 u)与 `src/drivelink.cx:294`(`dv_link_units`,即已链单元计数) |
| `cx/compiler/fwdmerge.cx:235-238` `fwm_location` 一族 | 前向合并时本地名改写为 `<name>__u<unit>`(后缀式,与 tapelink 前缀式不同);同处 `ls<N>` 标号加 `2097152*unit` 偏移,`S<N>`/局部标号加 strshift/labshift | `fwm_merge(...,int unit,...)`,调用方 `src/driveroute.cx:107-108` `dv_fw_merge(...,unitn,...)` |

同口径的旁证点(非 __u 字面,但同样随序号漂移):
- `cx/compiler/tapelink.cx:375`:入口按 `k=0..u-1` 逐个 `call __init_u<k>`;
- `cx/compiler/tapelink.cx:266-268,554`:`__init_u` 前缀识别(活性分析 `tl_dlive`,全局导出排除);
- `exec/parse2/units-text.tsv:5`、`exec/parse2/unitlocations-text.tsv:5`:`text3 "__u"`,网侧(k2-units / k2-unitlocations)以 `unit` 四字节字段输出位置前缀(`unitlocations-manifest.tsv` 的 `word_unit`/`prefix_*`),诊断位置同样带单元序号;
- 归档参考 `archive/reference-c/exec/c/fwdmerge.c:102` 同规则(只作 oracle,不改)。

消费点:
- 汇编/链接:改写后的名只在合成 tape 内部互引,`tl_kind==2`(`.global`)不改名,故对外符号不受影响;
- 活性与死代码剔除:`tl_dlive` 以 `_start` 与 `__init_u*` 为根;
- 诊断:单元位置记录带 unit 序号;
- 缓存:逐单元产物(tape、对象)若含 `__u<k>`,其字节随 k 变,逐单元复用失效(本版要解的核心)。

## 2. 为何漂移

k 是"本次编译单元在命令行/计划里的位次"(`dv_link_units` 递增计数、`unitn` 由驱动按序给)。同一单元内容不变,只要前面插入或删除一个单元,其私有名、`ls` 标号偏移、`__init_u` 序号全变,产出字节不同 -> 逐单元后端结果无法按内容身份复用,run-cache/rescache 只能整体失效。

## 3. 方案

- **后缀改为内容身份**:`U = hex16(sha256(单元规范输入身份))`,输入身份取该单元 tape 预改名字节(或 cxmod 计划里的单元源身份,二者择一,开版前定,口径写进 `exec/facts/`);`__u<k>_name` -> `__u<U>_name`,`name__u<k>` -> `name__u<U>`,`__init_u<k>` -> `__init_u<U>`。
- **入口调用顺序仍按链接序**:tapelink.cx:375 改为按链接序遍历已登记的 U 列表发 `call __init_u<U>`,初始化语义(顺序)不变,只换名字。
- **数值标号偏移**:`ls<N>+2097152*unit`、strshift、labshift 是链接期局部数值,不进逐单元产物身份即可不改;若逐单元产物需含已偏移标号,则改为"单元内从 0 编,链接时统一偏移",偏移留在链接期(一次性在 tapelink 做)。
- **同内容两单元**:同一 U 出现两次(同源文件被列两次)必须具名拒绝或按序消歧(`U` 后附链接期序号,仅在冲突时),规则写死并有夹具。
- **改写只经生成器/事实表**:`units-text.tsv` 的 `text3` 与网侧 `word_unit` 字段若需要变,走 事实表 -> 生成器 -> 网,不在 drive*.cx 里写特判。

## 4. 风险

1. **跨单元重名**:16 hex 截断碰撞概率极低但非零;链接期必须检测 U 重复(含截断碰撞)并具名拒绝,不静默覆盖。
2. **链接符号稳定性**:只改 `tl_kind==1` 私有名与 `__init_u`,`.global` 名不变;须核 `tl_kind==2` 判定在 U 化后不受影响(`__init_u` 前缀识别从"数字后缀"改为"十六进制后缀",tapelink.cx:266/268/554 三处要一起改)。
3. **缓存键**:U 由内容决定后,run-cache/rescache 键要把 U 的来源身份纳入;不得以 U 命中替代执行(铁律:不缓存测试结论)。
4. **诊断位置**:`unitlocations` 输出的 unit 字段是给人读的位置,保留序号还是换 U 需定;建议诊断保留序号(人读),产物用 U,两者分开。
5. **自举与 SID**:改 `cx/compiler/*.cx` 属产品输入,必起整链,两代 GEN 字节等价需重核;`kernel/` 不手改。
6. **三源一致**:fwdmerge 有归档 C oracle(`archive/reference-c/exec/c/fwdmerge.c`),对拍时 oracle 仍按序号,需在对拍层做名归一化,不改 archive。
