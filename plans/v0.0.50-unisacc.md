## 1. 设计判断(为什么这么做)
- **核心不慢,粘合层慢。** 0.0.49 实测:131 作业波 276.9s,42 网全键验证 7.2s,两代对比 6.5s。时间与返工集中在三处:(1)整程序 e3 是唯一单体阶段;(2)编排工具(chain-step/release-build/all-waves)各自重复掌握驱动知识、硬写路径与次序;(3)版本/构造器/阶段边界存在第二份真相。
- **身份是脊柱。** 一切靠内容寻址与字节等价判定;0.0.49 的缺陷几乎都是身份链被悄悄切断(硬接线旧构造器、旧 B 路径单元数为 1、F-v2 漏迁移的版本消费者)。
- **60 秒时限是架构的强制函数。** 它逼出了产品已有的 `st_span` 阶段边界;应把「阶段+检查点」做成产品原生,而不是工具借内部 API 拼接。
- **分解必须自带同源小规模 oracle。** 0.0.49 Mac/Win 片靠「中等程序默认 vs 分相镜像 cmp0」证明;跨版本结构对照无判别力(已证伪)。

## 1b. 预见(cc 2026-11-10,随 G0 复现实测补入)
- **可复现性的不变量要显式化**:G0 在不同物理根复现 0.0.49 时,Linux 片 SHA 相同,但 Mac 合并帧差 6643B(疑为 #line 物理路径,F-v2 裁定)。结论:帧/收据允许依赖物理根,**产品产物(切片/内核/P4/APE)绝不允许**;`build/graph.tsv` 增 `root_dependent` 列,graph-check 对产品节点强制 no;新增 `check-root-independent`(两根构造产物比较)。否则 CI/他机复现无从谈起。
- **60 秒上限会持续制造贴线相位**(0.0.49:P3 59s、Mac B 43s):每个图节点应声明可拆维度(作业/单元/目标/阶段),调度器按上一波实测自动再分块(grk 的作业波自适应已是雏形),成为 G2 的通用机制,不再逐相位手改。
- **oracle 随代际重基线**:0.0.49 的数值只作一次性引导证明;之后每个候选的等价判据是自身两代不动点 + 同源小规模 oracle + CI,G0 不得硬编码任何 0.0.49 哈希。
- **测试债要在本版还一部分**:s9 daily(≈544 项)/release 档自 0.0.47 起未跑;0.0.50 候选在 S 单 step 落地后,至少跑一次 daily 档并如实披露结果。

## 4. 不变量
- 不删断言、不缩覆盖、不放宽时限;未实跑不记 PASS;两代相等只证不动点,语义正确需同源 oracle。
- 缓存命中只代表输入未变;每周冷构造审计,不一致即关闭增量。
- 跨窗口依赖的合同写进计划文件,不只放 out/。
- 交付前私有克隆跑 integrate-patch 至 READY_TO_COMMIT;新工具带同名 check 并登记;新工具交付须附一次真实规模实测(0.0.49 freeze-plan 教训)。
