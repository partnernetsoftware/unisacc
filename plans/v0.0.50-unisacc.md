## 1. 设计判断(为什么这么做)
- **核心不慢,粘合层慢。** 0.0.49 实测:131 作业波 276.9s,42 网全键验证 7.2s,两代对比 6.5s。时间与返工集中在三处:①整程序 e3 是唯一单体阶段;②编排工具(chain-step/release-build/all-waves)各自重复掌握驱动知识、硬写路径与次序;③版本/构造器/阶段边界存在第二份真相。
- **身份是脊柱。** 一切靠内容寻址与字节等价判定;0.0.49 的缺陷几乎都是身份链被悄悄切断(硬接线旧构造器、旧 B 路径单元数为 1、F-v2 漏迁移的版本消费者)。
- **60 秒时限是架构的强制函数。** 它逼出了产品已有的 `st_span` 阶段边界;应把「阶段+检查点」做成产品原生,而不是工具借内部 API 拼接。
- **分解必须自带同源小规模 oracle。** 0.0.49 Mac/Win 片靠「中等程序默认 vs 分相镜像 cmp0」证明;跨版本结构对照无判别力(已证伪)。

## 3. 排期(以 0.0.49 实测为基线)
1. 第一批并行(纯工具,不换 SID):G0、S、R、D 中不依赖图的项,以及 L(lint 先上「第二真相源」与子进程 timeout/`--` 两条规则,它们直接对应 0.0.49 返工)。LSP 排在 L 稳定之后,本版可不做完。
2. G0 落地后:G0b、G1 → G2。
3. 产品候选:Y 先行(解除方案 X 与贴线风险),随后 B2、H。
4. 每包完成立即回写 `agentwork/phase-times.tsv`(带证据路径),未测标 UNMEASURED;发布说明数字只引用 phase-times。

## 4. 不变量
- 不删断言、不缩覆盖、不放宽时限;未实跑不记 PASS;两代相等只证不动点,语义正确需同源 oracle。
- 缓存命中只代表输入未变;每周冷构造审计,不一致即关闭增量。
- 跨窗口依赖的合同写进计划文件,不只放 out/。
- 交付前私有克隆跑 integrate-patch 至 READY_TO_COMMIT;新工具带同名 check 并登记;新工具交付须附一次真实规模实测(0.0.49 freeze-plan 教训)。
