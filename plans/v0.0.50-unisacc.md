# unisacc 0.0.50 计划:主题「构造图化」(cc 2026-11-09;草稿,0.0.49 实测后复核)

## 0. 设计命题
0.0.49 把**身份**拆开了(版本串出 SID、SID 变为分包摘要)。0.0.50 用这个身份**把构造链变成一张显式的有向图**:每个节点有输入摘要和输出摘要,只重做摘要变了的节点,独立节点跑满 16 核。

当前的症结是同一件事:改一处,全链重做;链是串行的;裁决靠人。三者的根是**没有节点级身份**。

| 现状(0.0.47/0.0.48 实证) | 根因 | 0.0.50 设计答案 |
|---|---|---|
| 131 作业波 1800 秒(自报) | 作业粒度由脚本硬编码,无输入摘要,表一变全跑 | 作业=图节点,按输入摘要判脏,脏节点并行 |
| 改生成器 → 42/42 网失效 | 生成器与网之间依赖是整文件 | 依赖写成表,按函数/阶段挂接(H 已启动) |
| whole-o 单作业 72–100 秒 | 每单元重复头展开(帧为源码 41 倍),同 OS 两架构重复做 | 单元节点以头文件闭包摘要为键,跨架构共享前端 |
| 发布前裁决 14460 秒 | 裁决=人读证据 | 裁决=对证据表的一次查询,人只读一页 |
| 冻结返工 5580 秒 | 冻结路径手写 | 冻结路径由图的节点输入集合导出 |

**范式不变**:图本身也是事实表(`build/graph.tsv`:节点、输入、命令、输出、预算),调度器是通用执行器,不写专用 shell/Python 编排。

## 1. 不变量(防止提速变成降质)
1. **缓存命中不是通过**:节点命中只代表「输入摘要未变」。资格结论仍由该节点绑定的验证给出;验证不因命中而省略。
2. **冷构造审计**:每周慢车道全冷重建一次,与增量产物逐字节比对;不等则增量机制判失败并回退为全构造。
3. **确定性前提**:节点输出必须只由声明输入决定;未声明的输入(时钟、路径、环境变量)由 `graph-check` 机查,查不出的节点不得入图。
4. 一个候选只含一类大改;不删断言、不缩覆盖、不放宽时限。

目标耗时(冻结→可发布):0.0.49 ≤44 分钟;**0.0.50 ≤20 分钟**(固定成本约 4 分钟:六目标 CI、读回、发布)。

## 3. 排期与并行
- 第一批并行(无依赖):G6 的证据表格式、G7 的冻结导出、K 的接口草案。
- 第二批:G1 → G2 → G3(单条链,各为独立候选,不混类)。
- 第三批:G4、G5(依赖 0.0.49 B2 的实测帧量)。
- 每包完成立即测「冷/热」耗时并回写 `agentwork/phase-times.tsv`,未测标 UNMEASURED。

## 4. 风险与回退
| 风险 | 回退 |
|---|---|
| 增量产物与冷构造不一致 | 冷构造审计失败即关闭增量,走全构造;不放宽 |
| 图输入集漏列(隐式依赖) | `graph-check` 在 CI 不通过即阻断 |
| 流水线化改变错误报告顺序 | 保留串行模式作对照,`stream-pipe` 字节等价批次 |
| 0.0.49 的 B2/F 未达成 | G4/G2 顺延,0.0.50 先补齐 0.0.49 |
