# unisacc v0.2.x 路线：高阶应用（草案，主人 2026-10-01）

> **主人裁定（2026-10-01）**：0.2.x 系列专注**高阶应用**——沙箱、容器、镜像、虚拟、仿真、高性能、硬件、网络、harness + agent 等。前提是 0.0.x 把编译器做成可用的工具链（`.o`/链接/汇编，0.0.17–0.0.18），0.1.x 把可信边界与语义覆盖做实；0.2.x 用这台编译器和它的 tape/tapebin 做**上层产品**。
> 产品原则沿用：**默认即运行**（`unisacc FILE.c [args]` 无 `-run`/`-o` 即运行）；每项要有六目标的具名验收，不把 POSIX 能力说成 Windows 也有；不自动开工，开工前再细化成 R 表；顺延两次即降级或砍掉。

### harness + agent（自 0.1.x 附录移入）

- **agent harness**（主人提出，cdx 归纳 2026-10-01）：unisacc 自编的跨架构 CLI+TUI harness，对标 pi-agent，只暴露 mind/file/exec 三种工具；两个 Markdown 工作流（默认工作流、可由 mind 编辑的工作流记忆）是可检查的数据，不伪装成权重。边界：同一 C 核驱动 CLI/TUI；mind 管工作流/记忆的读、提议、原子写入与版本记录，file 管文件，exec 有界执行。宿主适配两列：POSIX（termios/ioctl、fork/exec/waitpid，依赖 0.0.17 R17-5/R17-7）与 Windows（Console/ConPTY 等价输入输出、CreateProcess/WaitForSingleObject，独立条目，不借 R17 的名）。验收：产物由 unisacc.com 自编、六目标能启动并完成最小任务；CLI/TUI 同一工具事件轨迹；记忆编辑重启可恢复；exec 超时；真实仓库任务与 pi-agent 同输入对照（工具调用/耗时/结果）；harness 自身进 realprog 语料。

### 包市场 + agent 友好（原 0.1.x 文件中的 0.2.x 主线，原文保留）

- **v0.2.x 主线：包市场 + agent 友好（政委 2026-09-30 方向；合并设计；远期，不影响 0.0.14 与 0.1.0–0.1.3 顺序）**
  - 定位：包更少，但每个都可复现、有证明、有权限边界、一份 tapebin 跑遍六平台，并且是 agent 最放心用的运行时。参照：npm（低门槛但碎片/投毒/抢注，事后补锁文件与 provenance）、PyPI（C 扩展逐平台逐版本编 wheel、可信发布）、JSR（发源码、自动文档与类型、质量分、作用域名、兼容 npm）。独有优势：tapebin 目标无关（R14-7），三阶段自举一致（N22），安全检查器（v0.1.3），C99 条款账本（R14-6）。
  - **v0.2.0 包格式**（依赖 R14-7 落点 A）：`.tapebin` + 清单（名、版本、依赖、权限、导出接口，机器可读；名带 `@作用域`），按内容哈希寻址，同哈希永远同字节；本地 `unisacc pkg pack|verify|run`。验收：清单规格文档 + 三个示例包；`pack` 两次逐字节同；`verify` 拒绝任何一字节篡改；六平台 `-run` 同一包同输出（六 runner 演示矩阵加一行）。
  - **v0.2.1 发布即证明**（依赖 v0.2.0、N22）：市场端用可复现工具链（固定版本的 `unisacc.com`，其 sha 记入回执）从源码重编，与上传的 tapebin 逐字节一致才上架；质量分 = 重编一致 + 内存安全检查器结论（v0.1.3：已证明函数比例 / 运行时检查比例）+ C99 条款覆盖（R14-6）+ 文档/接口完整度；每项分数都由门禁产出、可回放。验收：一个最小市场服务（可先是仓库内 CI 作业）对首批包给出证明与质量分；不一致的上传被拒并说明差异字节偏移。
  - **v0.2.2 权限清单 + 沙箱**（依赖 v0.1.3 步骤 1 的 tape 安全模式）：包声明文件 / 网络 / 进程 / 环境权限，运行时强制（未声明即拒绝并结构化报告），默认最小权限、可审计日志；被投毒的包偷不走越权的东西。验收：一组越权红例（读未声明路径、发网络、起进程）全部被拦并给出机器可读诊断；正常包零改动通过。
  - **v0.2.3 接生态**：首批官方包 = zlib、sqlite、lua 等纯 C 库（真实项目阶梯的产物），每个带证明与质量分；第二前端（tape 上的小语言/脚本方言）稳定后再评估桥接部分纯 JS / Python 包。验收：三个官方包在六平台 `-run` 通过各自自测；用它们写的示例程序按内容哈希复现。
  - **agent 友好（与包管理一起设计，贯穿 v0.2.0–v0.2.3）**：① 按接口/能力搜索包（清单与文档机器可读，JSON 输出）；② 装包与运行默认沙箱、最小权限、审计日志；③ `-run` 当场试跑、验证后 `-b` 固化成 `.com`；④ 诊断与错误输出结构化（`--diag=json`：file:line:col、构造名、建议修法），便于模型自修；⑤ 内容哈希 + 可复现让 agent 的结果可回放、可验证。验收：一个 agent 端到端演示——搜索包 → 沙箱试跑 → 读结构化诊断修一处错 → 固化 → 回放校验哈希——写成门禁。
