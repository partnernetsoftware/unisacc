# 启动器与六片逻辑转网:反思与路线(rev3 草稿,只读分析,未改仓)

取数:2026-11-19,共享检出 main 661f967ca3,已装产品 0.0.80(APE 7,388,948 B,sha 110ab298)。实跑:`tools/com-tree.cx -- --models`、`tools/handwritten-census.cx -- --report`、`tools/cx0-extract.cx -- --check --all`、`tools/check-cxmod-tri.cx`、`wc -l`。未实跑的数标"旧数"或 UNMEASURED。

## A 结论与主张

所有者的观察成立,而且比字面更重:APE 里原生机器码占 67.9%(头 3,146,240 加四个 gzip 片 1,867,437),网只占 19.4%(40 模型 1,431,674);按 2026-11-07 的 81 单元 .text 表(lnx/x86_64,旧数),片内只有 21.4% 是必须留下的薄层,2.6% 能直接变表,其余 76% 是无界变换与带 IO 的编排。主张三条:(1) "表化"只解决 2.6%,先做是因为零风险而不是因为收益大;(2) 剩下 76% 没有"移植"路径,只有两条路:逐块重写成事实表加生成器规则(代价等于重写,e3 一条流对应 1.1 MB 模型与 exec/ 下大量表),或者让平台无关层(L2 program)只编一次成执行器字节码、六片共用一份,后者才是结构上回应所有者观察的唯一杠杆,但要先过执行器资源合同门和一次慢速比实测;(3) 上一轮评估"构造时间上不成立"需要修正:对大块逻辑,构造时间是成立的(见 E),不成立的是运行期启动开销与体积。

## D 分版本路线

`build/version-seq.tsv` 里 0.0.84 为计划、0.0.85 至 0.0.89 为建议,且 plans/roadmap-v0.0.80-v0.0.89.md 第 32 行已把"宿主逻辑继续转网"移出窗口(理由:范式纯度,用户价值低)。本路线不推翻各版主类,只占用驱动类与模型类的空位;要采纳须由主调度改版本序表。

| 版本 | 一类大改 | 内容 | 验收 | 失败降级 |
|---|---|---|---|---|
| 0.0.84(现定:执行器与模型包) | 不变,加度量随行 | (1) 用 0.0.84 候选重量六片 81 单元 .text,替换 2026-11-07 旧表;(2) 每多装一个模型的毫秒数实测(现引 12 至 30 ms 为旧数);(3) 执行器资源合同门(OOM 具名可恢复、失败注入、步数上限) | slice-migration-gen --check;check-core-run-diff;coreapi | 度量缺失则后续各版只做表化,不开流 |
| 0.0.85 | 驱动类:路线与阶段判定入表(第一块) | 新事实表(mode 0 至 5 x level 0 至 2 x 6 目标 x 终点流)-> 生成器 -> D 行或静态表;route、stages、driveroute、drive 中的同义分支改查表;6 个 FINITE 单元同批 | 全键域枚举改前改后逐格相同;6 目标整程序 -o 17 份与上一版逐字节相同(本版预期零变化,有变即缺陷);七流 stream 管道 cmp 0;三代不动点 | 逐单元回退,表与生成器保留为对照臂 |
| 0.0.86(现建议:库包源类) | 不变,工具随行 | CX0 语料金标:733 个工具加 tests/module 的规划输出逐单元哈希入表(PREPARED,不记 PASS) | 生成器 --check | 无产品影响 |
| 0.0.87 | 模型与网类:带子校验并入 tapecheck | 先普查 tapegate 与 tapecheck 模型的重叠;重叠部分删手写、差集扩现有模型,不新增模型 | nn 逐项求值(net-check 全键);拒绝合同逐条负控保留;-o 17 份逐字节相同 | 普查显示重叠低于一半则本版改做 asmtext 与 enc 事实同源 |
| 0.0.88 | cxmod 类:CX0 判定入表 | 指令名单、上限、拒绝文案从 plan.cx 抽成事实表,三投影由表加骨架生成;机制(模块图、IO)留原生 | cx0-extract EXACT;CXMOD_TRI failed=0 gaps=0;语料金标全同;自举不动点 | 只入上限与文案两张表 |

优先序理由:第一块选路线入表而不是 cxmod。cxmod 的"三源重复"在源头上已经解决(单一权威加两份 EXACT 投影,6,216 行里 4,084 行是生成物,普查基线仍把它们算手写,口径该改);再往前一步就是整体入流,属最重、带自举环的一步。路线判定键域有限、可穷举、不加模型、运行期零开销,且包里已有 1823 行同类 D 行,是唯一同时满足"收益确定、风险最小"的一块。缓存身份不选:全是 IO 与哈希。

## E 对迭代速度的影响

依据(build/phase-times.tsv 与 prd.md 3.7,多为 0.0.49 实测):131 作业波 276.9 s;routes 29.7 s;p3 58.8 s;每代六片串行和约 632 s(lnx 49 至 61 s 两片、osx 142.4 s 两片、win 118.5 s 两片),三代约 1,900 s;整链热 1,613 s(chain4),私有整链 3,538 与 3,752 s;网增量演练改一处重建 3 网 12.07 s 对全量 175.36 s。

- 变快:片是产品自己编的,耗时近似正比于片内源码量。某块逻辑离开片,六片 x 三代都少编它;按 .text 占比粗估(未实测),cxmod 一块(6.5%)三代省约 120 s,而新增一张网分摊约 6.6 s 加 routes/p3 增量。所以对大块,构造时间是净收益,这一点修正上轮结论。
- 更大的收益在依赖粒度:逻辑在网里,改它只动 L3,改表到可跑约 8 s(p3-swap,旧数);在片里则要走三代 x 六片。但前提是整链按内容寻址(0.0.84 速度道)真正落地,且"网变了、片源没变"时能证明片字节不变并复用,否则每次仍重跑三代。
- 变慢:131 作业波与 p3 随模型数增长;p3 已贴 60 s 上限,再加模型须先分片。表化(0.0.85)不加模型,不受影响。
- 三代自举是否缩短:表化不缩短(2.6%);只有 L2 走字节码才明显缩短(上界每代 632 s 降到约三分之一),且那时六片只剩薄层,g1 等于 g2 等于 g3 的比较对象也变小。
- 运行期:推理已占冷编墙钟约 78%;每加模型多一次装载。日常 733 个 .cx 工具都过 CX0,CX0 入流会让每次冷跑变慢,须靠单元缓存兜住,500 ms 门要重核。

## F 风险与一条不愿听的话

- 自举环:CX0 或包解码进网后,产品要靠网才能编自己;宿主 C 投影(src/cxmod.c,gcc_cx 在用)不能删,所以"三源变一源"的终点是"一张表生成三份",不是只剩一份。
- 验证成本转移:手写代码有编译器与单测;网只有全键枚举与差分。无界输入的逻辑进网后,拒绝合同与 OOM 行为要重新逐条立负控,数量不比原来少。
- 旧数风险:本文体积判断全部建立在 2026-11-07 的单一片 .text 表上,0.0.84 重量前不要据此承诺字节数。
- 版本序冲突:现路线已把此方向移出 0.0.80 至 0.0.89 窗口;采纳本文等于顶掉 0.0.85、0.0.87、0.0.88、0.0.89 的现建议内容或与之并道,须主调度裁定。

不愿听的话:靠"转网"缩小六片这件事,按现有网的形态(表状有限状态模型)做不到。能表化的只有 2.6%;把无界编译逻辑改写成表加生成器规则,是把复杂度从 .cx 挪到 exec/ 与 seed/gen.c,行数未必减少,可读性更差。若目的是体积,最便宜的两刀与网无关:把 42.5% 的未压缩 win 头压起来(按其余片 12% 至 21% 的压缩率估可省约 2.5 MB,启动路径要改,S1 旧评估未做)和清掉约 500 KB 填充。若目的是范式纯度与每目标一份源,真正要投的是"L2 编成执行器字节码",它是一个新编译目标级别的工程,应先用 0.0.89 的一个单元实验决定做不做,而不是按清单逐块往下排。
