# cxlibc：上层 .cx 禁止直接调用 libc/POSIX（全名单棘轮，2026-10-30）

## 问题

主人问：cx 的上层能不能用 lint 限制，不许用 `#include`，也不许直接调 libc 和 POSIX？

- `#include` 已经有棘轮：`tests/cxinclude.cx`。L0 边界以外的 .cx 模块不许写 `#include`，边界见 `tests/cxinclude-boundary.tsv`。
- libc 原来只有 `tests/cxraw.cx`，它的名单是手写的 70 个名字，见 `raw_names`。名单之外的 printf、snprintf、fprintf、exit、realpath、signal、qsort、getpid、S_ISREG、WEXITSTATUS 等都查不到。

## 做法

名单改为自动推导，不再手写。

1. `tools/symindex.cx external [--names] (--tracked | FILE...)`：对每个调用方文件，取它分片里的 C 行（调用），找出没有被任何已索引 .cx 定义的名字，再逐个分类：
   - **lang**（不计数）：va_start、va_arg、va_end、va_copy、offsetof、defined、`__attribute__`、`__builtin_*`、`_Static_assert`、`_Generic`、INT64_C 等。if、sizeof 这类 C 关键字在词法阶段就已经排除。
   - **本地**（不计数）：调用方自己有这个名字的 D 行或 X 行，或者文本里出现 `NAME(...) {` 这种定义形态。后一条用来兜住 parse 漏掉的定义：`#if/#else` 两个分支各开一个 `(` 时，括号深度会算错，之后的 D 行全部丢失，tools/cxcc.cx 就是这种情况。
   - **libc**：名字在扁平前导 `include/cx-flat.h` 里有定义、原型或宏（用同一个 parse() 解析前导得到 D、P、X 行），或者是 `R (*NAME(...))(...)` 这种返回函数指针的形式（signal）。目前一共 629 个名字。原型和对象宏都算在内，因为前导声明了它，就等于提供了它，例如 setpgid 在前导里只有原型。
   - **runtime**（暂时允许，只计数）：上面这些名字里以 `_` 或 `cx_` 开头的，如 cx_read、cx_fmt、cx_write、cx_run…；另外，任何 .cx 都没有定义、但以 `_` 或 `cx_` 开头的名字也归这一类。
   - **repo**（不计数）：任何已索引的 .cx 里有这个名字的 D 行或 X 行。只有 P 行不算定义：只有原型、没有定义的名字，调用会转发给宿主，所以记为 host。
   - **host**：其余所有名字。包括前导之外的宿主 libc 函数（socket、getaddrinfo、clock_gettime、time、mmap、nanosleep 等：time.h 和 sys/mman.h 都不在扁平前导里），curl、termios，以及经 `#include` 引进来的 .h 里的 C 函数（tests/cases 下的 rl_*）。
   - 两条修正需要重读调用方的文本：写成成员形式的调用（前面是 `.` 或 `->`，例如 `ops->read(`）不算对这个名字的调用；host 类名字如果还以普通标识符出现过（函数指针变量或参数，或者取了地址），整条去掉。
   - 输出：每个有外部调用的文件一行 `EXTERNAL FILE libc=N host=M runtime=R names=…`，names 只列 libc 和 host 名字并排序。`--names` 改为每个名字一行 `NAME FILE name kind sites=K`。最后是汇总行 `EXTERNALS files= scanned= libc= host= runtime= lang= prelude_names=`。
2. `tests/cxlibc.cx` 和基线 `tests/cxlibc.tsv`（FILE、COUNT 两列，COUNT = libc + host）：
   - `--check`：文件超过自己那一行，或者没有行但计数大于 0，就报这个文件，rc 1。
   - `--write`：只会往下调。只要还有超基线或缺行的文件，就拒绝（rc 1，不落盘）；否则按当前计数重写，并去掉计数为 0 的行和 stale 行。
   - `--init`：只用来写第一份基线；tsv 已经存在时拒绝。
   - 豁免：`tests/cxraw-layers.tsv` 里的前缀和精确路径，加上 `include/`、`tools/cxcc-hostinc/`。不扫：archive/、ujs/（论文 B）。
   - apps/csih 属于上层，在扫描范围内，它的行记为 csih 的债，本次没有改 csih 的文件。
   - 内部调用一次 `tools/bound 50 sh ./unisacc.com tools/symindex.cx -- external --tracked`。
3. `tools/ratchets.cx` 并行跑五个棘轮；`tools/check-ratchets.cx` 改为期望五行 RATCHET。

## 实测（2026-10-30，本机 lnx/x86_64）

- 耗时：`symindex external --tracked` 冷编译约 7 s，之后约 1.0 s（索引是热的，另外要重读调用方文本，大约 12 MB）。`tests/cxlibc.cx --check` 约 1.2 s。`tools/ratchets.cx` 五个并行跑，墙钟约 4.6 s。
- 初始基线：扫描 722 个上层 .cx，计数大于 0 的有 526 行，合计 23462 次（libc+host），其中 host 156 次。runtime 另计 2793 次，不进基线。tools/symindex/fixture/ext/caller.cx 一行（8）是夹具故意调用的，和 facts.cx 那一行（4）一样会长期保留。

## 已知不精确之处（如实记录）

- 只做词法判定，不展开宏，也不做类型检查。由宏生成的函数如果被调用，会记成 host。
- 前导按文本解析，`#if` 的各个分支都算进去，所以 libc 集合是所有平台的并集。
- repo 定义取自整个索引（含 archive/、ujs/）。别的文件如果因为 `#if` 括号失衡丢了 D 行，那里定义的函数被其他文件调用时会记成 host（例：tools/cxcc.cx 定义的 cxcc_drive，在调用方文件里记成 host）。本文件内的同类问题已经由 `NAME(...) {` 判定兜住。
- 前导名字如果被调用方用作同名局部函数指针（例如参数也叫 write）来调用，仍会记为 libc。host 类名字会做变量判定，libc 类不做，否则 `atexit(free)` 这种取地址写法会把真正的调用也一并去掉。
- tests/cases 下经 `#include` 引进 C 头文件的调用（rl_* 等）记为 host。这部分本身也是 cxinclude 要管的债。
- 本机验证不等于跨平台资格。
