## 排序理由

- R20-2/R20-3 处理的是用户实际踩到的“组合未覆盖 + 诊断误导”（dsh 多次复报），收益最大，且都已顺延过一次。
- R20-4 是三项的前提（转发补全、动态库、cc 混编），先做。
- R20-1 与上面独立，cdx 主导，可并行。
- 塞不下时，P2 中未标★的项（R20-6 的后半、R20-12）先顺延；标★的只能做或降级。

## 流程（沿用 0.0.19 的 R19-0）

冻结前 `release/tools/precheck.sh`；队列在独立工作树里跑；作废按被声明输入的树哈希判定；构建候选期间不改可执行输入（0.0.19 一次候选因 selfcheck.sh 中途变动而失败）；新增功能的套件先在本机计时，单项超过 40 秒即拆分（0.0.19 七红中五项是源码变大后的超时）。


## R20-1 C99 种子构造器

目标：以支持 C99 的宿主编译器构建 C 构造器，从与 Python 相同的事实表、控制规则与资源生成权重、网络包与 `unisacc-seed.com`。先作为独立对照实现，成熟后替换 Python 默认构造路径。不是重写运行时编译器，也不要求仅靠原有 18 张 gold 表推导全部控制过程。

排期：移出 0.1.x 待批候选，纳入 0.0.x，计划在 0.0.20 交付；不挤入当前 0.0.18 主线。开工先清点 Python 构造路径、输入闭包与工具依赖，再细化每片工作量；不得把登记说成已经完成。

| 片 | 交付 | 验收 |
|---|---|---|
| A | 复测已有 `iterate/construct/construct.c` 与 `iterate/kernel/genmodel.c`，登记可复用范围与现行格式缺口 | 旧 18 表 UNS2 与 Python 逐字节同；不把旧格式通过冒充 P3 完成 |
| B | 现行 δ / 网络的 C99 构造路径，先一个完整阶段再推广 | 同输入与 Python 逐字节同；全域 net=table；显式记录规则装配代码与依赖 |
| C | P3 包与 APE seed 构造，生成物来源清单 | 同冻结输入、工具链与选项下包及 seed 字节同；从 TSV/规则到 seed 的命令不调用 Python，外部编译/打包工具具名列出 |
| D | 默认切换与文档同步 | 六目标 N22 与相关完整门禁绿；构造耗时、字节账和无 Python 干净环境复建证据；未成熟时保留 Python 默认且如实记未完成 |

已有 iterate/ 先只复测和复用，不在旧开发工具目录继续扩建；新实现的目录归属在开工设计中确定。当前 N22 的宿主 cc / Python 构造边界说明保持事实，实际切换后再改。
