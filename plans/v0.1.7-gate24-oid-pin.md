## (2) 完整设计合同与补丁草案 (Patch Draft, 基于 `3788ea84ff`, 未应用/未编译)

### 1. 参数合同与空 OID 显式拒绝 (`tools/root-current.cx`)
- 新增选项 `--expect-oid <40-hex>`:
  - 使用独立布尔 `has_expect_oid = 1` 追踪是否传入该参数。
  - **显式空值 (`--expect-oid ""`) 或非 40-hex 字符串**: 绝不视作未指定! 参数阶段立即输出 `ROOT_CURRENT\tRED\treason=expect-oid-invalid\t...` 并退出 **`rc=2`**。
  - **合法 40-hex 但在仓内不是已存在的 commit**: `crc_git_resolve_oid(repo, "<OID>^{commit}", ...)` 失败 -> 输出 `ROOT_CURRENT\tRED\treason=expect-oid-missing\t...\texpect_oid=<OID>` 并退出 **`rc=1`**。
  - **同时传 `--expect-oid <OID>` 与显式/隐式严格 `--expect-ref main` (含 `--no-candidate-ahead`) 或 `--expect-ref HEAD`**: 要求 `<ref>^{commit} == <OID>`, 不等则 fail-closed 退出 **`rc=1`**, `reason=expect-oid-ref-mismatch`。

### 2. 标签快照与变化拒绝 (消灭 "固定了树却读了可变 tag")
- **单次完整原子快照 (`crc_tag_snapshot`)**:
  - 在 `crc_resolve_repo_source` 锁定 `g_expect_oid` 后, `crc_expect_version` **仅执行一次**:
    `git for-each-ref --format=%(objecttype)%09%(creatordate:unix)%09%(*objectname)%09%(objectname)%09%(refname:short) refs/tags/`
  - 为每个出现的 `v<V>` 缓存:
    - `tag_annot`: `"tag"` 为 `1`, `"commit"` 为 `0`;
    - `tag_ts`: `creatordate`;
    - `tag_target_oid[41]`: `objecttype=="tag"` 取 `%(*objectname)` (必须为 40-hex), `objecttype=="commit"` 取 `%(objectname)`; 若同短名重复出现异值或格式畸形直接报 `git-tags-unreadable`。
  - 同一运行内的祖先 tie-break (`merge-base --is-ancestor`) 与后段 `release_commit_oid` 交叉比对 **一律直接消费 `tag_target_oid[]`**, 不得再次按 `refs/tags/v<V>` 字符串做二次解析。
- **调用末尾二次稳定性复核 (TOCTOU 侦测)**:
  - 当处于严格公开模式或显式 OID/ref 检查时, 在最终放行 `PASS` 前, 用一次复核验证:
    1. 若请求了 `CRC_REF_MAIN` 或 `CRC_REF_HEAD`: 当前 `refs/heads/main^{commit}` / `HEAD^{commit}` 必须仍等于入口冻结的 `g_expect_oid`;
    2. 选中公开版本对应的 `refs/tags/v<expect_ver>^{commit}` 必须仍等于 `tag_target_oid[best_idx]`。
    - 任一发生漂移 -> 立刻 fail-closed 退出 **`rc=1`**, `reason=repo-state-changed-during-check`。
- **历史 `--expect-oid <OLD_OID>` 如何对待后来新增 tag**:
  - `crc_expect_version` 只在 **`<OLD_OID>:build/version-seq.tsv`** 列为 `已公开` 的版本集合 `pub[]` 内查找与排序 tag。后来新版本 (`v0.1.4`, `v0.1.5`) 不在 `OLD_OID` 的 `已公开` 集合中, 自动被过滤忽略, 不影响按 `<OLD_OID>` 重算该历史时刻的公开预期; 仅当 `v<V>` 本身在仓库内被强行改指与 `<OLD_OID>` 内部 `candidate.tsv`/`public-readback.txt` 矛盾时, `tag-commit-mismatch` 才拒绝。

### 3. 结构化 Readback 帧与严格模式证据/Commit 矩阵

#### `public-readback.txt` 三锚点结构化解析 (`crc_readback_meta`)
禁止在全文件任意位置识别裸 40-hex! 按真实格式定义 3 个严格位置锚点:
1. **`targetCommitish` 帧**: 以 `{"isDraft":` 开头的 JSON 行中解析 `"tagName"` (若存在须等于 `v<VER>`) 与 `"targetCommitish":"<40-hex>"`; 格式错误或同文件多行冲突分别返回 `-2` / `-3`。
2. **Scoped tag 裸 OID 帧**: 状态机只在精确整行 `READBACK_STEP metadata PASS` 出现后、`READBACK_STEP tag PASS` 出现前的**唯一紧邻子段**内接受 1 行裸 40-hex 行 (恰好 40 个小写十六进制字符); 该窗口缺失合法 40-hex 或出现多条不一致或非 40-hex 行则返回 `-2` / `-3`。
3. **`C47_*_READBACK` 总结帧**: 行前缀 `C47_` 且含 `_READBACK ` 时解析 `\tcommit=<40-hex>` 或空格分隔 `commit=<40-hex>` token (校验后跟空白或行尾, 不截断错字符); 畸形返回 `-2`, 冲突返回 `-3`。
4. **SHA 帧**: `READBACK_SHA unisacc.com <64-hex>` 与 `READBACK_SHA\tunisacc.com\t<64-hex>`。

#### 严格模式 vs 默认兼容模式证据与 Commit 真值表
设 `strict_ev = (no_cand_ahead || has_expect_oid || g_ref_mode == CRC_REF_MAIN)`:

| 字段/状态 | 默认兼容模式 | 严格公开模式 (`strict_ev`) | 失败码 / 原因 |
|---|---|---|---|
| `expect_sha` 任意来源解析畸形 (`-2`) | RED `rc=1` | RED `rc=1` | `expected-sha-malformed` |
| `candidate`/`receipt`/`readback` SHA 冲突 (`-3` 或异值) | RED `rc=1` | RED `rc=1` | `expected-sha-conflict` |
| 严格证据缺失 (`receipt` 或 `readback` SHA 缺) | 若另两源或 `candidate` 存在可用; 全无则 RED | **必须 `ape-receipt.txt` 与 `public-readback.txt` 同时存在且一致** (防剥离证据只留未回执 `candidate.tsv` 绕过) | `expected-evidence-missing` (`rc=1`) |
| `readback` commit 帧畸形 (`-2`) / 内部冲突 (`-3`) | RED `rc=1` | RED `rc=1` | `expected-commit-malformed` / `expected-commit-conflict` |
| `cand_commit` / `rb_commit` 互冲 | RED `rc=1` | RED `rc=1` | `expected-commit-conflict` |
| `readback` 无 commit 帧 / `tag_target_oid` 无 | 允许仅按 SHA 对齐 (向后兼容无完整 readback 旧夹具) | **必须同时存在且非空** (防剥离 commit 字段绕过) | `expected-commit-missing` (`rc=1`) |
| `tag_target_oid` 与 `release_commit_oid` (`cand`/`rb`) 异值 | RED `rc=1` | RED `rc=1` | `tag-commit-mismatch` |
| 非候选实际根 `actual_bj_commit` 与 `release_commit_oid` 异值 | 若无 `release_commit_oid` 才跳过 | **强制校验 `actual_bj_commit == release_commit_oid`** (不再因 `C0a` 覆写 `candidate.tsv` 而跳过) | `root-build-json-commit-mismatch` |
