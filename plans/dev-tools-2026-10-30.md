# 开发加速工具：已建与待建（2026-10-30，cc）

总原则见 AGENTS.md"用工具、造工具"一条。每个工具的入口都写在 prd.md 能力速查里，并各有 check-*.cx 和登记的批次。

## 已建

| 工具 | 解决的反复劳动 | 批次 |
|---|---|---|
| `refactor.cx sites` | 全仓查调用点，代替成百次 grep | refactor-tool |
| `refactor.cx find/apply` | 按规则机械改写，逐文件核验，不一致就还原 | refactor-tool |
| `refactor.cx sweep` | 多轮批量改写，每次调用跑一轮，可续跑，失败的文件进 skip 名单；代替手写的 shell 循环 | refactor-tool |
| `refactor.cx rename` | 标识符全仓改名，走 apply 核验 | refactor-tool |
| `tools/tape-gap.cx` | 某目标的 lowering 缺口一次列清 | tape-gap-tool |
| `tools/ratchets.cx` | 四个棘轮并行跑，只列出超基线的行 | ratchets-tool |
| `tools/register.cx` | 检查登记成批次、校验、试跑，失败只撤回自己加的两行 | register-tool |
| `tools/edit-span.cx` | 按行段替换，首末行断言 | （已有） |
| `tools/affected.cx`（子代理在做） | 改了哪些文件 → 该重跑哪些批次，并行跑 | affected-tool |
| `tools/symindex.cx`（子代理在做，设计见 plans/symindex-design-2026-10-30.md） | 按内容寻址的符号索引，用时间戳预筛；提供 def、calls、uses/users、undeclared | symindex-tool |

## 待建（按收益排序）

1. **共享检出下的"只提交自己的行"**。今天出过两次事故：
   - 一次是 `git diff` 看不到别人已经 `git add` 的改动；
   - 一次是按路径提交 tests/coverage.tsv 时，把别的代理刚追加的一行带进了提交（8d50d63095，带进了 affected-tool 的 coverage 行）。

   先做一个守卫：`own-diff FILE KEY...`，列出相对 HEAD 改动、但不属于这些 KEY 的行，有就退出 1。之后视情况做临时 index 的部分提交，即把 2026-10-30 run-startup-bench.cx 那次的手工步骤做成工具。
2. **use-lint**：由 symindex 的 `undeclared` 提供。编译器修好隐式声明（plans/indirect-proto-2026-10-30.md）之前靠它守住。
3. **affected 改用 symindex 的 uses/users**：去掉重复的 use 图解析。
4. **跨文件的块级改写**：例如 `#pragma unisa use` 去重、排序、补缺。用 symindex 判断某文件实际调用了哪些模块的函数，自动补上直接 use，修掉间接可见的调用。
