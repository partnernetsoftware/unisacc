# L0 补信号处置、raise、退出处理与 symlink（2026-10-30，cc）

csih 车道要替换 8 处 signal/raise/atexit 和 1 处 symlink。前导的 `signal()`/`sigaction()` 只填进程内的表，由前导 `raise()` 读取，从不调用内核（`include/signal.h` 文件头已写明）。所以外部发来的 SIGTERM/SIGINT 不会进处理函数，SIGPIPE 也忽略不了。

## 接口

| 模块（use） | 文件 | 函数 | 说明 |
|---|---|---|---|
| `sys.sig` | `cx/sys/sig.cx` | `int sy_sig_handle(int sig, void (*fn)(int))` | 用 rt_sigaction 真正注册到内核，SA_RESTART。处理函数运行期间本信号被阻塞。返回 0 或 -errno：sig 越界、fn 为 0、SIGKILL/SIGSTOP 都是 -EINVAL；macOS/Windows 返回 -ENOSYS |
| `sys.sig` | `cx/sys/sig.cx` | `int sy_sig_default(int sig)`、`int sy_sig_ignore(int sig)` | SIG_DFL、SIG_IGN。返回 0 或 -errno。macOS 走 sigaction 系统调用（46）；Windows 返回 -ENOSYS |
| `sys.sig` | `cx/sys/sig.cx` | `int sy_raise(int sig)` | kill(getpid(), sig)，经内核投递。返回 0 或 -errno；Windows 返回 -ENOSYS |
| `sys.sig` | `cx/sys/sig.cx` | `int sy_atexit(void (*fn)(void))`、`void sy_exit(int code)` | 模块自带的表，最多 32 项，后注册的先运行。从 main 返回时运行（模块析构函数），调用 sy_exit 时也运行。fn 为 0 返回 -EINVAL，表满返回 -ENOMEM |
| `sys.fs` | `cx/sys/fs.cx` | `int sy_symlink(const char *target, const char *link)` | 返回 0 或 -errno。参数为空返回 -EINVAL，link 已存在返回 -EEXIST，允许悬空链接；Windows 返回 -ENOSYS |

## 处理函数怎样进入

- 编译产物用 unisa tape ABI，不用平台 C ABI。x86_64 上第 0 个参数是 rax，而内核把信号号放在 rdi。arm64 上返回地址放在 x7 tape 上，而内核把它留在 x30。所以不能直接把 CX 函数地址交给内核。2026-10-30 的探针证实：直接注册时处理函数能运行，但收到的信号号是 0。
- 运行时做一页代码：sys.mem 先映射，写入后改成读+执行。页里放入口 thunk，把信号号搬进 tape 参数寄存器，再跳到 `syg_dispatch`，由它按 `syg_fn[sig]` 调用户函数。
  - Linux x86_64：入口是 `mov %rdi,%rax; movabs $syg_dispatch,%rcx; jmp *%rcx`；restorer 是 `mov $15,%rax; syscall`（rt_sigreturn），配 SA_RESTORER。
  - Linux arm64：入口是 `mov x16,sp; sub x7,x16,#16; str x30,[x7]; ldr x16,=dispatch; br x16`。不需要 restorer，内核走 vdso。
    - 实测：在 qemu-user 下，tape 指针 x7 在硬件 sp **下方** 56 字节。若信号帧压在 sp 上，就会覆盖活着的 tape 帧。
    - 所以 arm64 一律用 sigaltstack（256 KiB）加 SA_ONSTACK，thunk 从备用栈上信号帧的下方开始 tape。
  - 机器码字节都用 `as` 和 `aarch64-linux-gnu-as` 汇编核对过。
- macOS 的 sa_tramp/sigreturn token 协议没法实跑，所以 macOS 不提供处理函数（-ENOSYS），只提供忽略和默认两种处置。

## 限制

- **前导 atexit 不能直接转发。** 前导的 atexit 表每个单元一份：模块单元里注册的函数，只有调用该单元 exit() 时才会运行。探针 `out/sig-probe/p3.cx` 证实，模块里注册的那项从不运行。
  - 编译器的析构函数链会在 main 返回、main 所在单元 exit 之前运行，sy_atexit 就挂在这条链上。
  - 别的单元调用 exit()、调用 _exit、因信号死亡，这三种情况都不会运行 sy_atexit 表。需要的地方改用 sy_exit。
  - sy_exit 只调用本单元的 exit，不刷新调用方单元 fopen 打开的流。
- **errno 每个单元一份。** 处理函数若调用本单元的前导函数，应自己保存并恢复 errno。
- **线程。** arm64 的备用栈只设给第一个注册处理函数的线程。

## 检查

- `tools/check-cx-sys-sig.cx`，批次 `cx-l0-sys-sig`，共 28 条。信号用例都在子进程里跑：以 `-- child a|x|c|r` 重新运行本文件，由 sy_spawn_pipe 启动，再用 sy_wait_status 从外部观察结果。
  - a：sy_raise 和另一进程的 `kill -TERM` 都会让处理函数以 15 运行；忽略 SIGPIPE 后，向读端已关的管道写入返回 -EPIPE，进程不死；main 返回后才运行 atexit，退出码 0。
  - x：32 项注册成功，第 33 项返回 -ENOMEM；sy_exit(7) 按后进先出运行全部 32 项。
  - c：sy_sig_default 之后 raise，进程死于信号 15，atexit 不运行。
  - r：在处理函数内先恢复默认再 raise，等处理函数返回后进程才死于 15。这是 csih term.cx 的用法。
  - 拒绝用例：越界信号号、SIGKILL/SIGSTOP、空 fn 都返回 -EINVAL。
  - symlink：lstat 结果为 kind 'l'；stat 和 realpath 都解析到目标；重复创建返回 -EEXIST；空参数返回 -EINVAL；允许悬空链接；目录不存在返回 -ENOENT。
- 本机 lnx/x86_64 实跑：`CX_SYS_SIG ok=28 failed=0`。
- lnx/arm64：用 `-b lnx/arm64` 编出二进制，在 qemu-aarch64-static 下直接运行四个子模式，输出与 x86_64 一致（143 即信号 15）。这是 qemu-user 的信号模拟，不是真机。
- osx/x86_64、osx/arm64、win/x86_64：只编到 `-b` 二进制，没有实跑。win 的 tape 经 tape-gap 检查为 gaps=0；其它目标用 `-t` 出 tape 时，宿主 mmap 无法解析（sys.mem 原有情况）。
