- **v0.1.3 内存安全检查节点（政委 2026-09-30 方向；可选但默认开；不影响 0.0.14 顺序）**
  - 立场与分工：**模型**推断所有权 / 生命周期 / 边界并写成标注（表状决策，进网络）；**确定性、可审计的检查器**逐函数验证标注（经典代码，不交给权重——否则保证退化为概率）；验证通过的函数按原生速度编译，未通过的默认自动补运行时检查；`--safe=strict` 像 Rust 一样拒绝编译；`--safe=off` 一键回到纯 C。卖点：现有 C99 代码不改一行拿到接近 Rust 的保证。
  - 三步，每步单独有用、单独验收：
    1. **tape 运行时安全模式**（带边界与生命周期的指针，参考 Fil-C / CHERI 的胖指针与时间安全；先服务 `-run` 与 agent 沙箱）。验收：一组越界 / 释放后再用 / 双重释放 / 悬垂返回的红例在 `-run --safe` 下确定性地被捕获并报 file:line:col；examples 与 tests/c 全部探针在安全模式下输出不变；开销写进 research（相对纯 `-run` 的倍数）。
    2. **最小标注规则 + 检查器**（参考 Cyclone / Checked C / Rust 借用检查；先只管释放后再用与越界）。验收：标注语法与检查规则写成规格（含健全性论证：检查通过 ⇒ 该函数无步骤 1 能捕获的错误）；检查器对 tests/c 的一个手工标注子集全部通过、对红例全部拒绝；检查器本身有独立测试且不含任何网络查询。
    3. **模型自动补标注**：标注推断做成一个（或几个）有限表 → 网络，与 δ 框架同一套构造与穷举验证；在 Lua 5.4 与 SQLite 上量三件事：可证明函数比例、误报（要补运行时检查但其实安全）、漏报（为 0 是硬约束，由检查器保证）；已证明处去掉运行时检查后性能回到原生。
  - 安全默认库：带长度的字符串与切片、arena、清理钩子（include/ 里的 L1 自研体，随 -ftrim-libc 按需带入）。
  - 论文 D（[research/paper-d-intent.md](../research/paper-d-intent.md)）描述这个可选节点及其对软件工程质量的提升；命名与格式对齐 A/B/C。

## 权重本体与推理（0.1.x 研究候选，不自动开工）

背景和快照身份见 `prd.md` §5.2。研究对象是构造出来的网络参数、动作序列、状态结构和推理成本；P3 包的压缩比不是本项成功判据。先采每银行的静态单元/权重位宽与动态访问次数、激活长度分布、动作次数，按阶段列出权重字节、运行内存、加载时间和同身份五次编译中位数。已有 FX-6 的 SIMD 负结果不能用静态长银行数量推翻。

1. **阈值段聚合实验**：对两个输出差分权重都相同的连续阈值段使用精确整数表达式。先用独立解释器逐银行穷举原观察域，验证下一状态和动作序列逐项相等；统计加入段边界/长度后的净字节，并以真实轨迹分别测长银行与全流水线。验证整数中间值界及声明返回优先级。只有全域与速度都过关才进入产品表示。
2. **动作/银行模板统计实验**：将动作参数标注为寄存器、立即数、状态、字符串等不同编号域，计算 alpha 归一化后的模板数、参数熵、共享前后缀及跨网络重定位成本。模板必须能展开回原动作顺序、常量、停止/拒绝行为。先提交统计与预算；净收益不足则停止，不凭去重率推断字节或速度。
3. **后续有界原型**：若前两项显示足够收益，再分别实验跨网络等价子图、精确 int8/int16/int32 混合表示与连续 arena、分层阈值电路、模型自动导出的动作执行块。每项保持通用执行器不含 C 语言特判；报告新增执行器字节、冷/热装载成本、单次延迟和批量吞吐。局部 10 倍要注明是哪个银行/动作块；全模型 10 倍与整机 10 倍分别取证，不能外推。

门禁：构造期全域 net=table；结构合并还需反展开或显式状态/动作映射，覆盖缺边、EOF、声明返回和拒绝；阶段输入输出及全套产品门禁不退。旧权重与新表示同源同输入对拍。严禁把答案表、手写编译决策或有损量化计作网络优化。


## 产品原则（主人裁定 2026-10-01，各版沿用）

- **默认即运行**：`unisacc FILE.c [args]` 不带 `-run`/`-o` 就是运行模式；写文件要 `-o`。0.1.x 的 harness、狗粮启动器、文档与示例一律按此写，不再出现“像 cc 一样静默写 a.out”的说法（0.0.17 R17-10 落地）。

- **DNS 跟随转发路线**（0.0.25 N1 评估、0.0.26 起实现）（0.0.24 X2 评估，2026-10-04）：不内置 UDP 解析器；getaddrinfo/freeaddrinfo/gai_strerror 随 libc 转发（prd §5.1）交给系统 libc，Windows 走 DnsQuery 或 ws2 的 getaddrinfo。验收：解析一个 /etc/hosts 之外的名字，结果与系统 cc 构建的程序一致；转发不可用的目标仍明说 EAI_NONAME。
- **POSIX 兼容主线：lua、sqlite、minicon、agenterm**（0.0.25 N2 出缺口清单）（政委 2026-10-04 定）：以这四个真实程序为验收对象推进 POSIX 兼容，参考路线和产品路线都要编译并通过各自的测试；缺的 libc 和系统调用按“转发优先、自研兜底”补（prd §5.1）；每补一类接口就配一个与系统 cc 对拍的探针。lua 已在 realprog 基线里，sqlite、minicon、agenterm 先做缺口清单再排期。
- **TLS 跟随转发路线**（随 N1 评估）（cdsh 2026-10-04 再次要求 HTTPS POST 并校验证书）：不内置 TLS 实现；转发给系统 TLS 库（macOS Security.framework / Network.framework，Linux 上的 libssl，Windows SChannel），证书用系统信任库。验收：unisacc.com 编出的程序对 https 端点 POST 成功，证书错误时拒绝。先于 DNS 的前提是转发路线在产品侧可用；0.0.25 先评估产品路线 macOS/Linux 转发的范围，再定 DNS 和 TLS 的具体版本。
- **向 cosmocc 那种 POSIX C99 头文件面进化**（主人方向，grk-yche 2026-10-05 转述）：对标 cosmocc 的头文件集合，不再为单个用户堆特例。现状：POSIX.1 常见 82 个头里 include/ 有 37 个；缺的有 pthread.h、dlfcn.h、regex.h、pwd.h、grp.h、fnmatch.h、glob.h、sys/mman.h、sys/resource.h、wctype.h、fenv.h、tgmath.h；C99 第 7 章库账本约 35%。复数与三字符组仍不做。做法沿用“转发优先、自研兜底”（prd §5.1），每补一个头配一个与系统 cc 对拍的探针；从 0.0.27 起每版排一批（先 dlfcn.h、pwd.h、sys/mman.h，与 N2 缺口清单合并），不要求一次补齐。
