## v0.1.x 路线（草案，2026-09-28 调整；2026-09-29 主人要求：其中工程型条目已提前到 v0.0.12 计划，此处保留证明型条目——T2、P-2 全走查器、T3 机器证明、.o、wasm）

原则：每个 0.1.x 版本只收一类问题，每项有可检验的完成判据；完成一项，就把它从论文 §8 的局限移到结果。不自动开工，开工前再细化成 R 表。

- **v0.1.0 可信边界扩大（证明为主）**
  - T2 首例：选最小的完整阶段——剪枝，约 322 个状态——机器证明网络执行与参考执行的模拟关系（初态关联、状态不变量、终态匹配、发散敏感），再评估推广到预处理。
  - P-2 全走查器：“每次询问的键都在定义域内”从玩具走查器推广到全部走查器。
  - 外部裁判覆盖：经典 18 表中具名裁判过半；33 个网络的裁判登记齐全，并由门禁检查。
  - 维护面：决策代码行数账本连续三个版本的数据，显示手写决策逻辑净减少，并与表示迁移分开报告。
- **v0.1.1 自构造与平台**
  - 网络包与多平台容器由编译器自身构造，N1 = N2 = N3 覆盖包与容器，而不只是固定包下的驱动自举。
  - Windows 原生驱动自举。
  - 各单架构产物在对应原生机器上跑完整套件，不只烟测。
- **v0.1.2 语义与覆盖**
  - T3 前置：写成规格的 C 子集、ABI、未定义与未指定行为清单；在此之上做大规模差分裁判（如随机程序生成器对拍），并写清它与证明的边界。
  - 仍是代码的部分进表：机器码字节模板、Windows argv 等宿主模板迁入声明规则。
  - 容量：静态上限改为可证明的界或动态增长，覆盖现有 610 MB 数组源码这类规模问题。
- **v0.1.3 内存安全检查节点（政委 2026-09-30 方向；可选但默认开；不影响 0.0.14 顺序）**
  - 立场与分工：**模型**推断所有权 / 生命周期 / 边界并写成标注（表状决策，进网络）；**确定性、可审计的检查器**逐函数验证标注（经典代码，不交给权重——否则保证退化为概率）；验证通过的函数按原生速度编译，未通过的默认自动补运行时检查；`--safe=strict` 像 Rust 一样拒绝编译；`--safe=off` 一键回到纯 C。卖点：现有 C99 代码不改一行拿到接近 Rust 的保证。
  - 三步，每步单独有用、单独验收：
    1. **tape 运行时安全模式**（带边界与生命周期的指针，参考 Fil-C / CHERI 的胖指针与时间安全；先服务 `-run` 与 agent 沙箱）。验收：一组越界 / 释放后再用 / 双重释放 / 悬垂返回的红例在 `-run --safe` 下确定性地被捕获并报 file:line:col；examples 与 tests/c 全部探针在安全模式下输出不变；开销写进 research（相对纯 `-run` 的倍数）。
    2. **最小标注规则 + 检查器**（参考 Cyclone / Checked C / Rust 借用检查；先只管释放后再用与越界）。验收：标注语法与检查规则写成规格（含健全性论证：检查通过 ⇒ 该函数无步骤 1 能捕获的错误）；检查器对 tests/c 的一个手工标注子集全部通过、对红例全部拒绝；检查器本身有独立测试且不含任何网络查询。
    3. **模型自动补标注**：标注推断做成一个（或几个）有限表 → 网络，与 δ 框架同一套构造与穷举验证；在 Lua 5.4 与 SQLite 上量三件事：可证明函数比例、误报（要补运行时检查但其实安全）、漏报（为 0 是硬约束，由检查器保证）；已证明处去掉运行时检查后性能回到原生。
  - 安全默认库：带长度的字符串与切片、arena、清理钩子（include/ 里的 L1 自研体，随 -ftrim-libc 按需带入）。
  - 论文 D（[research/paper-d-intent.md](../research/paper-d-intent.md)）描述这个可选节点及其对软件工程质量的提升；命名与格式对齐 A/B/C。
