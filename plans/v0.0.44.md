## 已确认缺陷

- **C44-STDIO-01：输出错误状态传播。** 当前0.0.43候选4f0b493c下，默认运行以下探针并将stdout定向到Linux `/dev/full`，实际stderr为 `puts=0 fflush=0 ferror=0`；实际运行rc0。期望写失败能通过返回值和流错误状态被调用者发现。复现源码：

```c
int main(void) {
    int a = puts("probe");
    int b = fflush(stdout);
    int c = ferror(stdout);
    fprintf(stderr, "puts=%d fflush=%d ferror=%d\n", a, b, c);
    return 0;
}
```

保存为 `out/stdioprobe.cx`，执行 `sh ./unisacc.com out/stdioprobe.cx > /dev/full`。后续核查puts/fwrite/fflush/ferror共享的错误传播，再验证短写、EINTR、写满、关闭描述符和正常输出。当前目录快照工具使用检查write返回值的循环，已用默认运行路径验证拒绝写满；不据此宣称运行库缺陷已修复。

- **C44-ARCHIVE-01：历史归档接线与引用检查。** 整目录归档A批859文件的实际subtract-safety检查报告536处悬空引用：既有尚未迁移的文档／源码出处，也有 `STATE_DIR/results.json`、`CAND_DIR.queue/release-queue.log` 等模板被档案同名basename触发的误判。不能把536项全部当作虚警。下一版完成引用接线并修正模板上下文识别，继续拒绝真实悬空引用；不新增豁免。完整可逆补丁与逐件SHA／权限备份已保存在仓外，当前树恢复为已验证布局，不把此归档重构插入0.0.43发布前置。
