# stay-native 时间占比证伪

只读. 未跑热路径, 未跑批次. 结论: 现有表算不出时间占比, 不能说高于或低于 30%.

## 用了哪份时间

两份都看了, 都不是按单元或按函数的时间.

(1) build/speed-baseline.tsv. 列是 date, candidate, tool, metric, reps, min, median, unit, note. 201 行数据. metric 是工具整段 (first_e2e, cold_ms, 1MB sha), 不是 slice-units 的单元. 不用它做分子.

(2) tests/cases/perf-hot/baseline-sample.tsv. 这是 perf-hot 的夹具, 不是一次全单元实测. 开头几行只覆盖 funitcold:asmtext 的相位. 没有 99 个单元的时间. 不用它做分子.

没有第三份现成的 per-unit 或 per-function 时间表. 时间份额 UNMEASURED.

## 单位表里没有 stay-native

plans/slice-units.tsv 表头:

```
key source module uses lines heap recursive override note
```

全文检索 stay-native 为 0 行. 本窗口, w-agyneon, w-agy-h, w-agyneon2, w-agyneon3, 共享检出的同名文件都是这份表头, 都没有 stay-native.

override 的取值, 99 个单元:

| override | 单元数 |
|---|---|
| - | 93 |
| 留切片 | 5 |
| 迁VM字节码 | 1 |

行数合计 30329. 这是源码行, 不是时间. 不把 5/99 或 5 个单元的行数除以 30329 写成时间占比.

## 算术

要的式子:

```
share = sum(time of units whose destination is stay-native) / sum(time of all units)
```

分子的集合是空的: destination 列不存在, stay-native 行数为 0.
分母不存在: 没有与 key 对齐的时间.

所以 share 不是一个数. 不与 0.30 比较. 既不是高于 30%, 也不是低于 30%.

若 v0.2.x 计划把 stay-native 的时间份额写成低于 30%, 现有输入证伪不了那个数, 也支持不了那个数. 缺的是目的地列和按单元的时间, 不是再跑一次整链就能从这两份表现成的表里读出来.

## 字节占比代理

override 列 93 个减号不是没有目的地. 目的地由 tools/slice-migration-gen.cx 的规则派生, 写在 plans/slice-nn-migration.md. 留切片就是 stay-native.

字节取 plans/unit-text.tsv 的 .text 列 (ELF 节大小, 切片 lnx/x86_64). 99 个单元合计 2441257 字节, 与生成物第 9 行一致.

留切片名单取生成物第 17 到 43 行, 27 个单元. 与 unit-text.tsv 按 key 对齐, 无缺行, 字节和 515445. 与生成物第 9 行一致.

```
515445 / 2441257 = 0.211139 = 21.1139%
```

21.1139% 低于 30%. 这是字节代理, 不是时间. 时间份额仍是 UNMEASURED, 直到 agyneon 交出按函数的剖面.
