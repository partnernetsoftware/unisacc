## 主题

0.0.13 用真实程序把编译器逼出了 30 余处缺陷并修完；0.0.14 收两类账：**产品还不能编的 C**（六参数间接调用、缺失库面、`#line`）与**流水线自身的方法债**（0.0.13 为封版重跑了四次队列，每次都是流程缺陷而不是产品缺陷）。

- **R14-7 以 tape 为中心的可移植运行平台（政委 2026-09-30 方向建议，采纳为方向；本版只做两个可验收的小落点）**  [cc-unisacc 设计 / cdx 实现]

  - 落点 A（本版）：**tapebin 格式 v1 与运行时契约文档化**——prd FX-1 的编码（1 字节 opcode、寄存器对合 1 字节、变长立即数、符号表与常量池）定稿为 `docs/tapebin-v1.md`，附版本头与目标无关声明；实现 `.tape ⇄ .tapebin` 编解码，门禁 `tapebin-roundtrip`（裁定 2026-09-30：往返的等价对象是**结构化记录与 tapebin 字节**，不是任意文本，不做打印样式 ID）：对 examples/ 与 tests/c 全部探针的 `-S` 输出——① `encode(parse(t))` 确定（两次同字节，记录保序：.bss/.str 不提前）；② `decode(encode(t))` 与 `parse(t)` 的记录序列逐项相等；③ `encode(decode(b)) == b` 逐字节恒等（内容哈希稳定的根据）；④ 文本入口与 tapebin 入口的 `-run` 输出/退出码与 `-b <t>` 六目标镜像逐字节同；`to_text` 只需是确定性规范打印，TEXT_EXACT 仅可选（手写文本）；⑤（裁定 2026-09-30，本片必做）**产品也要发射**：`<产品> x.c -S --tapebin` 与 C 参考 `--tapebin` 对 examples/ + tests/c 全部探针逐字节同（经典适配层编码 E4/lower 的记录，不进网络）；⑥ 产品自发的 .tapebin 喂回产品 `-run`/`-b <t>` 与文本路径同输出/同镜像；⑤⑥进 `com-tapebin`，且该门禁把 .tapebin 字节原样交给 MODEL_COM（对不含适配器的 0.0.13 产品必须红——已实测 rc1）。另有 `tapebin-shape` 门禁：71 项 opcode/shape 由一份生成清单产出，C 参考、Python、exec/c 三方一致；头含 `origin_target`，`-b` 目标不符默认拒绝。验收：两门禁绿 + 文档有格式表与兼容承诺（v1 内只增不改）。
