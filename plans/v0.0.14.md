## 主题

0.0.13 用真实程序把编译器逼出了 30 余处缺陷并修完；0.0.14 收两类账：**产品还不能编的 C**（六参数间接调用、缺失库面、`#line`）与**流水线自身的方法债**（0.0.13 为封版重跑了四次队列，每次都是流程缺陷而不是产品缺陷）。

## 任务树（节点写目标 / 验收 / 负责；开工前再细化成红例）

- **R14-0 #21 ≥6 实参经函数指针调用**  [cdx 已开工，主人 2026-09-30 指派]
  - 设计（cdx，已批准）：新增目标无关 tape 操作 `callm r7, 0`——六实参弹入 r0..r5 后被调地址仍在 `[r7+0]`；lower 阶段按目标用保留 scratch（x86 `r11`、ARM `x16`）取地址后复用 `callr` 编码；前端不写 ISA 寄存器、被调侧约定不变、编码器无新字节规则。
  - 验收：fb12-21 两侧转绿并删 `tests/difftest.knownfail` / `difftest.com.knownfail` 行；`tests/diag.sh` 的 poscase 改为通过用例；README 限制表删行；difftest 四片、e4、libraryabi/carrier、exec-chain 178/178、selfcheck 绿；六 runner 演示集加一个六参数间接调用程序。
  - 约束：scratch 不得与 `weights/gold/regmap.tsv` 的任何 tape 寄存器映射冲突；vararg/压栈路径一致；gold 表若新增操作码走 `build-weights` 穷举验证。

  - 验收：每个函数一个 `tests/c` 红例对拍 gcc，两侧转绿；`cc -E -P -undef -nostdinc -Iinclude -D__UNISA__ include/X.h` 过；`emit-kernel` 重生成；`libneed.check_guards`；README 限制表删名。
- **R14-2 构建/门禁方法债（0.0.13 封版四次重跑的根因，全部有据）**  [cc-unisacc]

- **R14-6 C99 条款覆盖账本与门禁（主人 2026-09-30：兼容不能自吹，要给标准出处，套件要覆盖全部规范）**  [cc-unisacc；设计先于开工]

  - 账本 `tests/c99/clauses.tsv`：一行一个规范性子条款（5.1–5.2 环境、6.2–6.10 语言、7.1–7.26 库、附录 F/G 若声明不支持则如实写 `unsupported`），列：条款号 / 标题 / 状态（covered / partial / unsupported / not-applicable）/ 覆盖它的探针或套件（`tests/c/*.c`、c99 套件、difftest、corpus 条目）/ 备注（限制表行号）。翻译限制（5.2.4.1）逐项写实测值（struct 成员 256 vs 标准 1023 等）。

  - 探针来源：优先复用现有 tests/c（179 个）与 corpus（220）；缺口按条款补最小红例；对 7.x 库条款，未实现函数标 `unsupported` 并对应 README 限制表。
  - 验收：账本与门禁进 `gate --list`；README 的 "C99" 句子引用账本数字；每条 `partial/unsupported` 都能在限制表找到对应行。

- **R14-7 以 tape 为中心的可移植运行平台（政委 2026-09-30 方向建议，采纳为方向；本版只做两个可验收的小落点）**  [cc-unisacc 设计 / cdx 实现]
  - 立场：C 是第一个前端，`.tape`/`.tapebin` 是交付物；同一 IR 既可 `-run` 解释执行也可落成六目标 `.com`（今天已是事实），差别只在把它写成契约并稳定。
  - 落点 A（本版）：**tapebin 格式 v1 与运行时契约文档化**——prd FX-1 的编码（1 字节 opcode、寄存器对合 1 字节、变长立即数、符号表与常量池）定稿为 `docs/tapebin-v1.md`，附版本头与目标无关声明；实现 `.tape ⇄ .tapebin` 编解码，门禁 `tapebin-roundtrip`：examples/ 与 tests/c 全部探针 `.tape → .tapebin → .tape` 逐字节同、`-run` 两种输入同输出；`unisacc -b <target> x.tapebin` 就地落成原生。验收：门禁绿 + 文档有格式表与兼容承诺（v1 内只增不改）。
  - 落点 B（本版）：**狗粮靶子可行性清单**——盘点 minicon / agenterm 里用 cosmocc 或 tinycc 构建的组件，逐个列出依赖的 C 语言面与 libc 面，对照 README 限制表与 R14-1，选出第一个可切换的组件并写出切换步骤与验收（构建产物字节可复现、原测试通过）；本版只定靶与列清单，切换本身若在缺口修完后能 <1 天则顺手做。
  - 方向（0.1.x，不在本版）：agent 沙箱执行层（先 `-run` 当场跑，验证后固化成 `.com`）；tape 上第二前端（小语言/脚本方言 = 换一组表，是“模型换逻辑”的放大器）；tape → wasm 后端（prd FX 已有定位）。
  - 主指标：真实项目阶梯——miniz 已往返 → **Lua 5.4 跑过自测**（0.0.14 目标）→ SQLite；每个台阶写"挡在第几条"。卖点表述：三阶段自举一致 + 单文件签名 `.com` = 可复现可信工具链。
