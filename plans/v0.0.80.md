# 0.0.80 计划:对象产出合同

状态:计划(2026-11-19 草拟)。类型:驱动与对象产出类,一类大改;来源:plans/product-refactor-plan.md 的 F1 到 F4、F6,与 0.0.76 发布说明里的三条对象产出静默缺陷(NN-VERIFY-ELF-INIT、NN-VERIFY-WEAK、NN-VERIFY-FUNIT-SYSV)。

## 为什么这版先于 R2 接线收尾

(1) 静默错误优先:-c -funit 对象里带初值的全局与 const 全进 .bss 且没有 .init_array,交给系统 ld 链接后读到 0,没有任何诊断(F1);带参的 -funit 对外函数首参取 %rax 而非 SysV 的 %rdi(F2);weak 发射为 STB_GLOBAL(F3)。(2) 对象产出本来就要变字节,与"字节等价"的表重构(0.0.79)和 R2 接线(验收是运行输出与 rc)是三种不同验收,不能同候选:R2 接线收尾(W3b 变参入闭包、W3c drive 接线、W2d _unisa_env 暂定定义出 COMMON,及 F5 链接合同检查)拆到下一版。

## 版本约束与风险

- 产品输入:exec/enc、exec/lower、elfobject 相关表,以及前端属性传递(weak)可能触 cx/ 与 src/(先在设计单判定最小面;若触 cx/cx0 或前端表则按三源类另开)。一类大改 = 对象产出合同。
- 风险:arm64 与 osx、win 目标没有原生执行环境 UNMEASURED;对象产出变字节后整链字节比较的口径要写明(对象产出路径变,整程序 -o 路不变);F4 可能改 CLI 语义,先检查后改。
- 先 F1 设计单,设计评审后再并行开实现单;关键路径封顶 4 张实现单,超出即拆。
- 版本序列:原 0.0.80 行合并了"对象产出合同"与"R2 接线收尾",本计划只含前者;R2 接线收尾(W3b、W3c、W2d、F5)需要新增一个版本槽,下次整理版本序列时插入并顺延 netraw 等。
