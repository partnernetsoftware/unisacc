# unisacc v0.0.23 计划（2026-10-03 起草；0.0.22 发版中）

基线是 0.0.22 回执（发布后写入 research/r22-release-acceptance.json）。规则：一项最多顺延两次；第二次顺延的项目在本版要么做完，要么写明降级或砍掉，不再进入 0.0.24。“顺延”栏统计的是从首次排进某个版本算起，被移走的次数。

## 分工

- **cdx**：产品 δ 与 tape 格式（A、B、C、D）；论文 A/A2 正文。
- **cc**：参考实现、门禁、发版流程（E、F、H）；A2 实验（G）；为 cdx 的每一片补门禁（`--com` 变体、r21check 收紧）。

## 顺序与依赖

```
阶段 1（并行）：A3 产品 (name)(args) 等构造（cdx，最先做：它挡住了产品参加 Csmith 差分） ‖ E 依赖声明补齐（cc） ‖ F 发版流程的新问题（cc）
阶段 2：D 产品诊断（cdx，第二次顺延，本版必须了结） ‖ A1 Windows 转发、A2 cc 互调（cdx）
阶段 3：用 rc 标签流程发 0.0.23；G 论文 A2 实验（cc，不抢阶段 1–2）
```

## 下一版（0.0.24）主线候选：TSV 表 DSL 优化

前提：0.0.23 的 K 迁移完成，完整测试套件和本地发版队列全绿并有回执。不许边迁移边优化。内容：等价状态合并、死状态消除、共享动作序列合并、表到网络的更紧凑编码；每项优化都要证明优化前后语言行为不变（全域枚举加对拍），并在账本里记录表与网络的体积变化。

**0.0.24 另一项（董秘转主人 2026-10-03）：进程与临时文件不留孤儿**。2026-10-03 在 m4pro 上清掉了 1,669 个暂停状态（T）、父进程已退出的 tests/bound.py 进程，另有 26 个同类孤儿（csmith 的 ref 程序、一个 12 小时前的 build_candidate.sh、realprog.sh），共占约 13G 交换区。要做：bound.py 超时或收到中断时，连同整个子进程组一起收掉（新进程组 + killpg，暂停的进程先 SIGCONT 再终止）；构建和队列脚本（build_candidate.sh、queue.sh、release.sh、gatequeue.py）在退出路径上清理子进程；$TMPDIR/unisacc-* 等临时目录由创建者在退出时删除，另加一个定期清理（超过 3 小时、且没有活进程持有的目录）。验收：人为制造超时和 Ctrl-C 后，没有遗留进程和临时目录。 **已落一片（cdx，2026-10-03）**：tests/bound.py 在 /bin/ps 被拒（沙箱 EPERM）时仍对整个进程组 killpg；旧版此时抛异常、不收子进程，孙进程占住管道——很可能就是 1,669 个暂停孤儿的来源。本机 bound 门禁与 boundcheck.py 复核 rc=0，复核后暂停态 bound.py 为 0。其余（SIGCONT 后终止、构建/队列脚本退出清理、临时目录回收）仍留 0.0.24。

**0.0.24–0.0.27 方向（主人定调 2026-10-03 19:51，经项目管理；取代 c5236ea 的“0.0.24 主线 = C 种子层”）**：① C 重写种子层预算到约 **0.0.28** 才开始，0.0.24 不是硬目标；最终 C 种子层完全不依赖 Python。② 顺序：先 K2 收尾 → **冻结 DSL 并写出语法与语义规格**（opts 键与值前缀进门禁并封顶；去掉 @stack 的 getattr 回调、@fmt 对 str.format 的依赖、=vN 不透明绑定；集合遍历顺序等隐式顺序改为表内显式规则；动作序列移出 facts；清死数据）。③ **补测试**：每个表条目、每个 DSL 操作配独立用例，判对错不依赖 Python 产物或 graphhash 基准，再量覆盖率（主人判据 TDD；呼应 prd §6.1 表行覆盖率+见证）。④ DSL 冻结后，C 版作为规格的权威实现，Python 只留历史参照。依据：项目管理报告 /workspace/ceo/reports/unisacc-seedlayer-20261003-1835.md（box 上）。
