# unisacc 0.0.47 计划(cc,2026-11-07;0.0.46 已于同日正式发布)

## 主题:从「能编」走向「可信」
0.0.46 证明了六目标原生可跑、构造链可复现;未证明的是:对合法 C99 的覆盖(外部语料 ctests 5/5、GCC 4/5、Lua 0/1、SQLite 拒)和对非法 C99 的拒绝(A12 实测 8/12 被静默接受)。0.0.47 只做能把这两个数字推向「可信」的事,其余让位。

## 并行车道与规则
- 产品输入改动先在私有分支做;0.0.46 已发布后合入 main 无阻;每次合入前主树棘轮 13/13、toolsloc 基线按实测写并说明(提交前钩子已拒绝超基线)。
- 不改冻结需求:六 ISA 切片、同候选原生证据。切片瘦身只做「搬迁试点」(`cx/driver/sys` 与 `cx/sys` 去重、trace/net 移出 L0),且先过 VM 的 OOM 具名可恢复门。
- 候选 c47-1 的构造/CI/全批沿用 0.0.46 流水线(五片并行、冻结快照、s8c-bind 一键绑定);全批目标:NOT-AVAIL 162 → 先降到 ≤80。

## 风险与预案
- 约束检查补齐会改变既有「接受」的行为(用户可见):发布说明必须列出,并在 CHANGELOG 写明。
- TAPE-END 改 tape 文法,所有 e3/e4/prune/lower 网与材料指纹全变:一次性重生,单独候选验证,不与 M1 同候选混测。
- 磁盘:/tmp 紧张;每个窗口自清自己的目录,s8c/s8b 记录落 ~/.unisacc-baselines。

## libc99posix 测试分层现状与缺口(2026-11-07,cc 回答主人提问)
- 性质:`exec/facts/libc99posix.tsv`(29 行,每行 6 目标的主机导出名/cx-own 体)→ `tools/libc99posix-gen.cx --write` → `cx/compiler/libc99bind.cx`。它是「契约表+生成器」,**不是** 18 张事实网之一,也不是字节流阶段。
- 已有的分开测试:① `check-libc99posix.cx`(批次 `libc99posix`,lnx/x86_64 源码级):事实漂移拒绝,原八项绑定合同,Windows 两目标用 `-c -funit` 编译公共 P0 头面(含四个 cx-own 体);② `libc99posix-gen --check`(表→生成物一致);③ `libc99posix-audit`(批次 `libc99posix-audit`):扫 include/*.h,GAP=310 个函数名无契约。④ 原生层面只有 CI 的 FFI 探针 strdup/pread(Windows x86-64 与 Linux 逐字节一致)。
- 缺口:没有「逐行、逐目标、原生执行」的探针;表中 host-export 行在 osx/win 上是否真的解析到正确的主机符号,只靠编译级检查,不是运行级证明。
- 方案(0.0.47 M9,P2):由表生成探针(每行一个最小调用,期望值来自表的 constraint 列),经 `candidate-native.yml` 在六目标原生 runner 跑,输出逐行 PASS/FAIL 并入 evidence 表;生成器 `--check` 覆盖探针与表一致;310 个 GAP 先按头文件分级(P0 头面已覆盖,其余明确 NOT_CLAIMED)。owner 暂定 cdx2(M8 之后)。

## M10 切片逻辑 NN 化(主人定向,2026-11-07 更正)
方向(主人原话归纳):**六个切片全部保留**;切片里的大部分「逻辑」迁为 NN(事实表→生成器→网/执行器程序);切片剩下的主要是与系统对接的薄层——FFI、dl、host syscall/ABI 的封装。切片体积下降是结果,不是手段。此前我写的「头部压缩/去重为主」偏离方向,已作废(头部压缩仅作附录备忘,不排期)。
### 薄层(留在切片)
`cx/sys/{mem,fd,io,fs,env,time,sig,proc,process,poll,tty,posix,dl,dlcall,ffi,hostid,kernel}` + `src/host*.cx` 的 fd/clock 部分 + `cx/driver/{input,output}`。以此为「切片终态」边界,先冻结成文档化合同(sy_* 原语签名表+六目标实现状态)。
### 待 NN 化的逻辑(来自 plans/unit-text.tsv 分类)
pure-transform 24KB、finite-state 48KB 直接迁表;needs-large-state ≈1.36MB(≈74%)需要「CX→执行器字节码」路线(VM)。
