# unisacc 0.0.47 计划(cc,2026-11-07;0.0.46 已于同日正式发布)

## 主题:从「能编」走向「可信」
0.0.46 证明了六目标原生可跑、构造链可复现;未证明的是:对合法 C99 的覆盖(外部语料 ctests 5/5、GCC 4/5、Lua 0/1、SQLite 拒)和对非法 C99 的拒绝(A12 实测 8/12 被静默接受)。0.0.47 只做能把这两个数字推向「可信」的事,其余让位。

## 并行车道与规则
- 产品输入改动先在私有分支做;0.0.46 已发布后合入 main 无阻;每次合入前主树棘轮 13/13、toolsloc 基线按实测写并说明(提交前钩子已拒绝超基线)。
- 不改冻结需求:六 ISA 切片、同候选原生证据。切片瘦身只做「搬迁试点」(`cx/driver/sys` 与 `cx/sys` 去重、trace/net 移出 L0),且先过 VM 的 OOM 具名可恢复门。
- 候选 c47-1 的构造/CI/全批沿用 0.0.46 流水线(五片并行、冻结快照、s8c-bind 一键绑定);全批目标:NOT-AVAIL 162 → 先降到 ≤80。

## 风险与预案
- 约束检查补齐会改变既有「接受」的行为(用户可见):发布说明必须列出,并在 CHANGELOG 写明。
- TAPE-END 改 tape 文法,所有 e3/e4/prune/lower 网与材料指纹全变:一次性重生,单独候选验证,不与 M1 同候选混测。
- 磁盘:/tmp 紧张;每个窗口自清自己的目录,s8c/s8b 记录落 ~/.unisacc-baselines。

## 发布判据(0.0.47)
同候选六目标原生 CI 全绿;全批 NOT_QUALIFIED 状态必须比 0.0.46 更好(NOT-AVAIL、FAIL 均下降并逐项归类);A12 八项与 TAPE-END 在发布说明里从「已知限制」移到「已修复」。

## 评审补充(fable,2026-11-07,发布后)
- M4' 资源合同先于任何切片迁 VM:OOM panic→具名可恢复、inputn+1 溢出、无墙钟取消三项定为 0.0.47 决策门,不是副线;验收=逐分配点失败注入批次全 PASS 且活跃分配归零;SQLite amalgamation 要么编过要么 ≤10s 具名拒绝。
- A12 不逐错码打补丁到底:e3 增「类型类别×赋值上下文」「switch 常量集合」约束表(事实表→生成器→网),作为 arity/stmt 之后第五个「动态逻辑进表」;负例矩阵 63→≥75 行。
- TAPE-END 同次重生网时顺带给 tape 每函数加 `.unit N`/文件名元数据,让 lower/elf 的 `reject: not covered` 可定位(一次重生,两个收益)。
- M1' 语料入仓:c-testsuite 220 例+期望配对为批次 `corpus-ctestsuite`,首轮 accept/wrong/首错直方图,目标 accept ≥180/220。
- M5' 文档收敛:prd §3/§7.3/§9 事实由 com-tree/--list 生成;plans/ 活跃文件 ≤40;README ≤150 行,规格与历史移 docs/。
