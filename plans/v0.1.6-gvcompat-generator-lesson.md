# GV.compat 生成表手改为什么过了提交门

证据: a1f3b8d004ecbff0115450a81e9ae45ab3d77ba6, 84737d9354059d3ef8e1bef6a241d260f94fd0e3. 未跑重命令.

## 发生了什么

a1f3b8d00 在 exec/facts/k2-gen2.tsv 的 gen2parts.tentative.consts 里手加 FPS_FIRST=128 与 SBB=8192. 生成器 tools/facts-gen.cx 当时只写 TENTATIVE (84737d935 的 diff, 原行 k2_gen2). 表与生成器从此不一致.

预跑的 check-gen-all-check 跑 facts-gen --check, 报 DIFF k2-gen2 与 k2-libraryenv, 红停. 84737d935 把这两个常量写进生成器, 再生成 37 张表的头行, 才让 gen-all-check 46/46 PASS.

## 为什么每个门都放过

提交门不是没看见这张表. tools/precommit.cx:2171 把 exec/facts/ 前缀当成产品生成器输入 (derive.tsv 除外). 暂存 k2-gen2.tsv 会命中 dg_genall_gate (同文件 2227).

命中后, 因为暂存的不是 tools/*-gen.cx, tool_only 被清成 0 (同文件 2240-2241). 门于是不跑 --only facts-gen, 而跑完整 gen-all-check, 时限 bound_s=20 (同文件 2215, 2309). 46 个生成器在 20 秒内跑不完.

超时不当红. tools/check-gen-all-check.cx:21 写明挂起在时限内允许提交. 所以手改生成表过了提交门. 预跑没有这 20 秒放行, 才在 check-gen-all-check 红停.

其它门不看生成器是否能重写出这张表. 棘轮和登记门只看源码形状, 不跑 facts-gen --check.

## 一条便宜的提交门

不加新工具. 改现有产品输入提交路径 tools/precommit.cx 的 dg_genall_gate:

暂存路径命中 exec/facts/ 且没有同时暂存 tools/facts-gen.cx 时, 不要把 tool_only 清掉. 把 facts-gen 放进 only_list, 用已有命令:

```
sh ./unisacc.com tools/gen-all-check.cx -- --root <index-tree> --only facts-gen
```

DIFF 或 ERROR 拒绝提交. 超时也拒绝, 不再走 GEN_ALL_GATE_UNAVAILABLE 放行. 生成器源本身被暂存时仍跑 --only facts-gen, 因为手改表和漏改生成器是同一类 DIFF.

这比全量 gen-all-check 便宜, 并且就是预跑红停用的那一个检查, 只是提前到提交. 不放宽时限, 不把手改表再生成一遍来掩盖 DIFF.

## 审查结论: 不落地

010ea39fc 与 f4e2e3a05 都不进 main, 也没有安全子集. 一个什么都放过的门是假绿. 提交时漂移门改到 v0.1.7, 解冻后重新设计. 上面那条便宜门是初稿, 不是落地设计.

agy-h 第二轮 989cafa44: precommit.cx:2225-2227 的归属解析差一, 所有者列表对上 0 个生成器, 于是每张手改表都通过. H1 被打断. 冷预算仍然打不中 run-cache.

## v0.1.7 设计要求

下一作者从这四条起, 不从 010ea39fc / f4e2e3a05 起.

(1) 读暂存 index, 不读工作区. 归属行必须来自 `git show :path` 或 write-tree 解出来的那份, 不能 cx_read 工作区文件.
(2) 所有者抽取必须精确, 每个生成器一条测试. 差一不能把列表收成空. 未匹配到写入者时全量检查, 不能默认 facts-gen, 也不能默认通过.
(3) run-cache 目录必须稳定. 不能每次 mktemp. 键按内容, 并且生成器进程的 cwd 要能命中已有缓存. 冷编译撞上短时限再拒绝, 会把好提交拒掉, 也不是门.
(4) ERROR 与超时都拒绝. diff=0 error=1 不能掉进 pc_handle_gate_unavailable 放行. 超时不能放行. 两条都要有单独的红用例, 不能只靠 DIFF 字串.
