# W5 容量解耦计划：UNITOK2 64 单元上限上调

日期：2026-11-02。只写计划，不改源码。目标：解除 `UNITOK2` 单元数 ≤64 这一层容量约束，让 osx/win 三片的 whole-o 路线与整程序 `-o` 不再被"一个程序最多 64 单元"卡死。

## 1. 64 上限写在哪一层（已定位，三处）

| 层 | 位置 | 内容 | 性质 |
|---|---|---|---|
| K2 模型表 | `exec/parse2/units-result.tsv:4` | `main2 EXTENT * $state0 [["CMPI","unit",64]]` | 手工模型表，`CMPI` 把单元计数与常量 64 比较，>64 走 `DEAD.frame` |
| 运行期校验 | `cx/cx0/bundle.cx:34` | `if(b.unit_count<1||b.unit_count>64||...)` reject | 独立一层，读 CX0BND1 包头的 LE32 unit_count |
| 运行期构造 | `cx/cx0/bundle.cx:85` | `if(!end||units==64){cxb_fail(&r,"plan-unit-line")}` | cx0 bundle 构造器逐个单元，第 64 个后拒绝 |
| 文档契约 | `exec/pipeline/formats.md:259`、`exec/c/PACKAGE.md:252` | `LE32 unit count (1..64)`、`validates up to 64 frames` | 与上述一致，需同步 |

**关键事实**：`units-result.tsv` 是**手工模型表**（git 历史显示"Declare complete unit framing"等手写提交），`tools/facts-gen.cx` 只读不写它，`seed/gen.c` 里也没有 `units-result` 的 install 调用——它经 `exec/parse2/units-manifest.tsv` 的 `rows units main2`（`#! base build/parsebase.py`，已归档的参考实现）进入网。当前生成入口是 `seed/gen.c` 的 generic driver（`seed-gen parse2/units OUT --locations`，对应 `source-package.cx` 的 `warnunits` recipe `stage=parse2/units`）。

## 2. 改成构造参数 vs 上调，各动什么

### 2a. 先上调（一步，不改生成器架构）

- **改 1 处模型表**：`exec/parse2/units-result.tsv:4` 的 `CMPI unit 64` → `CMPI unit 128`（目标值见 §3）。
- **改 2 处运行期**：`cx/cx0/bundle.cx:34` 的 `>64` → `>128`、`:85` 的 `units==64` → `units==128`。
- **改 2 处文档**：`formats.md:259`、`PACKAGE.md:252`。
- **重建链**：`source-job-wave` 的 `warnunits` recipe（parse2/units 的 gen/tbl/net 三相位）→ `kernel-build` → `release-build` → `entry-build`。这是慢车道，改表必须"事实表 → 生成器 → 表 → 模型重建"。
- 内存代价：运行期 unit 相关表（`STATIC` 槽位、unit-indexed 区域）会随 64→128 增长，需实测二进制与全程序时间（见 §4）。

### 2b. 后参数化（两步里的第二步，可选）

- 把 `CMPI unit 64` 的常量从手写动作值改为构造参数（gen.c 从 `exec/facts/k2-units-tokens.tsv` 或新增 `exec/facts/k2-capacity.tsv` 读），使"单元上限"成为一张事实表的一行，改上限不碰模型表动作。
- 成本：gen.c 的 `parse2/units` generic driver 要加一个常量绑定（`bind` 列或 `facts` 引入 `UNIT_MAX`），units-manifest.tsv 的 `main2` 行引用 `@const:UNIT_MAX`。这属"事实表 → 生成器"的新增机制，工作量大于 2a，但让第二次上调（若结构改善继续拆模块）变成改一行事实表。
- 建议：**先 2a 上调到 128 解阻塞，参数化作为债务记录**，等 PAPERA-SHAPE 再拆时若还嫌 128 不够再参数化。

## 3. 目标值选型

| 候选 | 依据 | 评估 |
|---|---|---|
| 96 | 与已落地的 `CXM_MAXU 96`（cxmod 模块图）对齐 | 够用但无余量；PAPERA-SHAPE 再拆 dv_main 可能又顶 |
| 128 | 当前 33 根→67 单元，加拆分后估 ≤90 | 有余量，`CMPI` 是 LE32 单元计数（`formats.md` 已 LE32），128 不碰格式字段宽 |
| 256 | 最大余量 | 内存/表大小代价需实测，可能超 60s 时限 |

**倾向 128**：LE32 字段天然支持，128 给结构改善留约一倍余量，又不会让 unit-indexed 运行期区域（`48<<40` 起的 per-unit 记录）爆炸。最终值以 §4 实测为准。

## 4. 慢车道纪元步骤与耗时估计

复用 `out/epoch-pp1/` 纪元的已打通链（prepare-context 已过、source-job-wave 107→131 job 已过、gen 42/42 start 已过）：

1. **改表 + 改 2 运行期 + 2 文档**（0.5h，纯编辑，含 `git apply` pp-tables.patch 同款先存后改）。
2. **table-lint / sim --cov**：`warnunits` 的 `CMPI unit 128` 新分支覆盖，`sim --cov` 确认 65..128 单元接受、129 拒绝（0.5h）。
3. **source-job-wave `warnunits` 三相位**（gen/tbl/net，recipe `parse2/units --locations`）：gen 是 42 之一，单 recipe 约 1–2min/相位（bound 40 逐 job）。
4. **kernel-build**：模型网 → kernel（约 3–5 步，≤55s/步）。
5. **release-build**：p3 包 + 五片（osx/win 走 whole-o，正是本改动解锁的路由；约 1–2min）。
6. **entry-build**：入口候选 + 链接（约 35–40s）。
7. **独立候选实跑**：65 单元 rc0、129 单元 rc1 具名拒绝（边界回归）；两代字节等价（selfhost-mixed 可选）。

总耗时约 **25–40min**（与 pp-negative 试点、dev-methodology "构造 25min" 一致）。每一相位发 cc 一行进度。

**前置**：本纪元当前卡在 `gen-*` 阶段 11 个 lower stage 的 `seed-gen: unknown constant binding`（已记入 board 债务），分层收敛后先解这个卡点，W5 才能跑完整纪元。

## 5. 对 osx/win 三片与整程序编译的解锁效果

- **osx/x86_64、osx/arm64、win/x86_64 三片**：当前 `release-build` 的 whole-o 路线（`rb_is_whole`）在 67 单元下必挂 `malformed unit frame`（>`CMPI unit 64`）；上调到 128 后这三片可直接走 whole-o（`-funit --target osx|win` 仍 `NOT_IMPLEMENTED object`，但 whole-o 不再卡单元数）。
- **整程序 `-o`**：33 根 + use 闭包展开 67 单元，上调后整程序 `-o` 恢复可用（此前 67>64 拒绝）；结构改善继续拆模块也不顶表（到 128 为止）。
- **不与 lnx 对象路线冲突**：lnx 已走 entry-build 对象路线（每对象 1 单元 + 链接 96 输入），本改动对 lnx 是纯增益、无回归。

## 6. 未核实项（显式）

1. 单元上限 64 是否还有第 4 处硬编码（已扫 `units-result.tsv`/`bundle.cx`/`formats.md`/`PACKAGE.md`，但未扫运行期 `STATIC` 槽位表的实际分配上限，需 `grep -rn "64\|unit_count\|STATIC"` 在 cx/ src/ 全量复查后确认）。
2. `CMPI unit 64` 之外，`units-result.tsv` 内是否有隐式依赖"单元数 ≤64"的数组/槽位假设（如 `STATIC` 资源槽按 64 分配）。
3. 128 下的二进制增长与全程序时间是否仍 <60s（需实测；若超则按 `rb_phase` 分相，不放宽时限）。
4. `seed/gen.c` generic driver 是否已在 `parse2/units` 阶段正确读 `units-result.tsv`（units-manifest 的 `rows units main2` → `k2-units-tokens` 事实 → 我观察到 `k2-units-tokens` 由 `facts-gen.c` 生成，但 `units-result.tsv` 的进入点需跑一次 `warnunits` gen 相位确认，而非仅静态推断）。

## 7. 建议

- **分两步**：先 2a 上调到 128（改 1 表 + 2 运行期 + 2 文档 + 慢车道重建），解 osx/win 阻塞；参数化（2b）列为债务，等 PAPERA-SHAPE 再拆或需第二次上调时做。
- 顺序放在 pp-negative 试点与 W4/W4b 之后、PACKAGE-01 剩余切刀之前（因为切刀会增加单元数，必须先解容量）。
