# W6 冻结期只读扫描：doc-only 工具的 .tsv/生成器引用

日期：2026-11-02。范围：仍存在的 `tools/` 文件中，`plans/tools-inventory-2026-11-02.tsv` 标为
`code_refs=0` 且 `doc_refs>0` 的剩余项。**只读，不改代码**。

## 方法

- 候选：106 个仍存在于 `tools/` 的 doc-only 文件（已归档/不存在的跳过）。
- 语料：全仓 1,214 个 `.tsv`（排除 `out/`、`archive/`、`plans/`，保留 `tests/`、`exec/`、`cx/`、`release/`）。
- 分类：check/批次表（`tests/cxraw.tsv`、`cxlibc.tsv`、`cxplatform.tsv`、`cxinclude.tsv`、`cxapis.tsv`、`cxtrunc.tsv`、`cxcc/units.tsv`、`batches.tsv`、`coverage.tsv`）单列；其余 `.tsv` 命中为“非 check 引用”。
- 生成器：`.tsv` 内容含 `Generated by tools/<name>` 或 `生成器` 且出现文件名，单列。

## 结果

- 106 个 doc-only 文件中，**95 个**在某个 `.tsv` 出现；绝大多数只出现在上述 check/批次表，属于计数登记，不是运行时/生成器依赖。
- **6 个**有非 check `.tsv` 或生成器引用，W6 的“清 check 表即可归档”规则不适用于它们：

| 文件 | 非 check .tsv | 生成器标记 | 判定 |
|---|---|---|---|
| `check-cx-layers.cx` | `tests/cx-module-freeze.tsv`, `tests/cxlayers-unresolved.tsv` | - | 模块层冻结/未决表是检查输入，保留 |
| `cx-driver.cx` | `cx/workspace/packages.tsv` | - | 包图 manifest 的入口，保留 |
| `cx-pipeline.cx` | `cx/workspace/packages.tsv` | - | 同上 |
| `link-malformed-input.cx` | `tests/formats-domain-matrix.tsv`, `tests/waivers-0.0.43.tsv` | - | 矩阵/豁免表引用，保留 |
| `ucn-pp-gen.cx` | `exec/pp/rescan-byte.tsv`, `exec/pp/rescan-result.tsv` | 同左 | 事实表生成器，保留 |
| `ucn-table.cx` | `exec/lex/ucn-byte.tsv` | 同左 | 事实表生成器，保留 |

## 处置

1. 这 6 个**不进入** W6 归档队列；与 `ucn-identity-tables`/`runtime-budget-cases` 同类，需等生成器/矩阵链迁移另案。
2. 其余 100 个 doc-only 文件若未来归档，仍需先清其 check 表行并复核运行时入口；本次只确认没有额外 `.tsv`/生成器引用。
3. 冻结期不动任何 `tools/ tests/ cx/ src/ include/ weights/ exec/`；本文件只记录扫描结果。
4. 复扫命令（只读）：
   `grep -RIn --include='*.tsv' --exclude-dir=out --exclude-dir=archive --exclude-dir=plans '<tool-basename>' .`

## 备注

- 本次结论与 W6 教训一致：`.tsv` 可能承载事实表、矩阵和生成器声明，不能只扫 `.cx/.sh`；归档前应把 `.tsv`、`.git/hooks`、CI、systemd/cron、脚本入口一起查。
- `tests/cxraw`/`cxlibc`/`cxplatform`/`cxcc/units` 的命中是计数登记；清理它们是 W6 的常规动作，不等同于运行时调用。
