## 首刀：前置 Tape 验域（方案 A）

| 项 | 内容 |
|---|---|
| 主刀 | cdx：`exec/tapecheck/`（新增）、`exec/c/compiler.c`、构造/打包清单 |
| 验收 | cc：`tests/tapedomaincheck.cx`（黑盒，动态 C）、本文件、登记行 |
| 只读旁证 | cdx2 |

验收条件（与 cdx 对齐过的六条）：
1. `?\n` 的 `.tape` 在 `-S`、`-c`、`-o`、`-run` 下都 rc1、stdout 为空、不创建输出文件、stderr 点名原因与行号；不能是末端编码器的拒绝。
2. 未知操作码、操作数个数、非法寄存器、坏整数、坏 `.str`、坏记录头各至少一条负例，同样四项齐全；超时、信号、燃料耗尽不算拒绝。
3. 正例不回退：合法 `.tape` / `.tapebin` 输出逐字节不变。
4. 验域是模型流里的显式阶段（有限表加通用执行器），与 `unisa/tape.py` 对拍；不在 `compiler.c` 里手写解析器。缺模型时拒绝，不放行。
5. Windows `.hostcall` / `.hostaddr`：显式库模式合同与参考一致性未齐前，win 接受不记产品绿。
6. 产品闭包变更用 `fix:` 前缀或登记 freeze-waivers；单项套件逐个跑，每个 ≤60 秒；不 seal、不开整闸。

## 起点实测（0.0.42 候选 `ba11d636…`，2026-10-14 实际跑过）

`tests/tapedomaincheck.cx`：控制通过（产品自己写出的 592 字节 tape 被原样接受）；6 条负例 × 4 模式 = 24 格，46 处失败，rc1。要点：
- 六条负例在 `-S`、`-c` 下全部 rc0 并写出输出。
- `imm r2`（缺操作数）在四种模式下都被接受，`-o` 写出了可执行文件。
- `imm r9, 0`（非法寄存器）`-o` 被接受；`-run` 以信号 11 结束（退出码 139）。
- `-o`、`-run` 下出现的拒绝来自后段，不点名原因，也没有行号。

所以缺陷不止 NEG-001 一条输入：Tape 形状规则在产品入口整体没有执行。

## 决定（2026-10-14）

- **步数上限（机房主任代裁）**：出货产品的核心步数上限是常量；只有测试构建可从环境变量 `UNISA_MAXSTEPS` 读取。宿主环境不得改变核心步数上限。证据 `research/c43-host-env-inputs.md`（候选 0556ea9f 上设 1000 或 0 即令所有编译 timeout）。
- **逻辑源名（cc 自裁，政委授“你评估你决策”）**：保持现行语义——核心看到的源名就是命令行写法（与 gcc 相同），不改产品。依据：同一源在两个物理目录各用相对路径编译，`-S` 输出与 `-run` 打印的 `__FILE__` 完全相同（实际跑过）；物理目录只在用户自己写绝对路径时进入输出，那是用户给出的显式输入，不是宿主状态。`\0cli/source` = argv 原样写法登记为核心显式输入。pp-literals 封存出现的“目录泄漏”来自封存工具自己用了随机绝对临时路径：修在 tests/ 侧，封存与对拍一律用相对路径或固定逻辑名。basename / 相对化等方案不采纳。
