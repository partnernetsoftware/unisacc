# 路线图 0.0.80 到 0.0.89(修订版 2,2026-11-19)

来源:项目所有者要求(每版内容不能太少,继续分功能道与速度道,分而治之做得更好)加 fable 外部顾问的两轮独立评估(高层产品评估与分治四方向)。本版取代 plans/roadmap-v0.0.80-v0.0.89.md 的第一版排序;第一版的速度基线表仍有效。

## 总判断(顾问结论摘要)

(1) 产品内核(单文件、六目标、默认 -run)立得住,但近三版投入偏基础设施:0.0.77 到 0.0.79 产品输入约 +530/-280,tools 与 tests 新增约 1.4 万行。(2) 连续 NOT_QUALIFIED 已让裁决失去信息量,资格要拆成可达的两级。(3) 速度道的主矛盾是选批粗和读集按文件算,不是再把各段降两三成。(4) 分治:单网构造只要 1.3 到 2 秒,整链 30 分钟花在三代六目标自编译,所以真正没分好的是依赖粒度(按文件而不是按消费的行列)、网按变体整份复制(93% 状态在四个近似复制的族里)、表与网之间没有声明的接口。

## 原则(修订)

(1) 四道:功能道(产品输入,一类大改)、速度道(tools、tests,每版 1 到 2 项,每项必须同时退役一个旧机制或旧工具,带基线与目标秒数)、资格道(每版 1 项,不改产品输入,以三个只降计数验收:UNKNOWN 数、expected-fail 数、state-unverified 条数)、用户道(每版 1 项,不改产品输入:能用清单、examples 与 realprog、文档口径对账)。后两道不占候选键,不增加整链风险。
(2) 容量:每版功能 2 项、速度 1 到 2 项、资格 1 项、用户 1 项;开工到公开目标约 3 小时;功能道不增到 3 项(独立复核是关键路径)。
(3) 资格分级:Q-P(产品资格:产品资格域 606 批整域同候选实跑加 CI 42 格,UNKNOWN 为 0,expected-fail 每条带到期版本)为一等目标,目标版 0.0.83;Q-全(现定义:每个 IMPLEMENTED 批次都有同候选 PASS)降为远期。
(4) 固定步骤:每版公开后把共享检出 Root 升到上一公开版(现落后 8 版)。
(5) 内存安全定位:改称 own-lint(所有权 lint,不是 Rust 式保证);续投前置采用门:Root 已升级且至少 20 个 tools 文件启用 safe 并统计查出的真实缺陷数,有产出再续投,没有就冻结;-run 运行期检查(释放后毒化、隔离区、越界哨兵)先评估再排。
(6) devsvc 冻结功能面,只修缺陷与冷启动,并保留一条不经 devsvc 的应急读路径;其路线与预算从编译器版本里分出。

## 并行工具线(不占版本槽)

register --sync 第 1 单(coverage 与 manifest 事务,复核中)与第 2 单;table-lint 与 net-health 工具线(跨网输入声明表、sb_read 认子程序返回、check-table-lint);devsvc 冷启动;unit-frontcache-equiv3 追因;tools 分三档(发布关键、日常、一次性)并归档疑似无用约 132 个。

## 风险与约束

- 复核仍是关键路径:加项加在不改产品输入的资格道与用户道,不加在功能道。
- 速度项验收是同一门下的实测秒数,不靠放宽门或缩覆盖;未达目标也记基线与原因。
- 协作风险(顾问):复核者与作者同类模型、简报由作者方写;速度道由 cdx 改裁判(门)。对策:每 3 版用一组种入已知缺陷的固定候选走一遍发布流水线(门的门),必须全部被拦下;门与裁判类改动的提交前独立复核保持。
