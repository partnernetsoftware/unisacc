## 七、Z3 前置设计裁定:`sy_proc_capture` 与 `ext.procx np_exec`(ccogweco 2026-11-22)

### 1. 实体归属

- **实体**:`cx/sys/proc.cx` 新增 `sy_proc_capture`。它是 L0 双路捕获的唯一实现,持有 `pipe` + `fork/exec` + 非阻塞读 + `sy_poll` 轮询 + 终止/回收的全部逻辑。
- **封装**:`ext/sysx/exec.cx` 的 `np_exec` 改为薄封装,调用 `sy_proc_capture` 后把两路拷进调用方给的 `mg_buf`。`build/std-surface.tsv` 第 135 行 `np_exec` 的 `stab` 由 `incubating` 降为 `alias-of:sy_proc_capture` 一类的封装态(表类改动,不占 A 槽)。
- **不动的**:`ext/sysx/processcore.cx` 的 `pc_run`/`np_run` 是另一条契约(自带 `envadd`、`sys_kill_tree` 残留报告、`why` 文案、`residue`),它依赖 `/proc` 遍历与 reaper,**不在本版改动范围**;`std-surface.tsv:133` 对 `np_run` 的说明"由 np_exec 取代"保持原样,只是实现路径改为经 `np_exec` -> `sy_proc_capture`。
- **为什么不是反过来**:`cx/sys` 是 L0,`ext/` 是上层;L0 不能依赖 `ext/`,所以实体必须在 `cx/sys/proc.cx`。现有 `np_exec` 自己写 fd 轮询与 pid 管理,正是 L0 该有的能力,错位在目录不在逻辑。

### 2. 签名与语义

- 类型与签名(与 `plans/prep/l0-checks/check-l0-capture.cx.draft` 的四参形态一致):
  ```
  typedef struct { mg_buf out, err; } sy_capture_t;      /* 调用方 mg_init,mg_free 自理 */
  int sy_proc_capture(const sy_spawn_t *o, sy_exit_t *st, sy_capture_t *cap, long cap_bytes);
  ```
  `mg_buf` 来自 `cx/mem/grow.cx`;`cx/sys/fs.cx` 已 `#pragma unisa use mem.heap/mem.bytes`,同层内用 `mem.grow` 不破 L0 边界。
- 语义(逐条与现有 `np_exec` 契约对齐,不新增行为):
  1. `cap->out`/`cap->err` 由调用方 `mg_init`,只追加不释放不接管;`cap->err` 不需要时传 `cap->err.p == 0 && cap->err.n == 0 && cap->err.cap == 0` 的空 `mg_buf`,此时 stderr 并入 out(与 `np_exec` 的 `err == 0` 一致)。
  2. `cap_bytes` 是**每路**新增字节上限;为负得 `-EINVAL`;任一路超过即返回 `-EMSGSIZE`,该路恰好 `cap_bytes` 字节。
  3. `o->deadline_ms > 0` 时到期:杀子(先 `SIGTERM`,宽限 200 ms 后 `SIGKILL`,与 `np_exec` 相同),回收后返回 `-ETIMEDOUT` 且 `st->timed_out = 1`。
  4. 统一返回契约:成功 0;参数错误 `-EINVAL`;超 cap `-EMSGSIZE`;截止 `-ETIMEDOUT`。
     - 与 `sy_proc_wait` 的差异是有意的:`sy_proc_wait` 以 `0 + timed_out` 表达截止,调用方必须查标志位;新接口把"超时"放进返回码,漏查 `st` 也能识别。`np_exec` 封装层把 `-ETIMEDOUT` 翻回 `0 + st->timed_out=1`,所以 `check-ext-procx-exec.cx` 的 `timeout-flag`、`term-ignored-killed`、`grandchild-with-deadline-returns` 三条断言一字不改仍绿。
     - 头注释必须同时写明:超 cap 的那一路恰好 `cap_bytes` 字节已留在缓冲里;超时路径下两路保留已读到的前缀,不丢弃。
  5. 子进程固定进自己的进程组(`pgroup=-1`),超时杀整组;离开进程组的后代不在本合同内(与 `sy_proc_wait` 注释一致)。

### 3. 平台分层

- 读循环、cap、超时、进程组语义全写在 `cx/sys/proc.cx` 的**无平台分支**主体里,只调 `sy_poll`/`sy_read`/`sy_proc_kill`/`sy_proc_try_wait`。
- `_WIN32` 具名拒绝在第一行:`#if defined(_WIN32) return -ENOSYS;`。理由:`sy_poll` 在 win 已具名拒绝(`cx/sys/poll.cx:11` 注释),没有 `poll` 就无法做到"写满一路不死锁",所以不能假装实现。`cap=proc-tree` 不是这条能力的正确词表项,不扩词表,直接 `-ENOSYS` 并在头注释写明。
- `__APPLE__` 无额外分支:`sy_poll`/`sy_proc_*` 在 osx 已实现。**(未验证)**:osx 上 `poll` 对管道 EOF 的 `POLLHUP` 行为未在本机实测,CI 首次上是首个真实样本,列为风险。

### 4. 迁移步骤

1. 在 `cx/sys/proc.cx` 落地 `sy_proc_capture`(含 `#pragma unisa use sys.poll` 与 `mem.grow`),不改 `sy_pipe2` 位置(Z2 在改)。
2. `ext/sysx/exec.cx` 的 `np_exec` 改成:`sy_capture_t` + 两个 `mg_buf` -> 调 `sy_proc_capture` -> 按原契约返回。`npx_pump`、`NPX_*` 常量删除。
3. `build/std-surface.tsv` 第 135 行 `np_exec` 的 `note`/`stab` 改为封装态;新增一行 `cx.os sy_proc_capture`(14 字段齐全)。
4. 现有 `tools/check-ext-procx-exec.cx`(批次 `ext-procx-exec`)**一字不改**继续跑;它是本迁移的对拍 oracle,绿了才算封装等价。
5. 新建 `tools/check-l0-capture.cx` 直接打 L0 实体,五条断言见下。

### 5. 对拍方案

- **对拍 oracle**:迁移前后各跑一次 `sh ./unisacc.com tools/check-ext-procx-exec.cx`,逐行比 `PASS`/`FAIL` 集合与 `EXT_PROCX_EXEC` 计数。迁移后集合必须是迁移前集合的超集(不允许丢项)。
- **补充对拍**:`plans/prep/l0-checks/check-l0-capture.cx.draft` 的 256 KiB stderr + `out\n` 用例,作为"两路各自完整"的独立 oracle(字节数与内容双比)。
- **变异自证**:把 `sy_proc_capture` 的 cap 判定改 `>=` 为 `>`、把超时分支删掉、把 `sy_poll` 换成忙等,三种变异下 `check-l0-capture.cx` 必须各红一次,否则该断言不算数。

### 6. `tools/check-l0-capture.cx` 可执行验收清单(五条断言 + 变异)

| 编号 | 名称 | 用例 | 断言 |
|---|---|---|---|
| C1 | 两路各自完整 | `sh -c 'head -c 262144 /dev/zero >&2; printf out\n'`,cap=1 MiB | `rc==0` 且 `outn==4` 且 `errn==262144`,与 `sh -c ... 2>e >o` 的文件字节相等 |
| C2 | 超 cap 得 -EMSGSIZE 并杀子 | `sh -c 'head -c 100000 /dev/zero'`,cap=1000 | `rc==-EMSGSIZE`,out 或 err 恰好 1000 字节,另一路 0;调用后 `/proc/self/task/<pid>/children` 为空 |
| C3 | 截止得 -ETIMEDOUT | `sh -c 'sleep 5'`,deadline_ms=300 | `rc==-ETIMEDOUT`,`st.timed_out==1`,墙钟 < 2000 ms,`/proc` children 为空 |

| C4 | 写满一路不死锁 | `sh -c 'head -c 200000 /dev/zero >&2; printf ok'`,cap=1 MiB,无截止 | `rc==0`,`outn==2`,`errn==200000`(200 KiB 远超 64 KiB 管道容量) |
| C5 | 无残留 fd | 上面四条各调用前后 `/proc/self/fd` 计数相等 | 计数相同,且 `sy_proc_capture` 结束时三路 fd 均 `-1` |
| M1-M3 | 变异自证 | 分别改 cap 判界、删超时分支、`sy_poll` 换忙等 | 对应 `check-l0-capture.cx` 各红一次,记录红行 |

- 每一行输出格式:`PASS\tcapture.<name>` / `FAIL\tcapture.<name>`,末行 `CHECK_L0_CAPTURE<TAB>ok=N<TAB>failed=M`。
- 批次登记:`tools/register.cx -- l0-capture IMPLEMENTED ...`(验收命令 `rc0:CHECK_L0_CAPTURE`),本轮改动只提交 `cx/sys/proc.cx`、`ext/sysx/exec.cx`、`build/std-surface.tsv`、`tools/check-l0-capture.cx`、`tests/batches.tsv` 的本人行。
