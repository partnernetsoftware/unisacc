**最短链实测(改一个无害表值→重构造→验证→还原)**:

- (a) 只在 `control-result.tsv` 末尾加一行注释 → `gen parse2`(gcc 版)6.58 s → δ JSON 与基线 `cmp` 全同(A-JSON-SAME)→ `git checkout` 还原。确定性成立。
- (b) 只把第 4–5 行的 `state3` 改成 `state3z`(同一节、目标与 `$state3` 同步改)→ **1.17 s 失败:`seed-gen: expected string value`**,无文件名、无行号。原因:`state3` 是 `control-fresh.tsv:4`(`block S r state3`)分配的 fresh 名,改 result 表必须同步改 fresh 表 — 这正是「每修一项改 3 张表」的根源。
- (c) 把一条动作改成错误元数 `["PUSH"]` → `seed-gen: invalid PUSH action`,同样无定位。
- 结论:有效最短链(改表→δ→tbl→net)≈ 6.4 + 7.6 + 1.6 ≈ **15.6 s**(gcc 版生成器)或 ≈ 49 s(产品编出的生成器);加 lint(27 s)+ 棘轮(32 s)≈ 75–110 s。真实 A12 一项 30–120 分钟的大头不在这里,而在:3 张表耦合排错、重打默认网进 pkg、真实 probe、固定 suite。

### 不适合进表的边界

- **无界状态**:UNBOUNDED 单元(13 个/706,889 字节)与堆分配、递归(自调用)、IO(sys use/host)按 slice-nn-migration 规则走 VM 字节码或先拆分;一热域每状态最多 257 键,超域只能 `--each` 分级,级数 ≤3。
- **带副作用的序列与循环结构**留在机制或生成器(`prd.md:51`「能进表:一步决策;留在机制:循环与递归结构、带副作用的序列」)。
- **switch 常量集合**是「集合成员」判断,集合大小无界:进表的只能是「重复判定」的机制键(已见/未见),集合本身仍在机制的 SBINTERN/存储里。
- **T1 只证「网 = 表」**:表是否对,仍靠产物比对与外部裁判(§3 #8);迁表不减少对 oracle 的需要。
