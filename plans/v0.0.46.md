# 0.0.46 计划（待启动）

<a id="registered-requirements"></a>
## 已登记需求（主人2026-10-31）

基于 `unisacc.com`、`gcc_cx.com`、`clang_cx.com` 与 cx 架构，做两个对标 agent harness 的工具：`cx-pi` 对标 Pi（`badlogic/pi-mono` 的最小 harness 路线），`cx-omp` 对标 OMP（`oh-my-pi`，把 IDE 接进 agent 的路线）。当前仅登记，未设计、未实现，不构成 0.0.43 收口前置。

参考对照（都是 TypeScript/Node 实现，只作行为对照，不作实现模板）：

| 对照 | 路线 |
|---|---|
| Pi（`pi.dev`、`badlogic/pi-mono`） | 最小 agent harness：会话、工具调用、上下文管理，插件面窄 |
| OMP（`oh-my-pi`） | Pi 的 fork，把 IDE 与更多工具面接进 harness，提示词与工具面更厚 |

| 编号 | 需求 | 设计与验收方向 |
|---|---|---|
| C46-HARNESS-01 | `cx-pi`：最小 harness | 会话循环、工具调用、上下文压缩、中断与恢复；工具面按最小集（读、写、改、跑命令、搜）。实现语言为 cx，产物是 `.com`，不引入 Node/Python 运行时。 |
| C46-HARNESS-02 | `cx-omp`：带工具面的 harness | 在 `cx-pi` 之上加工具面（诊断、批处理、并行子任务、外部编辑器/IDE 桥），与 `cx-pi` 共用同一套会话与工具合同，不各写一份。 |
| C46-HARNESS-03 | 共用模块与权重 | 两个 harness 复用同一组 cx 模块（文本、内存、进程、网络、流＋网），不复制实现；模块边界走 0.0.45 的外部调用合同。 |
| C46-HARNESS-04 | 与自身工具链打通 | harness 能把 `.cx` 源码当一等输入：用 `unisacc.com`/`gcc_cx.com`/`clang_cx.com` 实编、跑测试批次、查 `tools/` 现成工具，而不是靠 shell 拼命令。 |
| C46-HARNESS-05 | 可对照的能力证据 | 给出与 Pi／OMP 的可比项：工具调用回合、上下文处理、中断恢复、失败拒绝；用同一批任务对拍行为，不以功能列表充数。 |

约束（沿用本仓规则）：

- 除源码与注释外用中文；工具沉积在 `tools/`，带 `check-*.cx` 并登记批次。
- 不新增 Python/shell 算法；兼容壳只作薄入口。
- 分层走「层就是目录」（`cx/sys/`、`cx/mem/`、`cx/text/` 为 L0），新 `.cx` 六项棘轮计数为 0。
- 未实跑的项记 UNKNOWN，不记 PASS；不为了对拍放宽时限或删断言。

与 0.0.43／0.0.44／0.0.45 的关系：0.0.43 收口当前版本；0.0.44 修 `.cx` 模块化与内存安全；0.0.45 把流＋网能力开成外部可调用模块与权重；本版在此之上做应用层工具，不提前插入前两版范围。
