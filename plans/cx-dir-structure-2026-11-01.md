# cx/ 目录结构整理提案

## 实测事实

| 目录 | 文件数 | 被 `use` | 未被 `use` |
|---|---:|---:|---:|
| `cx/compiler/` | 331 | 29 | 302 |
| `cx/runtime/` | 339 | 42 | 297 |

- `cx/compiler` 与 `cx/runtime` 有 314 对同名文件，内容不同（前缀不同），都是 `tools/nametab-gen.cx` 生成：同一张事实表生成 compiler 侧与 runtime 侧两个副本。
- 约 600 个文件是 13–20 行的 `*_count`/`*_at` 名字表骨架；真正手写的大模块只有 `asmtext.cx`(2190)、`cxmod.cx`(1256)、`tapegate.cx`(675)、`tapelink.cx`(408)、`bindstage.cx`(92)。
- 多数生成物当前没有调用者；`cx/runtime/stream_attributes.cx` 等流壳 10–20 行、步骤返回 0。
- 生成器支持 `--out DIR`，输出路径写死为 `DIR/compiler`、`DIR/runtime`。

## 问题

1. 源与生成物混在同一层：读目录分不清哪些是手写、哪些是 `--check` 产物。
2. 生成物占据目录绝大多数，真实引擎被淹没。
3. 无调用者的生成物与有调用者的模块同权；无法一眼看出“这个模块没人用”。
4. 成对副本（compiler/runtime 同表）没有显式标记。

## 提案（分三步，均可单独验收）

### 步 1：生成物下移

- 输出改到 `cx/compiler/generated/`、`cx/runtime/generated/`。
- `tools/nametab-gen.cx` 的 `--out` 默认与 `--check` 路径同步；模块名不变，`use compiler.X` 不变（目录变化只影响文件路径，按 CX 解析是 beside-file，需要同时保留 `generated/` 作为模块解析路径，或把模块名改成 `compiler.generated.X`）。
- 二选一：保留 `use compiler.X` 并让解析器在 `cx/compiler/` 与 `cx/compiler/generated/` 两处查找；或改名 `use compiler.generated.X`，一次性更新 29/42 个调用点。
- 推荐前者：不动调用点、不动 CXIF 身份，只在 `cxm_adduse` 增加一个生成物目录查找；代价是解析规则多一条，需要写进 spec。

### 步 2：显式标记生成物

- 每个生成文件头已有 `Generated by tools/nametab-gen.cx ... Do not edit by hand.`。
- 增加 `cx/compiler/README.md`、`cx/runtime/README.md`，写明：`generated/` 下全部由生成器产出，`--check` 是唯一门禁；手写模块只在顶层。
- 无调用者的生成物不删：`--check` 仍需要它们存在；但在 README 里列出“当前零调用”的类别，避免人工误读为活代码。

### 步 3：空壳与流壳

- `cx/runtime/stream_attributes.cx`、`stream_output.cx`、`stream_resource.cx` 等 10–20 行壳：保留，但在 README 标注 `SKELETON`，不参与 33 对象闭包。
- 若未来 TDD 补深，再按 C44-CX-SURFACE-01 处理；本轮不动行为。

## 棘轮/字节影响

| 步骤 | 影响 |
|---|---|
| 生成物下移 | `cxraw`/`cxlibc` 的行随路径变（同样计数，move 记账可复用）；`srcshape` 不受影响；CXIF 不变 |
| 解析器多目录 | `cx/cx0/plan.cx` + `src/cxmod.c` + `cx/compiler/cxmod.cx` 三源同步；`cx0-extract --check` 必须 EXACT |
| README/标记 | 无字节影响 |
| 空壳标注 | 无字节影响 |

## 边界

- 不动 `nametab-gen` 生成的表内容，只动路径与说明。
- 不删任何生成物；`--check` 是唯一真源。
- 两代逐字节相同与 `check-cx-layers` 每步都要跑。

## 本轮未改的边界（2026-11-01）

- `tools/nametab-gen.cx` 与它的 `--check` 未动；生成物仍在 `cx/compiler/`、`cx/runtime/` 顶层。
- 未新增 `generated/` 子目录；CX 解析器仍是 beside-file，没有第二查找路径。
- 未删任何零调用生成物；它们仍是 `--check` 的必检对象。
- 未改 `cx/runtime/stream_*` 空壳行为。
- 未改 `cx/cx0`、`cx/workspace`、`cx/crypto` 的 AMB 记法。
- 本轮只落地两件事：棘轮 `move FROM TO N` 记账（`tests/cxlibc.cx`、`tests/cxraw.cx`，提交 `a0704c4703`）；本提案（提交 `bc86b013c3`）。
