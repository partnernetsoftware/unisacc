## 一、范围(合同见 plans/proc-lifecycle.md 九条)

1. **(a) 合同与矩阵**:`plans/proc-lifecycle.md`(九条合同 + 状态 x 操作矩阵)、
   `tools/check-proc-lifecycle.cx`(逐格断言,允许先红)、批次 `proc-lifecycle`。
   状态:x 操作矩阵以检查为唯一判据,文档与数据不各存一份。
2. **(b) Z5 修订**:`sy_child_t` 的 REAPED 精确含义(一切信号与等待全禁,返回已存状态)、
   锚定规则(组清理前不回收组长,`waitid(P_PID, WEXITED|WNOHANG|WNOWAIT)` 放 `_os` 帮手,
   不读 `/proc`)、唯一清理原语 `sy_proc_end(grace_ms)`;`sy_proc_wait` 超时写
   `c->exit.timed_out`。
3. **(c) Z3 capture 改造**:`sy_proc_capture` 到期与超 cap 路径改调 `sy_proc_end`,
   并修三处读码推断:子进程关 1/2 且忽略 TERM 时无界挂起;非 Linux 无 `/proc` 时存活
   探测恒假把正常退出报成超时;`px_run` 在 `rp_kill_tree` 已回收根后读未初始化的 `st`。
   每项先红后绿。
4. **(d) Z6/reaper 入参**:由 cdx 在 (c) 之后改 `rp_kill_tree` 收句柄;本版只提供合同,
   不碰 `ext/sysx/reaper.cx` 的实现归属(cc 指定 cdx 改)。
5. **subreaper 自查与返回三态**:`kill_tree` 未设 subreaper 时孤儿清扫返回具名拒绝而非 0;
   0/正数/负数三态在各入口统一。
6. **文档与文件头**:`cx/sys/proc.cx` 与 `ext/sysx/reaper.cx` 写清"运行期检查不是编译期
   所有权"、裸 pid 入口无保护、非 Linux 离组后代不受保护、Windows 全部 `-ENOSYS`。
