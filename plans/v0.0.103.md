## 1. 目标与依据

每动作 5.5 到 6.1 ns,占每步固定 10.0 ns 的 45 到 61%;每动作降到 3.0 ns 省约 13%。本版只做动作分派内联,不并固定段重写。

## 2. 范围

1. 动作实现从 `call core_action` 边界搬入两 ISA 各一份宏文件 `exec/c/asm/action-body-x86_64.inc`、`action-body-arm64.inc`,`action_*.S` 与 `run_*.S` 同 `#include`,单一来源;
2. 主循环把 `M_REGS` 快照提到整个运行外(只在 `run_*.S:68` 写一次),帧顶快照提到动作循环外;循环内直接跳动作体,不再每动作保存/恢复被调用者寄存器、不再重读 `M_REGS`/`M_FRAMES`;
3. 表跳转保留,不改动作语义;`core_action` 保留为"快照 + 内联体"薄壳,签名不变;
4. 两 ISA 同一提交改完。

## 3. ABI 边界

- `CoreModel` 布局不动,`CM_SIZE==160`,`layoutcheck.c` 断言不动;快照只落寄存器与栈。
- 不新增导出符号;不改 `core-abi.tsv`;`kernel/` 不手改,一律经 `tools/kernel-route.cx` 重构造。

## 4. gatekeeper 条件(逐条成为验收项)

1. **帧顶失效四类重算回写**:`INPUSH`/`INPUSHX`/`INPUSHXE`(`core_frame_push` 经 realloc,entries 可能搬家,`stack_x86_64.S:54`、`stack_arm64.S:50`)、`INPOP`(计数降)、`SWAP`(计数置 1)、`SBBLOB`(帧指针改指栈上假帧)。四类体尾一律从 `M_FRAMES+STACK_ENTRIES` 与 `STACK_COUNT` 重算帧顶,不做指针加减。
2. **两 ISA 寄存器分配表与栈槽参数化**:见第 5 节;宏文件内寄存器经 `.req`/`#define` 命名参数化,不硬编码,两 ISA 各一张表进本页并由 check 核宏名使用一致。
3. **runcheck 多动作序列**:`inpush-expand`、`inpop-restore`、`swap-then-read`、`sbblob-fakeframe` 四条加 `badop` 入口;三元组(退出码、输出字节、steps)守卫,steps 只对汇编侧断(归档 C 参考不写 `CoreResult.steps`)。现内核已实测 `RUNCHECK_K2 cases=70 status=PASS`、`RUNCHECK_BADOP impls=2 status=PASS`(私有,改写前基线)。

## 5. arm64 寄存器占用表(读 `exec/c/asm/run_arm64.S`、`action_arm64.S`)

| 寄存器 | run 循环(`core_run`) | 动作体(`core_action`) | 内联冲突与处置 |
|---|---|---|---|
| x19 | 机器块 `sp+96`(M_*基址) | 机器块(入参 x0) | 同义,直接共用 |
| x20 | 模型 `CoreModel*` | 动作指针(入参 x1) | 冲突:动作指针改用 run 的 x26 |
| x21 | 结果块(RESULT_REASON 等) | `M_REGS` 快照 | 冲突:regs 快照另配(候选 x27 让出后的寄存器或栈槽) |
| x22 | 输入上界(`cmp x23,x22`) | 帧顶指针 | 冲突:帧顶需另配被调用者保存寄存器 |
| x23 | 输入游标 | 当前操作码 w23 | 冲突:操作码改用临时寄存器(x8/x9,表跳转前即用即弃) |
| x24 | 状态/输出长度(w24) | 动作临时值 | 冲突:循环在动作段内是否活跃须逐行核;活跃则动作改用临时寄存器 |
| x25 | 当前状态号 | 动作临时值 | 冲突:同上 |
| x26 | 当前动作指针 | 输出缓冲基址临时(M_OUT/M_ERR/M_SCRATCH) | 冲突:动作内改用临时寄存器 |
| x27 | 动作计数 w27 | 未用 | 计数可移到栈 `[sp,#416]` 旁,让出 x27 |
| x28 | 产品桥保留(独立 tape 栈),不得用 | 未用 | 禁用 |
| x29/x30 | 帧/返回 | 帧/返回 | 内联后动作内的 `bl` 辅助调用仍需保 x30 |
| x8-x16 | 临时 | 临时 | 调用 `core_frame_push` 等后视为失效 |
| 栈槽 | `[sp,#400]`、`[sp,#408]`、`[sp,#416]`(动作数) | 自有 128 字节帧,`[sp,#112]` 出参、`[sp,#80]` 临时 | 栈槽参数化,内联后动作体用 run 帧内新划栈槽,偏移由宏参数给 |

结论:arm64 下 x20-x26 两侧语义全部冲突,可用被调用者保存寄存器只剩 x27(让出后)一个,不足以同时容纳 regs 快照与帧顶;需把 regs 快照或帧顶之一放栈槽(每动作一次 ldr,仍远省于 6 对 stp/ldp)。此项为原型首要测点。x86_64 表同理另列(本页未起草,待原型窗口补)。
