## 2. 工具 `tools/slice-freeze.cx`(约 220–280 行 .cx,只读，不写仓内)

```
sh ./unisacc.com tools/slice-freeze.cx -- check BASE_REV [HEAD_REV] --receipts DIR [--mode advisory|enforce]
sh ./unisacc.com tools/slice-freeze.cx -- list            # 打印冻结面 × 回归批次(给人看)
```

判定步骤:
1. 用 `git diff --name-only BASE..HEAD` 求出变更文件集，与清单的 glob 求交，得到命中集 H。H 为空时输出 `SLICE_FREEZE  hit=0`,rc0。
2. 要求 a,回归用例:BASE..HEAD 必须在 `tests/cases/` 下新增或修改至少一个文件，并且该用例所属批次在命中行的 `batches` 里。归属依据是 `tests/batches.tsv` 的输入列;按现有约定，用例文件名前缀就是批次名。不满足时报 `NO_CASE`。
3. 要求 b,批准:`agentwork/ledger.tsv` 在 BASE..HEAD 内新增一行 `kind=SLICE-CHANGE`。第 5 列以 `A ` 或 `B ` 开头并写明受影响目标，第 6 列含 `cc`。不满足时报 `NO_APPROVAL`。B 类在 enforce 模式下一律判红，因为 B 类应改走表和网。
4. 要求 c,字节对比:对 `targets` 中没有声明为受影响的目标，比较 `--receipts DIR/sl-*/receipt.txt` 的 `sha` 行与慢车道基线收据。基线收据路径从 `tests/slice-freeze.tsv` 头注释 `# baseline <rev> <dir>` 读取。有不一致报 `SLICE_DRIFT <target>`;缺收据报 `UNMEASURED <target>`,不算 PASS。
5. 末行输出 `SLICE_FREEZE  hit=N  case=ok|NO_CASE  approval=ok|NO_APPROVAL|B  bytes=ok|DRIFT|UNMEASURED  mode=...`。
   - enforce 模式：任一项不是 ok 就 rc1。
   - advisory 模式:rc0,只打印结果。

复用的接口:
- 收据格式:`tools/release-build.cx:996`(`sha` 与 `image` 行)和 entry-build 的 `receipt.txt`(lnx 两片的 `candidate` sha)。
- 批次名校验沿用 `tools/register.cx` 读 batches.tsv 的方式。
- git 调用用 `cx/sys/proc` 的 spawn,不自写 shell。

## 3. 三件套

- `tools/check-slice-freeze.cx`(约 120–160 行):在 `mkdtemp /tmp` 里 `git init`,搭最小夹具(假清单、假 ledger、假收据两套)。覆盖以下正负例:
  - hit=0 → rc0
  - 命中但缺用例 → NO_CASE
  - 缺批准 → NO_APPROVAL
  - B 类 → enforce 下 rc1
  - 未声明目标 sha 变化 → SLICE_DRIFT
  - 缺收据 → UNMEASURED,且不是 PASS
  - 清单里的批次名不存在 → 拒绝
  - 全部满足 → rc0
  - 全程不写仓内，结束前后 git status 相同。
- 用 `tools/register.cx` 登记批次 `slice-freeze-tool`(contract,lnx/x86_64,55s)。
- prd 能力速查加一行;toolsloc 基线同步。
- 另外按 AGENTS 规则做一次真实回放：用 c45-1 的五片收据当作 `--receipts`,对 `0b22d546e3^..0b22d546e3` 跑一次。该提交只改了 tools/,预期 hit=0,用来证明手造夹具之外的路径。
