## 条目

- **R17-10 默认即运行（P0，开工第一件）**：`unisacc FILE.c [args]` 无 `-run`/`-o` → 等同 `-run`（`--` 之后或第一个非 `.c` 参数起是程序参数，沿用 -run 的规则）；`-o OUT` 写宿主可执行；`-b`/`-S`/`-E` 不带 `-o` 时照旧写到标准输出（套件依赖 `-b T > file`），不再有静默 a.out；参考与产品两侧同改，ccparity 套件把“无模式 = a.out”条目改成“无模式 = 运行”，cli 套件加三例（无参运行、`-o`、`-b` 缺 `-o` 报错）；README 用法块与 `--help` 第一行改口。验收：主人的两条命令 `./unisacc.com examples/apps/procview.c`、`winlist.c` 直接打印输出。 **[v] 参考侧 2026-10-01**：预扫命令行，无 `-o/-b/-t/-S/-c/-E/-M*/-run/-dump-tokens/--tapebin/--version` 即 `-run`；cli 66/66、ccparity 52/52（裸调用改为“运行、不写 a.out”，三处需要文件的用例显式 `-o`）；产品侧同改，待 compilercheck 与新候选验证。

- **R17-1 三格式 `.o`**：**[v] Mach-O 参考侧 2026-10-01**：`-c -b osx/arm64|x86_64` 写 MH_OBJECT（三节、LC_BUILD_VERSION/SYMTAB/DYSYMTAB；arm64 用外部 PAGE21/PAGEOFF12 + ADDEND，x86_64 用 SIGNED 位移内含加数），ld64 `-e _start -lSystem` 链接，7 探针 × 2 架构运行与映像相同（x86_64 经 Rosetta）；同时把 `.data/.bss` 分界从“最后非零字节”改到“非零块的末尾”，避免一个初值尾部为零的符号跨两节。**[v] COFF 参考侧 2026-10-01**：`-c -b win/x86_64|arm64` 写三节 COFF（AMD64 REL32；ARM64 PAGEBASE_REL21/PAGEOFFSET_12A，加数写进指令字段），每个 Windows 导入是未定义外部符号 `__imp_Name`；lld-link 加 llvm-dlltool 生成的 kernel32 导入库链接；Windows 虚拟机里 hello/fact/ptr 两架构运行与映像相同（x64 在 arm64 Windows 上模拟）。坑：arm64 的 64KB tape 栈（bk_bss）不在 bkdlen 里，必须计入 .bss；`utmctl exec` 在来宾代理未起时也返回 0，就绪信号改用 `utmctl ip-address`。产品 δ 三格式待做。参考侧复用 ELF 写出器的结构（节、符号、重定位记录点 `x_rip`/`a_adrp_add`），格式层分三份：Mach-O（`MH_OBJECT`，`ARM64_RELOC_PAGE21/PAGEOFF12`、`X86_64_RELOC_SIGNED`）、COFF（`IMAGE_REL_AMD64_REL32`、`IMAGE_REL_ARM64_PAGEBASE_REL21/PAGEOFFSET_12A`）；产品 δ（exec/enc）同步写三格式；`tests/elfobj.py` 扩成 `objfile.py` 覆盖三格式，closure 把 `.o` 纳入逐字节对拍。验收：osx 两目标与 ld64/lld、win 两目标与 link.exe/lld 各链成程序并运行；三格式 `.text` 去重定位字段后与映像相同。
- **R17-2 自带静态链接器**：**[v] 参考侧 2026-10-01，tape 级链接**：`-c -b T -funit` 的单元对象是真的 ELF/Mach-O/COFF（全局/未定义符号、调用重定位 PLT32/CALL26/BRANCH/BRANCH26/REL32），另带一个不装载的节存本单元 tape（`UNISATAPE1 <目标> <长度>`）；`unisacc a.o b.o [-o prog]` 由 src/tapelink.c 把各单元 tape 合成一个程序 tape（本单元私有名改 `__u<k>_`、`.global` 按名相会、同名全局对象按 C 公共定义合一、各单元 `__init_u` 串成 `__init`），再走普通后端，六目标都可出；目标不一致或在非本机目标上运行都按名拒绝；系统 ld 不能链多单元（初始化链只有我们的链接器会做，见 docs/toolchain.md §7）。门禁 `linkunits`：tests/multi 的 6 组夹具两种顺序，单独编译再链接 = cc = 一步编译（21/21）。**产品侧链接 [v]**：exec/c/compiler.c 以 TL_PRODUCT 复用 src/tapelink.c 的合并核心，对象与 `.a` 输入在选路由之前合成程序 tape，交给产品的 tape 输入路由（编译决策仍全在模型）；用候选包手测：参考侧单元对象经产品链接，运行与写 ELF 都对。产品写对象（`-c -b`、`-funit`）在 cdx 的 δ 片里，驱动在路由就绪前按名拒绝。输入自家 `.o` 与 `.a`，输出六目标可执行文件（复用映像写出器的段布局，重定位解析与符号表合并新写）；`-L/-l` 从“接受但无效”变为对自家 `.a` 生效。验收：fb12 多单元夹具分别 `-c` 再链接，与一次性编译的行为一致；两侧（参考、产品）字节一致；**不**声称能链系统 `.a`。
- **R17-3 `ar`/`ranlib`**：**[v] 2026-10-01**：`unisacc ar rcs|t|x LIB.a [成员]`，参考与产品同一份代码（src/tapelink.c），写出的归档逐字节相同，系统 `ar t` 能读；长名用 BSD `#1/<长度>`；链接器接受 `.a`，只拉入定义了仍未定义的 `.global` 名的成员（经典规则，每个归档按序反复扫描直到不再拉入）。不写符号索引：我们的链接器按单元 tape 判断，系统链接器本就不能链多单元对象。`unisacc.com ar rcs|t|x`，GNU `ar` 格式（`!<arch>`），只为 R17-2 读 `.a`。验收：系统 `ar t` 能列出我们写的归档，我们能读系统 `ar` 写的只含自家 `.o` 的归档。
- **R17-9 互操作 (a)**：**[v] 参考侧 2026-10-01**：任何对象（`-c -b`）里，只声明不定义的 `extern` 对象是未定义符号（导出与未定义的数据名去掉 tape 的 `g_` 前缀以与 C 名相会），不再静默分配；映像模式不变。验收（elfobj 新腿）：cc/gcc 编的 `banner.o` 定义 `const char banner[]` 与 `int answer`，我们的对象读它们——Mach-O 两架构 ld64 链接运行、ELF arm64 在 Lima 用 GNU ld 链接运行，都打印 `banner from cc 42`。COFF 链接已手测（lld-link），运行待 Windows 腿。前端把未定义的 `extern` 数据声明记为 UND 符号（今天被静默当作定义），后端对其发 `R_X86_64_PC32`/`R_AARCH64_ADR_PREL_PG_HI21` 等重定位；验收：cc 编的 `.o` 定义 `const char banner[]`，我们的程序打印它，三格式各一例。
- **R17-5 库面**：**[v] 2026-10-01 第一步**：`include/unistd.h`（read/write/close/lseek/unlink、STD*_FILENO、SEEK_*，按需体）；顺带修参考侧嵌入头表只收顶层 `include/*.h`、`#include <sys/types.h>` 在仓库外失败的缺陷（产品包一直带着子目录）；realprog 3/6（jsmn-dump 转 ok，输入改用钉住的 cJSON tests/inputs/test1），棘轮 +1 达成。每个头/函数一个红例对拍 gcc；`setjmp/longjmp` 按两架构各写一份保存/恢复序列；4 MB `MAXSRC` 提到 16 MB 或改为分段读入（sqlite3.c 9.2 MB）。验收：realprog 棘轮至少 +1（lua 或 jsmn-dump），tools/corpus 不降。
- **R17-8 债**：**[v] Python 位域后置自增减 2026-10-01**：unisa/front/parse.py 对位域的 `x++`/`x--` 保留旧值本身（原来用“新值 ∓ 1”反推，无符号 5 位从 0 减到 31 再加 1 得 32）；tests/ccrun.knownwrong 删去该行，difftest 4 片全绿。**[v] 字符数组成员字符串初值**（见上）。**A1、A2、B1 按顺延规则降级到 0.1.x（2026-10-01）**：三项都已顺延过一次（0.0.16），其修复都在产品 δ（exec/parse2 的复合字面量、exec/pp 的续行列计数、exec 各阶段的拒绝位置），而本版 δ 的人力全部在主线的单元前端与三格式对象上；第二次顺延按规则不允许，所以降级而不是再顺。根因与修法已写在 archive/plans/v0.0.16.md 与本文件，登记到 plans/v0.1.x.md。五条各一个红例或 knownfail 清零；A2 的修法两侧同批（参考 `splice()` 记列或只在指令行/字符串/`//` 注释/token 中间删换行；产品 exec/pp P0 规则表加列寄存器）。
- **R17-6 流程**：**[v] E2 第一步 2026-10-01**：`ccrun-1..8`、`ccrun-malloc`、`opt-run-1..8` 进入本地门禁（gate.sh 356 项，--com 再加产品套件），每项 3–7 s；两类 0.0.16 的漏网回归今后在本地队列就会红。E1 与“一张清单生成两边”仍待做。E1 把 bindingcheck/warningcheck 的冷模型缓存预热做成 release.sh 的第 0 窗；E2 一张清单生成 gate.sh 与 all.sh，`ccrun`、`opt-run`、`native` 等进入本地队列（本版 0.0.16 的两个回归都是 linux.sh 才抓到的）。
- **R17-4 / R17-3b / R17-7**：原文不变（见 archive 里 0.0.17 草案的条目），只在主线收口后开工。

**不做**：训练；汇编器、动态库、完整调试信息（0.0.18）；cc 函数互调（0.0.18）；系统 `.a` 全量可链（不承诺）。
