## 3. 统一函数选址与实现设计

### 3.1 选址决策: `tools/cxlib/cachepin.cx` + `tools/release-keepalive.cx --pin|--unpin` + `tools/chain-ready.cx --prepare`

- **单一真源模块 (`tools/cxlib/cachepin.cx`)**: 将目录白名单枚举、安全目录打开、`.no-purge` 原子写/按版本回收逻辑收口为一个共享函数 `cp_pin_release_set(...)`, 避免 `release-keepalive.cx` 与 `chain-ready.cx` 各自维护两套清单而漂移。
- **CLI 入口 1 (`tools/release-keepalive.cx`)**:
  - 复用其已有版本校验 (`rv_valid`)、`--rev HEX`、`--cache-dir DIR`、零符号链接守卫 (`sy_lstat` + `sy_open_dir_nofollow` + `sy_fstat` + `sy_stat_trusted_owner`)。
  - 新增一次性非阻塞子模式 `--pin` 与 `--unpin`:
    - `sh ./unisacc.com tools/release-keepalive.cx -- VERSION --pin [--rev HEX]... [--cache-dir DIR]`
    - `sh ./unisacc.com tools/release-keepalive.cx -- VERSION --unpin [--rev HEX]... [--cache-dir DIR]`
  - 既有轮询模式 (不传 `--pin`/`--unpin`) 在第 1 轮自动调用一次 `cp_pin_release_set(..., unpin=0)` 并继续每 `interval_s` 刷新 `.keepalive-v<VER>`, 实现"`.no-purge` 显式豁免 + mtime 刷新"双保险。
- **自动接入入口 2 (`tools/chain-ready.cx --prepare`)**:
  - 在 `tools/chain-ready.cx:2295-2307` (`cmd_prepare`) 构建 `ident-helper` **之前**调用 `cp_pin_release_set(cache_abs, ver, revs, nrevs, /*create_core=*/1, /*unpin=*/0, &st)`:
    - 若任一目标写 `.no-purge` 失败, `cmd_prepare` 立即返回非零 (`READY=no`), 杜绝带未钉住缓存起链;
    - 现有 `release-post.cx` 在 Step 7 Y2 公开并关闭冻结后调用 `tools/release-keepalive.cx -- VERSION --unpin`, 精确释放 B/C 类 pin 而保留 A 类常驻 pin。

### 3.2 核心函数签名、标记格式与安全合同

```c
/* tools/cxlib/cachepin.cx (设计草案, 未落地) */
typedef struct {
    int pinned;      /* 本次成功写入或刷新 .no-purge 的目录数 */
    int unpinned;    /* --unpin 移除的目录数 */
    int absent;      /* B/C 类尚未创建的目录数 (跳过, 不报错) */
    int kept_other;  /* --unpin 时因属于 class=A 或其它版本而保留的目录数 */
    int failed;      /* 权限/符号链接/IO 失败数 (>0 导致整体返回非零) */
} cp_pin_stats_t;

int cp_pin_release_set(const char *cache_abs,
                       const char *ver,
                       const char revs[][48], int nrevs,
                       int create_core_dirs,
                       int unpin,
                       cp_pin_stats_t *out);
```

1. **`.no-purge` 文件格式 (原子写 `sy_write_atomic`, 权限 `0644`, 单行 TSV)**:
   `pin\tschema=v1\tversion=<VER>\tclass=<A|B|C>\twall_s=<TS>\towner=cachepin\n`
   - 相比空文件, 结构化内容让 `--unpin` 能精确区分 `class=A` (永不自动解钉) 与 `class=B/C` (仅解钉 `version=<VER>` 匹配者), 防止双版本并存时误删另一在途版本的 pin。
   - 若目录已有手工创建的空 `.no-purge` (无 `schema=v1`), `--unpin` 视为外部/人工钉住 (`kept_other++`), 绝不误删。
2. **目录创建边界 (`create_core_dirs`)**:
   - 仅当 `create_core_dirs == 1` 且 `unpin == 0` 时, 允许创建 A/B 骨架父目录 (`ident-helper`、`release-cm`、`chains`、`chains/bg-b1`、`chains/snap`、`prerun`) 后立即落 `.no-purge` ("先钉后用");
   - 具体版本子目录 (`release-v<VER>-*`、`prerun/v<VER>-*`、`evidence-*`) 与 C 类目录 (`e3cache`、`prep-cache`、`tlib`、`s9-native`、`derived`、`symindex`) 若尚不存在则记 `absent++`, 不提前制造空目录。
3. **零符号链接与属主强校验**:
   - 每级路径均核 `sy_lstat(p, &st) == 0 && st.kind == 'd' && sy_stat_trusted_owner(&st, uid)`, 再 `sy_open_dir_nofollow(p)` + `sy_fstat` 二次确认;
   - 目标 `.no-purge` 若已存在且 `sy_lstat` 非普通文件 (`mst.kind != 'f'`), 直接 `failed++` 拒绝覆盖 (防止符号链接篡改仓外文件);
   - 显式断言 `target_dir != cache_abs`, 永不写出 `$HOME/.cache/unisacc/.no-purge`。
4. **结构化输出行合同**:
   - 成功: `RELEASE_CACHE_PIN\tmode=<pin|unpin>\tstatus=PASS\tversion=<VER>\tpinned=<P>\tunpinned=<U>\tabsent=<A>\tkept_other=<K>\tfailed=0` (`rc=0`);
   - 失败: `RELEASE_CACHE_PIN\tmode=<pin|unpin>\tstatus=FAIL\tversion=<VER>\t...\tfailed=<F>` (`rc=1`); 参数/路径非法 `rc=2`。

### 3.3 外仓 `system-cleanup.sh` 配套协同加固 (2 处小改)

1. `system-cleanup.sh:68`: 增加 `! -name 'ident-helper' ! -name 'release-cm' ! -name 'borrowed-cm'`, 作为 A 类目录的第一道硬豁免;
