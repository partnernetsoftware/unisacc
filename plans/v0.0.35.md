## H1⁗ / D1′ 执行拆片

以下是只读审查后的实施计划，尚未实现。解冻后按 H1 三片、D1 四片推进，每片路径限定提交并向 cc 交付证据；拆片不降低原项验收，不把部分完成写成整项完成。

### H1⁗：按声明顺序记录联结历史

1. **H1-1：声明历史布局与对象入口。** 在领域布局源中分配每标识符 GSTAT（最终名字以布局审查为准），记录当前单元此前声明的联结，使用 unit_epoch 隔离；接 `control-result.tsv` 的文件域对象声明/记录入口。`units` 预扫描 STATIC 是终态，不可替代声明历史。反例：`extern int x; static int x;`；正例：重复 static、static 后 extern、不同单元同名 static。生成 facts 不手改。
2. **H1-2：函数原型与定义共用历史检查。** 覆盖全部文件域函数声明入口，不能仅挂 FN.def1 或 GV.record；复用 H1-1 历史检查。反例：普通原型后 static 定义；正例：static 原型后 static 定义，局部同名变量不能污染文件域历史。
3. **H1-3：位置诊断及产品验收。** 对照 `src/front_parse.c` 当前参考规则，用当前声明标识符位置报 file:line:col。对象/函数矩阵与参考、系统 cc 对照；八变体 graphhash、r21、exec-chain 和同源产品 diag 通过后，删除 staticafter knownfail。

### D1′：静态初始化上下文与合法常量边界

1. **D1-1：贯穿并恢复初始化上下文。** 设置并保存/恢复 toinit 或等价标志，覆盖 `control-result.tsv` GV.iv、`statics-result.tsv` SC.init/SC.aggr/SC.expr、`initializers-result.tsv` INITLIST 的递归路径。全局/静态局部初始化调用为反例，普通自动局部初始化调用为正例；本片只声明实际覆盖的入口。
2. **D1-2：约束求值调用与对象值读取。** 检查 `unarycontrol-result.tsv` U.call/U.var 和 `control-result.tsv` ADR.call.go 的调用/取值入口，按符号描述与静态初始化语境判断；不能仅因出现标识符而拒绝。覆盖聚合中的调用反例，并保留函数地址、数组/字符串衰变、静态对象地址等合法常量候选。
3. **D1-3：不求值语境与合法常量豁免。** sizeof 类型/表达式路径临时暂停相关求值限制并恢复；枚举、取址、成员地址等逐类验证。`sizeof(f())` 不发调用，合法地址初始化接受；涉及 VLA 的非常量 sizeof 不能一律豁免。条件/逗号等复杂形式以参考与系统 cc 分别锁定边界，不能只依靠裁掉输出实现正确性。
4. **D1-4：上下文泄漏、位置诊断及产品验收。** 检查静态局部与嵌套 INITLIST 的返回路径，用“静态初始化后再普通自动初始化调用”正例抓标志泄漏。诊断必须带位置；diag/diag.com、合法常量矩阵与 exec-chain 通过，同源产品运行接受探针后，删除 staticinit knownfail。

布局、表与模板改动同片重生成相应 facts 和图哈希；使用 graphhash 的 `--stage parse2` 精确选择八变体。小片只跑有针对性的检查，整项收口保留原门禁；不得改参考或加入豁免来迁就产品。H1/D1 必须在本版完成，不以拆片为再次整体顺延的理由。
