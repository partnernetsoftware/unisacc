# F1 对象产出合同设计单(0.0.80 工作项 0)

结论:最小改面是 elfobject(含 objectplan 符号列)把每单元的 __init_u 改为 LOCAL 唯一名并发射 .init_array 加 R_X86_64_64 / R_AARCH64_ABS64 重定位,不改前端;初值直写 .data/.rodata 要改 cx/compiler 的 __init_u 生成,触前端,不选为 F1。weak 必须改 cx/cx0 三源属性传递,另类立项。实现单 4 张:F1a、F1b、F2、F3(F4 检查与 F6 并行不占候选)。

## 一、现状取证(0.0.79 候选 APE ea10ab07,2026-11-19 实跑,lnx/x86_64)

(1) V-01:p03.c(int x=5; const int k=32)经 -c -funit,gcc -no-pie 链 m03.o,rc 0(期望 51)。节:.text、.data size 0、.bss size 0xb8、.rela.text、.symtab、.unisa.tape;无 .rodata、.init_array。x、k 为 OBJECT GLOBAL Ndx3 size 0;__init_u FUNC GLOBAL 在 0x56,体为 mov $5 / lea x / mov;mov $32 / lea k / mov;ret,只用 rax、rdi,符合 SysV 调用者保存约定。
(2) 正控补证:gcc 另写一个 .init_array 项指向 __init_u 一起链接,rc 51。证明方案 A(登记 .init_array)语义成立。
(3) 新发现:两个 -funit 对象(p03、q)同链,ld 报 multiple definition of __init_u。方案 A 必须同时把 __init_u 变 LOCAL(或单元唯一名),否则多对象链接即失败。
(4) V-02:p07 weak_hook 为 FUNC GLOBAL,与 strong.o 链接 multiple definition。
(5) V-03b:add_one(0) rc 17(期望 11);入口 push %r9; mov %rsp,%r9; ...; mov %rax,-8(%r9),首参取 %rax。
(6) arm64(-b lnx/arm64):节与符号布局同 x86_64(.data 0、.bss 0xb8、x/k GLOBAL Ndx3、__init_u GLOBAL)。add_one 首参取 x0(正确),但以 x7 作栈指针(sub x7,x7,#8; str x6,[x7]),gcc 调用方不设 x7,原生调用必错;无原生 arm64 执行环境,UNMEASURED。
(7) F4 前提:p03、p07、p02c 三例 -c 与 -c -funit 产物 cmp 同字节。

## 三、最小改面判定

方案 A(登记 .init_array):只改 exec/enc 的 elfobject 表与 objectplan 符号列,x86_64 与 arm64 共用 d0 节一次改两目标(check-objectplan-pair 记 COUPLING),不触 cx/ 与 src/。整程序 -o 路由 tapelink 显式 call __init_u<n>,不经 elfobject 写 ET_REL,预期 BIN16 不变;风险是 objlink 消费 -c 对象时若读 ELF 符号表找 __init_u,改 LOCAL 后需核(objlink 走 .unisa.tape 时无影响),F1a 的先导检查须实测。osx/win 的对象容器(unitcontainer)不在本单,登记 UNMEASURED。
方案 B(初值直写 .data/.rodata):要在 cx/compiler 生成阶段识别常量初值并改 tape 形状,触前端,影响 tapelink 与 fwdmerge,BIN16 大概率变,否决作为 F1。
weak:属性在前端 tape 中无绑定字段(V-02 的 GLOBAL 来自 objectplan 默认 info 17),丢失点在 parser 到 tape 的属性传递,需 cx/cx0/src 三源改,另类立项,0.0.80 只做 F3 检查先行(登记期望失败)。

## 四、验收设计

先失败检查草案 tools/check-objabi.cx(不入库),三例 gcc 互链:

```c
#pragma unisa use sys.proc
/* check-objabi: link unisacc -c -funit objects with gcc-built mains; expect rc 51, 11, 7. */
static const char *cases[3][4] = {
    {"p03", "int x=5;\nconst int k=32;\nint getx(void){return x;}\nint getk(void){return k;}\n",
            "int getx(void);int getk(void);int main(void){return getx()*10+(getk()==32);}\n", "51"},
    {"p02c", "int add_one(int v){return v+11;}\n",
             "int add_one(int);int main(void){return add_one(0);}\n", "11"},
    {"p07", "__attribute__((weak)) int weak_hook(void){return 1;}\n",
            "int weak_hook(void);int main(void){return weak_hook();}\n", "7"},
};
/* per case: write unit and main into a session dir (sr_default), run
   unisacc -c -funit unit.c, gcc -c main.c, (p07 adds strong.c returning 7),
   gcc -no-pie, run with 10 s bound, compare rc; print CASE name PASS|FAIL rc=got/want.
   Extra case p03+q: two units in one link must not hit multiple definition. */
```

预期输出(现候选):CASE p03 FAIL rc=0/51;CASE p02c FAIL rc=17/11;CASE p07 FAIL link;CASE multi FAIL link;末行 FAIL=4,rc 1。F1 后 p03 与 multi PASS,F2 后 p02c PASS,F3(另类)后 p07 PASS。
DELTA:elfobject/objectplan 表改动后 derive --check 与表哈希必变,记 DIFF 并列出行。BIN16:17 份整程序 -o 产物与 0.0.79 逐字节相同(变即失败)。FIX2、ENT3:对象网无 sim --cov 配方(OBJECTPLAN-NET-SIM-COV-NO-RECIPE),替代为 tools/formats-*.cx 对 -c 产物做结构对拍(节名集、符号绑定、重定位类型)加 readelf 黄金表,T1 补配方前 sim --cov 记 UNMEASURED。整链字节口径:对象路径产物预期变(列入 DIFF 清单),整程序 -o 17 份不变。
