## 1. 问题复盘与根因定因（静态源码 + `v0.1.5` 现场日志交叉取证）

在 `v0.1.5` prerun 运行过程中，`windows.tsv` 由 `plan --normal-jobs 8 --window-lanes 3` 生成（表头固定 `# window-lanes=3`）。在 `04:16` 重启 `prerun-drive run --resume --max-jobs 8 --window-lanes 5` 后，操作侧仍观察到宽度为 `3`，且随后在 `long` 阶段出现多起 `rc=124` 超时重跑。静态审阅 [tools/prerun-drive.cx](file:///home/devali/repos/unisacc/.claude/worktrees/w-agy-flow/tools/prerun-drive.cx) 与 [tools/prerun-watch.cx](file:///home/devali/repos/unisacc/.claude/worktrees/w-agy-flow/tools/prerun-watch.cx) 并核对 `/home/devali/.cache/unisacc/prerun/v0.1.5-ba12b08dfd/supervise.log` 后，定位出四处根因：

### (1) `pd_cmd_run` 在传入 `--window-lanes` 时完全跳过 `# window-lanes=` 表头解析与一致性校验

见 [tools/prerun-drive.cx](file:///home/devali/repos/unisacc/.claude/worktrees/w-agy-flow/tools/prerun-drive.cx#L1755-L1771)：

```c

        lanes = 1;
        if (at >= 0) {
            const char *start = (const char *)wb + at + strlen(key);

                mm_free(wb); return pd_refuse("invalid-window-lanes");
```

- 当 `run` 命令行传入 `--window-lanes 5`（`lanes = 5 != 0`）时，`if (!lanes)` 分支被整体跳过：
  - (a) 即使 `windows.tsv` 内的 `# window-lanes=` 损坏（如 `# window-lanes=99` 或 `# window-lanes=abc`），传入 `--window-lanes` 也会绕过 `invalid-window-lanes` 检查；
  - (b) 与紧随其后的 `timed-plan-exceeds-max-jobs`（第 1768 行校验 `# timing=wave-v1 jobs=J` 与 `--max-jobs`）不同，`pd_cmd_run` 对 `# window-lanes=3` 与运行期 `--window-lanes 5` 的不一致不做任何拒绝、预算核对或表头同步；
  - (c) 磁盘上的 `windows.tsv` 仍保留 `# window-lanes=3`，后续 `prerun-drive archive` 将其原样归档为 `release/evidence/<ver>/prerun-windows.tsv`，导致归档计划表头（`# window-lanes=3`）与实际运行日志（`windows=5`）产生证据失真；
  - (d) `pd_cmd_prepare`（第 2922-2951 行）写入 `prerun-env.tsv` 时记录了 `normal_jobs` 与 `keep_going`，但遗漏了 `window_lanes`。

### (3) `PRERUN_LANES` 仅输出当前波次实际凑齐数 `windows=queued`，未输出配置上限 `lanes`

## 2. `v0.1.7` 合同设计（主推方案 A：计划不一致硬拒绝 + 备选方案 B：带安全检查与表头同步的运行期生效）

根据任务要求（"make the run flag either effective with a safe check or a hard refusal when it differs from the plan; include the red-first test plan"），本设计将表头解析、一致性门禁与可观测性拆为正交合同，同时给出**主推方案 A（与计划不一致时硬拒绝）**和**备选方案 B（带安全门禁与表头同步的运行期覆盖）**。

### 2.1 公共基础合同（方案 A 与方案 B 均必须执行）

1. **无条件解析并校验 `windows.tsv` 的 `# window-lanes=` 表头**：
   - 新增静态帮手 `pd_parse_plan_lanes(const unsigned char *wb, int64_t wn, int *out_plan_lanes, int *out_has_hdr, int64_t *out_val_off)`：
     - 在 `window\tjobs\tphase\tcount\tids` 表头之前扫描所有 `#` 注释行；
     - 若存在 `# window-lanes=`：必须仅出现一次，且值为单字节 `'1'..'8'` 后紧跟 `\n`（或 `\r\n`）；否则无论 CLI 是否传入 `--window-lanes`，一律返回 `-1` 并触发 `pd_refuse("invalid-window-lanes")`（`rc=2`）；
     - 若不存在 `# window-lanes=`（旧版计划表）：`*out_plan_lanes = 1`，`*out_has_hdr = 0`。
2. **`prepare` 与 `prerun-env.tsv` 持久化 `window_lanes`**：
   - `pd_cmd_prepare`（第 2924-2949 行）写入 `prerun-env.tsv` 时增加 `window_lanes\t%d\n`（值为 `pd_plan_lanes`）；
   - `main()` 的 `run` 分支（第 3222-3229 行）在未显式传 `--window-lanes`（`lanes == 0`）时，若 `prerun-env.tsv` 含有 `window_lanes`，读取该值并与 `windows.tsv` 的 `# window-lanes=` 交叉校验。
3. **启动期立即输出 `PRERUN_LANES_CONFIG` + 波次行附带 `lanes=%d`**：
   - 在 `pd_cmd_run` 完成表头校验与 `PRERUN_FROZEN_SOURCE` 输出后、进入窗口循环前，无条件打印一行：
     ```
     PRERUN_LANES_CONFIG	plan_lanes=<P>	run_lanes=<R>	max_jobs=<J>	timed=<0|1>
     ```
     保证启动或 `--resume` 重启后，无需等待 `W0078..W0082` 等独占 `heavy` 窗口跑完，首屏即可核实当前生效的 `run_lanes`。
   - 第 1879 行波次启动日志改为：
     ```c
     printf("PRERUN_LANES\tfirst=%s\twindows=%d\tlanes=%d\n", wid, queued, lanes);
     ```
     - 保持 `PRERUN_LANES\tfirst=Wxxxx\twindows=K` 前缀与既有测试（`check-prerun-drive.cx:654,2018`、`check-prerun-watch.cx:157`）100% 兼容；
     - 同时显式携带配置宽度 `lanes=%d`，即便尾波只凑齐 `windows=3`（`queued=3`），日志与 `prerun-watch.cx` 也能区分「当前波次凑齐 3 个窗口」与「配置宽度为 5 路」。

### 2.2 主推方案 A：当 `run --window-lanes` 与计划表 `# window-lanes=` 不一致时硬拒绝（默认合同）

- **判定规则**：
  - 当 CLI 显式传入 `--window-lanes R`（`lanes > 0`），且 `R != plan_lanes`（含新计划表 `# window-lanes=P` 不相等，或无 `# window-lanes=` 的旧计划表 `plan_lanes = 1` 但传入 `R > 1`）时：
    ```c
    fprintf(stderr, "PRERUN_WINDOW_LANES_MISMATCH\tplan=%d\trun=%d\twindows=%s\n",
            plan_lanes, lanes, wpath);
    mm_free(wb);
    return pd_refuse("window-lanes-mismatch-plan");
    ```
- **选型依据**：
  1. 与第 1768 行 `timed-plan-exceeds-max-jobs` 保持严密对称：计划表头（`# timing=wave-v1 jobs=J` 与 `# window-lanes=P`）是契约输入，运行期不得静默偏离；
  2. 杜绝 `windows.tsv`（`# window-lanes=3`）与 `supervise.log`（`windows=5`）在 `archive` 归档后的证据不一致；
  3. 防止操作者在未重算 `PRERUN_LANE_ESTIMATE` 的情况下盲目调高 `--window-lanes` 触发 `v0.1.5` `W0083..W0088` 的 58 秒超时风暴；
  4. **如何合法调整宽度（含 `--resume`）**：由于 `pd_build_plan`（第 651-813 行）打包 `W0000..Wnnnn` 窗口的批次归属与顺序完全不依赖 `pd_plan_lanes`，操作者只需先重跑一次 `prerun-drive plan ... --window-lanes 5`（耗时 `< 20 ms`，原位更新 `windows.tsv` 的 `# window-lanes=5` 并重算 `PRERUN_LANE_ESTIMATE`，保留目录内已有的 `done.W*` 与 `strict-W*.tsv`），再跑 `prerun-drive run --resume --window-lanes 5` 即可零冲突续跑。

### 2.3 备选方案 B：带安全门禁与表头原子同步的运行期生效（若需免重跑 `plan` 直接在 `run` 调宽度）

若后续希望允许 `prerun-drive run --window-lanes R` 在安全范围内直接覆盖 `# window-lanes=P` 而不必重跑 `plan`，则须同时满足以下三条安全不变式：

1. **安全上界门禁 1（禁止超过 `--max-jobs`）**：
   - 若 `lanes > max_jobs`，拒绝 `pd_refuse("window-lanes-exceeds-max-jobs")`（`rc=2`）。
2. **安全上界门禁 2（计时计划表 `timed == 1` 禁止运行期扩宽 `lanes > plan_lanes`）**：
   - 在 `timed` 计划表下，只允许运行期**降级**（`1 <= lanes <= plan_lanes`，对齐 [tools/freeze-day.cx](file:///home/devali/repos/unisacc/.claude/worktrees/w-agy-flow/tools/freeze-day.cx#L821) 中 `if load1>12 downgrade to --window-lanes 2` 的降载规程）；
   - 若 `timed && lanes > plan_lanes`，拒绝 `pd_refuse("timed-plan-window-lanes-exceeds-plan")`（`rc=2`），强制要求通过 `plan --window-lanes R` 重新评估估算耗时后再运行。
3. **磁盘表头原子同步**：
   - 当 `lanes != plan_lanes` 通过上述安全门禁时，在启动任何窗口前，将内存中 `wb[val_off]` 处的单字符 `'1'..'8'` 更新为 `'0' + lanes` 并通过 `sy_write_atomic(wpath, wb, wn, 0644)` 写回 `windows.tsv`，确保 `windows.tsv`、`prerun-watch.cx` 与最终 `archive` 归档证据严格一致。

> 决策结论：补丁草案默认采用**主推方案 A（`window-lanes-mismatch-plan` 硬拒绝，rc=2）**，最简单、最确定且零隐式改表副作用；如需支持免 `plan` 的运行期安全降载/覆盖，只需开启方案 B 的两行判断与 `sy_write_atomic` 同步（已在第 3 节并列给出精确代码）。

## 3. 针对 `tools/prerun-drive.cx` 的补丁草案

### 3.1 新增 `# window-lanes=` 严格解析帮手 `pd_parse_plan_lanes`（插入 `pd_cmd_run` 之前，约第 1743 行）

```c
/* Parse and validate `# window-lanes=<1..8>` header line in windows.tsv buffer WB[0..WN).
 * Always validates header syntax even when CLI `--window-lanes` is also supplied.
 * Returns 0 on success (*out_plan_lanes in 1..8, *out_has_hdr in 0..1), -1 on malformed or duplicate header. */
static int pd_parse_plan_lanes(const unsigned char *wb, int64_t wn,
                               int *out_plan_lanes, int *out_has_hdr) {
    *out_plan_lanes = 1;
    *out_has_hdr = 0;
    int64_t pos = 0;
    while (pos < wn) {
        int64_t ls = pos;
        while (pos < wn && wb[pos] != '\n') pos++;
        int64_t le = pos;
        if (pos < wn) pos++;
        if (le > ls && wb[le - 1] == '\r') le--;
        if (le == ls) continue;
        if (wb[ls] != '#') break;
        const char *pfx = "# window-lanes=";
        int64_t pl = 15;
        if (le - ls >= pl && memcmp(wb + ls, pfx, (size_t)pl) == 0) {
            if (*out_has_hdr) return -1;
            if (le - ls != pl + 1 || wb[ls + pl] < '1' || wb[ls + pl] > '8') return -1;
            *out_plan_lanes = (int)(wb[ls + pl] - '0');
            *out_has_hdr = 1;
        }
    }
    return 0;
}
```
