# 0.0.45 计划（待启动）

<a id="registered-requirements"></a>
## 已登记需求（主人2026-10-24）

继续改良现有流＋网范式的模块，使其成为外部可以调用的工具能力；让不同用途的`.com`程序动态共用模块与权重，支持更丰富的测试、诊断及应用功能。当前仅登记需求，尚未完成本版设计或实现，不构成0.0.43发布前置。

| 编号 | 需求 | 设计与验收方向 |
|---|---|---|
| C45-FLOWNET-01 | 改良流＋网模块的可复用边界 | 沿现有Stream／Net合同整理可独立调用的能力、依赖及组合方式；保留流与网的语义区别，调用不要求复制整套编译器或另写一份实现。 |
| C45-CALL-01 | 形成外部工具调用接口 | 明确外部`.com`调用模块的入口、输入输出、资源与内存责任、诊断、拒绝及版本兼容合同；支持按需组合模块完成具体功能。API形式、承载格式和装载方式后续设计，不在登记阶段预定实现。 |
| C45-SHARE-01 | 多种`.com`程序动态共用模块和权重 | 明确模块／权重包的发现、加载、复用、身份和配对校验，避免每个工具各自复制逻辑与权重。分别计量公共模块／权重及每个调用程序的大小、加载成本和运行内存；不将多份拷贝或转调旧脚本称为动态共享。 |
| C45-SHELL-01 | 稳定通用壳与可独立重建的流／网数据包 | 外置流配置、模型转移／动作／权重及资源；规则变化只重建受影响模型，操作集／格式／ABI／宿主能力变化才重建壳。优先复用P3校验，显式装载，检查缺失／错配／不兼容；至少证明一次模型更新前后壳SHA不变。测试绑定壳与数据身份并按依赖定点复测，保留独立对照。当前七流开发容器尚为内嵌模型，外置能力未实现；实际API及包格式后续细化。 |
| C45-TOOLS-01 | 用实际工具证明能力可外用 | 至少用两个不同用途的`.com`程序复用同一组模块及权重，展示具体测试或诊断功能；逐项比较现有入口与外部调用的结果、拒绝和边界，覆盖缺失／不兼容模块、权重身份不匹配及资源释放。保留独立参考，不以同一实现对自身比较冒充对拍。 |
| C45-LOADER-01 | **通用 APE loader 模板（六 ISA 核心段）**（2026-11-03 主人提出，lab-loader L1–L5 已验证单格） | 实测（lnx/x86_64，`tools/lab-loader/`）：模板 = 多格式头 782B + 原生 boot 102,886B + 执行器切片 302,684B + 模型槽；真正的执行内核 UNIKERN 只有 7,144B（arm64 7,096B），其余是重复的 libc/sha 与 O0 编译的 runtime。换权重不换基座已证（两次生成执行器切片逐字节相同），utf8.com 冷启动 <1ms。做法：每 ISA 合并 boot 与 base 为一个"核心段"（UNIKERN + inflate + sha + manifest/IO + 包帧解析），runtime 改 O2，复用 C44-LIBCUNIT-01 的 libc 单元。估计目标 30–60KB/ISA（现约 406KB），五个原生切片合计约 150–300KB；win/arm64 无原生切片照实标。验收：lnx/x86_64 核心段 <100KB 且 utf8/e1 结果不变；其余格只出字节标 CI-ONLY，原生 runner 实跑后才算 PASS。合同见 `tools/lab-loader/CONTRACT.md`。 |
| C45-UJS-LOADER-01 | **ujs 复用同一 loader** | 合同（CONTRACT.md）已去 unisacc 专有假设：manifest 只靠 name/kind/arch/sha，kind 区分 base / stage / stage-classic / resource，stage 允许 N 行与 order。由论文 B 车道主人在 ujs/ 内接入其 nn 集；unisacc 侧只提供合同与模板，不改 ujs/。 |
| C45-STAGEBENCH-01 | **单流测试台**（并入 B2） | lab-loader L1 已让 7 个单流产物与整条流水线对应段逐字节相同（5.6 倍去重）；p3-swap 可单换一张网。把它整理成正式的单流单元测试层（stream-unit）：改一张网只重跑该流及其下游。 |
| C45-CX-OWN-C-01 | **编译期所有权检查（路线 C，spec CX-W-4/CX-W-8）** | 依据 C44-CX-OWN-01 的测量：函数内文本分析覆盖不到产品所有权。设计：E3 先产出带类型的控制流 IR（基本块、place/字段投影、借用、作用域终结、源码位置），CXIF 增所有权/效果字段做跨函数摘要；每条 IR 操作的抽象状态转移声明为表并构造成网，由通用执行器做工作队列与不动点。先量拒绝率与注解成本再定检查范围。会改产品字节与身份，走慢车道。 |
| C45-NAME-01 | **范式命名**（待主人定） | 候选：表网（Table-Net；方法名 Table-Constructed Networks，英文缩写 TCN 与"时间卷积网络"撞名，对外用全称）、构网（Constructed Neural Logic）、流网（与 2015 年光流 CNN FlowNet 撞名）。建议：方法 = 表网，单件 = 一张表网，执行器 = 统一核 UNIKERN，编译器流水线 = 表网流。定名后同步 `docs/glossary.md`、prd §0 并全仓统一。 |
| C45-MATERIALIZE-01 | **ISA 切片由模型推导出来，不再随包携带**（2026-11-03 主人提出） | 思路：包里只带一份与架构无关的编译器 tape（e4/prune 之后），每个 ISA 只带一个小核心段（C45-LOADER-01）；首次运行时由核心段跑包里已有的 lower/elf 两个流，把 tape 物化成本机的原生编译器，按（tape sha, 目标）缓存。理论依据：① lower/elf 本来就从同一份 tape 写出六个目标；② 实测 `unisacc.com t3.tape -b lnx/x86_64 -o a` 与直接编 `t3.c` 的产物逐字节相同，同一 tape 换 `-b lnx/arm64` 得到 aarch64 ELF；③ N22 两代自举逐字节相同，说明物化结果可以在发布时为每个目标预先算出 sha 写进 manifest，运行时校验后才 exec。体积：替换掉 win 头 1,592,832B 与四个 Unix 片约 998KB（gzip），换成一份 tape（未测，待实验）+ 五个核心段（目标 30–60KB/个）；与头文件压缩叠加有望进入 2MB 以内。风险：首次物化耗时（按现有 elf 速度估计为数秒，需缓存且随 SPEED 下降）；缓存目录不可写时的退路；macOS arm64 需签名（产品已写 ad-hoc 签名）；Windows 头仍须是可直接执行的 PE 核心段；编译器现为 43 对象链接、整程序 `-S` 不通（与 C44-UNITOK2-CAP 同根），需先能产出整编译器 tape。先做实验（lab-loader L6）再定。 |

与0.0.44的关系：0.0.44改进`.cx`语言／工具链的模块化及内存安全；本版进一步把编译器的流与网能力作为共享工具模块开放。后续排程基于已实现事实细化，思维树与记忆宫殿随状态变化原位更新。
