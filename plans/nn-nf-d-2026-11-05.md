# NN-NF-D 设计细化：数据写成代码 → S 行数据 + 网内解码循环（督导 2026-11-05）

依据：HEAD 28417627fc 冷跑 ctx（out/cT）42 张网实测；执行器 cx/core/execute.cx；不改执行器元数。

## 1. 现状实测（一次性启动段）

Q 行（动作序列）里长度 ≥64 且 LDI/STX/SBOUT/CORE_OUT 占比 >80% 的"数据写成代码"段：**963 段、共 197876 个动作**。
最大的是 START 段：

| 网 | 动作数 | 数据占比 | 组成 |
|---|---|---|---|
| shared-e3 / errorparse / warnparse | 15466 ×3 | 0.97 | LDI 8883、STX 4527、SBOUT 1608、SBINTERN 223 |
| shared-e4 | 5954 | 0.97 | LDI 3434、STX 1799、SBOUT 515 |
| 各 arm64 elf/object-enc（6 张） | 2110 ×6 | 0.82 | — |

e3 族 START 的前段就是 `exec/facts/k2-gen2.tsv` 的 `tyrows`（`exec/parse2/gen2-manifest.tsv:104` 的 mapseq，每行 `LDI t;LDI u;STX t tab u`）：
4352 行 = 13056 个动作。其中 tab ∈ {30000000(256 行), 31000000(4096 行)}，t 在各自表内**稠密连续**（0..255 / 0..4095），u ∈ {3,4,7,8,9,13,14,15}，全 <16。

按 netwire 的 zigzag varint 计，tyrows 这一段现编码 **69504 B/网**，三张 e3 族网共约 **208 KB**。

## 2. 解码格式（tyrows）

稠密表，每格一字节：
- S 行 `TY30`：256 字节，第 t 字节 = u（t=0..255）。
- S 行 `TY31`：4096 字节，同上。
- 可选 nibble 打包（u<16）：2048+128 字节；多一次 DIVMOD/ALUI，先不做，留给测量。

估算：两行 S 共 4352 B + 两段循环约 120 B ≈ **4.5 KB/网，省约 65 KB/网（-94%）**；三张 e3 族网合计约 -195 KB。

## 3. 网内解码循环（不改执行器）

现执行器能读 S 行的只有 `REJECT`（execute.cx:174 `result->reason=m->str[a[1]]`），**没有"S 行→blob"原语**。不改执行器时可行的两条路：

A. **资源路**：`SBCLR; SBOUT 'T' 'Y' '3' '1'; SBFIND r_blob`（execute.cx:164 → core_resource_find → core_host_fetch 取包内资源成 blob，cx/core/bytes.cx:32），再 `INPUSH r_blob`（:154，把 blob 当输入帧），循环体 `CORE_BYTE u; STX t tab u; ALUI add t t 1; ADV; CMPI t N; JUMP`，最后 `INPOP`。
   数据完全出网，进 P3 资源；网里只剩约 20 个动作。代价：包内多两条资源、启动时一次 host fetch。
B. **OUT→blob 路**：`SBCLR; SBOUT×N; SBSAVE r_blob; INPUSH r_blob` 再同一循环。
   SBOUT 每字节仍是一个动作（op 38 + 1 参，约 2–3 B/字节），只把 3 个动作/行压到 1 个，约 -60%，不如 A；这正是 NN-NF-C（长 OUT 序列→S+SBBLOB）要解决的，C 落地后 B 自然变成 A 的形态。

**选 A**（若 C 先落地，则改用 C 的 S→blob 原语，同一循环体不变）。需确认：①P3 资源键空间里放网私有数据是否合规（键前缀建议 `\0net/<网名>/TY31`，与 `\0hdr/` 同级）；②core_host_fetch 在 e3 启动时可用（产品路径是 ex_ri_fetch→hs_cli→rescache_fetch，src/host.cx:245）。

## 4. 等价判据

- 动作语义等价：解码前后 `memory` 中 tab+t 地址的值逐格相同。不能直接 cmp 网字节（网字节本身就变了），改为：
  ① 生成器 `--check`：由 tyrows 事实同时产出旧展开与新 S 行，断言 S 行第 t 字节 == 旧展开里 (tab,t) 的 u；
  ② 产物等价：同 rev 同输入（65/72 源夹具 + 单源）`-S` / `-o` 产物 cmp 相同；
  ③ T1（网==表）照跑。
- 字节差报告：每张受影响网的 result.net 字节前后、pkg 字节前后。

## 5. 启动相位耗时（实测，已装产品 928e3350，单源 `int main(void){return 0;}`，UNISACC_PROFILE=1，三次）

| 阶段 | ms |
|---|---|
| e2 | 2.18 / 2.23 / 2.79 |
| e1 | 0.15 / 0.21 / 0.22 |
| e3 | 3.30 / 3.80 / 3.36 |
| tapecheck | 0.12 / 0.13 / 0.16 |

整次 `-S` 墙钟 169–360 ms，模型执行 ~6 ms，其余是装载/解码/进程启动——**START 段 13056 动作在 e3 的 3.3 ms 里**。改后需同法复测：e3 应持平或下降（循环 4352 次 vs 直线 13056 动作），并加测装载（包解码）耗时，资源路多一次 host fetch。

## 6. 推广顺序

1) e3 族 tyrows（三网同一事实，一个生成器改动）；2) shared-e4 START；3) arm64 elf/object-enc 的 0.82 段（需先看是否同构）；4) lower/elf/e4 init、prune INIT（cc 指定随 D 一起）。每步一家族一提交，同 rev 报字节差。

## 7. cc 裁定（2026-11-05）

1. **不用 P3 资源键放网私有数据**：网的数据跟网走，否则网与资源成两处身份。§3 的 A 路作废。
2. **等 NN-NF-C 的 S→blob**；若 C 证明需要新原语，加一个最小原语（同意动执行器元数，六目标内核同步）。D 的循环体（§3）不变，只把数据源换成该原语产出的 blob。
3. 等价口径同意：生成器 `--check` 逐格、同 rev 产物 cmp、T1。

D 的实现因此依赖 C；在 C 落地前 D 只保留本设计与 §1/§5 的基线数字。
