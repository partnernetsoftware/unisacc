## 进入字节码试点前的决策门

1. 先确认资源错误可恢复、调用返回后的所有权，以及输入/输出属性表示合同；未经此门不把大状态编译逻辑直接搬进VM。
2. 测试矩阵至少包含空输入、长度边界、每类容器扩容、每个分配点失败、步数超限与取消；CX和两ISA核比较状态、reason、stdout/stderr及分配计数。现有`exec/c/asm/runcheck.c:12,53`的分配记账可复用，但本轮未执行这些测试。
3. 现有`CORE-INPUT-MEMORY-OOM`仍未修；`VM-BYTECODE-SLICE`完整实现/收益测量未启动。模型解码nrg上界、stack汇编容量保护、arm64全路径、XATTR/SETOT生产实际使用列为未证明，不能以本清单关闭。

## M10b 资源 API 合同设计（冻结候审；未实现、未执行）

本节只定义失败合同及可证伪实验，不修实现、不关闭上表缺口。L2 已推迟至 0.0.48；本节不是 VM 迁移承诺。下文新增状态、控制块、计数器与命令均为设计，不代表现有入口可运行。

### 源级核实与可复用边界

- 产品路径为 `cx/sys/kernel.cx:3-13,126-130`：`core_run` 将七项参数交给映射的 UNIKERN1；不是 CX 参考实现。服务表 `:31-42` 只有 calloc/realloc/free、字节原语、fetch、panic，没有取消/时钟服务。映射 `:108-115` 为进程生命周期；计数必须在预加载之后、每次调用开始时归零，不能把映射常驻误计为调用泄漏。
- CX 参考 `cx/core/execute.cx:188-202` 先分配寄存器、blob，再执行 `calloc(inputn+1,sizeof(I))`；`:54-55` 的 realloc 失败走 fatal panic。`cx/core/output.cx:7-10` 先更新 cap，再分别扩字节/属性，失败恢复不能仅给 panic 换成 return：须保留可清理的旧 owner，第二次扩容失败也要释放第一次已成功的 owner。
- x86_64 `exec/c/asm/run_x86_64.S:47-79,250-253`、arm64 `run_arm64.S:49-81,255-264` 同样初始化并 fatal panic；两边以 32 位加一后传分配器，不能以机器回绕代替 CX 有符号检查。正常输出转移及清理见 CX `:240-252`、x86_64 `:170-201`、arm64 `:178-190`。
- C ABI `exec/c/core.h:37-54`：fetch 返回 absent=0 / borrowed=1 / malloc-owned=2；panic 不返回；输入、模型借用。宿主 `src/host.cx:205-208` 直接 exit；`:249-276` 实际 fetch 还经过宿主资源路由。`hs_ns`（`:199-202`）存在不等于核已支持 deadline；`hs_alloc`（`:189-192`）也不是核分配服务的计数器。
- 可复用 `exec/c/asm/runcheck.c:12-26,52-69,93-106` 的移动分配 ledger、借用输入校验、输出释放及多 owner 动作模型。现有 `fail_at` 仅计 calloc，不计 realloc；realloc 用 malloc 并 assert 成功；`:27-30,74-76` 仅允许初始第 1/2 次 calloc 失败、允许剩余 owner 后 exit(2)。它能证明 fatal 负例，不能证明逐分配点恢复。现有 `call` 允许返回的 out/err 两个 owner，不能把它的断言直接写作返回即 live=0。

### 先冻结的最小 ABI / 返回状态

保留现有 0=accept、1=reject、2=transition failure、3=transition budget（reason `timeout`）语义；拟新增 4=resource failure、5=cancelled、6=deadline。资源 reason 为固定借用静态字符串 `out of memory` / `length overflow`；取消为 `cancelled`，墙钟为 `deadline exceeded`；新增非 reject 状态 `reason_n=0`，与已有 reject 的模型字符串长度区别。诊断由调用者渲染，核不打印 stdout/stderr、不 exit；OOM 不能伪装成 reject/timeout。CX、两 ISA、产品 sys.kernel 必须返回同一状态、reason 字节和输出所有权。

拟在所有 core_run 调用方同步迁移一次显式版本化资源控制块（无旧入口兼容 shim）：含取消查询、单调时钟/deadline、宿主上下文；同步修改 C/CX 声明、两 ISA 参数/布局及 UNIKERN1 服务协议和装载版本核验，旧 blob 必须明确拒绝而非错读。具体布局须实现前定稿，本设计不假称已有此 ABI。分配仍走当前分配服务，但须把失败从每个 helper/动作传播到统一 unwind；不得让 panic longjmp 穿过半更新 owner。fetch 的 0/1/2 不能表达资源/取消失败，须增设明确负状态并约定失败输出置空，接收 owned 指针后立即登记 owner；借用数据不得释放。同步宿主路由，不只改参考核。

4/5/6 一律丢弃本次 out/err 字节和属性（包括此前动作写入的诊断），结果两个 Buf 全零；因此返回时活跃调用分配=0，调用者无结果释放义务。0/1/2/3 保持现有输出政策：仅 0 转移 out，均可转移 err，仅字节归调用者；释放结果后 live=0。reason 不归调用者释放。所有路径释放寄存器、属性、嵌套帧/owned SWAP 输入、栈、稀疏内存、intern/blob/resource 缓存及半成品；模型/原输入/fetch borrowed 不变。清理不得再分配，不得因已取消而跳过。宿主加载/永久缓存单列基线，不能靠过滤未登记 owner 得出零。

### 注入一：逐分配点 OOM

最小载体复用 runcheck 的 owner 模型，先无故障完整跑一遍，记录有序分配请求数 N；把所有 calloc 与 realloc（含 NULL realloc、字节/属性分开扩容、host-owned fetch 分配）统一为一个每调用计数序列。第 k 次请求前 `attempts++`，`fail_after=k-1` 时只该次返回 NULL，realloc 失败不释放/改写旧块；free 不计入序列。对 k=1..N 逐项独立调用，不能只扫两次 calloc。无故障执行未覆盖的扩容分支，以最小专用模型分别触发并重复各自序列；每个分配点/分支须列事件 ID 和覆盖记录，不能拿一次模型的 N 宣称覆盖全部容器。

每个 k 必须返回 4/`out of memory`，out/err 全零、live=0、借用输入/模型哨兵未变、owned 资源恰释放一次；然后在**同一进程**关闭故障，运行固定小型合法 accept，比较输出及状态，释放结果后 live=0。对最后一次请求后 `fail_after=N` 的负控必须正常成功；禁用故障的移动 allocator 必须保持正常输出/属性语义。现有 fatal 子进程 exit(2) 只作改造前负控；若改造后仍触发 panic、signal、watchdog 或进程退出即失败，不能计恢复通过。ledger 需支持超过现有 128 槽的情形或让夹具显式限制模型规模，不得 ledger 自身 OOM 冒充被测点。

### 注入二：长度加一与乘法溢出

最小外部调用使用合法小模型、有效短 src、不可读保护页作为 input，分别传 `inputn=-1` 与 `INT_MAX`；要求在 input/src/model 内容读取及任何调用分配之前完成长度预检，返回 4/`length overflow`，分配尝试/输入读取/动作/transition/fetch 计数均为 0，结果全零、live=0。这里“读取 0”专指载荷访问；读取长度实参及合法的控制元数据不计。不能先创建寄存器/blob 再拒绝，也不能真的分配 INT_MAX 大缓冲。正常长度的保护页不是合法负控：应换有效单字节输入，证明接受输出及计数非零。

64 位两 ISA 的 int inputn 经合法加一后乘 8 本身达不到 SIZE_MAX 溢出，故不得伪称 `INT_MAX` 覆盖 size_t 乘法溢出。拟抽出实际分配必经的 checked_extent(count, extra, width, limit) 内部算术原语，测试入口只调用同一原语（不分配、不解引用）；以 `(SIZE_MAX,1,8)` 验加法，以 `(SIZE_MAX/8+1,0,8)` 验乘法，以 `(SIZE_MAX/8,0,8)` 验恰好可表示，另验 ABI 容量上限 INT_MAX 与宿主 long 上限。前两项必须拒绝且 allocator attempts=0；边界可表示项只返回计算结果，不进行大分配。对 inputn 使用更严格的 int 加一上限 INT_MAX-1；所有容器容量增长、nrg+1、元素乘宽和转 long/int 均使用相同前置检查思想，但不扩大本最小实验为未完成的全容器审计。若只复制一个测试算术函数而产品不走它，验收失败。

### 注入三：长期动作内取消 / 墙钟

现有 maxsteps 只能在 transition 前检查（CX `:212-217,235-238`；两 ISA run loop 同类），不能阻止一个动作内长循环。最小载体为单 transition 的 `ORES r0,65536; ACCEPT`（CX `execute.cx:135` 为逐字节循环；另见 SPAN `:123-128`、OFILL/output `:16-19`），使用 64KiB 输出而非巨额内存，maxsteps=1；拟固定 B=256，在 ORES 内第 2 个块边界触发，确保动作发生部分写入且未完成。实现必须使用有界小块处理并在动作内每至多 B 个处理字节/元素检查取消/deadline。只在动作前后检查或直接一次超长 libc 调用均不合格；需同时覆盖 transition 查询、长扫描/复制、清理前边界。阻塞 fetch/宿主 I/O 必须支持同一取消/deadline，或明确不进入该可恢复合同且不能用它声称墙钟有界。

确定性注入用查询次数触发器：进入目标动作并产生部分内部写入后，第 j 次 poll 返回取消；返回 5/`cancelled`，动作未到终点、poll/event 计数证明在动作内部停止，out/err 全零、live=0；同进程清除控制后小型合法调用成功。墙钟同一模型用假单调时钟，在动作内第 j 次查询越过 deadline，返回 6/`deadline exceeded` 并满足同样清理。负控为永不取消/未到期时同模型正常完成且输出等于基线；maxsteps=0 仍只得到旧状态 3，不能当取消证据。真实单调时钟另验从截止到返回不超过“一个 B 块最坏耗时+一次查询+清理”所声明界限；若动作块/宿主调用无可证明耗时界限，不承诺硬实时。外部 watchdog 仅为测试隔离保险，杀进程一律本用例失败，不是可恢复取消成功。

### 四路验收与命令草案

矩阵为 CX 参考 × {x86_64,arm64} 及实际产品 sys.kernel × {x86_64,arm64}；对象级 C/ASM runcheck 只作局部证据，不能替代产品携带 blob、kn_service 与真实宿主 callbacks。每路记录源码/核身份、ABI 版本、状态/reason/reason_n、out/err 原始字节与 owner 数、alloc/free/poll/动作事件；资源失败三个方案逐项一致，正常对照保持既有输出政策。arm64 必须真实执行或明确标模拟环境；未跑平台不判通过。计数只覆盖 core invocation；产品预加载、模型构造、测试 ledger 自身隔离并列明，host fetch owned 分配必须纳入而非漏记。

以下是**待实现测试入口的精确 CLI 合同草案，不是现有可运行命令**；`resourcecheck`、`--resource-check`、`--backend`、`--fail-after` 等目前不存在，本轮不执行。实现者须让入口直接驱动上述 ABI 与真实产品路径，不得写只返回预设状态的测试替身。`--all-points` 内部完成无故障计数、k=1..N 和 N+1 负控；`--same-process-recovery` 禁止每次 fork 替代恢复。

```sh
# 拟新增局部入口：在对应 ISA 的执行环境中运行同一组命令。
./resourcecheck --backend=cx-reference --case=oom --all-points --same-process-recovery
./resourcecheck --backend=asm --case=oom --all-points --same-process-recovery
./resourcecheck --backend=cx-reference --case=length --no-large-allocation
./resourcecheck --backend=asm --case=length --no-large-allocation
./resourcecheck --backend=cx-reference --case=cancel-deadline --same-process-recovery
./resourcecheck --backend=asm --case=cancel-deadline --same-process-recovery
# 拟新增产品集成入口：每个 ISA 均运行；禁止回落 CX。
./unisacc --resource-check=oom --backend=sys.kernel --all-points --same-process-recovery
./unisacc --resource-check=length --backend=sys.kernel --no-large-allocation
./unisacc --resource-check=cancel-deadline --backend=sys.kernel --same-process-recovery
```
