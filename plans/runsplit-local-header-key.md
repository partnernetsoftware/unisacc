# UNISACC_RUN_SPLIT 同目录头缓存失效修复稿

## 1. 问题描述与复现原行
- `UNISACC_RUN_SPLIT` 默认关闭，不影响默认产品路径；但在显式开启 `UNISACC_RUN_SPLIT=1` 时，修改源内 `#include "local.h"` 的同目录头文件内容会命中旧对象缓存。
- 实测复现原行（`local.h` 从 `#define VAL 11` 改为 `#define VAL 22`，同一 `XDG_CACHE_HOME`）：
  - `R1: VAL=11`（`R1=0`）
  - `R2: VAL=11`（`R2=0`，预期 `VAL=22`，实际命中旧对象）

## 2. 根因
- `cx/driver/runsplit.cx:358-359` 调用 `uo_key` 计算用户单元缓存键时，仅纳入了单元源字节与 `.cx` 强制接口头摘要，未扫描并纳入源内 `#include "..."` 所引用的同目录头文件内容摘要。

## 3. 修复方案
1. **方案 1（推荐，精准纳入键）**：在 `cx/driver/runsplit.cx` 为每个单元增加轻量引号头扫描（含传递 `#include "..."`），将解析到的同目录头路径与内容 `sha256` 摘要追加到 `uo_key` 的输入中；若遇到无法静态解析的宏包含或超过上限，则安全回退整程序路径。
2. **方案 2（保守兜底）**：单元源码中出现任意 `#include "..."` 时直接回退整程序路径。

## 4. 验收夹具
- 新增两单元 + 同目录 `local.h` 夹具：首轮 `VAL 11` 运行输出 `VAL=11`，原地改 `local.h` 为 `VAL 22` 后同缓存目录重跑必须输出 `VAL=22`（先红后绿）。
