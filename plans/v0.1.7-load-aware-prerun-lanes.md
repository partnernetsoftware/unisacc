# v0.1.7 负载感知 prerun 并发车道调度设计 (Load-Aware Prerun Lanes)

- 适用对象: `tools/prerun-drive.cx` (`pd_cmd_run` 窗口波次调度) 与 `tools/check-prerun-drive.cx`
- 状态声明: `DESIGN_ONLY` (`v0.1.5` 冻结与预跑收尾期间纯静态设计与先红测试计划, 未修改任何源码, 未运行编译、冷测试、生成器或批次; 运行态项全部保持 `UNMEASURED / UNCOVERED`)

---

## (1) 现状问题、实测锚点与政策边界

1. **现行静态车道缺陷 (`tools/prerun-drive.cx`)**:
   - `pd_cmd_run` (`tools/prerun-drive.cx:1744-1889`) 从 `--window-lanes 1..8` 或 `windows.tsv` 头 `# window-lanes=4` 读取固定宽度 `lanes` (`PD_DEFAULT_LANES=4`, `PD_MAX_LANES=8`, `:33-34`);
   - 每次波次拉起 (`while (queued < lanes)`, `:1856-1889`) 完全不读取在线核数 (`nproc`) 与 `/proc/loadavg`;
   - 波次中一旦出现 `rc=124` (超过 `PD_CHILD_SECONDS=58` 秒), 仅对当前单个 timed 窗口写入 `serial.<wid>` 退回单窗串行 (`:2031-2038`), 下一波次仍以满宽 `lanes` 并发冲入, 在主机高负载时诱发连锁超时雪崩。
2. **2026-11-27 实测锚点 (16 核主机)**:
   - 3 车道稳态下 `load1 ~= 2.6`, 运行平稳且留有充足余量;
   - 当主机负载爬升至 `load1 > 20` 时, 58s 窗口硬限开始频繁触发 `rc=124` 超时。
3. **不违背 2026-11-20 负载门禁退役裁定**:
   - `tools/prerun-drive.cx:7,1890,3199` 与 `tools/cxlib/loadavg.cx:4-6` 退役的是会阻塞、休眠干等或直接拒跑的 `--load-cap` 门禁;
   - 本设计**绝不阻塞、绝不 sleep 等待、绝不拒跑**, 始终保证有效车道数 `1 <= eff_lanes <= lane_cap <= PD_MAX_LANES (8)`, 仅在每波次开启多少条并发窗口车道上做有界自适应收敛。

## (2) 安全核数与负载读取设计

1. **在线核数 `pd_detect_ncpu()` (零子进程、无平台宏)**:
   - 沿用 `tools/cxlib/flowadmit.cx:76-80` 做法, 直接经 `sy_read_file("/proc/stat", ...)` 统计以 `cpu[0-9]` 开头的行数, 避免启动 `nproc` 子进程带来的 5s 超时与额外进程开销;
   - 文件不可读或统计结果 `<= 0` 时, 保守回落为 `1` (fail-safe, 不猜大核数)。
2. **一分钟负载 `pd_read_load1()`**:
   - 直接引入 `#pragma unisa use cxlib.loadavg`, 调用 `tool_load1_at(path)` (`tools/cxlib/loadavg.cx:12-17`);
   - 默认路径 `/proc/loadavg`; 不可读时 `tool_load1_at` 返回 `TOOL_LOAD1_UNREADABLE (99.0)`, 自动落入高负载保护档 (`load_lanes = 1`)。
3. **离线单测注入缝 (不影响生产默认路径)**:
   - `PRERUN_TEST_NCPU`: 仅当为 `[1, 1024]` 正整数时覆盖 `pd_detect_ncpu()`, 否则忽略;
   - `PRERUN_TEST_LOADAVG`: 非空时作为 `tool_load1_at()` 路径参数, 便于单测在波次之间原地更新文件内容以确定性复现负载尖峰与回落。

## (3) 车道宽度公式、硬上限与 `rc=124` 退避状态机

### 3.1 参数与硬上限

- `lane_cap`: 显式硬上限, 取自 `--window-lanes 1..8` (未指定则取 `windows.tsv` `# window-lanes=`, 旧计划默认 `1`), 严格夹紧到 `[1, PD_MAX_LANES]` (`PD_MAX_LANES = 8`)。
- `cpu_cap`: 核数安全上限, `cpu_cap = clamp(ncpu / 2, 1, PD_MAX_LANES)` (每条窗口车道预留 2 核突发编译与链接余量; 16 核 -> `8`, 8 核 -> `4`, 4 核 -> `2`, 1-3 核 -> `1`)。
- 负载水位常数 (相对 `ncpu` 自动缩放, 不写死单机魔法数):
  - `headroom_target = 1.0 * (double)ncpu` (16 核下 = `16.0`, 距 `~20` 超时拐点保留 `4.0` 缓冲带);
  - `surge_cutoff = 1.25 * (double)ncpu` (16 核下 = `20.0`, 精准对齐实测超时拐点);
  - `recover_cutoff = 0.75 * (double)ncpu` (16 核下 = `12.0`, 退避后仅在负载回落至此水位以下才允许试探性恢复);
  - `per_extra_lane_load = 3.0` (每多开 1 条额外车道须具备至少 `3.0` 核空闲余量)。

### 3.2 负载建议车道 `load_lanes`

```
if (load1 >= surge_cutoff || load1 >= headroom_target) {
    load_lanes = 1;
} else {
    double avail = headroom_target - load1;
    int extra = (int)(avail / 3.0);
    load_lanes = 1 + extra;
    if (load_lanes > cpu_cap) load_lanes = cpu_cap;
    if (load_lanes < 1) load_lanes = 1;
}
```

典型工作点核验:

| 场景 | `ncpu` | `load1` | `lane_cap` | `cpu_cap` | `load_lanes` | 最终 `eff_lanes` (无退避) |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| 今日实测 (3 车道) | 16 | 2.6 | 3 | 8 | 5 | 3 |
| 低负载默认计划 | 16 | 2.6 | 4 | 8 | 5 | 4 |
| 低负载大上限保护 | 16 | 2.6 | 8 | 8 | 5 | 5 (不无脑冲满 8) |
| 中负载 | 16 | 8.0 | 8 | 8 | 3 | 3 |
| 偏高负载 | 16 | 12.0 | 8 | 8 | 2 | 2 |
| 预警水位 | 16 | 16.0 | 4 | 8 | 1 | 1 |
| 超时拐点以上 | 16 | 20.5 | 4 | 8 | 1 | 1 |
| `/proc/loadavg` 不可读 | 16 | 99.0 | 4 | 8 | 1 | 1 |
| 4 核小机空载 | 4 | 0.5 | 8 | 2 | 2 | 2 |

### 3.3 `rc=124` 退避与受控恢复 (AIMD 状态机)

在 `pd_cmd_run` 主循环外维护波次级状态:
- `int backoff_cap = lane_cap;` (范围 `[1, lane_cap]`)
- `int clean_waves = 0;` (自上次 `rc=124` 起连续零超时的完整波次数)
- `#define PD_BACKOFF_COOLDOWN_WAVES 2`

每波次调度与收尾规则:
1. **波次前选宽 (`pd_select_wave_lanes`)**:
   - `eff_lanes = min(lane_cap, cpu_cap, load_lanes, backoff_cap)`, 强制 `eff_lanes >= 1`;
   - 用 `eff_lanes` 替换 `tools/prerun-drive.cx:1856,1861` 的静态 `lanes`;
   - 每当准备拉起可共享窗口时打印机读记录行:
     `PRERUN_LANE_SELECT\tfirst=%s\teff=%d\tcap=%d\tcpu_cap=%d\tload_lanes=%d\tbackoff_cap=%d\tload1=%.2f\tncpu=%d\n`
2. **命中 `rc=124` 立即乘性降宽**:
   - 波次内 (含 `pd_first_attempts` 首跑或当前窗口重试) 只要出现任一 `rc == 124`:
     - `int prev_eff = wave_eff_lanes;`
     - `int next_cap = prev_eff / 2; if (next_cap < 1) next_cap = 1;`
     - `if (next_cap < backoff_cap) backoff_cap = next_cap;`
     - `clean_waves = 0;`
     - 打印: `PRERUN_LANE_BACKOFF\tfirst=%s\treason=timeout-124\tprev=%d\tnew_cap=%d\tload1=%.2f\tncpu=%d\n`
   - 保留既有单窗 `:2031-2038` `PRERUN_RECOVER` (`from_jobs -> to_jobs=1`) 串行恢复逻辑不变, 两者正交互补 (单窗内降 `jobs=1`, 跨波次降 `backoff_cap`).
3. **冷静期后受控加性恢复**:
   - 若整个波次 (全部窗口) 均无 `rc=124` 且最终 `rc == 0`, 且 `backoff_cap < lane_cap`:
     - `clean_waves++`;
     - 当 `clean_waves >= PD_BACKOFF_COOLDOWN_WAVES` (2) 且当前 `load1 < recover_cutoff` (`0.75 * ncpu`):
       - `backoff_cap++`; `clean_waves = 0`;
       - 打印: `PRERUN_LANE_RECOVER\tfirst=%s\tnew_cap=%d\tload1=%.2f\tncpu=%d\n`
   - 若波次出现非 `124` 错误 (`rc != 0`), 不降 `backoff_cap` 也不累加 `clean_waves` (产品红与负载退避职责分离)。

### 3.4 CLI 兼容与回退开关

- 新增可选参数 `--window-lanes-mode auto|fixed` (默认 `auto`):
  - `auto`: 启用上述负载感知与 `rc=124` 退避逻辑, 受 `--window-lanes 1..8` 显式上限约束;
  - `fixed`: 保持原有静态 `lanes` 行为 (供对照测量与老用例显式固定宽度);
  - 非法值: `pd_refuse("invalid-window-lanes-mode")` 并返回 `rc=2`。
- `--load-cap` 保持现状: 仅打 `PRERUN_DEPRECATED` 忽略, 不恢复阻塞式门禁。
