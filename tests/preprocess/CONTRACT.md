# CX0 / E2 独立测试件合同

状态：2026-10-28 设计合同。独立套件尚未实现，下面的映射不读取旧日志当本次 PASS。它是 `plans/v0.0.43-units.md` 的 U1/U2 验收输入。

目标：从源码与模块供给得到明确的逐单元预处理结果，不依赖 E3/优化/后端碰巧接受来判断 CX0/E2 是否正确。独立套件必须有单合同选择、完整合同列表、缺口报告和有界分批执行，复用既有看门狗/执行会话设施；不再写一套候选收据解析器。

## 1. 三层责任

| 测试层 | 输入 → 输出 | 判断什么 |
|---|---|---|
| CX0 单元 | 明确源字节/模块供给/选项 → 版本化单元束或具名拒绝 | 模块身份、依赖、公开接口、逐单元前奏与确定性 |
| E2 单元 | 一个明确单元及资源 → UNIPP1 或具名拒绝 | C 预处理正文、位置、包含与状态清理 |
| 边界集成 | CX0 单元束 → 每单元 E2 输出 | 计划被真实消费、模块间无泄漏、映射及错误归属 |

产品编译运行只能作附加集成观察；预处理主 oracle 直接比较上述边界。重构前/后字节对照只作兼容性证据，不能取代手写 gold、规则来源及独立读取器。

## 2. CX0 必选合同组

| ID | 正例/边界 | 反例与拒绝/恢复 |
|---|---|---|
| cx0.identity | 单模块、目录模块、显式 C/CX 混合输入与逻辑名 | 缺文件、目录当文件、ENOTDIR/EACCES、身份冲突；不能一概当 ENOENT |
| cx0.lexical | 注释/字符串中的伪 pragma 不形成依赖；真实声明的位置明确 | 未支持版次/错误拼写/畸形声明按现行或显式新增合同拒绝 |
| cx0.graph | 链、分叉、菱形依赖去重、多个根、稳定顺序 | 循环、自依赖、缺模块、超限及错误后同进程恢复 |
| cx0.conditions | 明确依赖声明是否允许在条件区；选项与版次进入身份 | 宏/条件不能静默制造未声明依赖；先核现行行为再冻结精确 gold |
| cx0.interface | 公开原型/类型、私有 static 助手、直接/传递可见范围 | 公开名冲突、非法导出、漏类型、私有名字越界访问 |
| cx0.prelude | 每单元自动前奏、命令行强制头和接口输入有序 | 缺/错版接口、单元串用他人接口、重复/坏资源记录 |
| cx0.protocol | 手写最小/多单元记录，独立读写核字段与完整长度 | 截断、尾随、重复 ID、错目标/ABI、非法资源引用、整数/数量边界 |
| cx0.state | 重复调用一致，两个实例独立，拒绝后恢复 | 前次路径/依赖/符号/诊断不污染后次；拒绝不提交成功束 |

边界上的函数错误/参数数量也须具名核验；现有工具链若未实现检查，记录最小复现与 NEEDS_PRODUCT_CHANGE，不以运行碰巧成功代替静态保证。

## 3. E2 必选合同组

既有 `tests/stream-e2-domain-matrix.tsv` 的全部必选格保留，现有 62 个本机格是现阶段合同清单的基线，不代表穷尽 C99 的任意组合。新增需求必须有规范来源，缺实现的组合保留明确拒绝或未覆盖。

- 文本：空输入、LF/CRLF 续行、注释、字面量保护、字节长度和位置。
- 宏：对象/函数/变参宏、重扫/递归屏蔽、字符串化、已支持拼接、UCN 身份及原始拼写；参数/容量边界。
- 条件：嵌套、defined、表达式和短路、有效/无效分支、指令不平衡及恢复。
- 包含：引号/尖括号、有序搜索、嵌套/重复/guard、强制与自动头、缺失/空资源、读取错误归属。
- 环境：目标预定义宏、按顺序 -D/-U/-I/-include/-nostdinc；目标显式，宿主不隐式选语言语义。
- pragma：既有 pack/宏栈语义及未知指令策略；CX 模块控制行在适配后按合同消费，不重复规划。
- 输出：完整 UNIPP1 头、正文长度、续行与包含记录、强制/自动计数、原文件/行列。
- RI/资源：存在/空/缺失、跨单元和输入身份、有界失败、拒绝不提交输出及错误后恢复。

完整套件须分别报告“本机全合同”“目标写出/观察”“外国原生宿主”。未运行外国宿主不能令完整 all-six 合格；也不能因此隐藏已完成的本机合同。

## 4. 边界集成必选合同组

1. 单个 `.cx` 的隐式前奏在 E2 正文和区域计数里实际出现；源文件自身无手写 include。
2. 一个模块调用私有 static 助手；消费者只看到公开声明且 E2 输入准确，不直接重放提供者私有正文。
3. 菱形依赖不重复构造单元；每个单元看到规定的直接接口和传递类型。
4. 两单元同名宏/include guard/static 标识符相互隔离；缺接口与公开冲突归 CX0，坏宏/头归 E2。
5. 普通 `.c` 与混合 `.c/.cx` 的选项/前奏规则保持；原本明确拒绝的多单元 `-E` 不因内部束协议就冒称 CLI 已支持。
6. CX0 拒绝后 E2 不执行；E2 某单元拒绝后不发布整束成功，保持原诊断位置。
7. 计划封存后改活模块：按不可变字节继续或在身份核对时拒绝；禁止同一计划偷偷消费新实现。
8. 更换工作目录、模块提供顺序和两次实例运行：按合同比较稳定字段和源位置；绝对临时路径不污染规范输出。
9. 缓存命中仍核实际输入/接口/目标；私有实现变更与公开接口变更分别按包级依赖传播，不复用测试结果。
10. 完成一次产品正式接入：新驱动只适配参数、调用 CX0、逐单元调用 E2；旧 cxm 隐式规划不能继续作为第二套写路径。
11. 同一 CX0 计划交 unisacc 与 grk 所有的 GCC/Clang 适配器：公开声明、单元/依赖顺序和隔离相同；用独立 gold 核运行与拒绝，不要求跨编译器机器码相同。不支持的目标/协议具名拒绝，尚未交付/不可用的消费者记未实现/未运行。

## 6. 独立入口与合格条件

入口在第一实现提交固定，必须支持：列全合同、选单合同、选择 CX0/E2/边界组、在已封存的同候选会话中分批执行并聚合。每条命令及其后代最多 60 秒，不要求把完整套件塞进一次进程；编译/制备与测试执行分开计时，不缓存测试结论。

每个必选合同至少记录 ID、输入/资源、独立预期及来源、实际输出/退出/诊断、被测包及构造工具身份、目标和宿主。成功、明确拒绝、未覆盖、未实现、未运行与超时分别汇总。只要有必选合同缺证据，完整入口非零。

U1 完成要求 CX0 独立合同与畸形束读取拒绝齐全；U2 完成要求原 E2 合同、所有新增边界合同和一次实际产品接入均有本次证据。类型化 CXIF、Rust 编译期所有权、完整 C99 与六宿主资格继续分别列账，不能从这两步推定已具备。
