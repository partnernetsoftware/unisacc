# 0.0.43 阶段字节流身份与拆分方案

设计方案；父会话已核对下述主要源码定位，未实现阶段拆分、未运行拆后流水线。当前物理流水线不是抽象边界的否证：exec/pipeline/image-stages.tsv:2–8 为 e2/e1/e3/e4/prune/lower/elf；parse/type 集成于 e3，enc/image 集成于 elf。下列是可实施的逻辑合同边界，不声称已有全部独立产物。

统一核心身份：规范化协议版本 + 所有显式输入字节流哈希 + 模型/规则。共享执行器绑定为独立的实现见证，不能以整个含宿主适配的源码哈希冒充不可拆语义。资源的 bytes/显式 absent 响应是输入流；输出及拒绝覆盖是验收见证，不是输入身份。实际机器编译器、oracle、工具搜索路径、运行环境属于观测身份；目标 OS/arch 是显式目标合同，不是运行宿主。执行器实现身份须被钉住；宿主机器身份不应混入模型语义。

## 易误判处

1. ABI manifest 把外部声明与语言类型事实组合起来，并不证明所有事实都属宿主污染。核心应消费这些显式合同数据；宿主地址和进程loader状态才应隔离。
2. pp→lex 可封存到 typed tokens，但固定资源/宏/编码协议是前提；“早段结束于lex”不意味着任意ABI修改都能复用pp。
3. 外部符号请求可作为核心输出流；最终宿主地址不能成为 parse2/enc 的隐含输入。输出目标符号名与动态段合同不等于实际宿主读取。
4. 不据上述静态读取清单直接摘除 gatedeps。每套件先记录真实闭包及失败查找，做漏依赖负例；oracle/env只移入观测身份，不删除。

建议实施顺序：资源流严格模式→parse2外部合同流→run绑定适配器→opt/prune指令与根流→lower目标合同→enc/image边界。每次封存先钉输出/拒绝覆盖，再决定重跑传播；不会回填旧闸PASS。

## 占位符号与晚绑定（只是设计，未实现）

可行且符合字节流抽象：parse2 根据显式签名/调用约定/可变参数/布局合同输出稳定 symbol-id（建议声明规范编码的哈希或确定序号），保留本地/外部/弱/导出类别；type 不需要真实地址；opt 消费调用副作用合同；prune 消费导出根/可达性合同；lower 消费调用约定与重定位类型；enc 消费布局决定后生成占位字段和 relocation 流。image 写目标格式导入/重定位记录；真实宿主地址只在运行适配器加载/链接边界填入。

晚绑定不能延后所有ABI：参数寄存器、栈、返回形状、变参、结构布局必须在 type/lower/enc 前确定；外部函数名字不变但签名变，仍使这些阶段失效。地址晚绑定不代表未知调用副作用可以优化或未知导出根可以剪枝。

风险：PC相对分支距离/松弛需布局固定或保留可验证trampoline；symbol-id须稳定且无碰撞/重复定义歧义；别名、弱符号、版本符号、TLS、地址比较与数据初值需完整重定位合同；prune不可丢掉仅外部可达定义。晚绑定失败必须明确拒绝，禁止“占位0仍执行”。同一符号ID在多个单位的签名一致性必须跨单位核验；观测loader行为不能偷偷回流进核心身份。

## 外部合同不等于宿主状态

拆后 parse2 明确输入为 tokens/声明环境流、语言规则、外部声明的签名/类型/符号类别规范流；下游 lower 明确再消费目标调用约定和布局流。abi.manifest 是外部合同的容器，按字段投影后作为显式流输入，不直接将整个文件或宿主地址注入每个阶段。真正地址、加载器可用性与 oracle CC 归观测/运行适配器。ABI 改动如影响预定义宏/头资源，仍改变 pp 的显式输入，不按“早段”名字豁免。

表中的规则/执行器是模型调用协议，不把当前物理共享文件当逻辑不可分边界。每行所列是拟拆输入清单；缺一个语义输入时必须拒绝封存，不据静态表授复用。pp-literals 的44次实测只覆盖该叶 plain+locations，不能提升为全部pp域。

占位符号只是可选编码形式：更小的优先拆法是类型/调用契约与真实地址两个接口。仅需将现有 symbol 请求作为确定字节流留到适配器，未必先发明全局占位符机制；签名、布局、调用副作用、导出根不能推迟。以上均只是设计，没有产品域修改。

## 实测泄漏清单：随机源名（待修）

exec/pp/literalcheck.py:50 创建随机 TemporaryDirectory；:60–61 将其中 literal.c 的物理路径同时用作输入文件和显式源名，:72、:95、:109、:115 的模型调用沿用这一模式。tests/seals/exec-pp-literals/case-*.source-label 留存原测字节，是宿主随机目录进核心输入的实证；以前将其称为“显式传入”不能消除泄漏。旧数据只作历史见证，不改写为规范源名、不据此授跨目录复用。

修法：由调用适配器把物理读文件路径与逻辑源名分开，核心仅接固定源名协议（如 leaf/pp-literals/literal.c）、输入字节与显式资源流；__FILE__/诊断/位置输出仍保留逻辑源名语义。须验证两个物理目录下相同逻辑源名得到同字节输出，且逻辑名改变时对应语义改变，不可简单删掉所有源名。旧literalcheck调用的参数修正本身是harness改动；统一产品CLI/资源与位置边界需改 exec/c/run.c 等产品闭包，属于需重建候选的后续产品刀，本批不实施。
