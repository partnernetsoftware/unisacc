# CX workspace: first three independent tools

Run from the repository root with the installed product. The workspace owns package graph checks and scheduling; CX0 and E2 own their existing rules. Declared inputs are listed in `packages.tsv`; this list is not a complete compiler read audit. The E2 model is an argument to the test, never guessed from `out/`.

```sh
tools/bound 55 sh ./unisacc.com tools/cx-workspace.cx -- plan cx/workspace/packages.tsv out/workspace lnx/x86_64
tools/bound 55 sh ./unisacc.com tools/cx-workspace.cx -- build cx/workspace/packages.tsv out/workspace lnx/x86_64
tools/bound 55 sh ./unisacc.com tools/cx-workspace.cx -- test cx/workspace/packages.tsv out/workspace lnx/x86_64 cx0-plan contract -- /ABS/ROOT /ABS/ROOT/out/plan-cases
tools/bound 55 sh ./unisacc.com tools/cx-workspace.cx -- test cx/workspace/packages.tsv out/workspace lnx/x86_64 cx0-bundle contract -- /ABS/ROOT /ABS/ROOT/out/bundle-cases /ABS/E2_MODEL
tools/bound 55 sh ./unisacc.com tools/cx-workspace.cx -- test cx/workspace/packages.tsv out/workspace lnx/x86_64 cx0-e2 contract -- /ABS/ROOT /ABS/ROOT/out/workspace/cx0-e2 /ABS/E2_MODEL /ABS/ROOT/out/e2-cases
```

`build` requires a new output directory. An optional package after the target selects its dependency closure. Scheduling is sequential; each child has a 1–55 second process-group bound through the existing `cx_runv_timeout` API. The caller also supplies its outer 60 second bound. The adapter currently accepts only explicit `lnx/x86_64`.

`CXWORK1` is newline terminated TSV. Package declarations precede references. `P id source artifact unisacc seconds` declares a unique owned entry and artifact. `I package implementation|interface|test logical-name path` declares named content inputs. `C package source` adds a declared translation unit to the compiler command. `D package normal|build dependency` declares a graph edge. `T package test-id source seconds` declares a runnable test. Missing packages, duplicate entries/artifacts/inputs, cycles, undeclared compilation sources, unsupported targets and malformed rows are refused. File failures distinguish ENOENT from other errors.

Build receipts separate implementation/build, public interface, assembly and exact artifact SHA256. They say `PREPARED-no-test-result`. The compiler identity includes the installed product and its embedded runtime. The E2 adapter's disk headers and C execution sources are explicitly listed. `interface` rows currently bind the generated CXIF v0 header bytes, including its generated source identity; this is conservative and does not implement interface-only incremental compilation. CX0 plan has no separately extracted interface input yet. The two CLI artifacts are executable tools, not a binary library ABI; E2 still explicitly compiles the public bundle module as a compatibility source dependency.

There is no cache in this first implementation. Every build invokes the compiler; every test invokes its declared CX source. Test inputs are excluded from build keys. Test execution checks current build identities and artifact hashes against build receipts, then emits an `EXECUTED` record with the actual exit code and stdout path. Regular files passed as arguments, including MODEL and READER, enter the test key by SHA256 and are checked again after execution; declared test sources and built artifacts are also checked before and after. Stderr remains visible to the caller. An exit code is an observation of that declared test, not product or release qualification. Arbitrary test arguments and resource paths are explicit; semantic fixture validation belongs to the test. Compile, load, execution and validation phase timings are UNMEASURED.

The manifest is a declared input set, not an OS sandbox or complete compiler read audit. Extra input discovery, hermetic host headers, immutable snapshots, persistent caching, incremental relinking, cross-platform scheduling and compiled ownership checks remain unimplemented. Before/after byte checks detect observed changes but do not establish an atomic snapshot. Whole-tree source SID and existing product gates remain in force.
