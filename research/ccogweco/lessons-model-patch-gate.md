# 教训:模型表补丁交审前的结构自检(草稿,待并入技能页;2026-11-25 ccogweco)

## 现象

本轮一版模型表补丁交审时,夹具只验证了 rc 与产出对象(编译/运行成功),没有验证"生成图里含该状态与转移";
cdx 复核时抓出 `no transition`:新增规则在图上没有入口/出口,`states` 缺 `UM.end` 一类的终止状态。
这类缺口,只跑 rc 的夹具抓不到——编译通过、对象生成,图却是断的。

## 根因

- 改的是事实表模板(template)的 `move` 与 `rule`,两者在同一次生成调用里**存在顺序依赖**:
  move 先/后决定新状态是否先被登记进 states,再被规则引用;
- 生成器 `--check` 只校验可生成与表字节,不校验"每条新规则的入口状态与出口状态都在 states 里";
- 交审夹具只覆盖 rc 与产物,不覆盖结构断言。

## 固化(两条)

1. 改 `exec/parse2` 或类似事实表的补丁,交审前必须附:
   (a) "生成图状态与转移存在性断言"原行:图含新状态的入口与出口,例如
       `grep -c 'state.*UM.end' <生成图>`、`grep -c 'transition.*<新规则>' <生成图>`,
       以及 states 表与 rules 表的交叉计数(不允许只给 rc);
   (b) "正控与负控 -c 实跑原行":正控用新增构造编过;负控用删掉入口/出口的变体必须被拒(no transition 或
       对应具名拒绝)。两条都要原行,不写"已验"。
2. 交审说明里写明 move 与 rule 的写入顺序,以及该顺序对 states 生成的影响;顺序改了要重跑 (a)(b)。

## 候选(108/0.1.x)

- 生成器 `--check` 增加结构自检:每条新增规则的入口状态必须在 states 中、每个可达出口必须被登记;
  缺即 `REFUSE` 并点名 state/rule,不只比表字节。
- 交审夹具模板增加"图存在性"组:states 计数、transition 计数、新状态出入口 grep,作为默认断言;
  负控:删 states 一行后必须红。
- 归属:工具线(不触 SID);与 W0201 的"新增批实跑"教训分开落,但同属"结构断言先于 rc"。
