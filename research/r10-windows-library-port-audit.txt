CONCRETE BLOCKERS / MINIMUM CHANGE
A. CRC/P3: codec.h439-444 stores CRC table/current word in signed long; LLP64 makes shifts arithmetic and crc initial4294967295 truncates to-1. run.c258/294 PCRC is long*, lnum64 assignment truncates then header negative-check rejects high-bit CRCs. Actual frozen26def90 compiler.pkg has11/23 checksums >=2^31; stock Windows host reader will reject those. Use explicit uint32_t CRC operations/table, and validate lnum in64bit before assign uint32_t; retain LP64/selfhost result compatibility and all codec controls. Puff lengths unsigned long remain32bit but package/model extents are already <2GiB, so not the priority; signed bit accumulator only uses small bit counts, audit separately, do not rewrite entire puff.
B. Resource/process protocol: memory.c resource_u64(long) and libunisacc vals long[] truncate all callback/base/argv addresses above4GiB. c->process_slots long[2] occupies8 bytes; delta loads64bit argc@0 and argv@8, so argv reads outside array. Change only protocol words to uint64_t/int64_t/uintptr_t and callback declarations to fixed64bit types. API descriptors already uint64_t and core I already int64_t. Library callbacks six args need actual Windows host ABI bridge (ARM64 same GPR shape, x64 four regs plus stack).
C. OS memory layer: memory.c _WIN32 assumes __mmap/__mprotect unisacc intrinsics for both native host and selfhost. Distinguish __UNISA__ product branch from native _WIN32 adaptation using VirtualAlloc reserve/commit, VirtualProtect, FlushInstructionCache, VirtualFree release. Remove pointer sign checks through long; validate exact failed pointer (NULL on Windows, MAP_FAILED on POSIX). Check sizes/additions in64bit/size_t before <=2GiB bound; current long32 addition can overflow before reject.
D. Context lifecycle: libunisacc.c discard_image explicitly panics on Windows unload; library_stack_alloc uses POSIX mmap/mprotect/sysconf; library_mmap/munmap use POSIX flags and munmap. Require host memory helpers for image,guarded softstack,and guest-map tracking/free; use Win memory query/page size/VirtualFree semantics. Do not equate POSIX partial unmap with Windows allocation release. Setjmp normal explicit-exit recovery must be native tested, independent of unsupported guest SEH.
E. Host target: library_native_target returns Linux for all nonApple hosts. Add native Windows target selection (both ARM andx64) before us_relocate host-target guard. This is OS adaptation; it does not change compile decisions.
F. Dependencies/build: configure actual Windows libffi headers + static/import library for both target ABIs. Local zig ships MinGW headers and supports COFF objects; no ready Windows libffi artifact was found. No installation done. builders must select librarycall_windows_<ISA>.S, host SDK and correct ffi config; Windows public DLL exports/import library need explicit visibility/declspec policy (current GCC default-visibility alone is not proof of Windows DLL exports).
G. Models: library exit/memory/import injection deltas intentionally reject Windows resources or lack complete callback bridge forms today; enabling native host C alone cannot complete Windows library. This is a separate enc/lower target slice, not a C fallback compiler pass. Retain default ordinary CLI outputs.
