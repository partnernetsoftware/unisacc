# 表即网络

**以构造而非训练得到权重的神经编译器 unisacc：方法、验证与自举**

技术论文 · 2026 年 9 月 · 代码、权重与全部证据见本仓库

---

## 摘要

编译器中有一大类决策本质上是**有限函数**：字符分类、产生式选择、类型提升、指令与调用约定选择、镜像字段布局。unisacc 把这些决策交给**由真值表直接构造、而非训练**得到的确定性整数网络，并在每张表的**全部定义域**上逐键枚举，证明网络与表相等。

本文报告同一方法的两个实例。

- **经典实例**：18 张事实表，每张一个 one-hot → 整数仿射 → ReLU → 整数仿射 → 严格 argmax 的网络，由递归下降等经典代码在每个决策点询问；全部阶段在声明定义域上精度 1.000（表 1）。该实例实现了逐字节自举：历史验证中，它在五个目标的操作系统环境里不经 Python 重建出与自身逐字节相同的编译器。
- **网络编译器（当前产品）**：整条编译管线——预处理、词法、解析、优化、lowering、指令编码与镜像写出——被拆成字节流进、字节流出的阶段，每个阶段是一个由声明规则构造的有限转移函数 δ，编成整数阈值网络，由同一个通用执行器逐步运行。产品 `unisacc.com` 为单个 1.22 MB 文件，携带 32 个互异网络，服务 {Linux, macOS, Windows} × {x86-64, arm64} 六个目标；模型拒绝即报错，不回退到经典编译器。

理论上，有限输入域使“精确”成为全函数上的模型检验问题，而不是统计泛化问题；有限函数的构造式存在性是已知结果，本文的贡献在于：把它落实到一个真实的、能自举、面向六个目标的 C99 子集编译器上；把网络规模作为工程问题系统地缩小；并以全域枚举（网络 ≡ 表）与逐字节镜像等价作为判据。枚举**不**证明表符合 C 语义；这一层由外部裁判提供局部证据（§8）。SGD 作为对照臂保留，我们报告它在合并阶段与扩表后的系统性失败（§5）。

**关键词**：神经编译器；权重构造；精确网络；枚举验证；有限控制；自举

## 1　问题与命题

“把编译器做成神经网络”常见的两种做法都不令人满意：端到端地学习源码到机器码，得不到正确性保证；用网络辅助启发式（寄存器分配、内联），决策仍由手写代码兜底。我们取第三条路，把命题收窄成可以检验的形式：

> **命题。** 给定有限输入域与有限输出域，编译管线中“查表形状”的决策可以由构造出的网络精确完成；网络权重由真值表构造，**网络 ≡ 表**由穷举定义域验证。推理算法与语言无关、可以复用；但网络的宽度、存储与执行代价依赖具体函数，存在性并不保证“小”。

这里的“精确”指在该阶段**全部**合法输入上 argmax 与真值表一致，而不是测试集上的统计精度。之所以做得到，是因为每个阶段的输入被设计成有限笛卡尔积，定义域可以枚举完。**表 ≡ C99 语义**不在本命题之内（§3.4、§8）；本文不声称 CompCert 级的整机语义保持。

### 1.1　理论依据：从有限决策到确定性工作流

**研究主张（不是本文已证明的整机定理）。** 确定性模型推理原则上可以替代编译工作流中每一个**可计算的确定性环节**：把该环节分解成有限控制与存储，用模型实现有限控制的转移函数 δ，由固定的通用执行机制 E 完成读写与动作。“替代”允许把一次高级操作展开成多次模型调用，而不要求用一个有限输入网络一次处理任意长的程序。其目标形式为

\[
\mathrm{Compile}(x)=\mathrm{dec}\bigl(\mathrm{Run}_{E,\delta}(\mathrm{enc}(x))\bigr).
\]

`Run` 反复观测、求 δ、执行动作，结果分为接受、拒绝与发散；它不是有限次的固定前馈计算。确定性本身推不出可计算性，本主张限定于能由算法执行的环节。

**原理论证。** 对固定的确定性算法，可以采用有限控制、有限字母表与无界带存储的计算模型，其单步只读取有限控制状态与有限个局部符号（基本定义见 [Cambridge《Computation Theory》](https://www.cl.cam.ac.uk/teaching/2425/CompTheory/ct_handout.pdf)）。因此单步转移的输入与输出都可编码为有限集合；以动作序列为输出时，有限转移表只含有限多个序列，也可编码为有限的动作编号。再应用 §3.1 的有限函数构造，即得精确实现单步转移的网络。这是一条存在性路径，并不给出小网络、低开销或自动迁移算法；有限域网络构造本身也不是新理论（§10）。

论证有明确前提：无界的常量、标识符、地址与类型结构必须编码为有限符号序列，经通用读写机制访问，而不能直接作为 δ 的一个输入值；观测摘要的计算同样需要展开，“判断 typedef”“按 C 规则转换类型”“计算活跃性”之类的语言相关工作不能藏进 E；`enc` 与 `dec` 只做显式的表示转换，不能暗中完成词法、编码或链接。

| 档位 | 可以陈述的内容 | 边界 |
|---|---|---|
| **已证：T1** | 有限函数的构造式存在性（P-8）；发布权重经全域枚举与真值表相等（经典实例 18 个事实阶段共 8,506 个键；网络编译器 32 个网络逐一覆盖声明观察域） | 证明网络等于给定表；不证明表从旧代码提取正确，也不证明表符合 C 语义 |
| **证据：E** | 网络编译器与经典参考在全部门禁语料上逐字节一致（§2.5） | 经验证据，不是全程模拟证明 |
| **未证：T2** | 迁移后过程与参考过程的全程模拟 | 需初态关联、动作确定性与终止性、状态不变量、终态匹配及发散敏感条件 |
| **未证：T3** | 编译保持所声明源语言的可观察行为 | 须先固定语言子集、ABI、未定义与未指定行为；有限语料上的一致只是经验证据 |

**表示迁移与复杂度缩减是两个结论。** 把手写控制流编成 δ 表，运行时就可以用统一的执行机制解释它；但产生 δ 的生成器仍可能完整承载那些规则。因此“运行路径改为网络”与“需要维护的语言逻辑减少”必须分开检验：后者要统计声明规则、语言专用的生成逻辑、通用构造器、执行器以及仍在使用的旧实现；运行产物则另计模型、模板、库与适配层。收益应由相同覆盖下的复用、可核对性与完整成本支持，而不由文件扩展名或执行核大小决定。

## 2　网络编译器：当前产品

### 2.1　管线与执行器

产品路线为：**声明规则、动态事实与共享模板 → 有限转移与动作 → 构造整数阈值网络 → 通用执行器逐阶段处理字节流**。包加载器只接受网络格式的模型；运行核实际求阈值激活并累加出后继状态与动作序列编号，不以答案表或经典编译器兜底。完整规格（各阶段的协议、规则来源、限制与判据）见 [PRD §0.4](../prd.md#pipeline-design)。

**执行器的一步。** 当前控制状态选定一个观察银行；观察值是下一个输入字节（或 EOF）、续接栈顶，或上一动作的比较结果。网络对观察求出两个整数——下一状态与动作序列编号——随后执行该序列中的通用动作：前进、标记与回跳、寄存器与索引内存读写、输出字节或跨度、压栈与出栈、intern 等。执行核不含任何专门的 C、tape、ISA 或镜像判定原语，这些编译控制全部由阶段规则与动作承担。

**网络形态。** 这批网络采用状态内有序阈值表示：下一状态与动作编号由基值加上激活阈值处的差分构成。它与 §3 的立方体—ReLU 事实网络是同一方法的两种实现。

**两项不改变答案的运行核改动。** 剖析发现，只含 `#include <stdio.h>` 的程序在 e3 中走了 3.29M 步、扫描了 6.02 亿个阈值单元，其中 97% 来自同一个状态——续点返回。

1. **前缀求值。** 一个银行内的阈值严格递增（装载器拒绝其他情形），所以被观察 x 激活的单元必为前缀。运行核二分出前缀长度，只累加这些差分：同一网络、同一求和，不存答案行或前缀和。
2. **声明返回。** 栈键银行里“续点 k → k、共用同一动作序列”的行，含义是“弹栈并在栈所指的状态继续”。它依赖无界的续点栈，不是有限键到有限类的决策；按 §3.6 的判据应留给经典机制。构造器因此把这些行记为声明的返回集，只为其余行构造阈值单元。有限决策仍全部由网络回答；网络—表检查仍逐一比较包括返回在内的每个观察（e3 共 1,549,292 个），与改动前完全相等。

**不属于模型的部分。** CLI、文件与资源适配、包的读取与 CRC 校验、网络解压与装载是经典代码。`-run` 的最后一步也不是模型：宿主预留 OS 选择的地址并作为资源交给模型，memory 入口一次生成最终绑定的内存镜像，宿主按其中记录的长度校验、提交、复制、设权限、清指令缓存并进入入口；宿主不解释 C、tape 或指令。内置 C 库以头文件源码随包分发，每次编译都从预处理起全程处理。离线 Python 构造器仍负责绑定目标事实、词表与参数化模板。所以被替代的是编译阶段的**控制与决策**，而不是所有程序代码或规则信息。

### 2.4　速度：真实成本

网络编译器比经典路线慢，这是方法的真实成本，本文不回避。

| 负载（同机、全新进程、五次中位数） | 经典参考 | 网络编译器 | 比值 |
|---|---:|---:|---:|
| `calc.c` 的 `-run`（v0.0.9 候选） | 0.0108 s | 0.179 s | 约 16.6× |
| 最小程序启动（同上） | 0.0032 s | 0.029 s | 约 9.2× |
| `examples/fib.c` 编译到镜像（前缀求值与声明返回之后） | 0.0797 s | 0.312 s | 3.9× |
| `unisacc.c` 编译到镜像（同上，1 次） | 0.790 s | 10.15 s | 12.8× |

前两行见 [当前基准](r9-current-bench-20260928.json)；后两行来自 §2.1 的两项运行核改动之后的另测，改动前分别为 10.2× 与 25.0×（[S-17 证据](s17-final-evidence.json)）。

成本的主要来源已经定位：`calc.c` 的 2.7 KB 源码经自动头展开后，e2 输出约 67 KB，其中约 96% 是内置库，后续每个阶段都要处理这些库代码。为此加入了**按需保留库函数体**（`-libneed`，默认关闭）：头文件里的每个库函数体都有守卫，预处理阶段按程序实际用到的名字（在由头文件派生的依赖表上求闭包）定义所需的守卫宏。经典参考上，`calc.c` 的 tape 从 268 KB 降到 132 KB、镜像从 99 KB 降到 66 KB；e2 的网络实现与经典参考在 156 个文件 × 开关两态上 312/312 逐字节一致（[验收账本](r9-e2-libneed-acceptance-20260928.json)）。在 tape 层消除不可达函数是计划中的后续工作。

### 2.5　验证

- **网络 ≡ 表（T1）**：32 个网络逐一覆盖声明观察域，比较后继状态、动作序列与字符串；这不证明动作语义、表的提取或 C99 语义正确。
- **与经典参考逐字节一致（E）**：当前候选的前一版 `7608a31b` 通过了全部 189 项本地门禁、0 失败；`d61d0153` 已通过相关门禁与 32 组网络—表检查，全量重跑进行中。六个目标 × 3 个程序的签前烟测在前一候选上实际通过，其中 macOS x86-64 经 Rosetta、Linux x86-64 经 Lima 模拟、Windows 驱动经 ARM 客机仿真，不等于各平台的完整原生套件。
- **固定网络包的驱动自举**：macOS arm64 上 N1 = N2 = N3，完整 Mach-O 相同；这不包含模型包或 APE 容器的自构造。

## 3　经典实例：把编译器拆成事实表

### 3.1　键模式

每个阶段 `s` 声明一组字段 `(f₁:V₁, …, fₘ:Vₘ)` 与输出词表 `Y`。它的真值表（下称 gold）定义在完整笛卡尔积 `K = V₁×…×Vₘ` 上，由标签函数给出；例如 `isel` 与 `abi` 的多头标签由指令目录按函数派生，而不是手工标注。这样设计有三个后果：

- 在全部 gold 上评估既便宜又真正完整，不存在训练与测试的分布偏移；
- 网络学到的是一个全函数；
- 留出实验有明确语义，例如按某一维整体扣掉 `osx/arm64`。

前端遇到任何不在 `K` 中的键会立即断言失败，因此网络永远不会在定义域外被询问。

### 3.3　存在性

设键 `k=(k₁…kₘ)` 做 one-hot 嵌入，每个键分配一个隐藏单元 `u_k`：

```
W1[coord(i, kᵢ), u_k] = 1,  b1[u_k] = −(m − ½),  W2[u_k, f(k)] = 1
```

输入 `k` 时恰有 `u_k` 的预激活为 ½，其余单元都 ≤ −½，经 ReLU 后只有它存活，于是 argmax 等于 `f(k)`。精确网络因此一定存在，宽度上界为 `|K|`。这一结论本身是已知的（有限状态机的网络编码，以及 Tracr 式的程序编译）；我们的工作是把它做**小**，并用到一个完整的编译器上。

### 3.4　最小覆盖：发布的权重

朴素构造的总参数量为 796,490 θ。我们把每个单元看作键空间上的一个**立方体**——对每个字段取值集合的合取，未约束的字段记为“不关心”——于是构造变成带优先级的集合覆盖：

1. **域商化**：合并对标签不可区分的字段取值（按标签等价类作商），验证仍在原始定义域上进行。
2. **决策列表加贪心最大覆盖**：反复挑选覆盖最多“同一标签、尚未覆盖”键的立方体，得分最高的规则排在最前。仅此一步就把 796,490 θ 降到 71,828 θ。
3. **集合值字面量**：一个字段可以取一个值集合，而不只是单个值。
4. **归约与胜负排序**：删除冗余单元；输出权重 `W2` 取正整数，使更具体的规则严格压过更早的规则。
5. **跨头共享与加性分解**：多头阶段共享立方体。

结果是：`W1 ∈ {0,1}`；阈值 `b1 = −(|F|−1)` 不必存储（`|F|` 为单元约束的字段数）；隐藏激活 ∈ {0,1}；`W2` 为正整数（绝大多数阶段 ≤ 16，type 阶段最大 512）。隐藏层退化为**布尔合取**，输出层为整数加权投票。对 5 个小表，我们在该立方体表示类内求出了精确最小值（35 → 20 单元），其余用贪心覆盖；本文不声称任意网络的最小宽度等价于两级逻辑最小化。

**表的数据形态。** `weights/gold/<阶段>.tsv` 把每张真值表按键逐行列出，任何语言都能直接读；它由 `python3 -m unisa gold-export` 生成，`tests/kernel.sh` 检查它是否过期。“表即网络”于是落在两个文件上：表是 `.tsv`，网络是 `weights/built.uns2`，二者在每一行上给出相同的答案。

### 3.5　验证与形式化义务

构造出的网络按部署时的算术逐键运行——one-hot 输入、整数 gemv、`max(0,·)`、整数 gemv、argmax——覆盖原始定义域的**每一个**键。只要有一个键答错或出现最大值并列，构造即判为失败并拒绝发布。“精度 1.000”指这次枚举通过，而不是抽样估计。

### 3.6　什么交给网络，什么不交

判据是**形状**，不是难度：有限键到有限类的函数就进表；依赖无界结构（嵌套、递归、地址算术）的就留给经典机制，但经典代码在每个决策点上都必须**询问**网络，唯一入口是 `oracle.ask(stage, key) → 类名`。

常见的分工是**结构提出，表来裁决**。`peep` 表是典型（§6.2）：结构代码找出候选指令对并算出它们的关系——是否同槽、是否常量、跳转目标、寄存器是否已死；做不做、做哪一种改写，由表回答。`opinfo`、`prec`、`binsel` 原先都写死在代码里，现在都由构造网络回答，两个前端问的是同一张表。于是判据可以补一句：凡是“给定一个离散描述，选一个离散动作”的，都应进表。反过来，续点栈上的返回依赖无界嵌套，在网络编译器中同样作为声明的控制原语执行，而不编码成阈值单元（§2.1）。

### 3.7　部署内核与确定性

隐藏层是布尔合取，推理可以写成无乘法的形式：每个单元为每个字段存放若干 64 位掩码字，按取值下标选中字与位后合取；输出层把激活单元的 `W2` 加到对应类上，再取严格 argmax。生成的 C 内核不含 softmax、libm、malloc、乘法与浮点。全部 18 个阶段的权重合计 9,124 字节。

经典实例的 C 端 `inf()` 并不在每次询问时运行网络，而是查一张稠密表 `DENSE`，它由枚举构造网络得到；显式验收命令 `--check-oracle` 逐一比较全部 20,190 个“键—头”问题的查表答案与直接推理结果，差异为 0。DENSE 因此是网络的编译形态，其等价性来自全域核对。这一结论只适用于经典实例，不能用来描述网络编译器的逐步推理成本（§2.4）。

使逐字节闭环成立的是两件事同时成立：**构造是确定的**（同一份 gold 构造出逐字节相同的权重，`tests/acceptance.sh` 的 A-14 连跑两次比较）；**推理只用整数**（在整数宽度、掩码表示与累加范围满足内核约定的前提下，同一输入的结果唯一）。跨机器、跨编译器的一致性仍须由目标平台验证，这是 §4.2 六目标折叠与 §6 N1 = N2 = N3 的前提。

## 4　执行语义与多目标验证

### 4.1　tape

前端输出一条与目标无关的 *tape*：8 个 64 位寄存器 `r0–r7`（`r7` 为栈指针），65 种操作（整数、单双精度浮点、访存、控制流，以及 `.sys`、`.print`、`.argc` 等内建）。浮点值以 IEEE 位模式放在通用寄存器里；调用两端都由我们自己编译，因此不需要任何平台的浮点 ABI。

### 4.2　六目标折叠

tape 分别 lower 到 {lnx, osx, win} × {x86-64, arm64} 六个目标，lowering 中的 isel、abi、enc、reloc 同样由网络决定。每个目标生成真实的 ELF、Mach-O 或 PE 镜像，再由**按该目标 ABI 解释**的机器模型执行：模型持有该架构的具名寄存器，系统调用分发器只认 lower 出的 `(OS, 调用号)`，从不回看 tape。六份 (stdout, exit) 必须彼此一致，并与 tape 参考 VM 一致。

为证明 6/6 不是空洞的，我们做了故障注入：去掉 macOS 系统调用号的 class 位，结果必须退化为 4/6。另有套件在本机、Lima 中的 Linux 内核与 UTM 中的 Windows 11 上真实运行这些镜像。

### 4.3　“决策真的由网络做”的检查

只比对答案的测试发现不了“手写了一条与表一致的规则”，因为两者答案完全相同。为此两个前端都报告每个阶段被询问的次数，并要求 Python 前端在某个探针上询问过的每个阶段，C 前端也必须询问过。这条检查确实抓到过 C 前端只询问 pp、lex、parse 三个阶段的漂移。

## 5　训练对照臂

SGD 路线完整保留，作为对照：同一结构（one-hot 嵌入加两层网络），Adam（β₁=0.9，β₂=0.999），batch 16，学习率 0.032 → 0.014 → 0.006 → 0.0025 分段下降，一个阶段首次达到 1.000 即冻结。训练不在出货路径上。

- **单表可训。** 当时的 11 个阶段共 21,925 θ 都能训到 1.000（18.8 秒）。“能不能学会”不是问题。
- **合并阶段即失败。** 相邻阶段合成一个网络后，即使参数增至 12.8 倍（45,209 θ），精度也停在 0.8143；构造对合并后的表同样精确。
- **扩表需要重新调容量。** 加入浮点类型后，type 阶段在原宽度下掉到 0.9514，必须加宽才能恢复；构造只需重建一次，3 秒完成，结果仍然精确。
- **规模。** 目标数超过 24 后 SGD 塌缩到 0.4419；构造所需单元数随目标数近似对数增长（`units ≈ 39 + 4.2·log₂(targets)`）。
- **不稳定。** 99 次训练中有 30 次先命中 1.000 又掉下来，这也是必须“首次命中即冻结”的原因。

我们的解释是：规则的改变需要在 `(W1, b1)` 上做一次**联合的离散跳变**，而沿 W1 的小步梯度只会把单元关掉（“活板门”现象）。SGD 天生不擅长“再多一条规则”，而构造本来就是按规则逐条展开的。

## 6　自举

经典实例的自举分三层，每层都有逐字节判据：

1. **前端**：`unisacc.c`（C 前端，内含生成的推理内核与权重）把自己编成 tape。cc 编出的 unisacc 记作 A，A 编自己得到 B，B 编自己得到 C，要求 B = C，且与 Python 驱动编出的版本相同。
2. **后端闭环**：lowering、两个编码器与三种镜像写出器移植进 C。对每个探针的每个目标，`unisacc -b os/arch` 写出的镜像必须与 Python 后端从同一条 tape 写出的**逐字节相同**；表 2 所记运行为 94 个探针 × 6 个目标，564/564。
3. **无 Python 的原生自举**：cc 编出的 unisacc 写出自身的原生镜像 N1，N1 写出 N2，N2 写出 N3，要求 N1 = N2 = N3，并且另外 5 个目标的交叉输出一致。这在 osx/arm64、lnx/arm64 与 lnx/x86-64 上成立；在 Windows 上，win/arm64 与 win/x86-64（后者经系统仿真）也各自重建出逐字节相同的自己。这些运行均未调用 Python。

逐字节判据能暴露“解释器看不见”的错误：多级指针的高 32 位被截断、静态局部变量未保留、Linux arm64 的 argc 读错位置、`main(argc, argv)` 从未收到参数、镜像把 87 MB 的零写进文件（修正后 unisacc 自身的镜像从 91 MB 降到 639 KB）。这些错误都是在“原生运行自己编出的东西”时才暴露的。

### 6.1　把枚举用回手写代码

“枚举整个定义域，而不是抽样”的判据同样适用于实现中的手写部分，条件有两个：被测的东西是纯函数，且存在一个独立实现作差分对照。数据布局函数 `zero_last`（非零块在前、全零块在后，各自保持地址 mod 8）两个条件都满足：它是纯函数，且有 Python 参考与手工移植的 C 两套实现。

我们枚举了一个有界子域：所有长度 ≤ 3 的数据定义序列，字母表为 `{bss 1, bss 8, str 1, str 7, str 8, 全 NUL 的 str}`（取 1/7/8 是因为只有块长不是 8 的倍数时 mod 8 规则才可见），外加“同一符号被定义两次”的变体——共 762 条 tape，每条对 6 个目标各编一次，4,572 次镜像逐字节比对，12 秒跑完。

这次枚举立刻找出两个实现的语义分歧：同名符号定义两次时，Python 侧做的是**驻留**（第二次既不分配空间也不改地址），C 侧却重新分配并把符号移到新地址，两边镜像相差 8 字节。抽样之所以漏掉它，是因为触发条件“声明顺序 ≠ 地址顺序”在小程序里几乎不会自然出现：90 个探针、220 个外部语料程序、540/540 的逐字节闭环全部是绿的。唯一自然长出这种形状的输入是编译器自己——707 KB、1,874 个数据符号，第 282 个符号处顺序开始回退——它让六个目标**全部段错误**。

由此得到两条可迁移的经验：**构造—枚举不只是训练的替代品，而是一种可以贯穿整个实现的验证纪律**；**“逐字节相同”比“输出相同”强得多**，它不给实现留任何自由度，而差分对照让这条判据在没有形式规范时仍然可检。据此补充的三个套件——枚举布局（`layout`）、病态数据形状（`datashape`）、编译器自身闭环（`bigclosure`）——都要求“检查数必须为正”：此前一个不带参数的闭环脚本曾打印 `identical 0 differ 0` 并以 0 退出。

### 6.2　优化器也走表

`-O1/-O2` 是 tape → tape 的改写，两个后端吃同一条优化后的 tape，逐字节闭环照旧成立。结构性的一半是经典代码：把表达式栈顶留在寄存器里（`push; S; pop` → `mov`），以及在基本块粒度上求寄存器活跃性（最小不动点）。表状的一半是 `peep` 表：结构代码只找出一对指令并说出它们的关系——同槽的存与取、作为第二源的常量 0/1/2ⁿ、跳到下一条、跳到跳转、写一个死寄存器——**做不做、做哪种改写由网络回答**。它与其他表一样构造、全域枚举 1.000；两个前端的优化器问同一张网，`optpy` 套件要求二者输出逐字节相同。

一个实测改表的例子：`pow2 → 移位` 在 x86 上让镜像大了 24 KB（tape 的移位要经 `cl`），于是 gold 里这一格改为 `keep`——决策在表里，量了就改表，而不是改代码。结果是出货编译器（-O2 构建）的 arm64 镜像小 29%，自编译对 cc -O2 从约 11× 降到 4.0×。

| tcc | 0.02 s | 683,008 B | 0.55 s | 3.7× |
| unisacc -O2（自己） | 0.15 s | 677,154 B | 0.81 s | 5.4× |
| unisacc -O0（自己） | 0.10 s | 1,056,930 B | 2.05 s | 13.8× |

五个编译器二进制本身大小不同，逐字节相同的是它们执行同一自编译任务写出的目标镜像。在这一负载上，unisacc -O2 构建的编译器用时约为 tcc 构建版的 1.5 倍、cc -O2 构建版的 5.4 倍；这是单一负载的结果，不代表任意 C99 程序的代码质量。方法的贡献是可构造、可全域核对的表状决策，而不是速度优势。

**表 4　性质对照**

| 性质 | unisacc | tcc | cc（clang） |
|---|---|---|---|
| 表状决策可验证 | 每张表的网络在全部定义域上枚举核对；外部裁判覆盖具名阶段的部分事实（§8.1） | 手写代码 | 手写代码 |
| 一个二进制写出的目标 | 6 个：{Linux, macOS, Windows} × {x86-64, arm64} | 每个目标单独构建一个 tcc | 可多目标，但每个目标需要各自的链接器与 SDK |
| 外部链接器 | 不需要：ELF、Mach-O、PE 由自身写出，Mach-O 自带 ad-hoc 签名 | macOS 上用自带的 Mach-O 写出，依赖系统库 | 需要 ld |
| 逐字节可复现 | 自举不动点 N1 = N2 = N3，5 个真实目标上全程无 Python；构造与推理只用整数 | 未作为性质声明 | 未作为性质声明 |
| 分发形态 | 经典种子为单个 `unisacc.c`；产品为携带网络包的单个 `.com` | 多文件 | 大型工程 |
| 语言覆盖 | C99 子集；c-testsuite 216/220 | C99 大部分，另有 C11 部分、GNU 扩展、内联汇编 | 完整 C17/C23 |

表 4 中 tcc 与 cc 的描述是公开事实的概括，本文未逐项实测；unisacc 各项都有对应的门禁：`tests/closure.sh`、`tests/nativeboot.sh`、`tests/bigclosure.sh`、`tests/corpus.sh`。

## 8　局限与负结果

- **枚举只证明网络等于表，不证明表是对的**（§8.1、§8.2）。
- **产品范围。** 支持 C99 子集与自带头文件；多文件合成单一程序，没有系统目标文件链接器。`-c` 写出 tape，不兼容通常的 `.o` 流程；不能据此声称与 gcc 或系统 libc 完全兼容。
- **速度。** 网络编译器比经典路线慢 4–17 倍（§2.4），这是用统一执行器解释有限控制的真实成本。
- **自举边界。** 能编译自己只说明无需 Python 即可完成该重建任务，不证明全部 C99 程序语义正确，也不意味着编译器会自主提出改进。固定网络包的驱动自举不等于模型包或 APE 容器的自构造。
- **没有泛化。** 网络只在枚举过的定义域上有定义，这是设计而不是缺陷：扩展语言就等于扩表后重建。
- **量化与混合精度收益很小**（混合 dtype 只省 4.5%），2 比特量化在所有阶段都失败。
- **覆盖度。** 系统调用的参数形状、返回约定与导入名已进入 `abi` 表；仍未进表的主要是机器码的字节模板，操作码数据已合成一份 `catalog.ENCSPEC`，模板本身仍是代码。
- **容量是静态上限。** 编译器自身源码曾用到源码缓冲区上限的 99.4%。各项上限已放宽，`tests/scale.sh` 在自身用量超过任一上限一半时报警，并以 -O2 编译运行一个 80 万字节、6,000 个函数的生成程序；bss 的虚拟空间大小不等于峰值 RSS。

### 8.1　外部裁判的覆盖

[裁判账本](referee.tsv) 对 18 个经典阶段作如下分类；`tests/docs.sh` 核对阶段集合与所列裁判文件存在，但不证明裁判覆盖了整张表。

| 分类 | 阶段 | 能说明什么 |
|---|---|---|
| 外部裁判具名（4） | type、abi、prec、tyinfo | 有局部外部核对来源，范围见下表 |
| 实现间一致性（6） | lex、enc、reloc、regmap、peep、opinfo | 比较两个实现；二者共同依赖同一错误规则时仍可能一致 |
| 尚无具名直接裁判（6） | pp、parse、scope、irsel、pfconv、binsel | 下游测试可能间接触达，但不逐格担保 |
| 不在主编译路径（2） | isel、combo | 仍可验证网络等于表，不计入主路径语义覆盖 |

| 外部核对 | 覆盖与限制 |
|---|---|
| type | 以宿主 cc 的 C11 `_Generic` 检查结果类型，覆盖 4,275 个键中的 1,400 个 |
| abi | 以宿主系统调用头文件核对编号与目录映射；只涉及实际宿主的 OS 与架构 |
| prec | 324 个有序运算符对：291 对在所选常量上可区分两种分组且一致，33 对无法区分 |
| tyinfo | 27 项宿主事实：11 种类型的大小，8 种整数的有无符号与窄化属性 |

因此应表述为“18/18 个阶段有网络—表枚举验证，4/18 个阶段登记了有特定覆盖范围的外部裁判”，而不能说“4 张表已全域证明等于 C”。网络编译器的 32 个转移网络不自动继承这份登记，它们对 C 语义的证据来自与经典参考的逐字节对拍（§2.5）。

### 8.2　gold 本身会错

枚举只关闭**网络 = 表**，对**表 = C** 什么也没说。本项目的 `type` 表里曾有一条错规则——`int + int` 的结果类型写成了 `long`——在整个项目期间都存在：枚举 1.000、全部套件绿，因为求值恰好在 64 位里进行，打印出的数字没有错。它只在 `sizeof` 与符号性上露出来，而没有探针去问。

为此加入了第一个“问表是不是 C”的仪表 `tests/gold_audit.py`：以系统 cc 为裁判，对 10 个数值类型两两 × 14 个二元运算共 1,400 个键，用 C11 `_Generic` 让 cc 回答结果类型、用编译错误回答“非法”，逐键与 gold 比对。首跑发现 200 个键有误（比较运算的结果类型写成了 long，与上一条同源），在 gold 中改正并重建权重；唯一的有意偏离记在 `tests/gold.knownfail` 并写明理由。**表的每一格都应有一个外部裁判**，否则“精确”只是精确地复制了错误。

裁判也不止参考实现一种：**代价表的裁判是实测**。`peep` 表里“乘以 2 的幂改为移位”语义完全正确，却让 x86 镜像大了 24 KB，于是这一格改为 `keep`。语义表对照参考实现，代价表对照测量——外部裁判是方法的一部分。

## 9　复现

从种子复现经典方法需要 Python 3.11+ 标准库与系统 C 编译器；使用已构建的编译器、经典原生自举与网络编译器的驱动自举都不需要 Python。无需 GPU，也无需运行训练对照臂。以下为独立的实验入口，按仓库规则每步不超过 60 秒，长套件分批记录。

```bash
python3 -m unisa build-weights          # 由 gold 构造全部网络并枚举验证
python3 -m unisa acc                    # 表 1：各阶段在完整定义域上的精度
python3 -m unisa run examples/hello.c --fold   # 六目标折叠，期望 6/6
./tests/build_ref.sh                    # 用 cc 编出参考 unisacc
./tests/closure.sh examples/*.c tests/c/*.c    # 镜像逐字节闭环
./tests/nativeboot.sh                   # N1 = N2 = N3，无 Python
./tests/gate.sh --list --com            # 列出全部门禁，再按 --suite 分批执行
TCC=<tcc 构建目录> ./tests/bench_vs.sh   # 表 3：与 tcc、cc 的横向比较
```

网络编译器的构造与候选验收入口见 [`exec/c/BUILDING.md`](../exec/c/BUILDING.md)；功能与性能测试使用真实的 `.com`，经典命令不替代其验收。

## 10　相关工作

把有限自动机精确编码进网络可以追溯到 Omlin 与 Giles（1996）；Tracr（2023）把 RASP 程序编译为 Transformer 权重，其有限域查表式 MLP 构造即本文复述的 P-8，不是新定理。与它们相比，本文把“构造而非训练”落到一个能自举、面向六个真实目标的完整编译器上，并进一步把整条管线表示为由构造网络驱动的有限控制；把网络规模作为工程问题系统地缩小；以全定义域枚举与逐字节镜像等价作为**网络 ≡ 表**的判据，局部外部语义核对见 §8.1。

**精确解存在但 SGD 不可达**属于已建立的定理家族：Shalev-Shwartz、Shamir 与 Shammah（ICML 2017），以及 Shamir（2018）、Malach 与 Shalev-Shwartz（2020）、Barak 等（2022）已给出梯度方法在若干离散目标上的失败形态。我们的贡献限于**实例与机理**：合并阶段上 12.8 倍参数仍到不了 1.000，以及“改规则需 \((W_1,b_1)\) 联合离散跳变”的活板门现象（§5）。形式化边界与文献细目见 `prior-art.md` 与 `formalization-roadmap.md`。

同一方法在 JavaScript 与 WebAssembly 上的迁移见伴生文 Paper B（[`ujs-paper.md`](ujs-paper.md)）。
