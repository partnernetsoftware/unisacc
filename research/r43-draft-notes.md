Draft release notes for 0.0.43, updated 2026-10-25. The E4 candidate passed its three-stage fixed point and is sealed by immutable GHCR digest. Unsigned six-native-platform demo smoke and its strict matrix passed in release-check 40121986516 attempt 1. Complete M7, Darwin-specific acceptance, signing/notarization, final signed-byte courts and publication remain pending. Final release claims must be tied to the actual candidate and acceptance receipt.

## What changed in the product

- **Bundled library and file-reader repairs.** `vsnprintf(NULL, 0, ...)` and the `vprintf` path are repaired; `dup2`/`fopen` survive library trimming; `setenv`/`unsetenv` update `environ` consistently with subprocess creation; `fileno` reports the stream descriptor. On POSIX, `cx_read` reports a directory read failure even when all eight stdio states are occupied. Bare and repeated `enum E;` declarations are accepted. Named F1 probes, provenance checks, E3/PP seals and the 657-file differential are recorded in `research/c43-f1-evidence/`; individual suite acceptance remains subject to the final queue.
- **Declarator and `sizeof` fixes (silent wrong code removed).**
  - `sizeof *(P+n)`, `sizeof (P-n)[i]` and `sizeof *(A+n)` on a pointer to an array used to give the pointer width (8 for `int (*)[3]`); they now give the row size (12). The row is tracked explicitly and cleared by a cast or a comma (e02d924a).
  - `int (**fpp)(int)` and a parameter `(**p)` used to be recorded as an ordinary function pointer, so `(*fpp)(x)` called through `&fp` and crashed in 0.0.42. The extra `*` is now counted, the same as for a typedef'd `F *` (726dfec2).
  - `sizeof` operands keep their start and declarator sizes (c989780c).
  - Accepted now: a struct member that is an array of a typedef'd array, or a pointer to an array of a typedef; a typedef declarator list that continues with another declarator; a file-scope comma declarator that starts with a function pointer; `_Static_assert` at file and block scope; a compound literal of a char array from a string; `sizeof(+bitfield)` (an rvalue).
- **Compound assignment to a bit-field computes in the promoted type (silent wrong code removed).** `x.f op= y` on an unsigned bit-field narrower than `int` ran in `unsigned int`, although C99 6.3.1.1p2 promotes the field to `int`. So `/=` and `%=` with a negative operand, and any comparison of the value of `x.f op= y`, were wrong: with `unsigned b:5` holding 4, `b /= -1` gave 0 where gcc gives 28, and `((b += 1) - 10 < 0)` gave 0 where gcc gives 1. This was wrong in the product since R14-8 (387b0a11). The E3 tables now use the promoted type, and the value of `x.f op= y` is promoted like the value of `x.f = y`. Regression probe: `tests/c/b_bitfield_compound.c`.
- **New named refusals (an honest `not covered` instead of wrong code).**
  - `int (**p)[N]` is refused as `not covered: pointer to pointer to array`. In 0.0.42 it was compiled with one pointer level dropped.
  - `int (*x[N])[M]`, an array of pointers to arrays, is refused as `not covered: array of pointers to arrays` (9df1417c, ruling R10 item M3). It was compiled with one level dropped: `int (*x[3])[3]; sizeof(*x[0])` gave 4 where gcc gives 12, and a runtime use crashed. The real fix is deferred to 0.0.44 (see Known limitations).
  - Wrong-code declarations that were found by the new enumerated probe set (`tests/tdescprobe.cx`) are now either correct or refused; the product has no WRONG row left in that set.
- **More C99 diagnostics, both fronts.** `int ;` (a declaration that names nothing) is rejected; void objects, arrays of void and `sizeof(void)` are rejected; a `return` is checked against the function result type; an empty scalar or block-scope declaration is refused; a bare anonymous struct or union is refused without clobbering the tag.
- **Compile outputs and refusals are deterministic and clean.**
  - The same source compiles to the same bytes twice. Outputs no longer carry the source path, the `-I` directory, a system-header host path or the forced-include directory (the logical source name is the command-line spelling, as with gcc).
  - A refusal writes its diagnostic to stderr and nothing to stdout, and never creates or rewrites an output file. `-run` with `-o`, `-S`, `-c`, `-E` or `-b` leaves no output file. A successful compile writes only the output file.
  - `-include`: the position of a diagnostic inside a forced header, `__FILE__`/`__LINE__`, absolute include directories for nested headers, and `-iquote` search now behave as in the classic reference (9ed67c03, e7c05741, 926a8925).
- **Tape domain.** Raw Tape, decoded Tapebin and E3 input are validated by a finite model before any output, and the product fails closed when that model is missing (0571eb62). Tape integers are explicit 64-bit words; negative `.bss` sizes and underscore integers (`1_000`) are refused by name; CRLF tapes lower and encode like LF tapes; a Tapebin `.bss` length may be up to 2^63-1 on every C reader and the writer. `.librarycall` without bindings and a scalar where a struct is wanted are refused by name in the classic reference as in the product.
- **Late binding of host library symbols (ordinary functions and data).** For ordinary fixed-signature functions and for library data symbols the E3 and lower fragments no longer contain host addresses: loader requirements come from a finite side-stream model and are bound after the lower output has been validated. An address-free fragment is identical in two contexts whose host addresses differ. Providers cannot supply addresses; a missing provider is refused at the binding step and nothing is written or run. Hosted `.sys6 exit`/`exit_group` now route through the library exit callback like `.exit`/`.sys`. Typed fixed-signature, variadic, callback and the `-run` bridge keep the 0.0.42 path (see Known limitations).
- **Host C library forwarding with `double` arguments works on Linux.** `uffi_init` only opened the macOS libffi, so on Linux a prototype with a floating-point parameter or result returned an uninitialised value (`remainder(7.0, 2.0)` gave a garbage number). It now tries `libffi.so.8`, `.7` and `.6`.
- **More of the C99 library surface.** `math.h` (the six comparison macros, ten more functions with exact results, and forwarded prototypes for the remaining C99 functions); `wchar.h` (wide memory and string functions, `wcstol`/`wcstoul`, `wcstok`, `wcsftime`, `wcscoll`, `wcsxfrm`, `wcstoll`/`wcstoull`, C-locale multibyte conversion); `inttypes.h` (`strtoimax`, `strtoumax`, `wcstoimax`, `wcstoumax`, `imaxdiv`); `stdlib.h` (`lldiv`); `stdio.h` (`fgetpos`, `fsetpos`); `string.h` (`strxfrm`); the C99 types in `wchar.h`, `stdio.h`, `stdlib.h`, `inttypes.h` and `fenv.h`. Functions marked as forwarded are provided by the host C library.
- **`.cx` prelude and modules.** A `.cx` unit is compiled with `cx.h` ahead of any `-include` in both drivers; neighboring `.c` files and host-forwarding stubs retain their own include behavior. The product supports `#pragma unisa module` and `#pragma unisa use`, and `-cx-plan` enumerates their compilation units. Native test consumers use this path. The compiled-tool cache now binds every direct and transitive module body, so a module implementation change forces recompilation. Later module-root and compiler-decomposition work remains deferred.
- **E4 block summaries reduce repeated scanning.** The model reuses block summaries instead of repeatedly scanning the same input (d09bd1decb). On one fixed 8,446,684-byte input, the generic C neural-network executor completed in about 30.5 seconds and the ISA kernel in about 33.3 seconds; the 5,227,535-byte output matched the independent C implementation byte for byte. Eight named comparison cases also passed. These are measurements of the specified execution step, with preparation and checking accounted for separately; they are not an end-to-end compilation-time guarantee.
- **Gate tooling now runs on the product.** Fifteen gate checkers (wave 1: freezecheck, reviewedtreescheck, revivedscan, frontboundscheck, doceditcheck, inventory, auditnet; wave 2: draftguard, seedletexit, copycontract, identity-include-consumer, lib-callable-mechanism, lib-carrier-mechanism, lib-resolver-host, full-signature-call) and subtract-safety, stagechain, regcheck, tdescprobe and the stream/net seal-modules suites are `.cx` programs run by `unisacc.com -run`; the Python originals were deleted where the `.cx` is byte-for-byte equivalent (10b11c4c, 9a1f146c, 7a4cafa8). This does not change the shipped bytes.
- **Preparation caches reuse complete typed/callsite materials.** Complete cached materials now produce a hit, and unrelated checking-script changes no longer invalidate typed preparation. Independent comparisons and full neural-network checks still run; prepared materials do not cache a test verdict. The ordinary seven-stream models and additional native resources still share a cache key, so adding native resources can unnecessarily rebuild the models. Splitting those keys remains pending.
- **Carrier test preparation uses native constructors and separate phases.** Four default-run `.cx` nodes prepare tools, construct models and execute the original import/package checks. Preparation uses the existing C constructors, with commands and complete source/header identities bound to the material cache; the Python preparation path remains an independent comparison. All eight final materials matched it byte for byte. The four nodes completed under their original 33-second limits, and missing or modified constructor materials were refused. This is developer test infrastructure, with mandatory legacy oracles still present.
- **Classic reference fixes** (it is the differential reference, not the shipped compiler): `(**p)(...)` keeps its pointer level; it now refuses `#if`, block and loop nesting and `#line` names beyond its fixed tables with a named, positioned error instead of writing past them; Tape numbers and x86 immediates keep 64 bits on LLP64 hosts; narrow unsigned bit-fields promote to int; `(char[]){"..."}` is sized by its string; a failed `-E -o FILE` leaves FILE as it was.
- **Pending final-candidate claim review (M4/M7).** Earlier product probes and the historical CONTRACT sweep support the implementation descriptions above. The new candidate has version, hello and O2-summary smoke checks recorded, but final affected-unit and complete acceptance results must still be checked before these become release claims.

## Known limitations

These are known defects, listed rather than fixed in 0.0.43. They are not regressions of this release unless stated.

- **An enum tag defined inside an initializer designator.** `int (*fps[])(int) = { [sizeof(enum E { EA = 1, EB })] = f, f };` is refused by name (`not covered: enum tag redefinition`); gcc accepts it. The brace-list pre-scan parses the designator once before the real pass. Probe: `tests/c/candidates/designator-sizeof-enum-tag.c` (found by the R3a spike, `research/c43-r3a/REPORT.txt`).

- **Declarator type shapes (tdescprobe).** The enumerated probe set `tests/tdescprobe.cx` covers the derivations of {pointer, `[3]`, function `(int)`} to depth 3 over `int` (18 distinct declarations such as `int *x[3]`, `int (*x)[3][3]`, `int (**x)(int)`) in up to eight `sizeof` contexts (`x`, `*x`, `**x`, `***x`, `x[0]`, `x[0][0]`, `(*x)[0]`, `*x[0]`): 106 probes, each size also computed by the system cc. Baseline for the shipped product: 83 OK, 23 REFUSE, **0 WRONG**.
  - **WRONG set (silent wrong code): empty** after the M3 refusal. Before it, `int (*x[3])[3]` probes 083 and 084 gave 4 for 12 (the baseline then read 86 OK / 18 REFUSE / 2 WRONG).
  - **REFUSE set (23 probes, all named, none produces code):**
    - `not covered: pointer to pointer to array`, declaration `int (**x)[3]`, probes 069-076 (all eight contexts).
    - `not covered: array of pointers to arrays`, declaration `int (*x[3])[3]`, probes 077-084 (all eight contexts, including plain `sizeof x`, which was correct before M3 and is now refused with the rest of the shape).
    - `not covered: sizeof operand`, seven probes: `int *x[3]` with `**x` (016) and `x[0][0]` (018); `int **x[3]` with `**x` (046), `***x` (047) and `x[0][0]` (049); `int *(*x)[3]` with `***x` (055); `int *x[3][3]` with `***x` (063).
  - What is not covered by the probe set: other base types (`char`, struct), `A2` and multi-dimensional shapes beyond the above, global/local/parameter/member/typedef contexts, decayed use, calls and run-time subscripts. A shape outside the set can still be wrong. The probe set is extended in 0.0.44 (roadmap R0b).
  - The fix is a canonical type descriptor (TDESC) as the single source of sizes, planned for 0.0.44. A WRONG may only turn into OK that way, never by another path patch; the ratchet reports any change of verdict in either direction.
- **Classic reference: 13 WRONG, 8 REFUSE (the same probe set).** The classic reference compiler gives silently wrong `sizeof` results on 13 probes: 055 and 063 (`***x` as above); 079, 082, 083, 084 (`int (*x[3])[3]`: `**x`, `x[0][0]`, `(*x)[0]`, `*x[0]`); 085-087, 089-092 (`int (*x)[3][3]`: `x`, `*x`, `**x`, `x[0]`, `x[0][0]`, `(*x)[0]`, `*x[0]`). It refuses 069-076 (`int (**x)[3]`) by name. The system cc and the Python reference give the model size on all 106 probes; the product refuses 055 and 063 (`not covered: sizeof operand`) and 079, 082, 083, 084 (`not covered: array of pointers to arrays`), and gives the cc size on the other seven, so it is the classic route that is wrong. Related and logged, not fixed: the classic reference mis-sizes `int (*)[3][2]`, `int (**)[3]` and `&*row` (`tests/c/candidates/sizeof-rows-classic-gaps.c`). Classic is a ratcheted reference (`tdescprobe-classic`), not the shipped compiler; it is fixed in 0.0.44 (roadmap R9).
- **Hexadecimal and other non-decimal immediates in Tape (hex-A′).** `imm r2, 0x1f` (and `0b`, `0o`) is accepted by the Tape domain, `-S`, `-c`, the classic compiler and the Python reference, but the back end refuses it with `not covered: an operand that is not a register or an integer` on `-run`, `-o` and `-b`; the image route accepts decimal only. This is a named refusal, not wrong code. Planned for 0.0.44; the fix must carry the C readers (`ts_integer` accepts decimal and `0x` only) in the same change.
- **Data extents of 2^31 and above.** A Tape `.bss`/data extent of 2^31 or more is refused by the model with `not covered: tape data directive` on both the text and the Tapebin routes. The classic compiler and the Python reference accept it, so this is a registered reference-wide, product-strict split, kept as a refusal on purpose (extending the table to a 64-bit extent range needs a separate decision). A Tapebin length of 2^63 or more is `invalid tapebin` on both C readers.
- **Windows `.hostcall`/`.hostaddr` library-mode qualification remains incomplete.** This contract (spec L-4) has no explicit mode, target or capability input yet. On win/x86_64 the product and the classic compiler write the same image for a tape with `.hostcall`, while the Python reference refuses it (`foreign host ABI is only supported on osx or lnx`). Until the references agree, acceptance of these library-mode images cannot count as a product pass. Their native execution has not been established for the final candidate. This limitation is separate from the required six-platform candidate CI.
- **Late binding beyond ordinary functions and data.** The `library/bindings` and `codeprivate` paths still embed host addresses (`libunisacc.c` passes the exit/mmap/munmap callbacks, the `process/dl` slots and the callable dispatch to lower as scalar resources; typed, variadic and callback bindings are frozen with the bridge dispatch addresses; spec LB-1 end). Fixed typed binding (2c2) exists only in a `--librarytyped` build and is not in the shipped product; the callback and variadic migrations and the `-run` host bridge stay on the old path (LB-4). Their status table is in `research/c43-latebind-status.md`; rows that were not run are UNVERIFIED there and are not claimed here.
- **Building the library runtime on glibc.** `exec/c/libraryresolver.h` uses `RTLD_DEFAULT`, which glibc only defines under `_GNU_SOURCE`, and `-std=c11` does not define it; the library checks need `libffi-dev` and `-D_GNU_SOURCE` on Linux. Ruled by cc (2026-10-23, source-side): `exec/c/libunisacc.c` defines `_GNU_SOURCE` on Linux before its first header, so only `libffi-dev` remains a host requirement; the carried headers never test `_GNU_SOURCE`, so unisacc-built bytes do not change.
- **Timeout and resource qualifications.** R11 records the accepted H1 timeout obligations for `exec-selfelf`, `exec-selfelf-package` and `exec-driver-core-build`; the final exit table must identify their actual outcomes on the final inputs. An H1 timeout is not a PASS. Resource checks classified `RESOURCE_UNKNOWN` retain their OPEN execution obligation under `research/c43-resource-disposition.md`; they are not passed or silently omitted. Final members, counts and dispositions remain pending complete M7 results. Other failures and unlisted timeouts require their own disposition.
- **Ledger corrections completed.** The eight parse2 fresh-order rows were attributed to the bit-field promotion repair, independently regenerated and checked with the original binding-swap negative. Freezecheck uses an explicit freeze start; TP-9 and the Tape documentation now agree on underscore-integer refusal. The corresponding gates passed in the recorded F3 sweep; the current F4 rerun retains those obligations.
