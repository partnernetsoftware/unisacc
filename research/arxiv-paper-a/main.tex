\begin{abstract}
unisacc is a neural-network-based compiler: compilation stages run on integer threshold networks and one generic executor; weights are constructed from a TSV table DSL, not trained. T1 is key-by-key equality on the declared domain (Definition~2), not sample fit. The decision-network instance is 18 decision stages. The network-compiler instance is seven byte-stream stages: preprocess (pp), lex, parse, opt, prune, lowering, encode + image (enc). parse2 is an implementation name of the same contract, not a separate stage. An out-of-domain key fails; logits are not read; rejection does not fall back to the table. N1 = N2 = N3 is unsigned successive-generation byte identity on five named targets (osx/arm64, lnx/arm64, lnx/x86-64, win/arm64, win/x86-64), not a semantic self-host. Key identities: op-74 totals 8,509 keys; the op-87 label total is 8,769 keys; not interchangeable before a seal. Source \texttt{910f1e0a} / \texttt{0.0.42} is not a sealed release measurement. The referee ledger is \texttt{research/referee.tsv}. This paper's contribution is constructed exact integer decision networks checked by exhaustive T1. Learned training comparison is not in this paper; see preregistered study A2. Enumeration proves network = table, not table = C.

\medskip
\noindent\textbf{Keywords:} neural-network-based compiler; constructed weights; T1; byte-for-byte self-hosting; N1=N2=N3
\end{abstract}

\section{Contributions}\label{introduction}

\begin{enumerate}
\item \textbf{Method.} TSV table DSL $\to$ constructed weights $\to$ exhaustion on the declared domain (T1). The weights are not trained.
\item \textbf{Two layers.} The network-compiler contract is seven byte-stream stages: one generic executor $E$ runs finite transitions $\delta$. The decision-network instance is 18 decision stages, queried at ask points or via the enumerated DENSE table.
\item \textbf{Implementation.} unisacc, a six-target C99 subset. The decision-network instance self-hosts byte-for-byte on five targets without Python. The six shipped targets include osx/x86-64; the five-name N1 list does not. Network-compiler driver self-host is not package self-construction. Source identity: Appendix~\ref{artifacts-and-evidence}.
\end{enumerate}

This paper's contribution is constructed exact integer decision networks checked by exhaustive T1. Learned training comparison is not in this paper; see preregistered study A2.

Not claimed: table = C99, whole-compiler semantic preservation (T3), or a speed advantage.

\section{Definitions}\label{problem-formulation}

\textbf{Definition 1 (decision stage).} Stage $s$ has fields $(f_1{:}V_1,\ldots,f_m{:}V_m)$, output vocabulary $Y$, and total $G_s:K_s\to Y$ on the finite product $K_s$. These 18 stages are the decision-network instance, not the seven byte-stream stages.

\textbf{Definition 2 (exact / T1).} $N$ is exact for $s$ iff for every $k\in K_s$, $\operatorname{argmax} N(k)$ is unique and equals $G_s(k)$.

\textbf{Check / artifacts.} \texttt{python3 -m unisa build-weights --from-tsv --check} compares TSV-built weights with the shipped file and writes nothing. \texttt{python3 -m unisa acc} enumerates the declared domain; an error or a tie fails. The reading is T1 = 1.000. Tables are \texttt{weights/gold/*.tsv}. Constructed weights are \texttt{weights/built.json}.

\textbf{Definition 3 (query discipline).} Use only $\mathrm{ask}(s,k)$. Do not read logits. Do not fall back to the table on rejection. $k\notin K_s$ fails. On the normal C path, DENSE is the shipped lookup enumerated from the network. Rejection and out-of-domain failure still do not fall back to the gold table.

\[
\mathrm{Compile}(x)=\mathrm{dec}(\mathrm{Run}_{E,\delta}(\mathrm{enc}(x))).
\]

$\delta$ takes the control state plus one finite observation and returns the next state and an action-sequence index. $E$ performs storage, stack, and output only. A TSV row \texttt{state, observation, next, actions} expands to a finite total $G_s$; the constructor emits $N_s$; the check proves only $N_s=G_s$. DSL syntax and the T2/T3 obligations are in \texttt{research/paper-a-notes.md}. T2a, T2b, and T3 are not theorems of this paper.

\section{Construction}\label{weight-construction}

A one-hidden-unit-per-key one-hot construction yields an exact network of width at most $|K|$ (Lean \texttt{naive\_exact}). Shipped decision stages use a cube cover: the hidden layer is a Boolean conjunction and the output layer an integer vote (cube cover; details in \texttt{research/paper-a-notes.md}). The parameter count 796,490$\to$71,828 in the notes is not a new measurement on this tip. \texttt{decision\_list\_exact} covers only the globally monochrome first-hit case and does not prove the shipped networks. The release check is the integer network with strict argmax on the declared domain; a wrong answer or a tie rejects the build.

The op-74 total of 8,509 keys and the op-87 label total of 8,769 keys are two identities and are not interchangeable before a seal. On this tip the live \texttt{weights/gold} eighteen-stage \texttt{\#field} domain product is 8,770 (against 8,769 in \texttt{research/seal-remeasure-20261009.md}; the difference is opinfo 72$\to$73; the header of \texttt{weights/gold/opinfo.tsv} says 73 keys). Hidden units total 569, matching the README stages table and \texttt{weights/built.json}. 8,770 is not 8,509 and is not written as the label 8,769. combo is an isel$\cup$abi control and is off the ship path; the census total below includes that row.

Exactness is constructed. The weights are derived from the gold tables (\texttt{weights/gold/*.tsv} is the tables as data): $W_1\in\{0,1\}$, $b_1$ is recoverable from $W_1$, and $W_2$ is a small power of two. The hidden activation is always 0 or 1, so inference has no multiply and no float. Verification is exhaustive. Each stage is a total function on a finite domain, so network = table is decided by enumerating every key (the total is the table above). That does not prove table = C. Whether the table is right about C is checked separately against the system compiler (\texttt{tests/gold\_audit.py}, \texttt{difftest}).

The deployment kernel is integer: one-hot, integer affine, ReLU, integer affine, strict argmax. No softmax, floating point, multiplication, or libm. The same table constructs the same weights. This paper does not quote a weight-byte total.

\section{Seven byte-stream stages and two instances}\label{from-decisions-to-a-pipeline-the-network-compiler}

The decision-network instance is 18 ask stages. The network-compiler instance is the seven stages below. They are not interchangeable. Each stage is a constructed integer threshold network run by one generic executor. parse2 is an implementation name of the same contract, not a separate stage.

\begin{center}
\footnotesize
\begin{tabular}{p{0.22\textwidth}p{0.34\textwidth}p{0.36\textwidth}}
\toprule
stage & input $\to$ output & role \\
\midrule
preprocess (pp) & source bytes $\to$ preprocessed text & line continuation, comments, directives, macros, conditionals, includes \\
lex & preprocessed text $\to$ typed token stream & keywords, identifiers, operators, literals, longest match \\
parse & token stream $\to$ tape & declarations, scopes, types, precedence, statements, init, calls \\
opt & tape $\to$ tape & peephole / stack-to-reg style rewrites on tape \\
prune & tape $\to$ tape & drop unreachable whole functions on image/run routes (public tape out skips prune) \\
lowering & tape $\to$ target ops + data & ABI, regmap, syscalls, layout, reloc \\

\bottomrule
\end{tabular}
\end{center}

The short names pp, lex, parse, and enc may match names of the 18 decision stages. They are the seven-stage byte-stream contract and are not interchangeable with the ask-domain tables.

The tape has eight 64-bit registers and 71 operations in \texttt{SHAPE}. The executor has no primitive for C, the tape, an ISA, or an image format.

The decision-network instance calls \texttt{ask} from classic recursive descent, lowering, and image writing; no fallback. The network-compiler instance runs the seven stages; a model rejection is an error. This tip has no same-identity size or speed measurement; this paper claims none.

Threshold-prefix evaluation and declared returns do not change network answers: same network, same sum; the network--table check still covers every observation, including returns. Host code still loads packages and retains \texttt{src/tapelink.c}, \texttt{src/asmtext.c}, and \texttt{src/fwdstub.c}. Build-time Python is in the trusted base.

\section{Self-host, T1, and referees}\label{implementation}

Decision-network instance, byte equality:

\begin{enumerate}
\item Front-end fixed point: A compiles itself to B, B compiles itself to C, B = C, and both match the Python front end.
\item Back-end closure: 94 probes $\times$ 6 targets, 564/564; the compiler itself 6/6.
\item No Python: N1 = N2 = N3 on osx/arm64, lnx/arm64, lnx/x86-64, win/arm64, and win/x86-64 (the last under system emulation).
\end{enumerate}

N1 = N2 = N3 asserts only unsigned successive-generation identity. The network compiler's driver self-host is N1 = N2 = N3 on macOS arm64 for a fixed network package and does not construct that package.

T1 runs every cube network with deployment arithmetic on every key of its declared domain; an error or a tie fails construction. On the normal C path the decision-network instance reads DENSE and compares table lookup with direct inference.

Six-target fold: the machine model recognises only the (OS, call number) from lowering. The six (stdout, exit) pairs agree with each other and with a tape reference VM. Clearing the class bits of macOS system-call numbers must yield 4/6. This tip has no native-versus-emulation matrix.

The ledger is \texttt{research/referee.tsv}: eight stages have named external referees, six have only cross-implementation agreement, and two have no direct referee yet. So 8/18 stages have external referees. The rows below are the external entries. The table is a pointer, not a proof of C.

\section{Boundaries}\label{discussion-and-limitations}

Systematic construction-versus-training comparison is preregistered study A2. This paper has no training table.

The verification discipline has exposed cross-table combination gaps under one identity. Details are in \texttt{archive/research/r20/design-review-2026-10-01.md} and \texttt{research/paper-a-notes.md} and are not restated here. T1 asserts only network = table on one table's declared domain.

This tip has no same-identity census of the seven stages, no speed measurement, and no platform matrix. The corpus does not extend to arbitrary C99. Build-time Python is in the trusted base.

Related work, as pointers only: exact network encodings of finite-state machines \citep{omlin1996,siegelmann1995}; weights constructed from programs \citep{weiss2021,lindner2023}; table-driven compilers \citep{johnson1975,glanville1978,fraser1992}; trained controllers \citep{graves2014}; proved semantic preservation \citep{leroy2009,kumar2014}; diverse double-compiling \citep{wheeler2009}. Gradient-method failures are left to A2.

\section{Conclusion}\label{conclusion}

On table-shaped decisions, exactness is decidable by exhaustion. unisacc runs constructed weights on two layers: 18 decision stages, and seven byte-stream stages. The decision-network instance meets N1 = N2 = N3 on the five targets in \S\ref{implementation}. Whether a table equals C is answered only by the named referees, inside their coverage.
