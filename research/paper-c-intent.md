# Paper C 意向书：种子机与迭代脱离——把"确定性模型推理替代编译"推广为管道方法

**状态**：意向书（2026-09-25）。不是草稿，也不做任何结果声称。
**关系**：独立成文。引用 Paper A（[`unisacc-paper.md`](unisacc-paper.md)，C99 编译器）与 Paper B（[`ujs-paper.md`](ujs-paper.md)，UJS → WebAssembly），把两者当作**两个已完成的实例**，而不重复它们的内容。

---

## 1　一句话

任何"把一种输入确定地变成另一种输入"的系统，都可以拆成两类环节来建：一类是有限键到有限类的**表状决策**，交给构造出来的精确网络；另一类是**结构性粘合**，交给经典代码。对一个新场景，只需要先造出第一阶段的**种子机**。此后系统在自己的产物上迭代，每一代都用逐字节不动点来检验，直到不再依赖种子机。

## 2　动机：A 与 B 都走过同一条路

| | 种子机（第 0 代） | 脱离种子的证据 |
|---|---|---|
| Paper A | Python 前后端与构造器 | C 写的 unisacc 用自己的后端造出自己，N1 = N2 = N3 逐字节相同，在五个真实目标上全程无 Python（A-35）；Python 退为参考实现与回退手段 |
| Paper B | Python 构造器与 path-B 模拟 | `compiler.wasm` 与 `compiler.ujs`，stage2 ≡ stage1（ujs M3） |

两条线都不是事先设计成这样的，而是边做边收敛到同一个形状。Paper C 的任务是把这个形状**明确写出来、证明它、再验证它能迁移**。

## 3　方法（待严格化）

1. **分而治之**：把目标管道 P 写成阶段的组合 P = g_n ∘ t_n ∘ … ∘ g_1 ∘ t_1。其中 t_i 是有限表（键模式 K_i → 类 Y_i），g_i 是结构代码。每张 t_i 按 Paper A 的方法构造，并在 K_i 上枚举证明精确。
2. **种子机**：第 0 代用任意方便的语言实现 g_i，并**询问**同一批 t_i 网络。它的唯一职责是造出第 1 代。
3. **迭代脱离**：第 k 代由第 k−1 代产出。当第 k 代和第 k+1 代逐字节相同，并且在第 k 代的构建路径上已经没有种子的任何成分时，就称系统**脱离了种子**。
4. **孪生检验**：脱离之前，种子与后代并存。每项改动都要求两者输出逐字节一致，例如 Paper A 的 closure、stages、optpy。这是防止两份实现各自漂移的机制。

## 4　需要的理论

- **组合精确性**：每张 t_i 在 K_i 上精确，并不能推出整条管道精确。还需要**定义域闭包**：对一切合法输入，g_{i−1} 交给 t_i 的键都落在 K_i 之内。Paper A 在运行时用 P-2 断言检查这一点，Paper C 需要把它变成可证明的性质，例如对每个 g_i 做类型或抽象解释意义上的论证。
- **不动点与可信度**：G1 造出 G2、G2 = G1 逐字节，这只说明 G1 是**一个**不动点，不说明它**正确**。这里要正面处理 Thompson 的 *Reflections on Trusting Trust*，并考虑用 Wheeler 的多样双编译（diverse double-compiling）作为证据形式。种子与后代是两份独立实现，恰好提供了"多样"这一条件。
- **确定性**：构造是确定的（同样的 gold 得到同样的权重字节），推理只用整数（无浮点、无乘法），因此结果跨机器可复现。需要证明，逐字节闭环成立的前提正是这两点。
- **表与裁判**：枚举只证明"网络 = 表"，不证明"表 = 语义"。每张表都需要一个外部裁判：语义表对照参考实现（如 A 的 gold_audit 对照 cc），代价表对照实测（如 A 的 pow2→shl 被实测否决）。Paper C 需要把"裁判"形式化为方法的一部分。
- **脱离的判据与代价**：种子何时可以删除？删除之后，改动靠什么验证？候选答案是：保留冻结的种子作为第二实现，只用于双编译检验，不再承担开发。

## 5　实践计划（至少三个新场景）

新场景要求：不能是编译器本身，并且管道里既有表状决策也有结构。候选：

- 汇编器或反汇编器（编码表天然是表；可复用 A 的 I5 编码规格表）；
- 正则或词法生成器（状态转移是表）；
- 协议或文件格式解析器（字段分派是表）；
- 构建系统的依赖求解（规则匹配是表，图遍历是结构）。

每个场景都报告同一组指标：种子的规模、表的数量与键数、到达不动点所需的代数、脱离后孪生检验的覆盖面，以及失败案例。

## 6　风险

- 组合精确性的证明可能只对一类"键由结构直接投影出来"的管道成立，需要如实界定适用范围；
- 有些场景没有自然的"自产"回路（产物不是自身的实现语言），这时"脱离种子"需要换一个判据，例如由场景的产物驱动下一代的构建工具；
- 实践越丰富，越容易把工程技巧误写成方法。所有声称都只绑定到可重跑的门禁，不写未经测量的数字（沿用 Paper A 和 B 的规则）。

## 7　与 A、B 的边界

A 和 B 各自证明"方法能做成一个编译器"。C 不再证明这一点，而是回答三个问题：**它为什么能推广、推广需要满足什么条件、推广的步骤能否机械化**。A 和 B 只作为证据被引用。
