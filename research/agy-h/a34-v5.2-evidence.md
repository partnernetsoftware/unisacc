## (4) 实测通过的无冲突登记与门禁重放命令序列

已在全新 `9f3bd3225` 私有 git 仓依次实跑通过 (`REG_MANIFEST bad=0 hard=0`, `PRECOMMIT staged_cx=9 blocked=0`)。说明: 因 `check-nn-external-e2e` 含 `{candidate}` 占位且检验候选新行为, `tools/register.cx` **必须带 `--no-run`** (不带 `--no-run` 时 `register.cx` 会用尚未含 A3-4 v5.2 的已装产品去跑 `check-nn-external-e2e` 而红 21 项), 实际 E2E 证据由构造候选后跑 `check-nn-external.cx -- --e2e <cand>` 产出:

```sh

  check-nn-external-e2e \
  tools/check-nn-external.cx \
```

## (5) 已知缺口清单 (实话实说, 均不以等价名义掩盖)

- **幸存变异 `25, 26, 29` (`cx/driver/nnext.cx`) 未击杀 (明确列为验证缺口, 不当等价)**:
  - `25` (`cx/driver/nnext.cx:87` `for (i = 0; i <= cxn_nsnaps; i++)`): 当 `cxn_nsnaps == 32` (满 32 槽) 时 `<=` 会越界读取 `cxn_snaps[32]`, 属 C 未定义行为越界读, 当前普通运行无 ASan/MSan 内存检测故未触发崩溃。
  - `26` (`cx/driver/nnext.cx:88` `if (!(cxn_snaps[i].buf))`): 反转释放条件会漏放所有非空模型负载缓冲造成堆内存泄漏 (并对空指针调用 `mm_free(0)`), 当前单测无分配计数配对或泄漏检测钩子故未转红。
  - `29` (`cx/driver/nnext.cx:151` 删 `cxn_find_snap` 末尾 `return 0;`): C 层控制流到达函数结尾不返回值属未定义行为 (碰巧在 x86_64/gcc 下 `%eax` 残留上一次 `tx_eqz` 为 0 而通过), 无等价保证, 未被编译期 `-Werror=return-type` 或运行时独立检出。
- **其余未击杀变异 (`15, 17, 28, 33, 38, 39, 45`) 与覆盖边界**:
  - `15` (`cx/sys/fs.cx:164` `n == 1`) 在 Linux `/proc/self/exe` 上不可观测; `17` (`cx/sys/fs.cx:158`) 位于 Darwin `__APPLE__` 条件分支。
  - `28` (`cx/driver/nnext.cx:163` `"invalid nn stage namX"`): 前序 `cxn_valid_stage()` 已在 `nnext.cx:371` 以 `"invalid nn stage"` 拦截坏名, `cxn_alloc_snap()` 第 163 行的 `"invalid nn stage name"` 属于冗余防守死分支 (未达断言)。
  - `33` (`cx/driver/runsplit.cx:467`), `38` (`cx/sys/fs.cx:165`), `39` (`cx/sys/posix.cx:142`), `45` (`cx/driver/nnext.cx:113`) 为未补强负控的边界/错误路径缺口; `src/*` 的 9 个 E2E 函数由 `{candidate}` 批覆盖, 未纳入单位补丁 `mutation-gate --coverage-check`。
- **平台与运行时合同边界**:
  - Darwin / Windows 真实硬件构建与运行未执行 (`UNMEASURED`), `-ENOSYS` 回落与显式硬拒仅在源码与 Linux `-ENOSYS` 模拟构造上验证; 默认普通编译 (`未设 UNISACC_NN_DIAG`) 回落内嵌时不向 stderr 输出额外提示以保输出逐字节兼容。
  - `nnext.cx` 末尾 1 字节 EOF 校验 (`tr != 0`) 仅在读取期间文件增长竞态下可达, 常规单线程回归未覆盖。
  - 外部 `e2.nb` 在场时 `-E` (`rc=0`) 输出 `UNIPP2` 帧 (`17932B`) 为预存路由-阶段名绑定问题 (非本补丁引入)。
  - 显式 `--nn-dir` 指向不存在目录按 5 态合同视作 `ABSENT`, 静默回落内嵌并放行缓存。
  - 同尺寸原地覆写 (非原子 rename 替换) 不检测, 已在合同注释与 `same-size-inplace-overwrite` 记录中明示 `UNSUPPORTED-DOCUMENTED`。
