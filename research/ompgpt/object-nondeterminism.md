# v0.1.0 单元对象跨源码目录不可复现

已证实：公开候选 APE、`pkg.bin`、源码提交及编译选项相同，源码绝对目录变化仍使中间对象字节变化。固定同一源码路径、重新生成到空输出目录则 102 件逐件 SHA 相同。结论只涉及中间对象，不否定整链 g2/g3 最终镜像固定点。

| 独立对照 | 同摘要 | 摘要不符 | 读失败 |
|---|---:|---:|---:|
| 首份 r1 对历史清单 | 0 | 102 | 0 |
| 异源码根复构对 r1 | 0 | 102 | 0 |
| 固定源码根复构对 r1 | 102 | 0 | 0 |

`args.o` 在两个新源码根下分别为 118360 与 118384 字节。`cmp -l` 首差是从一开始数的第 41 字节，即 ELF64 `e_shoff` 的低字节。段头表起点 `0x1cb78` 与 `0x1cb90`。第一个内容不同的节是 `.unisa.tape`：两份都位于 `0x93b3`，长度 `0x137c0` 与 `0x137dc`。直接 `cmp` 证实此前 `.text/.data/.rela.text/.symtab/.strtab/.shstrtab` 字节一致，移位后的 `.init_array` 与其重定位内容一致。

tape 文本的 `UNISATAPE1` 长度变化与两个 `.unit` 记录吻合；两处十六进制各自解码到 `<root-a>/src/driver/args.cx`、`<root-b>/src/driver/args.cx`，每处差 7 个路径字节，十六进制差 14 个字符，两处合计 28 字节。样本差异是绝对源码路径元数据，不是机器码或时间戳。冻结版 `src/runcache.cx:597` 已明确相对与绝对路径可令 `.unisa.tape` 不同。未找到符合历史 SHA 的旧 `args.o` 副本，不能声称历史对 r1 的全部差异也只来自路径；历史构造器为 gen1，r1 使用公开 APE。

风险：分发中间 `.o` 或转存 tape 可能泄露构建路径，跨根字节比较与按内容复用也会受影响。三版已公开资产路径扫描零命中，范围见 `public-asset-path-audit.md`。

交 fable 的 v0.1.4 选项：对声明源码根内的单元，`.unit` 只编码规范仓相对身份，诊断路径与可链接载荷分离；构造缓存键绑定路径规范版本。根外依赖不得压成 basename，须有显式稳定映射或在发布构造具名拒绝。验收：两个不同绝对根用同一冻结输入分别构造，102 件 SHA 全等，合并 tape 无绝对根，路径同名不同单元及根外输入负控分别验证，六片 g2/g3 与现有诊断合同重验。未改产品。
