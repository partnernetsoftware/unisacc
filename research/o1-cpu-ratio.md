# O1：产品编出的程序与宿主 cc 的纯 CPU 比率（0.0.27，2026-10-05）

同一份 C 源码，分别用宿主 cc（Apple clang）`-O2` 和 unisacc.com 0.0.26 `-O2 -o` 编成 macOS arm64 镜像，各运行一次，取 `/usr/bin/time -p` 的 user 时间。两边输出逐字节相同。机器：本机 M 系列，负载约 2–3。单次计时，只能看量级。

| 程序 | 内容 | cc -O2（秒） | unisacc -O2（秒） | 倍数 |
|---|---|---|---|---|
| fib | 递归 fib(36) | 0.02 | 0.08 | 约 4 |
| sieve | 埃氏筛 6000 万 | 0.18 | 0.48 | 约 2.7 |
| matmul | 400×400 double 矩阵乘 | 0.04 | 0.26 | 约 6.5 |
| hash | FNV 风格整数循环 3 亿次 | 0.28 | 1.65 | 约 5.9 |
| qsort | 500 万个 int 用自带 qsort 排序 | 0.40 | 2.20 | 约 5.5 |

结论：产品编出的代码比 clang -O2 慢 3–7 倍，内层整数循环和浮点循环差得最多。0.0.26 里 seed/gen.c 慢约 9 倍，主要是重复读 facts（cdx 已用缓存解决），不是这个比率本身。

后续可做的（未排期）：内层循环的寄存器分配、循环不变量外提，以及 qsort 的比较回调开销（自带 qsort 每次比较都经过一次通用调用）。源码在仓外的临时目录，要复现就照表里的描述重写。
