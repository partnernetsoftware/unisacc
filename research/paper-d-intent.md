## 1　一句话

在"表状决策交给构造网络、结构性粘合交给经典代码"的编译流水线里，加一个默认开启、可一键关闭的内存安全节点：**推断**（所有权 / 生命周期 / 边界的标注）是表状决策，交给模型；**验证**（逐函数检查标注成立）是经典代码，确定性、可审计，绝不交给权重；验证通过的函数按原生速度编译，未通过的自动补运行时检查（严格模式则拒绝编译）。现有 C99 代码不改一行，就得到分级的、可解释的安全保证。

## 2　为什么是这个分工

| 环节 | 交给谁 | 理由 |
|---|---|---|
| 标注推断 | 网络（有限键 → 有限类，穷举验证） | 与 Paper A 的每一张表同构；错误的推断只会导致"需要运行时检查"或"严格模式被拒"，不会导致漏报 |
| 标注验证 | 经典检查器 | 保证的来源；构造网络也可精确实现给定验证表，但网络与表相等不能证明验证规则健全。此方案选择小型经典检查器作为独立可信基，须有健全性论证与独立测试 |
| 运行时后备 | tape 安全模式（胖指针：边界 + 生命周期） | 让"未证明"也安全，只是慢；这是 Rust 没有的退路 |

目标是在声明的语言子集与威胁模型下证明漏报为 0；目前尚无该证明，不能作为已实现保证。误报（安全却未能证明）与性能开销是可量化、可逐版收敛的指标。

## 3　三步（每步单独成立）

1. tape 运行时安全模式（Fil-C / CHERI 思路）——先服务 `-run` 与 agent 沙箱。
2. 最小标注规则与检查器（Cyclone / Checked C / Rust 借用检查的最小交集：释放后再用、越界）。
3. 模型自动补标注；在 Lua 5.4 与 SQLite 上量可证明比例、误报、开销。

## 4　需要的理论

- 标注语言的健全性：检查通过 ⇒ 无第 1 步可捕获的错误（对所选 C 子集与 ABI 给出证明或明确的假设清单）。
- 推断表的定义域：什么样的键（函数局部的形状特征）足以决定标注；域太大时如何分表（同 Paper A §5 的分表方法）。
- 分级编译的正确性：同一函数在"已证明 / 运行时检查 / 拒绝"三种处置下语义一致。

## 5　实验与可复现性

- 红例集（越界、UAF、双重释放、悬垂返回、整数溢出导致的越界）与它们在三种模式下的行为矩阵。
- Lua 5.4、SQLite、miniz：可证明函数比例、运行时检查覆盖的函数比例、性能（纯 C / 安全模式 / 分级）。

## 6　与先行工作的关系与风险

- Rust：安全靠重写；这里靠不改代码的推断 + 后备。CHERI：靠硬件；这里靠 tape 与运行时。Checked C / Cyclone：靠手写标注；这里标注由模型补、由检查器验。Fil-C：全部运行时检查；这里把已证明的部分还给原生速度。
- 风险：推断表的域可能不够"有限"；C 的别名与不定长数组让健全性证明的假设清单变长；性能后备可能过慢以致默认开启不被接受。每一条都对应第 3 节的一步作为止损点。
