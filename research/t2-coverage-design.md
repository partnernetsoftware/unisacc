# T2 design: manifest-row coverage + witness (read-only study, nothing implemented)
Legend: [R] verified by reading code; [G] guess / not measured. Measurements run: none (only wc/grep).

## 0. What a "row" is (proposal)
Three row kinds feed edges [R]:
- (a) leaf rule rows: 4 columns `state keys target actions` in `exec/<stage>/*-byte.tsv|*-result.tsv` (section form: 5 columns), parsed by `finite_rules.load` (exec/finite_rules.py:108-170; lineno known at :111, dropped on return at :200 `return explicit`).
- (b) template rows: 9 columns in `*-template.tsv`; `expand_template` (finite_rules.py:293) keeps `lineno` per block body (:309,:311) then emits synthesized 4-col `lines`, which load() re-numbers (install_template :458-466 passes `lines=`), so original lineno is LOST at load.
- (c) manifest DSL rows (exec/DSL.md §2-3; 9 ops). Most are glue (let/call/foreach/holder = 1300+ of ~2500); only `rows`/`table`/`template` create edges. Coverage unit for (c) = the `rows`/`table`/`template` line, derived from (a)/(b) hits, not separate.
Row counts incl. comments-stripped, all four suffixes+manifest [R, via wc]: pp 1936, lex 315, parse2 10281, enc 3437 (incl. enc/arm), lower 1328 (~17k lines total, upper bound; includes glue). Facts rows (exec/facts/*.tsv, 210 files) are data, not rules: report separately, out of slice 1.
Row-to-edge is many-to-many: one row with keys `*`/ranges/@class covers up to 257 keys; `defaults` fill gaps (load :186-193). So a row is covered iff ANY of its (state,key) edges is hit; also report per-row key fraction [design choice].

## 1. Row -> transitions in the built graph [R]
- Entry: exec/build/gen.py:44-59 loads base executor E, `assemble.Run(E,E.P,flags,E.results).run(man)` (gen.py:59); graph is `E.g` (G or Delta, exec/build/graph.py:12/68). Output JSON = {start, states{name:[mode,{key:[next,seqid]}]}, seqs} (gen.py:64-66). No provenance in the JSON.
- Op `rows` -> `install_rows` (finite_rules.py:212) -> `g.on(state,[key],target,actions,mode)` per key (:221). Op `table` same; op `template` -> `install_template` (:458) -> `g.on` (:466), then graph edits (alias/label/split-at/rewrite-tail, :470-) and `_companions` (:402-) rewrite seq ids of existing edges AFTER install. Edges keep identity (state,key) through these; only the seq id changes. [R]
- Edge-ownership rules: `G.on` (graph.py:25-32) is first-writer-wins per (state,key); `Delta.on` (:76-79) is last-writer-wins. So provenance must be recorded AT the winning write, using each class's own rule. `G.finish` (:34-42) and `Delta.finish` (:83-) add DEAD/HALT "unreachable" edges (no row: report as `<totalised>` pseudo-row; hits there = reject path, count separately). `Delta.finish` also DELETES unreachable states (:101-102) -> those rows can never be hit: natural "dead row" finding.
- Fresh labels (`{fresh:SCOPE:KIND}`, assemble.py:201-204; procs.py counter n) make state names run-specific; keying provenance by state NAME is fine within one build, but a side table must be written by the same build that produces the JSON (not rebuilt separately; ordering of fresh is a contract, tests/freshorder.tsv).
- Existing provenance [R]: only the fresh-order recorder `UNISACC_FRESH_LOG` (exec/build/procs.py:10-26: atexit append of `n owner kind caller`, off by default; notes at :12-13 that manifest lines are unavailable because `rows()` in assemble.py drops them). No row->edge table exists. Mutation-based provenance exists only in tests/manifestentries.py (below).

### Cheapest recording point (proposal, [G] on effort)
Env `UNISACC_ROW_LOG=PATH` (off by default, same shape as procs.py:14). Hooks:
1. finite_rules.load: keep `lineno` -> store `prov[state][key] = (path.name, lineno)` in a module-level dict alongside `explicit` (3 lines at :187/:176/:182 where `row[key]=answer`; overlay path :170-172 too). Return value unchanged.
2. expand_template: it already has `lineno` per body row; emit a `# @src name:lineno` marker or return a parallel list `srclines` so `load(lines=...)` can map synthesized line i -> template lineno (small change at :309/:311 and install_template :461).
3. install_rows/install_template: where `g.on(...)` is called, append `(stage, state, key, file, lineno)` to a log ONLY if `key` not already in g.st[state][1]` (G) or always (Delta, last wins). Log written at exit as TSV: `state<TAB>key<TAB>file<TAB>lineno<TAB>seqid`. seqid recorded after finish via final graph lookup (companions change it), so write the log from gen.py after `E.g.finish` using the JSON states, not at g.on time.
Result: side file `<delta>.rows.tsv` next to the delta JSON, gen.py unchanged when env unset. gen.py:64 JSON stays byte-identical => no graph-hash impact. A gate check "provenance-neutral" = build with and without the env, cmp JSON.
Risk [G]: mode `overlay`, `skip`, `ordered`, DSL `with`/`classmap`/`domain_keys` change key sets between load and g.on; logging at g.on (not load) is therefore the safe point; load's prov dict only supplies (file,lineno) by (state,key) after binding substitution of `$state` names (load :121-125 rewrites state names; key by final names).

## 2. Running stages on inputs; where to count hits [R]
- exec/pipeline/run.py chains stages from exec/pipeline/stages.tsv (rows E2=pp, E1=lex, E3=parse2, then enc/lower rows); each row's `exec` is a Python sim: pp `exec/pipeline/simrun.py DELTA IN` -> exec/pp/sim.py:179 `run(delta,x,srcpath,files,cov,maxsteps,...)`; lex `exec/lex/sim.py:29 run(delta,x,cov,files,maxsteps)`. Both ALREADY accept `cov` (a set) and do `cov.add((q,key))` per step (pp/sim.py:212-213, lex/sim.py:61-62). exec/lex/compare.py:47 already accumulates one `cov` over many files. So edge coverage (state,key) for pp and lex needs no executor change, only a driver that passes `cov` and dumps it. [R]
- C executor exec/exec.c (244 lines) and exec/c/core.c (415): `m->keys/next/seq` lookup at core.c:57-63, no counters [R, grep found none]. Hit counts there = an `ifdef` counter array per (state,index); not needed for slice 1: Python sims are the declared reference for tables and judging "edge was taken" does not require trusting graphhash or product binaries (the sim reads the JSON built from the TSV; independent of the C kernel). [G: assumed sims for parse2/enc/lower expose the same `cov` hook; I did NOT read them. exec/parse2 and enc stage runners are via stages.tsv `exec` column; the E3 exec shares simrun.py/pp sim per stages.tsv line E3 [R]]. Set membership (state,key) loses counts; add `collections.Counter` only if frequency is wanted (not needed for covered/uncovered).
- Trust: judge = Python sim over JSON built from TSV with this repo's assemble.py. Ground truth for inputs = the files themselves. We do not need graphhash or ua_ref for COVERAGE (hit/not hit); correctness of output is a separate gate (existing difftest). Caveat: stages after pp need the previous stage's output; with `--ref-feed` (run.py) one can feed the reference stream, but that makes parse2 coverage depend on ua_tdump output (a Python/C artifact). To avoid it, chain our own pp->lex->parse2 outputs and count only inputs where the earlier stage accepted.
- Inputs: tests/c/*.c (219 files [R, ls]); corpus/c-testsuite has 220 .c files [R, find] (dirs: ci runners scripts single-exec tests).

## 3. tests/manifestentries.py today [R]
- 257 lines; per stage builds a private copy of exec/<stage>/*.tsv in a tmp dir (build() :25-60, extended_build :120-155), takes ONE production manifest row slice (`rows\tdirective-scan...` for pp :36-38; `call output / template gen dispatch` for lex :44), assembles a subgraph (no whole graph, no hash), asserts edges `edge(machine,state,key)==(target,actions)` (check_pp :68-80: 6 contracts; check_lex :82; check_extended :221 for parse2/enc/enc/arm/lower), then mutates one operand (`TAKEB=SEENB`, `change_rule` :99-117 for 4-col rules) and requires the same assertion to fail (main :237-255; <10 s per stage asserted :250). Gate jobs: tests/gate.sh:98-100.. `manifest-entries-<stage>`.
- Coverage: it covers a handful of rows (pp 6 contracts) by construction-time contract, not by running C. It cannot say "row X is unexercised".
- Reuse: (1) `build()`/`extended_build()` tmp-dir isolation + `assemble.run` on a row slice = the way to build a per-row ablation (mutation self-check = "deleting/mutating row r breaks witness w"). (2) `change_rule()` addresses a 4-col row by (file,section,state,observation) and asserts hits==1; extend it to address by (file,lineno) from the provenance table and to DELETE the row. (3) Use as the optional "witness is load-bearing" second tier (T2 wording: "delete the row => output changes"); expensive: one stage rebuild per row [G: parse2 build is the slow one; commit msg in finite_rules.py:~405 says ~19 s parse2 before memoisation], so only run it for a SAMPLE or per changed row, never all ~17k rows.

## 4. Minimal first slice: pp (1936 stripped lines over exec/pp/*.tsv [R])
Files to add (proposal):
- `tests/rowcov.py`: driver. `python3 tests/rowcov.py --stage pp [--shard i/n] [--inputs FILE-LIST] --out DIR`.
  1. Build delta with `UNISACC_ROW_LOG=DIR/pp.rows.tsv python3 exec/build/gen.py pp DIR/pp.json` (flags: default target lnx/x86_64 = the one in tests; also --osx/--win/--arm64 variants add rows only under flags: build all four flag sets and union row ids; 3 extra builds, [G] ~ few s each).
  2. For each input run `exec/pp/sim.run(delta, bytes, path, files, cov=set)`; per input record the set of covered (state,key) -> map to row ids via the side table; keep FIRST input per row as witness (stable sort by file size then name: smallest witness first).
  3. Write `DIR/pp.cov.tsv`: `row_id<TAB>file:lineno<TAB>edges_total<TAB>edges_hit<TAB>witness` (witness `-` = uncovered), plus `pp.totalised.tsv` summarising DEAD/unreachable edge hits.
- `tests/rowcov.json` or tsv ledger committed: `file:lineno -> witness` (the "见证" record) and a ratchet number `covered/total` per stage (like decisionledger --seedpy ratchet, commit aa09c970): gate fails if covered drops or an old witness no longer hits its row; uncovered rows listed as a `tests/rowcov-todo.tsv` ratchet that may only shrink.
- Row id = `<stage>/<file>:<lineno>` (lineno moves when the TSV is edited => ledger entries keyed by that + sha256 of the row text, so a moved row is re-matched by text, not number).
- Optional (not slice 1): C executor counter via `-DROWCOV` in exec/c/core.c:57-63 for the product path; second oracle comparing Python sim hit set to C hit set.
Expected time [G, unmeasured]: pp sim in Python is per-step interpretive; a typical tests/c file preprocesses in well under 1 s but there are 219 files + corpus; assume 0.1-0.5 s/file => 20-100 s unsharded for pp, similar order for lex, parse2 several x slower (10k rows, large graph load: json.load of the parse2 delta alone likely seconds [G]). Hence shard by input: `--shard i/n`, each shard writes its own hit-set (`cov.<i>.json` = sorted list of "state\tkey" or row ids); a final cheap `--merge` job unions shards (<5 s) and writes cov.tsv. The build step is shared: write delta + rows.tsv once (cached by input-hash, as with `exec/stamp.sh fresh`, run.py:51), shards load them.
Gate job shape (fits tests/gate.sh `job NAME cmd` form, gate.sh:98): `rowcov-pp-0..3` (each: load cached delta, run 1/4 of inputs, wall <=50 s via `tests/bound 50`, jobs 4 / window 50 rolling queue per CLAUDE.md), then `rowcov-pp-merge` (depends on the four; checks ratchet and witness stability), then analogous groups for lex/parse2/enc/lower. Shard count chosen so each shard measured <40 s; add an in-script watchdog on each sim.run (maxsteps param already exists, pp/sim.py:179). Gate deps must be declared in tests/gatedeps.json (the existing manifestentries entries at :23850-23885 show the form).
Build step ownership: delta build per stage may itself exceed 60 s for parse2 [G]; reuse the existing artefact dir via `exec/stamp.sh dir` (run.py:25-26) rather than rebuilding.
