# 编译 = 有限 δ 的反复推理：理论框架草稿

> 状态：草稿（2026-09-25）。本文是**待论证的框架**，不是当前产品事实。
> 当前的 unisacc 只有表状决策经由模型，解析走查、符号表操作、lowering、编码
> 模板和镜像写出仍是普通代码（见 §9 的差距清单）。并入论文 A 与否、如何并入，
> 由主人与 cdx-unisacc 决定。

## 0. 初心

**用确定性模型推理等价替代编译。**

论文 A 已证的是一步：在给定的键之下，构造出的网络与 gold 表逐项相等（穷举，
零分歧）。这不足以撑起初心，缺的正是“整个编译过程是模型推理”这一层。本文试图
把这一层补上。

## 1. 诊断：为什么代码一直没稳定

C99 的语法与语义要素是有限的，这个直觉是对的；程序的集合是无限的，这也是对的。
二者并不矛盾，因为有限的规则可以靠递归组合来处理无限多的程序。问题出在我们把
**组合**放在了哪里。

实测（2026-09-25，`src/*.c`）：编译器源码 11,002 行，其中查询模型或稠密表的
位置约 50 处。其余代码（递归下降走查、类型与左值的传递、下标展开、寄存器与栈帧、
优化、机器码拼装）都是手写的普通 C，**不受枚举保护**。

0.0.6 之后修复的正确性问题，没有一个出在表里：三维数组下标、经函数指针调用的
结果类型、`fwrite`、头文件被用户宏污染，全部发生在手写代码里。所以“一直在补救”
不是理论崩了，而是理论只覆盖了编译器的一小部分，其余部分只能靠测试撞出来。

要让“有限、可枚举完”对整个编译器成立，就得让编译器的**全部语义**进入一个定义域
有限的对象，然后枚举它。

## 2. 机器模型

编译器表述为一台确定性机器

```
M = (Q, Σ, Γ, δ, E, enc, dec)
```

- `Q`：有限的控制状态集合。
- `Σ`：有限的输入字母表（经词法编码后的记号类别，见 §2.1）。
- `Γ`：有限的栈字母表（返回点、有限取值的属性）。
- `δ : Q × Σ × Γ → Q × Act* × Out*`：转移函数，**这就是模型**。定义域有限。
- `E`：固定的通用执行机制，反复执行“读取可见符号 → 求 δ → 执行动作”。
- `enc`：源程序到初始存储的编码；`dec`：终止存储到目标镜像的解码。

编译 = `dec ∘ E(δ)* ∘ enc`。

### 2.1 前提：δ 只看有限符号（采纳 cdx-unisacc 的意见）

δ 的每一步只能看到有限多的有限符号：控制状态、当前输入类别、栈顶若干格。

**无界的对象不能直接作为 δ 的输入**：任意整数、任意地址、标识符的拼写、整棵
语法树。它们留在存储里，由执行机制按 δ 发出的动作原样搬运、比较或寻址；δ 只看到
它们的有限摘要（例如“这个标识符在符号表里是类型名”的一个比特、“这个常量能否
放进 imm12”的一个比特）。摘要怎样从无界对象算出，是执行机制的原语，必须单独列出、
单独证明（§3）。

## 3. 执行机制 E 与分界原则

E 不是“无语义”的：寻址、算术、读写、调度、失败处理都有操作语义。要求是 E
**固定、通用、与 C 无关**，并且**不做编译决策**。

原语草案（待逐项确认）：

| 原语 | 作用 | 给 δ 的有限摘要 |
|---|---|---|
| `next` | 读下一个记号 | 记号类别（`Σ` 中的一个） |
| `push q` / `pop` | 压入 / 弹出返回点或属性 | 弹出的栈符号 |
| `sym.lookup` / `sym.bind` | 符号表查询 / 绑定（作用域栈） | 是否存在、是否类型名、有限的类型类别 |
| `num.*` | 常量的算术与比较（任意宽度，按 C 规则截断） | 若干判定比特（为零、为负、适合某编码宽度…） |
| `emit t` | 向输出追加模板 `t` 并按槽位填入存储中的值 | 无 |
| `fail k` | 以诊断 `k` 终止 | 无 |

**分界原则**：凡是“对同样的有限摘要可能给出不同结果”的选择，都属于 δ；E 的
原语只能是对摘要的纯函数、或对存储的无选择的搬运。审计方法：列出 E 的每条原语，
证明它不含任何以 C 语义为依据的分支。

## 4. 证明义务（三层）

| 层 | 命题 | 证法 | 现状 |
|---|---|---|---|
| **T1 一步等价** | 构造出的模型在 δ 的全部定义域上等于 δ_ref | 有限域穷举（论文 A 的方法） | 对现有 18 张表已达；对全体 δ 未做 |
| **T2 全程模拟** | `dec ∘ E(δ)* ∘ enc` 与参考编译过程逐步对应：初始编码正确；每步保持模拟关系；终止与发散一致；输出解码正确 | 模拟关系 + 对步数的归纳；E 的原语各自形式化（Lean） | 未做 |
| **T3 语义正确** | δ_ref 对 C99 语义正确（目标程序的行为等于源程序在 C99 下的行为） | **不能由枚举推出**。以标准条款构造 δ_ref，或以 cc 为裁判做全域对照，二者择一或并用 | 部分：difftest、corpus、fuzz 是对 T3 的抽样；A1/A2 是对表本身的审计 |

## 5. 完备性为什么变得可检查

δ 的定义域有限，所以“δ 是否处处有定义”可以枚举一遍直接回答。没有定义的格子，
就是某个 C99 情形没有被覆盖。这件事在发布之前就能看到，不必等某个程序把它撞出来。

今天的缺口是：手写代码里的覆盖情况无法枚举，只能测。把语义收进 δ，就把
“测出来”变成“数出来”。

## 6. 模型为什么不会无限扩大

程序的无限性只体现在两处：输入更长（E 多循环几步）、嵌套更深（栈更高）。δ 本身
不变。这和 CPU 用有限的指令集执行无限多的程序是同一个道理；tinycc 也是这样一台
机器，它的 δ 藏在 C 代码的控制流里。

δ 的大小由 C99 的有限要素决定：语法状态、记号类别、有限的属性取值（类型类别、
左值性、常量性、存储类…）、目标 ABI 与指令模板。它会收敛到一个上界。

## 7. 第一个实例：递归下降 = δ + 栈

（主人的直觉：从 tinycc 的递归下降入手。）

递归下降在数学上就是一台确定性下推机：

- 每个解析函数的每个“位置”是一个控制状态 `q ∈ Q`；
- 前瞻记号归入有限的类别 `a ∈ Σ`；
- “在 `q`、看到 `a` 时，走哪条产生式、做什么动作”是 `δ(q, a, ·)`；
- 递归调用 = `push` 返回状态；`return` = `pop`。

规模估计：C99 的解析状态数百个，记号类别约 100 个，表在 10⁴–10⁵ 格量级，可以
构造、可以穷举。

**typedef 歧义**：`T * x;` 是声明还是乘法，取决于 `T` 是不是类型名。由 E 的
`sym.lookup` 给出一个比特作为输入符号，δ 据此选择。这是 §3 分界原则的第一个
具体用例。

**属性**：类型类别、左值性、是否常量等取值有限的属性作为栈符号随状态流动，
语义检查与类型推导因此也进 δ。常量的值、标识符的拼写这类无界数据只在存储里，
由 E 搬运。

## 8. 其余各层按同一模式

| 层 | δ 的输入（有限） | 无界数据（留在存储） |
|---|---|---|
| 解析与语义 | 解析状态、记号类别、属性栈顶、符号表摘要 | 标识符拼写、常量值 |
| lowering | IR 操作类别、操作数形态、类型类别 | 虚拟寄存器编号、偏移量 |
| 寄存器与栈帧 | 有限窗口内的活跃性摘要 | 变量到槽位的映射 |
| 编码 | 目标、操作类别、操作数形态、立即数宽度类别 | 立即数、寄存器号、位移 |
| 镜像 | 目标格式、段类别 | 段内容、重定位地址 |

编码层现有的编码规格表（`catalog.ENCSPEC`）已经接近这个形态：模板有限，槽位
填入由机制完成。

## 9. 与现状的差距（不是产品事实）

| 部分 | 现状 | 目标形态 |
|---|---|---|
| 表状决策（18 张） | 模型，T1 已达 | 保持 |
| 递归下降走查（`src/front_parse.c`，5,142 行） | 手写 | δ + 栈（§7） |
| 预处理（`src/front_pp.c`，2,294 行） | 手写，1 处查询 | 待定：宏展开本身是否进 δ |
| lowering、优化、编码、镜像（约 3,350 行） | 手写，约 25 处查询 | δ + 模板 |
| 执行机制 | 不存在（语义散在各处） | 固定的小解释器，原语逐条形式化 |

**静态容量与理论无界存储分开**：产品里的 `MAXSRC`、`MAXMAC` 等容量是实现限制，
超出时以诊断失败（这属于 E 的 `fail`），不影响 δ 的有限性；理论模型里的存储是
无界的。

## 10. 待决问题

1. **δ_ref 从哪里来**：从 C99 标准条款逐条构造（可追溯，工作量大），还是以 cc 为
   裁判在全域上对照（便宜，但继承 cc 对“未指定行为”的选择）。可能两者都要。
2. **规模与性能**：δ 从 8,484 个键扩到 10⁴–10⁵ 格量级，构造与穷举的时间要控制
   在 60 s 规则之内（分片）。推理的运行开销要实测。
3. **优化器**：数据流分析的不动点迭代是否也表述为 E 的循环加有限的 δ，还是先
   把优化器排除在框架之外、只要求它保持语义。
4. **与论文 A 的关系**：T1 已在论文 A；T2、T3 与本框架是否进论文 A，还是另成
   一篇。
