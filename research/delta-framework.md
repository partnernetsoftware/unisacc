## 0. 动机

初心：**用确定性模型推理等价替代编译。**

论文 A 证明的是一步：在给定的键之下，构造出的网络与 gold 表逐项相等（穷举，
零分歧）。要让初心成立，需要把“编译过程”本身表述成模型的反复推理，并说明
这种表述需要证明什么。本文只做到：给出机器定义与信任边界，用一个小语法实例
展示“δ + 栈”的一步替代与模拟义务，其余列为开放问题。

**本文不主张**：
- 不主张把控制流表化就会减少 bug（没有因果证据）；
- 不主张枚举 δ 的全定义性就等于覆盖全部 C99（全定义的 δ 可以处处返回
  `fail`）；
- 不主张手写代码只能靠测试（手写代码同样可以形式化验证，CompCert 即是）。

## 1. 现状观察（只是观察，不是论证）

- 编译器源码 11,002 行（`src/*.c`），查询模型或稠密表的位置约 50 处。
- 0.0.6 之后的正确性修复都在表以外：三维数组下标（前端走查）、**一般函数调用**
  结果的指针性（前端，`pf_call` 沿用了最后一个实参的指针状态，见 7e32309；
  不限于函数指针）、`fwrite`（库）、头文件被用户宏污染（头文件实现）。

这些观察只说明：已证的部分（T1）没有覆盖出过错的部分。它不证明不稳定的原因，
也不证明换一种表述就会更稳定。

## 2. 机器定义

### 2.1 配置

输入字节串 `x` 是**固定的外部参数**，整个运行中不变，不属于配置。

```
C = (q, r, i, s, W, o, h)
```

- `q ∈ Q`：有限控制状态；
- `r ∈ R`：上一步动作序列返回的结果码，`R` 有限（初始为 `r₀`）；
- `i ∈ ℕ`：`x` 中的读位置；
- `s ∈ Γ*`：栈，`Γ` 有限；
- `W`：工作存储，无界的可寻址字典；
- `o`：输出字节串；
- `h ∈ {run, accept, reject(k)}`：停机状态，`k` 取自有限的诊断集合。

初始配置 `C₀ = (q₀, r₀, 0, ε, ∅, ε, run)`。

### 2.2 观测

`obs(C) = (q, r, b, t)`，其中 `b = x[i]`（`i ≥ |x|` 时为 `EOF`），
`t` 为栈顶（空栈时为 `⊥`）。**观测保留具体字节 `b`**（256 + 1 种取值），
把字节归入类别的工作在 δ 内部完成，不在 `obs` 里。`Obs` 有限。

### 2.3 一步

`δ : Obs → Q × Act*`，`Act` 是有限字母表；动作的参数只取自有限集合（栈符号、
字典的有限命名槽位、常量字节），无界数据只能在已命名位置之间搬运，
不作为参数出现。

```
step_δ(C) =
  let (q', a) = δ(obs(C))
  let C₁ = C with q := q'          -- 先更新控制状态
  in  exec(C₁, a)                   -- 再按顺序执行动作
```

`exec` 逐个执行动作，每个动作可以改变 `r, i, s, W, o, h`；执行到把 `h` 置为
`accept` 或 `reject(k)` 的动作即停止，余下动作不执行。`exec` 最后写入的结果码
成为新的 `r`。

### 2.4 运行与结果

从 `C₀` 反复应用 `step_δ`，直到 `h ≠ run`。结果区分三种：

- `accept`：结果为 `Accept(o)`；
- `reject(k)`：结果为 `Reject(k)`，`o` 不作为产物；
- 永不停机：结果为 `Diverge`。

`enc` 只把源文件作为 `x`；**词法分析不在 `enc` 里**。`dec` 只把 `Accept(o)`
的 `o` 原样写成文件；**编码与链接不在 `dec` 里**。

## 3. 信任边界：两个选项

评审指出：草稿第 1 稿里的 `num.*`“按 C 规则截断”、`next` 的词法分类、
`sym.lookup` 返回“是否类型名”，都把 C 的语义藏进了执行机制；而“纯函数”不是
分界标准（纯函数也可以包含整个编译器）。所以只剩两条路，必须二选一：

| 选项 | 执行机制的原语 | δ 承担 | 代价 |
|---|---|---|---|
| **A. 低层通用原语** | 字节比较、定宽位运算与加减、字典读写、栈操作、输出追加 | 词法、作用域、typedef 判定、C 的整数转换规则全部由 δ 实现 | δ 大；多字数据要由 δ 逐字处理 |
| **B. 高层原语 + 显式信任** | 保留词法分类、符号表查询、C 算术等高层原语 | 其余 | 这些原语是**语言相关的可信组件**，各自要单独证明；“全部语义进 δ”的说法撤回 |

本草稿不在这里选。初心“用模型推理等价替代编译”更贴近选项 A；选项 B 更贴近
可交付。

## 4. 小语法实例：候选状态设计（未完成）

只取一个受限语法，不涉及符号表、typedef、类型结构：

```
E → T E'        E' → + T E' | ε
T → F T'        T' → * F T' | ε
F → ( E ) | d          d ∈ {0,…,9}
```

分两个层次，不能混用：

- **识别器**：只判定 `x` 是否属于该语言，不输出。有限控制、有限栈字母表、
  不用工作存储，是一台确定性下推机。
- **翻译器**：输出后缀式。它需要把读到的数字原样写出，因此需要动作
  `copy_current_byte`（把 `x[i]` 追加到 `o`），这是一个与语言无关的搬运原语；
  由于观测保留具体字节（§2.2），δ 也可以不用该原语而对 10 个数字逐一给出
  “输出常量字节 d”的动作，两种写法择一，本稿选 `copy_current_byte`。

**候选状态设计**（未定稿，完整的 `Q`、`Γ` 与 δ 表尚未写出）：每个非终结符的
过程体按调用点切分为若干续点，例如 `E` 有“调用 `T` 之前”“`T` 返回后、调用
`E'` 之前”“`E'` 返回后”三个续点；`Q` 取全部续点，`Γ` 取全部返回续点加上
翻译器中待输出的运算符。给出完整列表之前，本节不作任何规模或正确性的断言。

**一步替代**：手写递归下降的每一步（进入过程、匹配终结符、返回）对应机器的
若干步；把 δ 构造成网络后，T1 是这张有限表上的穷举。

**模拟义务**（仅列出，未证明）：

- 定义关系 `R(手写过程的状态, 机器配置)`：调用栈 ↔ `s`，读位置 ↔ `i`，
  已输出 ↔ `o`。
- **发散敏感的对应**：手写过程的每一步，由机器的 ≥ 1 步匹配；或者允许 0 步
  匹配，但每次 0 步匹配都必须使一个良基秩严格下降。只有这样，一端停住而另一端
  无限运行的情形才会被排除。双向模拟是一种可选的证明组织方式，不是必需条件。
- **终止**：第 1 稿给的度量“剩余输入长度 + 栈上待展开的非终结符数”**撤回**，
  它不单调（`E → T E'` 不消费输入，待展开的符号由 1 个变为 2 个）。正确的路线
  是：先写出完整的转移，再证明两次消费输入之间的“展开 / 返回”阶段是良基的
  （该文法无左递归，这是论证的依据，但需要写出来），然后以消费输入推动整体
  终止；或者引用已有的预测解析终止证明。**目前未证。**

这个实例即使完成，也只说明“小 LL(1) 文法可以这样做”，不推出任何关于 C99 的结论。

## 5. 证明义务的分层

| 层 | 命题 | 注意 |
|---|---|---|
| **T1** | 构造出的模型在 δ 的有限定义域上等于 δ_ref | 论文 A 的方法；只证局部表 |
| **T2** | 机器执行与参考过程之间存在发散敏感的模拟 | 每步由 ≥ 1 步匹配，或 0 步匹配时有良基秩严格下降；只靠有限步归纳不能得出终止与发散的一致。双向模拟可选，不是必需（参见 Leroy 的 CompCert 后端论文） |
| **T3** | 参考过程对源语言语义保持（或精化） | 先固定：C99 子集、目标 ABI、未定义与未指定行为的处理、可观察行为的定义。以 cc 做全域对照**不是**证明（源程序域无限，cc 也不是语言规范）；逐条实现标准条款也不是证明 |

除 T1 之外，还至少需要：**语言覆盖**（接受的程序集合等于所声明的子集）、
**摘要充分性**（δ 看不到的信息确实与决策无关）、**可达性**（可达配置满足的
全局不变量）。“δ 在局部上处处有定义”只是其中很小的一部分，可以枚举，但不蕴含
其余各项。

## 6. 开放问题

1. **信任边界**：选项 A 还是 B（§3）。
2. **C 前端的机器模型**：带符号表、typedef 查询、无界类型结构与语义动作的
   前端，不是普通 DPDA。需要什么样的工作存储与动作集合，尚未定义。
3. **规模**：C99 各层的 δ 规模**未估算**（第 1 稿的 10⁴–10⁵ 没有推导，撤回）。
   有限控制的存在也不保证表的规模实用。
4. **无界对象的清单**：输入长度与栈深之外，还有标识符、符号表、类型结构、
   输出、工作空间。每一类的表示与访问方式都要定义。
5. **优化器**：是否纳入本框架。
6. **与论文 A 的关系**：由主人与 cdx-unisacc 决定。
