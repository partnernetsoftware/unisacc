# 编译 = 有限 δ 的反复推理：研究草稿

> 状态：研究草稿，第 2 稿（2026-09-25，按 cdx-unisacc 的六点评审修订）。
> 本文不是已成立的框架，也不是产品事实；不并入论文 A，不开实现。
> 当前 unisacc 只有表状决策经由模型；解析走查、符号表、lowering、编码和镜像
> 写出都是普通代码。

## 0. 动机

初心：**用确定性模型推理等价替代编译。**

论文 A 证明的是一步：在给定的键之下，构造出的网络与 gold 表逐项相等（穷举，
零分歧）。要让初心成立，需要把“编译过程”本身表述成模型的反复推理，并说明
这种表述需要证明什么。本文只做到：给出机器定义与信任边界，用一个小语法实例
展示“δ + 栈”的一步替代与模拟义务，其余列为开放问题。

**本文不主张**：
- 不主张把控制流表化就会减少 bug（没有因果证据）；
- 不主张枚举 δ 的全定义性就等于覆盖全部 C99（全定义的 δ 可以处处返回
  `fail`）；
- 不主张手写代码只能靠测试（手写代码同样可以形式化验证，CompCert 即是）。

## 1. 现状观察（只是观察，不是论证）

- 编译器源码 11,002 行（`src/*.c`），查询模型或稠密表的位置约 50 处。
- 0.0.6 之后的正确性修复都在表以外：三维数组下标（前端走查）、**一般函数调用**
  结果的指针性（前端，`pf_call` 沿用了最后一个实参的指针状态，见 7e32309；
  不限于函数指针）、`fwrite`（库）、头文件被用户宏污染（头文件实现）。

这些观察只说明：已证的部分（T1）没有覆盖出过错的部分。它不证明不稳定的原因，
也不证明换一种表述就会更稳定。

## 2. 机器定义

### 2.1 配置

```
C = (q, i, s, W, o, h)
```

- `q ∈ Q`：有限控制状态；
- `i`：输入位置（输入是字节串，长度无界）；
- `s ∈ Γ*`：栈，`Γ` 有限；
- `W`：工作存储，一个无界的可寻址字典（键、值都是字节串）；
- `o`：输出字节串；
- `h ∈ {run, accept, reject(k)}`：停机状态，`k` 取自有限的诊断集合。

初始配置 `C₀ = (q₀, 0, ε, ∅, ε, run)`。输入读尽时观测给出 `EOF`；空栈时观测
给出 `⊥`。

### 2.2 观测、转移、执行

- **观测** `obs : C → Obs`，`Obs` 有限：`obs(C) = (q, 输入的下一个字节或 EOF,
  栈顶或 ⊥, 由上一步动作返回的有限结果码)`。
- **转移** `δ : Obs → Q × Act*`，`Act` 是有限字母表；动作的参数只能取自有限集合
  （栈符号、字典的有限命名槽位、输出的常量字节），无界数据不作为参数，只能通过
  “在工作存储中已命名的位置之间搬运”来引用。
- **执行** `step_E : C × Act* → C`，按顺序执行动作。

`Act` 的具体集合是本草稿的开放点之一（§3）。

### 2.3 编码与解码

`enc` 只把源文件原样放入输入；**词法分析不在 `enc` 里**，它必须由 δ 完成，
否则就是未论证的组件。`dec` 只把输出字节串原样写成文件；**编码与链接不在
`dec` 里**。

编译 = 从 `C₀` 反复 `C ↦ step_E(C, δ(obs(C)))` 直到 `h ≠ run`，结果是 `o`。

## 3. 信任边界：两个选项

评审指出：草稿第 1 稿里的 `num.*`“按 C 规则截断”、`next` 的词法分类、
`sym.lookup` 返回“是否类型名”，都把 C 的语义藏进了执行机制；而“纯函数”不是
分界标准（纯函数也可以包含整个编译器）。所以只剩两条路，必须二选一：

| 选项 | 执行机制的原语 | δ 承担 | 代价 |
|---|---|---|---|
| **A. 低层通用原语** | 字节比较、定宽位运算与加减、字典读写、栈操作、输出追加 | 词法、作用域、typedef 判定、C 的整数转换规则全部由 δ 实现 | δ 大；多字数据要由 δ 逐字处理 |
| **B. 高层原语 + 显式信任** | 保留词法分类、符号表查询、C 算术等高层原语 | 其余 | 这些原语是**语言相关的可信组件**，各自要单独证明；“全部语义进 δ”的说法撤回 |

本草稿不在这里选。初心“用模型推理等价替代编译”更贴近选项 A；选项 B 更贴近
可交付。

## 4. 小语法实例：δ + 栈的一步替代

只取一个受限语法，不涉及符号表、typedef、类型结构、语义动作：

```
E → T E'        E' → + T E' | ε
T → F T'        T' → * F T' | ε
F → ( E ) | n
```

`n` 是单个数字字节。输出是后缀式。

这是一个 LL(1) 文法，它的递归下降识别器是一台确定性下推机：有限控制、有限栈
字母表、**不用工作存储**。

- `Q = {E, E', T, T', F, ret}`，栈字母表 `Γ` = 返回点加上待输出的运算符。
- `Σ = {n, +, *, (, ), EOF, 其他}`（字节到这 7 类的分类由 δ 自己按字节做出，
  属于选项 A 的写法）。
- δ 是 `|Q| × |Σ| × |Γ ∪ {⊥}|` 的有限表；每一格要么给出（新状态，动作序列），
  要么是 `reject`。

**一步替代**：手写递归下降的每一步（进入一个非终结符的函数、匹配一个终结符、
返回）对应机器的若干步；把这张表构造成网络，T1 就是在这张有限表上的穷举。

**模拟义务**（草稿，待定形式）：
- 定义关系 `R(手写识别器的状态, 机器配置)`：调用栈 ↔ `s`，输入位置 ↔ `i`，
  已输出 ↔ `o`；
- 证明每一步手写识别器的一步，对应机器的有限步且保持 `R`；机器的每一步也能
  对应回去（双向，否则发散的对应无法得出）；
- 终止：用“剩余输入长度 + 栈上待展开的非终结符数”作良基度量；
- 结论形式：对所有输入，两者同时接受并输出相同，或同时拒绝。

这个实例只证明“小 LL(1) 文法可以这样做”，不推出任何关于 C99 的结论。

## 5. 证明义务的分层

| 层 | 命题 | 注意 |
|---|---|---|
| **T1** | 构造出的模型在 δ 的有限定义域上等于 δ_ref | 论文 A 的方法；只证局部表 |
| **T2** | 机器执行与参考过程之间存在模拟 | 若不同步、允许零步或多步模拟，终止与发散的一致需要良基度量或双向模拟，不能只靠有限步归纳（参见 Leroy 的 CompCert 后端论文） |
| **T3** | 参考过程对源语言语义保持（或精化） | 先固定：C99 子集、目标 ABI、未定义与未指定行为的处理、可观察行为的定义。以 cc 做全域对照**不是**证明（源程序域无限，cc 也不是语言规范）；逐条实现标准条款也不是证明 |

除 T1 之外，还至少需要：**语言覆盖**（接受的程序集合等于所声明的子集）、
**摘要充分性**（δ 看不到的信息确实与决策无关）、**可达性**（可达配置满足的
全局不变量）。“δ 在局部上处处有定义”只是其中很小的一部分，可以枚举，但不蕴含
其余各项。

## 6. 开放问题

1. **信任边界**：选项 A 还是 B（§3）。
2. **C 前端的机器模型**：带符号表、typedef 查询、无界类型结构与语义动作的
   前端，不是普通 DPDA。需要什么样的工作存储与动作集合，尚未定义。
3. **规模**：C99 各层的 δ 规模**未估算**（第 1 稿的 10⁴–10⁵ 没有推导，撤回）。
   有限控制的存在也不保证表的规模实用。
4. **无界对象的清单**：输入长度与栈深之外，还有标识符、符号表、类型结构、
   输出、工作空间。每一类的表示与访问方式都要定义。
5. **优化器**：是否纳入本框架。
6. **与论文 A 的关系**：由主人与 cdx-unisacc 决定。
