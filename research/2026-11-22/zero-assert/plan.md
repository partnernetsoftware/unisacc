# R69 零断言守卫送审方案

## 证据与现状

- `tests/run-batch.cx:208` 用 transport、退出码、前后产品身份和恰好一条标记行裁定 PASS。输出 `BATCH_RUN` 和 `BATCH_TIMING` 同处 212 至 228 行。
- `tools/cxlib/allsession.cx:398` 的最终裁决在 425 行逐字节匹配旧 PASS 行。499 行执行裁决，636 行重读封存日志并复判。两条路径应调用同一严格字段解析器。
- 初查 948 个去重源中 348 个未命中关键字，守门人按另一规则复算为 531 有、417 无。差异说明两者都是静态线索，不能估计零断言分母。主体很可能是有断言而无汇总计数。按批 ID、候选、目标和参数采样，像 `tests/tools-compile.cx` 同一源的 182 批逐项核实。
- `tools/check-win-argv.cx:90` 同一标记混合 PE 结构断言和 native=NOT_RUN_FOREIGN，且退出 0。结构合同与原生运行合同应分成两个证据单位。前者按实际断言计数，后者在适用 Windows 格上另跑，其他宿主仅记 NOT_APPLICABLE。

## 协议与裁决

(1) 计数由共享断言库在独立收据通道输出，由每次执行的实际断言入口累加，包括失败。运行器私有接收端绑定当前批、运行随机身份和退出状态，拒绝 stdout/stderr 的计数伪装。仅有库式文本格式仍不足以证明来源，接收通道与断言调用点须同时审查。检查直接绕过库向通道写入的代码不得登记。禁止用清单长度、循环计划数、PASS 行抓取或常量代填。同一标记重复、计数键重复、非法十进制、溢出、缺字段和 F 大于 N 均具名拒绝。transport、身份、材料、标记及退出码旧守卫继续有效。汇总批按子批身份累加库收据，任一预期子批缺收据或为零均具名失败，不能用外层探针的正数遮盖。

(2) `BATCH_RUN` 行尾追加版本化字段 `assertions=N`、`failed=F` 和 `assertion_policy=v1`。计数缺失用 `UNKNOWN`，真实零用 `0`，永不相互替代。正计数且 F=0 才能走正常 PASS。新批缺数或为零分别具名 FAIL。超时仍 UNKNOWN。只做构造的批优先移出严格断言分母并记 PREPARED。确需过渡的旧批只能由下述限期表准入，回执明确 `assertion_policy=legacy-exempt`，汇总单列，不能宣称已实测断言。已实测零次不通过旧批缺字段豁免。

(3) `tests/zero-assert-baseline.tsv` 逐批登记 `id, definition_sha256, use_closure_sha256, target, kind, reason, expires`。定义摘要绑定完整行、入口和实参，闭包摘要绑定入口文件及传递 use 依赖的规范路径和内容，以排序、版本和长度编码。动态或未解析依赖不能沿用豁免。审计数据另存执行证据及运行器身份。kind 仅允许已核实缺计数或具名构造过渡，不认通配。版本用可信槽版本按数值三段比较，当前版本达到 expires 即失效。到期不自动续。--write 只删除已经有计数或退出严格分母的条目，--check 对上一公开 Git 版本逐键比较整行，禁止新增、复活、延期和换键。初次入表由审评按影子证据固定快照。

(4) NOT_APPLICABLE 由注册平台列与实际宿主/目标匹配决定，复用平台匹配代码。批 stdout 的 NOT_RUN、SKIP、NOT_RUN_FOREIGN 只能解释缺执行，不能授权不适用。声明适用却未执行仍 FAIL 或 UNKNOWN。每个非本机适用格在其适用平台必须提供正计数。按相同目标矩阵逐格与上一公开版对比 NOT_APPLICABLE 集合和数量，只降不升，独立于零断言豁免棘轮。混合平台拆开裁决，保留原有结构覆盖。

## 验收与十个变异

同一夹具从直接批、资格单提交布局、封存复判三处对拍。保留正常正计数、真失败、超时、历史只读重放、过渡未到期、外来平台隔离及原生适用平台正计数的正负矩阵。记录新旧分母、例外剩余数与处理每批额外耗时。

(1) 删除零次拒绝，带合法标记且 rc=0 的零计数夹具必须转红。

(2) 把缺数默认为正数，未登记新批只有标记的夹具必须转红。

(3) 让 NOT_RUN_FOREIGN 接受为 PASS，声明平台与宿主不同的夹具必须转红。

(4) 让 stdout 自报 SKIP 绕过平台表，声明适用却没有执行的夹具必须转红。

(5) 删除到期比较，当前版本等于 expires 且仍缺数的旧批必须转红，并含 0.0.9 对 0.0.10 边界。

(6) 删除唯一字段约束，断言数键先 0 后 1 及先 1 后 0 的两行负控必须转红。附带篡改封存 RAW 后重放拒绝，避免只测生产点。

(7) 允许 stdout 手写 assertions=1 通过，未走共享断言库的批必须红。

(8) 只比较批次定义摘要，修改入口源或传递 use 文件后沿用旧豁免必须红。

(9) 放过上一版基线不存在的手加行，--check 必须红。另以独立夹具证明平台降级造成新增不适用格被拦。

(10) 只看汇总批外层正计数，子批零次或无收据仍汇总为 PASS 的变异必须红。
