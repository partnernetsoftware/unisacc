# v0.0.22 阶段契约子计划：主动发现类型形状丢失

状态：执行中；S1 首片四组声明符等价关系、三方共 8 个输入已通过。首轮发现的参考侧 `int v[][3]` 行宽丢失及 `T *v[]` 指针层数丢失已由参考侧修复；结论以重新构建的同源私有参考为准。归属：[v0.0.22 主计划](v0.0.22.md) P1-A 的正确性基础；不延后 Windows 转发、cc 互调及 E3 追平。这些反例归属前端解析阶段，而非 18 张事实表的权重错误。

## 可检查的假设

1. 一份声明符的基类型、指针层数、数组维度、函数形状、typedef 来源和限定符在 E3 类型描述符形成前不能静默丢失。C99 形参数组调整只改最外层：`T v[]` 与 `T *v` 等价，`T *v[]` 与 `T **v` 等价；内部指针与数组行宽继续决定 `sizeof` 和下标步长。
2. 网络与表的全域相等只覆盖阶段 δ 对其键的回答。输入键或状态没有保留必要的类型形状时，二者仍可能一致地给错答案。逐字节参考对拍只证明已测输入上的一致，不证明 C99 语义；系统 cc 是独立但仍有限的裁判。
3. 同一构造在形参、返回、成员、局部和全局位置，以及原样与 typedef 展开后，应产生相应的类型关系。拒绝要按名、带位置；接受却错码为 P0。
