## 语法裁定（不等于实现）

`sh ./gcc_cx.com -run [编译选项] FILE.cx [编译选项] -- [程序参数...]`；clang 同形。`--` 前是宿主编译参数、恰好一个 `.cx` 主文件；`--` 后逐项原样传程序，允许空字符串、空格、引号、反斜杠、`-o`、`--` 等，不经 shell 重新解析。无 `--` 则无程序参数。程序的 `argv[0]` 是本次临时可执行文件路径，不承诺与源码名或 unisacc 相同。

`-run` 只处理 `--` 前或结尾，不能透传编译器。0 个或 2 个以上 `.cx` 主文件、或 `--` 前出现 `-o FILE`、`-oFILE`、`-c`、`-E`、`-S`、`-shared` 时具名拒绝、退出 2，不调用编译器或程序。`--` 前的 `-Wl` 和 `-Xlinker` 整类拒绝，诊断含 `linker option`；不维护不完整的链接器输出选项拼写表。`--` 后同形字符串原样交程序。验收须验证 `-Wl,--output=PATH` 和 `-Xlinker --output=PATH` 均拒绝且 PATH 不生成；Windows `/OUT:` 不从 Linux 实证推断。`-include`、`-I` 等已知吃值选项的参数即使后缀是 `.cx` 也不计主文件；`-includeFILE` 是选项。主文件两侧其余选项在驱动的 C99 前导选项之后交宿主编译器，未知选项不吞。原有非 `-run` 模式与其参数解析保持不变，不把裸 `--` 重解释为程序参数。

响应文件裁定：本机 `gcc examples/hello.c -o out/cx-w7-intended @out/cx-w7-rsp.txt` 中响应文件含 `-o out/cx-w7-rsp-output`，实际写出后者。`-run` 的 `--` 前任一 `@` 开头参数具名拒绝、退出 2，诊断含 `response file`；不调用编译器或程序，也不展开文件。`--` 后 `@` 原样交程序，非 `-run` 行为不变。验收须验证响应文件内含 `-o` 时拒绝且不生成指定文件。安全展开响应文件不在本合同。

## 进程与产物

1. 调用既有 CX 模块展开与宿主编译路径；不得将源码交给系统编译器直接忽略 `use`，也不得调用 `unisacc.com` 作为后备。
2. 每次运行建立独立、权限受限、不可预测的临时目录，路径由宿主安全创建原语原子取得；编译目标是该目录内从未存在的可执行文件，不能复用固定路径、已有产物或测试结论。目录父路径、平台 API 和错误行为明确；进程并行时互不碰撞。避免先创建可预测文件、关闭后在共享目录重新打开的竞态。
3. 编译退出非零、无法启动、无法创建产物、无执行权限均不得启动程序；保留有意义的编译诊断及状态。成功后以参数数组启动目标，继承当前工作目录、标准输入/输出/错误和环境；不另经 shell，保留交互和重定向。
4. Linux 正常退出传递程序退出码，驱动不额外向 stderr 写行；信号终止返回 `128+N`，并写一行 `gcc_cx: program killed by signal N`（clang 同形），不重发信号。无法创建临时目录、启动失败或等待失败退出 2，stderr 具名 `failed to start`。现有 `cxproc_run` 把正常退出 128+N 与信号 N 都折成同一个整数，不能仅据整数判信号；实现须保留终态类别。Linux 显式传 `environ`，Windows 空 envp 才表示继承。Windows 状态与信号另按平台合同实证，不以 Linux 结果推断。
5. 对编译失败、启动失败、运行结束后的临时文件做尽力清理，保证不删除不属于当前调用的路径。不可捕获终止/断电不保证清理；Windows 可执行文件仍在使用时的删除语义须按实际 API 处理和测试。清理失败应可诊断，不能掩盖程序失败，也不能伪装成已清理。
6. 现有无 `use` 的快速路径与含 `use` 的模块路径都须覆盖；不得由一个路径的通过推断另一个路径。`-run` 的可执行产物不可被通常的对象缓存或不同调用共享。

信任边界：`-run` 执行用户源码并允许宿主编译选项，不是沙箱，也不保证不受信任的编译器、插件、选项或程序不能访问宿主文件。输出冲突拒绝和私有临时目录解决的是本合同列明的参数冲突及调用间产物隔离，不证明任意编译器选项无副作用。

Windows 裁定与证据边界：`tools/cxcc-hostinc/spawn.h:236-250` 把 `GetExitCodeProcess` 的返回值截取低 8 位再编码为 wait 状态；`tools/cxproc.cx` 据此解码。若沿用此 shim，合同只承诺退出码低 8 位与该 API 返回值低 8 位相同，不承诺高 24 位。驱动拒绝和程序均可能退出 2，拒绝必须有具名 stderr。该适配文件明确未实跑，Windows 仍记未验证，不以 Linux 结果补证。

## 验收矩阵

同一候选驱动源码分别由宿主 gcc、clang 构造，在真实 Linux 宿主用两者各运行：

| 场景 | 必须观察 |
|---|---|
| 无 use 与跨模块 use | 正确输出及程序退出码；含 use 必须实际调用模块函数 |
| 参数 | 空字符串、空格、引号、反斜杠、`--`、以 `-` 开头的值均与传入逐项一致 |
| 环境与 IO | 设定环境变量、cwd、stdin 并核对 stdout/stderr；不得从 shell 拼字串间接伪造 |
| 程序退出 | 0 与非零可区分；信号须同时观察 128+N 与诊断，并与正常退出相同数值区分 |
| 编译失败／无编译器／启动失败 | 保留编译器诊断和退出码；启动/等待/临时目录失败退出 2 并具名 `failed to start`；程序副作用未发生，不执行旧文件 |
| 参数冲突 | 零／多个源及 `-o`、`-c`、`-E`、`-S`、`-shared` 拒绝且不调用编译器；编译器 argv 不含 `-run`；无 `-run` 的 `-o` 仍写指定文件 |
| 并发与临时物 | 每驱动使用独占 ready/gate；ready 完整写入后原子发布；仅双 ready 齐、两个进程存活且未超时才放行。观察临时路径不同、输出不串及各自清理；单侧不就绪负例必须超时失败、回收所属进程与临时文件，不触及其他文件 |
| 状态边界 | 不调用 unisacc 的情况下通过宿主驱动构造与运行；候选、已安装、平台切片各自记账 |
