# 0.0.43 LLP64 S2–S4：E2 预定义、头文件、宿主桥

状态：源码和表已提交，未安装。Windows 实机运行 NOT_RUN，不记 PASS。证据目录 `out/c43-llp64-s234-01/`。

## 合同
- **S2 预定义**：`exec/pp/predefines.tsv` 新增可选的 `model` 行，只有 lnx/osx 定义 `__LP64__`。win 改为 `_WIN32 _WIN64 __x86_64__|__aarch64__ __UNISA__`。lnx/osx 的预定义资源字节不变。
- **S3 头文件**：头文件内的条件判断一律用 `_WIN64`，不用 `__LP64__`，因为宿主 gcc/clang 在 win 上定义 `_WIN64`。
  - LLP64 下 long 是 4 字节。size_t、ptrdiff_t、ssize_t、off_t、intptr_t、int64_t、intmax_t、time_t、clock_t 等都拼成 8 字节的 long long。
  - limits/stdint/inttypes 的极限值、后缀和 PRI/SCN 宏都按 LLP64 取值。
  - C/POSIX 规定为 long 的接口签名保持 long，例如 strtol、ftell、tv_nsec、telldir、ldiv_t。实现内部用 64 位计算，再按 LONG_MIN/LONG_MAX 截断。
- **S4 宿主桥**：新增 `include/sys/_word.h`。`__u_word`/`__u_uword` 是宏，lnx/osx 上展开成 long/unsigned long，`_WIN64` 上展开成 long long/unsigned long long。只在 `_WIN64` 分支里静态断言它是 8 字节且等于指针宽度。
  - `__hostcall` 参数数组、内建调用结果、句柄和指针强转一律用 `__u_word`。宿主 thunk 按 64 位槽读取（`src/back_encode.c` 的 BK_HOST_*）。
- **库裁剪键表**（`unisa/libneed.py`）按全文文本、忽略 #if 计算调用图。因此 win 分支放在函数体内，不复制函数体，不引入新的被调名，注释里也不写被调名。改后键、函数体和闭包与改前完全相同。

## 改动路径
- **S2**：`exec/pp/predefines.tsv`、`exec/facts/export.py`（只改 predefines 读取和拼接位置）、`exec/facts/pp-gen.tsv`（生成物）。
- **S3/S4**：include 下 28 个文件，即 27 个修改的头文件加新增的 `sys/_word.h`。清单见 `out/c43-llp64-s234-01/changed-hdrs.txt`。

## 遗留和影响
- **Python 依赖**：`exec/facts/export.py`（Python）仍是 pp-gen 等事实表的生成器，`unisa/libneed.py` 仍是库裁剪键表的来源。本批没有新增 Python 算法，但继续依赖这两个文件。
- **export.py 哈希涟漪**：另有 25 张事实表的 `# input exec/facts/export.py` 注释行随之过期，数据行不变。本批没有改写这些表，等主刀裁定。
- **pp-autoinc-gen.tsv** 没有覆盖：
  - 本批差异只在 29 行输入哈希注释（27 个头文件、新 `_word.h`、export.py），数据行与基线生成完全相同。
  - 历史漂移是 `=keys` 行，以及 pp-layout 和 cx.h 两行哈希，与本批无关。
- **RI 和消费者影响**：
  - win 的 `\0predefines/win/*` 内容变了。
  - 包含这些头文件的编译，其 `\0hdr/` 输入身份都会变。
  - `unisa_safedel.h` 是 compilerpack 和 nninputs 的依赖输入，它的字节变化会改变构造输入身份。
  - lnx/osx 的展开结果不变。
- **宿主驱动**（cxcc 用 gcc/clang 直编这些头）：在 win 上，size_t 等类型改为 8 字节，属于修正。驱动维护方需要知情并复测。
- **另报的既有缺陷**：E3 在 `_Static_assert` 里对数组 typedef 求 sizeof 得到 8，表达式里则是 64。已装产品同样如此，最小复现是 `out/c43-llp64-s234-01/sim/sa1.c`。与本批无关。
- **未覆盖**：pthread.h 在 win 上是 `#error`；termios、fenv、wctype、regex 中的 long 在 win 上不参与编译，未改。
