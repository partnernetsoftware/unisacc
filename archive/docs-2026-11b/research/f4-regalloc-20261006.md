# F4 寄存器分配调研（只读；标注：[跑过]=实际执行，[读码]=读源码得出，[设计]=只是设计）

## 1. 现状

**tape 只有 8 个虚拟寄存器 r0..r7，没有空闲的。** [读码]
- r7 = 栈指针（x86 上就是 rsp，unisa/catalog.py:130 REGMAP 注释），r6 = 帧指针（函数序言 `store64 [r7+0], r6 / mov r6, r7`，[跑过] 见下 §5）。
- r0..r5 是表达式求值的临时寄存器兼调用参数寄存器：调用时参数先压栈，再按 k 从高到低 `load r_k,[r7+0]` 弹进 r0..r5（src/front_parse.c:1612-1620；超过 6 个参数走栈）。`.argc/.argv/.hostcall/callr r5` 等隐含使用固定寄存器。
- 映射（catalog.py:130-135，back_lower.c:895-900 经 regmap 阶段查表）：
  x86_64: r0..r7 = rax rdi rsi rdx rcx r8 r9 rsp；arm64: r0..r7 = x0..x7。
- 后端自留的临时：x86 r11（unisa/emit_x86.py:191 SCR；back_lower.c:961 callm 用 x16/r11）、arm64 x16/x17（back_encode.c:93-94 A_IP0/A_IP1，内置桩里还用 x10 等）。x86 内置辅助例程（x_itoa，back_encode.c:870-900）自己占用 rbx、r12、r13、r14；Windows 路径有 save 区（back_lower.c:889）。
- 空闲物理寄存器（现 REGMAP 与固定临时之外）：
  x86_64 共 16，用掉 rax rdi rsi rdx rcx r8 r9 rsp r11 = 9；rbp r10 rbx r12 r13 r14 r15 = 7 个可用（但 rbx/r12-r14 被 itoa/win 辅助例程占用，需改为保存/恢复或避开；Win64 下 rbx rbp r12-r15 是被调用者保存，宿主回调 `.hostcall` 会按其 ABI 保留）。
  arm64 共 31，用掉 x0-x7 x16 x17 = 10（外加栈桩的 x8-x10 暂存，见 back_encode.c:385）；x9-x15 与 x19-x28 可用，约 15+ 个，数量充裕；x19-x28 本身是 AAPCS 被调用者保存。
- 局部变量的表示：帧槽 `[r6-N]`，N 来自 symoff[si]（front_parse.c:1576，1303）。读取形如 `.ld rK,[r6-N],4` / `load64 rK,[r6-N]`；写入常先算地址再存：`imm r2,24 / sub64 r0,r6,r2 / mov r4,r0 / ... / .st [r4+0], r0, 4`（-O2 之后仍然这样，见 §5 的 s、i 两变量）。即标量写入不是直接 `[r6-N]`，而是“把帧地址算进寄存器”，且前端没有“地址是否被取走”的信息写入 tape。
- 参数：序言把 r0.. 存进 `[r6-8]`、`[r6-16]`…（§5 `store64 [r6-8], r0`）。

## 2. 现有 pass（src/opt.c 单文件 897 行，无 opt_*.c 拆分）[读码]
- 挂在 front_parse.c:6201：`if (nerr==0 && optlevel>0) opt_stack()`；opt_stack (opt.c:889)：最多 4 轮 opt_round，-O2 再最多 4 轮 peep_round。
- **文本级**：操作对象是输出缓冲 `out` 的“行”(ol_s/ol_e/ol_n，OPT_MAXL=1M 行)，不是结构化 IR。
- -O1：栈顶入寄存器（push/pop 对变 mov，opt.c:1-10 H1）。
- -O2：有基本块切分 bl_split(opt.c:254)、每块的读写摘要 bl_summarise/bl_solve(391-441，对 r2..r5 做逐寄存器活跃性数据流 `bl_live`，ol_zok 开关，切不出块就关)、ol_dead 死写消除、ol_local 局部窥孔(454)、peep_round 窥孔规则表（BF_PEEP_*，含 pk_stfuse 存储融合、pk_load/pk_store/pk_movat）。
- **有**：寄存器活跃性（仅 r2..r5、块级）、基本块/跳转目标(ol_target)。**没有**：帧槽（内存）活跃性/别名分析、取地址判定、循环识别、对 r0/r1/r6 的活跃性。

## 3. 最小可行方案 [设计]
**层次选择：tape 级，新增 -O2 pass（紧接 opt_round 前或后），不在后端分配。** 理由：现有契约是“优化后的 tape 经两个后端降级，闭包逐字节相等”（opt.c 头注释），后端 back_lower 只做 1:1 映射，在那里加分配会分裂 tape 语义；且 tape 是 exec/ 模型对拍的单位。

前提难点：tape 现在**没有空闲虚拟寄存器**。必须先扩 tape 寄存器文件，二选一：
 (A) 把 r8..r13（等）加入 tape 与 REGMAP（catalog.py REGMAP 从 8 元组扩成 14 元组；regmap 阶段的 key 域、BH_REGMAP_Y、`while (j < 8)` back_lower.c:896、bk_rmap[]、bkf_* 事实、编码器的寄存器字段宽度、`ol_reg/ol_mask` 的 rN 位掩码(opt.c:279，目前 6/8 位) 全要放宽；.ld/.st 等编码在 x86 要 REX.R/B 已部分有 r8/r9）。arm64 直接用 x19..x24，x86 用 rbx? 不：用 r10 r12-r15 rbp。
 (B) 不扩 tape，只在 -O2 且函数“叶且无 .print/.hostcall/callm”时让后端用固定的物理 callee-saved 寄存器——需要新 tape 伪指令（如 `.reg rN, [r6-off]` 声明），本质仍要 tape 改动。推荐 A。

pass 步骤（单函数内，标量 int/long/指针，4/8 字节槽）：
1. 候选槽：函数内所有出现 `[r6-N]` 的偏移；扫描整函数文本，若槽地址以 **非 `.ld/.st/load64/store64 [r6-N]` 形式**逃逸（`sub64 rX,r6,rK` 其中 rK 是 `imm N` 后产生地址并被用于 `.ld/.st [rX+0]` 之外的用途——如 `mov` 后传出、与 call 同用、add 偏移（数组/结构成员）、`.lea`），则剔除。注意写入也是 “imm N; sub64 r0,r6,r2; mov r4,r0; .st [r4+0]” 的模式，需要先做**地址形窥孔**把这个模式规整为 `.st [r6-N]`（这是 pass 第 0 步，单独就能减 3 条指令）。数组、结构、vla（curvla）、地址被取（`&x`、传引用/复合字面量）、别的 `[r6-N±k]` 部分重叠访问均排除。
2. 不变量：(i) 槽 N 在整函数里只经窄/宽度一致的 `.ld/.st`（width 4 需要保持 int 截断/符号扩展语义：存 4 字节、读 4 字节带符号扩展——提升后每次 `.st` 要补一次 sext32，每次 `.ld` 变 `mov`；`.ld ..,4` 的符号/零扩展选择要看 .ld 的变体）；(ii) 无 setjmp/longjmp/信号读帧（调用 setjmp 的函数整函数禁用）；(iii) 无 inline asm / `.hostcall`。
3. 跨调用：tape 没有被调用者保存约定（r0..r5 全是 caller-save，r6 由序言保存）。方案：新增寄存器全部定义为 callee-saved——函数用到 r8+ 的序言保存、尾声恢复（使用帧槽或 push）。**第一阶段只做“叶函数”(函数内没有 call/callr/callm/.hostcall/.sys 类)**，这时 r8.. 即使不是 callee-saved 也没有危险，但仍需序言/尾声保存，因为调用者可能也在用。若不想动调用约定：叶函数 + 仅用“调用者没用过的”不可知 → 必须保存。因此建议一次定为 callee-saved，序言 `store64 [r6-K], r8`，约 +2 条/用到的寄存器；跨调用变量因此自然可行（第二阶段）。回调桥（interop 的 .hostcall/ccw 入口，back_lower.c:930-950 把宿主寄存器映射成 r0..r5）和 `callm`、自编译 unisacc 的 setjmp/线程（bk_threads）需检查对 r8+ 的保存。
4. 分配：先到先得，按静态使用计数 × 循环深度（需要简单的回边识别：`jump` 目标行号小于当前行，即循环）选 top-K（K≤可用寄存器数），每槽一个寄存器，无需区间分析（整函数独占，因为不做寄存器共享）。这就是“叶函数 + 循环变量”最小版。形参：序言的 `store64 [r6-8], r0` 变 `mov r8, r0`。
5. 必须与现有 -O2 的 r2..r5 活跃性分析（ol_zok[2..5]）共存：新 pass 放在 opt_round 之前，让后续的 mov 合并（ol_mov、peep）消掉多余搬运。
6. 估计改动（实际改前不要当真）：opt.c 新 pass 约 250-400 行（C 子集，无结构体/函数指针特性，可被自编译）；扩 8→14 寄存器：catalog.py/ckernel/regmap 表 + back_lower.c + back_encode.c（x86 REX、arm64 寄存器域）+ front_parse tape 读入/tape 解析器(tapebin、tapescan.h、tapelink、tapeprune 的 rN 范围检查) + emit_x86.py/emit_arm.py/exec_target.py（Python 参考后端）约 150-300 行；kernel/ 与 weights/ 由 `python3 -m unisa emit-kernel` 重新生成（不手改）。

## 4. 风险与验收 [设计，门禁名来自读仓库]
- **模型侧同步**：exec/opt/*-result.tsv、exec/opt/check.sh 是“E4 在通用执行器上跑，-O0 tape 经 -O1/-O2 表 == 参考同级 tape”；新 pass 改变 -O2 tape，因此 E4 的 δ 表（exec/build/gen.py opt --o2）必须重新做，否则对拍必红。接受却不一致 = bug，做不出来的要“拒绝并报未覆盖”（CLAUDE.md）。另外 exec/lower（tape→后端降级，REGMAP 阶段、寄存器域）、exec/enc、weights/gold 里的 REGMAP/寄存器字段表（gold.py:575 MREGS）、tapebin/tape 编码（`tapebin_encode.inc`、`tapebin_shape.inc`、tapescan.h）、exec/pipeline/*check_tape_text 都会因扩寄存器或新伪指令受影响；kernel/ 生成物（unisa_model.inc 等）与 graphhash.tsv/gatedeps.json 需刷新。扩寄存器（方案 A）影响远大于新 pass 本身——可考虑先只做“地址形窥孔”（§3 步骤 1，不扩寄存器）作为 0.0.32 的第一个可落地增量，其改动完全落在 E4 opt 表一侧。
- 语义守护：tests/opt.sh（-O2 与 -O0 的 -run 输出一致、closure 逐字节、-O2 自举不动点）、tests/difftest_o.sh（对 cc -O2 与 -O0/1/2 四向）、tests/csmithdiff.py（固定种子 Csmith，对系统 cc；需 Homebrew csmith；MODEL_COM 时也测产品）、tests/difftest.sh、tests/optpy.sh、exec/opt/check.sh、tests/opt_partition_check.py。再加：专门的小探针——int 溢出/符号扩展的 4 字节变量、`&x` 逃逸、数组与同名偏移重叠、setjmp、循环嵌套、回调（`.hostcall`）。
- 其他风险：Windows x64 ABI（rbx/rbp/r12-r15 被调用者保存，宿主函数返回后值保持，但 `bk_save` 区与 win 的 itoa 辅助使用 rbx/r12-14 要避开或保存）；macOS/Linux 的 `.print` itoa 例程占 r12-r14；arm64 用 x19..x28 要在序言保存（后端的 AAPCS 帧）。tape 文本变大小也会改变各目标二进制尺寸（发版哈希/seed 基线需重做）。
- 每次门禁运行 ≤60 秒，按 gate.sh --suite 分批，别一次全跑。
