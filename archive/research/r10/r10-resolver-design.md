Simplified R10 resolver review — read only, design only, no runtime evidence

Verdict: YES. For a declared-name resolver this satisfies PRD §114–117 and is preferable to the earlier per-name fetch/USLTAPE2 design. The requirements say injected -> loaded process -> dlopen, with the choice made by δ; they do not require lazy name discovery or a three-section output. Once us_declare_import supplies all external names/types, C can mechanically enumerate ALL address candidates at compile start and serialize one frozen USBIND2. Both stages can independently select the same record using one shared finite-rule decoder/selector. This removes the runtime resource fetch extension, selected-record output, and USLTAPE2 framing. Keep USLTAPE1 and ordinary CLI unchanged.

Required concrete boundaries:
1) Host API: us_declare_import(name,sig) stores caller-supplied ABI/object facts; us_load_library(path) opens RTLD_NOW|RTLD_LOCAL and owns handles in declaration order. us_add_symbol remains borrowed explicit injection. Host performs no C parsing, unresolved-name selection or winner selection. dlsym gives addresses only; signatures/extent/writable are trusted declarations, not discovered facts. Function and data records share this format. Undeclared external names reject in this first explicit-declaration chain; no automatic dlsym type inference is claimed.
2) At compile start enumerate every declared/injected name: explicit injection candidates, RTLD_DEFAULT candidates and every context-owned handle's dlsym result. Emit all successful candidates; missing lookups simply yield no record. Candidate order is not priority. Use RTLD_LOCAL so context handles do not pollute RTLD_DEFAULT accidentally; already globally loaded libraries legitimately form process candidates. An unresolved declared name must not be converted into a source definition or fake data BSS.
3) USBIND2 minimum extension: retain existing length-framed complete USBIND1 record payload, permit origin u8 0 injected/1 process/2 dlopen, add ordinal LE64 immediately after origin, then existing ABI/variadic/address/argc/descriptors/extent/writable/supported. Version magic USBIND2\n, count LE64; each record_len counts payload only. Injected/process ordinal=0; dlopen ordinal=1..64 (load order). Enforce count/byte caps, complete LE64 bounds, nonzero supported user-space address and nonwrapping address+data extent. USBIND1 remains decoded under its current unique-name/origin0 semantics. Version2 duplicates are legitimate across origins; duplicate (name,origin,ordinal) is malformed, including same-address duplicates of the same identity. Different origins returning the same address are valid. No partial/trailing input accepted.
4) Shared δ algorithm: decode complete records and group by exact interned name. Validate wire structure for ALL records. Maintain best record using tuple(origin rank,ordinal); compare full64 ordinal and descriptor fields. Never have C discard a candidate as incompatible. After selection, E3 checks selected declared ABI against true source descriptor. A bad highest-priority declaration rejects rather than falling through to a lower-priority candidate. Unsupported metadata is representable; unsupported winning ABI rejects. An unsupported lower-priority candidate must not invalidate a valid selected candidate merely because it is unsupported (malformed wire still rejects). This requires separating structural validation from supported-call validation in today's LBI decoder.
5) Real source definitions retain precedence, including definitions later than an extern/prototype. Current E3 final wrapper scan and lower data.DEFINED preference provide the correct locations. For functions E3 wrapper embeds selected address; lower validates the same immutable candidate registry/capability. For data lower repeats the SAME selection and four-fact check before address emission. Both must use the shared finite rules, not separately handwritten ranking ladders. Ordinary CLI absence of bindings remains byte-identical.
6) Preserve the entire frozen USBIND2 in c->binding_blob at successful compile; E3, lower and us_relocate receive exactly these bytes. Do NOT enumerate again in relocate: changed process loader state could otherwise make E3's immediate function address and lower's data choice diverge. Mutations through add/declaration/load invalidate tape/signatures/image/closures and advance a context generation; active mutation rejects. Failed load/registration does not discard a valid previous generation. Process addresses and injected addresses are borrowed: host must keep them live; library-owned dlhandles stay live until all script images/closures are destroyed, then dlclose exactly once during context destruction. New compile refreshes candidates. No resolver result is a distributable cross-process model/cache fact.

Actual implementation changes, not architectural blockers:
- Existing E3 LI.named and common LBI.named reject a repeated name immediately. They must distinguish V1 uniqueness from V2 candidate identities and produce selected arrays.
- Existing origin decoder accepts only origin0; supported/variadic checks currently reject before a winner can be selected. Decoder/selector must move semantic support checks after selection while preserving bounded parsing.
- Root supplies frozen candidate serialization and handles/typed declarations. No runtime fetchhook or output envelope change is necessary. Existing ResourceInput arrays need no extra slot: replace the current bindings blob under the same key.
- Linux host dlfcn/-ldl and Windows loader/host adaptation remain explicit platform slices; Apple-only host_dl_slot cannot prove six-platform library support.

Minimum proofs/tests: shuffled candidate order gives same winner; injected/process/two local handles with same name produce distinct outputs and correct precedence; later real source definitions win; conflicting selected ABI rejects; lower-priority unsupported metadata is skipped only after valid wire decoding; duplicates/high32/ordinal64 limits/truncations/unknown version reject; V1 regressions unchanged; function plus writable integer/pointer data in same blob runs natively O0/O1/O2; source has no matching import declaration -> named rejection; candidate snapshot is identical across E3/relocate; mutation invalidation, failed load recovery, two contexts and callback/exit lifecycle retain current tests. No test was run during this review.

The earlier complex proposal was unnecessary under explicit import declarations. Its only extra benefit would be discovery of names not known until parsing; that is deliberately absent from this bounded slice, not a PRD requirement for the declared resolver chain.
