### 1a 运行库副本重复(cc 加项,CORE-MIN 候选)

76/76 个对象都各带一份私有的隐式运行库。这些运行库符号和最小对象 hostnative.o 的符号同名;hostnative.o 可执行节共 3,558B(其中 `__init_u` 96B)。

| 运行库符号(每个对象都有,binding=LOCAL) | 单份字节(hostnative) | 不同内容数/76 |
|---|---|---|
| _u_st_raw | 633 | 2 |
| _u_st_slot | 584 | 8 |
| _u_st_wflush | 405 | 2 |
| _unisa_environ_init | 358 | 2 |
| __main_ret | 320 | 76 |
| ferror | 275 | 16 |
| write | 199 | 2 |
| exit | 195 | 1 |
| atexit | 175 | 2 |
| _unisa_fd | 165 | 4 |
| _u_st_flushall | 93 | 2 |
| __unisacc_R* 10 个 | 各 6 | 1 |

- 运行库字节合计 **269,058B**(76 份,每份 3,382..4,718,均值 3,540),占 ELF 1,780,462 的 **15.1%**。只留一份时可省 **264,340B**。cc 推断的约 267KB 已得到实测确认。
- 同一函数的原始字节有多种,原因是重定位和地址不同。这些副本在功能上是否等价 → **UNMEASURED**(要用不受重定位影响的比较)。
- 来源:include/cx-flat.h、stdio.h、stdlib.h、sys/_exit.h 里的 `static` 函数,用 `#if !__UNISA_FTRIM_LIBC || __UN_<name>` 守卫(例如 cx-flat.h:371 `_u_st_raw`,stdlib.h:853 `_unisa_environ_init`)。因为是 `static`,每个翻译单元都会各生成一份。
- 去重路径(候选,未实施):运行库只在一个单元里出一份非 static 的实体,其余单元在 `__UNISA_FTRIM_LIBC` 下改成外部引用。`__main_ret` 每个对象内容都不同,要单独看。`_unisa_environ_init` 是 constructor,只留一份时要保证它最先执行(stdlib.h:856 已经有"别的单元已填好就返回"的保护)。省下的字节和行为等价 → **UNMEASURED**(要实际构造一次才能得到)。
