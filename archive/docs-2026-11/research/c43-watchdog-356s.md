# c43 看门狗疑点：外层 58 秒为何未截断到 356 秒（只读，2026-10-15）

**结论先行**：找到一个**真实漏洞**，它违反“看门狗清理所属子进程”的规则，但**不能解释本次 356 秒的全部现象**，因为那次运行的日志已被 15 秒的绿色重跑覆盖，无法取证。外层 `tests/bound.py` 本身对直接子进程的 58 秒计时是有效的（已复现 3 秒截断返回 rc=142）。

## 1. 机制（读源码）

- `tests/bound.py`：`Popen(start_new_session=True)`；超时则 `stop()`：先 SIGSTOP 根进程，再用 `ps -axo pid=,ppid=` 沿**父子链**收集存活后代并 SIGSTOP，然后 `killpg(根)`，再逐个 SIGKILL 已收集的 PID，最后只 `wait` 直接子进程（`bound.py:4–60`）。
- `tests/bound.c`（门禁里大多数作业用的 C 版）：`fork`+`setsid`+`alarm`，同样依赖父子链的 ledger 冻结（`bound.c:27–56`，注释已写明“Nested setsid changes process groups, but not the frozen parent ledger”）。
- 因此**只要某个后代在超时前已脱离父链**（中间进程先退出，后代被 reparent 到 init 或 subreaper），且它处于自己的 session/group（嵌套 `bound` 或 `setsid` 都会这样），外层的 ps 遍历与 killpg 都覆盖不到它。

## 2. 复现（本机，可重跑）

- 对照：`bound.py 3 sh -c 'python3 tests/bound.py 60 sleep 30'`：中间进程仍存活，外层遍历能找到内层与 sleep，3 秒返回 rc=142，无残留。**安全。**
- 漏洞：`bound.py 3 sh -c '(python3 tests/bound.py 60 sleep 40 &); sleep 100'`：中间子 shell 先退出，内层 bound 与其 sleep 被 reparent 到 PID 1（`ppid=1`，独立 pgid）。外层 3 秒返回 rc=142 时，**sleep 40 仍在运行**（4 秒时仍在，其存活上限是内层的 60 秒计时）。**漏洞成立：外层不等于清理。**

## 3. 对 356 秒的解释（可能性，未证实）

- 外层计时的墙钟上限**不**会被该漏洞直接撑大：外层在 58 秒返回。356 秒的墙钟来自**调用方**：若调用方用管道（`| tee`、`$(...)`）或等待标准输出 EOF，就会等到仍持有写端的孤儿结束。本次 `gate.sh` 输出走管道时，内层或脱离的后代持有写端，墙钟可以远超 58 秒。这与“rc1、variants 空、15 秒重跑绿”相容。
- 另一条可能：`process.wait()` 等待被 SIGKILL 的进程进入不可中断睡眠（D 态，如 I/O 或内存压力），超时后等待本身变长。未证实。
- 挂起/虚拟机暂停：`bound.py` 与 `bound.c` 的计时基于单调时钟，在休眠期间不计，因此会让墙钟超过 58 秒。未证实（宿主记录未取得）。
- `gate.sh:160` 有 `( … ) &` 后台子 shell 写入结果文件；若 gate 被外层杀死，这类子 shell 可能成为孤儿。是否为本次源头未证实。

**无法判定的一点**：356 秒那次运行的进程树与日志已丢失（`/tmp/c43acc.lib-union-scalar-1.log` 已被 15 秒重跑覆盖）。要定论，需要在同一条件下重现 356 秒并在超时时抓取 `ps -eo pid,ppid,pgid,etime,args` 快照与调用方的等待对象。

## 4. 是否违反 60 秒规则

- **违反的是“清理所属子进程”，不是 58 秒计时本身**：孤儿在外层返回后仍会运行，直到其内层计时结束（本复现为 60 秒，若内层无计时则无上限）。
- 对“每次运行上限 60 秒”的规则：外层进程自身按时返回；但若调用方等待孤儿的输出，则**调用方的墙钟会超过 60 秒**。这是一个真实的规则风险，应当修。

## 5. 建议修法（只是设计，待 cc 定；不改看门狗）

1. 让看门狗能看见全部后代，不依赖父子链：Linux 上 `prctl(PR_SET_CHILD_SUBREAPER)` 使孤儿重挂到看门狗下，遍历时能收到；macOS 无该接口，改用进程环境中的唯一标记（如 `UNISACC_BOUND_TOKEN`）并在超时时扫描 `ps eww` 找同标记进程。
2. 嵌套 `bound` 与 `setsid` 的子进程继承同一标记，使外层能杀到内层的子进程。
3. 调用方不要等待 EOF：输出重定向到文件后再读；或在超时后对输出管道做显式关闭。
4. 回归探针：本笔第 2 节的两条命令，修后漏洞用例应在 3 秒后无残留。
