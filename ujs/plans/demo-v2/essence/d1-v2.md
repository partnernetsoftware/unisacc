# D1 飞机为什么有重量，世界为什么有速度

上一轮的 Forge 空白画布只能支持面板取证。本轮从 Dash 更新帖取得作者演示，沿作者在评论中给出的独立试玩地址读到 fighterv2 的公开发布模块。三者分别能证明外观、操作意图和当前发布版的实现。原帖声称的代码大小只适用于作者当时描述的版本。[首发](https://x.com/creativedash/status/2122000830895386680)、[作者更新与视频](https://x.com/creativedash/status/2122389375673913491)、[Forge 分享页](https://forge.ui8.ai/share/frag_1eb8944c-57b1-42ca-a909-5c2d7e517c24)

## 实现线索

以页面实际加载的程序为准，按机身、投影、世界、出图四步对读。Dash 的首发 32 KB 是作者当时的说法，本轮核对的是后来发布的 fighterv2。两份复刻分别是 PKekbar 的战斗分支与 programad 的独立作品，素材与程序只作内部取证。

|取证项|Dash 的 fighterv2|Fighter + Guns v9|Raidwing|
|---|---|---|---|
|机体表示|解码 13 个水平层，每层宽 34、长 46 格。只取有颜色的格，围绕翼面支点转动。|内联解码器同样产生 13 个 34 x 46 的子数组，与作者版一致。额外敌机及其他物件有自己的尺度。|绘制实体用各模型的宽、长、高与有色体素列表，体素带局部坐标与颜色。不同模型可用不同分辨率，本次未核出玩家飞机单一固定层数。|
|遮挡与投影|先用机翼、机头、机身竖轴把局部点变到相机空间；投影尺度为 S/(1+qV)，V 是视深，q 随视角变化。整机按视深远先近后；机内按各层与眼平面的距离降序，侧视时沿层厚补样，避免机翼裂开。|内联机体函数对 13 层计算到眼平面的距离并插入排序，场景的飞机队列也按视深排序。旋转后在低分辨率缓冲内投影。|有俯视与带焦距的投影路径；机体先按姿态转换体素坐标，像素绘制时与浮点深度缓冲比较。有些预览或模型路径另按视向排序。|
|岛、地面、云|有种子的 2048 x 2048 循环地形叠加六个尺度的噪声，用高度分布和目标陆地占比求海平面。云用独立 1024 x 1024 循环图，最多 8 个高度单位，在世界坐标中随时间平移；投影地面和云时共享视点。|内联地形同样可见从粗到细的多尺度噪声和岛云参数。该分支另有建筑、船及关卡，未逐项核实其生成规则。|岛屿关卡有自己的陆地比例和地色，地形按种子合成六个尺度再按分位划陆；云使用独立的 512 x 512 图与高度范围。|
|像素与主循环|布局时用视口宽高分别除以 Pixel size 并向上取整。手动 3 即三倍像素，0 自动按面积选 2 至 12。先画世界、天空、尾迹和飞机，再叠 HUD，主图用 Canvas 2D 提交并硬边放大。发布版另设火焰层。|同样可见按面积或指定 Pixel size 定缓冲大小，主图通过 ImageData 提交并硬边放大，另有 WebGL 火焰上下文。|主画布初始 240 x 320，布局按视口重算实际缓冲；每帧循环更新颜色、深度并提交 ImageData，CSS 硬边放大。没有把 Dash 的 Pixel size=3 作为固定约束。|

复查时从作者试玩页的入口选择 fighterv2，依次看模型尺寸、场景中的 buildWorld、drawWorld 和 drawJet，再看组件的 layout。复刻一可在 HTML 内搜 1564*13、putImageData 和 pixelated；复刻二可在入口指定的脚本内搜 createImageData、Float32Array 和 requestAnimationFrame。本轮作者场景模块 SHA-256 前 12 位为 `6fd81cbc5f7e`，战斗分支 HTML 为 `901c906aaaf8`，Raidwing 脚本为 `661de6a639aa`。[Dash 入口](https://fly.ui8.dev/src/main.tsx)、[机体](https://fly.ui8.dev/src/lib/jet-model.ts)、[场景](https://fly.ui8.dev/src/lib/eject/scene.ts)、[Fighter + Guns](https://2kp1v13.sharehtml.org/)、[Raidwing 绘制程序](https://raidwing.plocky.fun/game.661de6a639.js)

战斗分支另可在内联程序定位地形边长 2048、云图边长 1024、云层厚度参数 8 和云底高度 40。绘制时按时间在云图两个方向取模平移，速度参数分别为 7 和 3，云量决定可见等级。滚转时岛岸随视点改变，云还有自己的平移量。这比评论中的 Mode 7 类比更能解释两个深度层的相对运动。[战斗分支](https://2kp1v13.sharehtml.org/)

### 提交所有者审的 D1 路线

选择 UXE 实例切片。按高度存原创机体的调色板格，只把可见外壳的有色格提交为有厚度的实例。这样在滚转接近侧视时仍能看到翼厚；深度测试可同时处理机翼、岛和云的遮挡。世界用同一持久飞行状态与相机投影，先在低分辨率绘制，再用最近邻放大。沿用 G1 提交、G4 跨帧状态和现有实例渲染。独立的 2D 软件缓冲可直接模拟原版排序，但需另建世界投影、深度、相机和像素提交链，第一切片优先复用 UXE。[现有 WebGL 实例、深度及采样](../../../practice/uxe/renderer-webgl.js)

待批准后先验三个角度：同一机体在正后、斜后和侧滚时翼端位置、厚度及遮挡是否正确；再验同一转弯输入中近岛、云和地平线的相对位移。用固定姿态在逻辑分辨率检查缺格及透明边，在 1280 x 720 检查硬像素放大。透明混合、实例数量、帧耗和 WebGPU 一致性尚未实测。若机身外壳超预算，先比较相邻同色格合并前后的像素与耗时，再决定是否需要软件缓冲。

## 线上预览与原作差距

对象为作者站 `fly.ui8.dev` 与已发布的 `c551d9f`。Chrome 从虚拟时间预算 3 至 13 秒逐秒截了 11 张；页面各自冷启动，部分帧相同，连续动作时序另看作者视频。内部并排图 `/tmp/cdx2-d1-reference-vs-live.png` 左为作者站，右为发布页。原作截图和视频只作内部证据。

| 项目 | 原作实际表现 | 已发布预览的差距 |
|---|---|---|
| 飞行手感 | 默认背后视角，指针转向；作者视频转弯时机体滚转和视野变化连贯 | 以键位控制离散转向和升降，镜头斜后偏高，缺少指针和转弯过渡；两端同操控延迟未测 |
| 像素层叠 | 小比例、明暗分块的剪影，尾焰先于机身细节抓住视线 | 逐格光照形成积木纹，机背发灰，单个尾喷，斜视下机身过大 |
| 敌机与目标 | 起飞即可看到三架目标和锁定框 | 空域没有目标、锁定或交战 |
| 爆炸与粒子 | 作者视频可见火焰、烟和弹射反馈 | 飞机没有互动尾焰、尾迹、命中和爆炸 |
| 速度感 | 水面浪点与近岸高速掠过，远岛和云移动较慢，尾迹和火焰补充加速线索 | 只有少量稀疏的海纹和几个相近尺度的物体，HUD 数字变化明显于画面变化 |
| 云岛与配色 | 近岸连续、远岛层叠，海水深浅与泡沫分带，云在不同深度层 | 四座近似平顶岛和几组同类云，海面近似平色，地平线过早截断 |
| HUD | 机炮、导弹量及锁定框把注意力留在飞行路径上 | 网页卡片显示速度、高度和键位，缺少场内态势 |
| 音效 | 作者操控面板设有音效、音量和救援电台；发布页输入前的取证只记录画面 | 预览没有音频路径；原作各动作音效需实际带声操作确认 |

重做先验机体的可读轮廓与镜头，再验有视差的高度场和云海，最后验可玩目标、反馈与 HUD。解决的是镜头、材质和反馈差距，素材与布局按原创方案设计。每项提供同类机位的并排图供人工验收。
